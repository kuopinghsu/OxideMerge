[.lead]
OxideMerge is a visual comparison and merge tool for Windows, macOS and Linux.
Use it to review file and folder changes, combine edits and resolve merge conflicts.
It also compares binary files, images and web pages. OxideMerge is written in Rust and
is inspired by WinMerge.

This guide is also available in xref:user-guide.zh-TW.adoc[繁體中文].

[NOTE]
====
*Keyboard shortcuts on macOS.* This guide uses the Windows and Linux key names.
On macOS, use Command (kbd:[⌘]) for kbd:[Ctrl], except for kbd:[Ctrl+Tab], which uses Control.
Use Option (kbd:[⌥]) for kbd:[Alt]. Menus and tooltips show the shortcuts for your platform.
====

== About this guide

This guide explains everyday comparison and merge workflows. Start with <<first-comparison>>
for a short walkthrough, then use the chapter for your comparison type.
Menu paths such as *File → Open...* identify the menu and command to choose.
Command-line examples assume that `oxidemerge` is in your `PATH`; otherwise, use the full
path to the executable. Replace example paths with your own paths.

=== Main capabilities

* Compare two or three folders, including supported archives, and copy, delete or merge items.
* Compare and edit text, copy changes between versions, and resolve version-control conflicts.
* Compare binary bytes, image pixels and web page content.
* Exclude irrelevant differences with comparison options and reusable comparison rules.
* Export reports and patches, or save projects and text comparisons for later review.
* Run comparisons from scripts and use OxideMerge with Git.

The interface includes English, Traditional Chinese, Simplified Chinese, Japanese, Korean,
German, French, Spanish, Russian and Brazilian Portuguese.

=== Key terms

Side or pane:: One version in a comparison, shown on the left, in the middle or on the right.
A pane is the area that displays that version.
Difference:: A change between the compared versions. In text comparisons, it may span several lines.
Common ancestor or base:: The original version from which two edited versions were created.
In a three-way comparison, place it in the middle.
Conflict:: Different changes to the same area that require you to choose or edit the result.
Merge:: Copy or combine changes into a destination version.
Filter:: A rule that selects which files and folders are included.
Comparison rule:: A rule that changes which text differences count, without editing the source files.

IMPORTANT: A merge changes its destination. Before copying or saving, check the source,
destination and output path. Use read-only panes to protect versions you only need to inspect.

== Installation

Download the package for your operating system and processor from
https://github.com/kuopinghsu/OxideMerge/releases[GitHub Releases].
Releases also include English and Traditional Chinese PDF guides. The release page lists each
download's SHA-256 digest for verifying it.

[cols="1,3"]
|===
|Platform |Package

|Windows 10 or 11, x64 / Arm64
|`oxidemerge-<version>-windows-x64.zip` or `oxidemerge-<version>-windows-arm64.zip`.
Extract it and run `oxidemerge.exe`; there is nothing to install.

|Linux x64 / Arm64
|AppImage (Ubuntu 20.04, RHEL 8, Debian 10 and newer) or TAR.GZ archive.
Choose `linux-x64` for Intel/AMD or `linux-arm64` for 64-bit Arm.

|macOS 11 and newer
|`oxidemerge-<version>-macos-universal.dmg` (Apple silicon and Intel).
|===

Linux::
Use a desktop session with X11 or Wayland.
Run `chmod +x oxidemerge-*.AppImage` before starting the AppImage.
Without FUSE, start it with `--appimage-extract-and-run`.
File dialogs require `xdg-desktop-portal`, normally included with your desktop environment.
Install a suitable CJK font, such as Noto Sans CJK, to display Chinese, Japanese and Korean text.

macOS::
Open the DMG and drag *OxideMerge* to *Applications*.
The app is signed ad hoc and is not notarized, so macOS may block the first launch.
Try to open it once, then choose *Open Anyway* in *System Settings → Privacy & Security*.
Up to macOS 14, Control-clicking the app and choosing *Open* also works.
From Terminal, you can use the full executable path. To make the shorter `oxidemerge`
command available, create a link in an existing directory in your `PATH`, for example:
+
[source,sh]
----
sudo ln -s /Applications/OxideMerge.app/Contents/MacOS/oxidemerge /usr/local/bin/oxidemerge
----

Building from source::
Install a Rust toolchain from https://rustup.rs/ and run `cargo build --release --locked`
from the repository root. The executable is `target/release/oxidemerge`
(`target/release/oxidemerge.exe` on Windows).
See xref:../README.md#development[Development in the README] for prerequisites and checks.

== Getting started

[[first-comparison]]
=== Your first comparison

. Choose *Compare files or folders* on the start page.
. Select an older file as *Left* and a newer file as *Right*.
. Enable *Read-only* for either side that you want to protect, then click *Compare*.
. Press kbd:[Alt+↓] to move to the next difference.
. To merge a difference, check the destination and use the arrow pointing toward that pane.
. Review the result. Use *File → Save as* for a separate output file, or *Save* to update
  the pane's current file.

For a comparison without edits, keep both sides read-only. Export an HTML report if you need
to share the review without sending the original files.

=== Choosing a workflow

Review two versions:: Open two files or folders. Use read-only sides when changes are not needed.
Combine two edited versions:: Open three versions in the order left, base, right.
See <<three-way-merge>> for output selection and conflict review.
Resolve a conflict file:: Open the single file with conflict markers. See <<conflict-files>>.
Review many changed files:: Start with a folder comparison, then open *All differences*.
Repeat the same comparison later:: Save a project. To preserve the text and review notes,
save a comparison instead. See <<projects>> and <<saved-comparisons>>.

=== The main window

.The start page
image::start.png[Start page]

The window has these parts:

Menu bar:: *File*, *Edit*, *View*, *Compare*, *Merge*, *Tools* and *Help*.
Commands that are unavailable for the current tab are disabled.
Buttons at the top right:: *Open*, theme selection, *Options*, *Command palette* and
*Help & Shortcuts*.
Tabs:: Each comparison opens in a separate tab.
Right-click a tab to close it, the others, the tabs to its right, or all of them.
kbd:[Ctrl+Tab] and kbd:[Ctrl+Shift+Tab] switch tabs, and kbd:[Ctrl+W] closes the current one.
Status bar:: The number of differences, the current line or offset, and at the right end the
interface language.
Change the language under *Options → General*, or start OxideMerge with `--lang`.

Starting OxideMerge without a comparison shows the start page.
It has *Compare files or folders*, *Open conflict file*, and the list of recent comparisons.
Right-click a recent comparison to change its paths or remove it from the list.

=== Opening a comparison

There are several ways to start a comparison:

* *File → Open...* (kbd:[Ctrl+O]) or *Compare files or folders* on the start page opens the
  *Select files or folders* dialog.
* Drop two or three files or folders onto the window.
  Dropping a single item opens the dialog with that item filled in.
* Pick a recent comparison on the start page, from *File → Open recent*, or in the command palette.
* Start OxideMerge from the command line (see <<command-line>>) or from the file manager
  (see <<file-manager>>).

In the *Select files or folders* dialog:

. Enter or browse for the *Left* and *Right* paths.
  A path can be a file, a folder or an `http://` or `https://` address.
  Enable *3-way compare* to add a *Middle* path.
. Enable *Read-only* next to a side to protect it from changes.
  *Swap left/right* exchanges the two sides.
. For folders, choose *Include subfolders*, a *Filter* and the *Compare method*.
. Choose *Compare as* to select text, binary, image or web page comparison.
  *Automatic* selects a type from the paths, extensions and file contents (see <<compare-types>>).
. Click *Compare*.

TIP: *File → New text compare* (kbd:[Ctrl+N]) opens two empty sides.
Paste text into them with kbd:[Ctrl+V], or double-click a line to type.

[[compare-types]]
=== Comparison types

With *Compare as* set to *Automatic*, OxideMerge selects the comparison type in this order:

. An `http://` or `https://` address on any side opens a web page compare.
. Folders on every side open a folder compare.
. Archives on every side are extracted and compared as folders.
. Files that all have image extensions (`.png`, `.jpg`, `.gif`, `.bmp`, `.tif`, `.webp` and more)
  open an image compare.
. A file with a zero byte in its first 8 KB opens a binary compare, unless an unpacker plugin
  turns it into text (see <<unpackers>>).
  UTF-16 text with a byte order mark still counts as text.
. Anything else opens a text compare.

*Compare as* in the dialog, *Compare → Compare as* in an open tab, or `-t` on the command line
overrides automatic selection.
Each comparison type supports different operations:

Text:: Lines side by side, with changed words highlighted.
Editable panes support text changes and merging. Comparison options and rules determine
which changes count as differences.
Use it for source code, configuration files, CSV and anything else that is readable text.
Binary:: Bytes in a hex view.
Differences can be copied and saved, but there is no line alignment: a byte inserted near the
start shifts everything after it.
Image:: Pixels, side by side, overlaid, swiped, blinking or as a difference image.
Differing regions can be copied between images.
Folder:: The items of two or three folders, compared by the chosen compare method.
Items are copied, deleted and merged here, and each file opens in its own compare.
Web page:: Two or three pages, as visible text, full page or visible area screenshots with the
text differences highlighted, HTML source or downloaded resources.
Web pages are read-only: nothing is saved back to a server.

Each type is described in its own chapter below.

=== Getting help

* *Help → Help & Shortcuts* (kbd:[F1] or kbd:[?]) lists every keyboard shortcut and mouse
  action by view, and shows where the settings file is stored.
* *Help → Command palette* (kbd:[Ctrl+K] or kbd:[Ctrl+Shift+P]) searches commands, recent
  comparisons and settings.
  Type part of a name, then press kbd:[Enter].
  Settings that can be switched on and off show whether they are on.

== Folder comparison

.A folder compare
image::folder.png[Folder compare]

A folder comparison lists the items in two or three folders and shows their comparison results.
Results appear while the comparison runs: files are compared during the folder scan, and
differences and unique items are listed as soon as they are found.
When a long comparison finishes while the window is in the background, OxideMerge asks for
attention.

=== The folder list

Each row shows the *Name*, the *Folder* it is in, the *Comparison result*, the dates and sizes on
each side, and the *Extension*.
Click a column header to sort by it.

The comparison result can be:

* *Text files are identical* or *Text files are different*;
* *Binary files are identical* or *Binary files are different*;
* *Folders are identical* or *Folders are different*;
* *Left only*, *Right only* or *Middle only*, for items found on one side;
* *Left is different*, *Middle is different* or *Right is different*, in a 3-way compare;
* *Error*, when an item could not be read.

The status bar counts the identical, different and unique items and the errors.

In *View → Folder list*:

* *Tree mode* shows subfolders as a tree.
  Turn it off for a flat list.
  kbd:[→] and kbd:[←] expand and collapse a folder, and the toolbar has *Expand all* and
  *Collapse all*.
* *Show* hides or shows *Identical*, *Different*, *Left only*, *Middle only* and *Right only*
  items.
* *File compare below the folder list* shows the differences of the selected file under the list,
  without opening a tab.

=== The toolbar

From left to right:

* *Refresh* (kbd:[F5]) compares again.
* *Expand all* and *Collapse all*, in tree mode.
* *Copy to right* and *Copy to left* copy the selected items.
* *Select by name...* selects the items whose names match wildcards such as `*.c; *.h`.
* *All differences* opens every changed text file in one tab (see <<all-differences>>).
* *Export HTML* saves an HTML report (see <<reports>>).
* *Filter* chooses which files and folders are compared (see <<filters>>).
* *Rules* chooses the compare rules file for this compare (see <<compare-rules>>).
* *Compare method* chooses how files are compared.
* *Find by name* (kbd:[Ctrl+F]) shows only the items whose names contain the text.

[[compare-methods]]
=== Comparison methods

[cols="1,3"]
|===
|Method |How files are compared

|Full contents
|Text files are compared line by line, using the compare options and rules.
Files differing only in ignored ways count as identical.

|Quick contents
|The bytes are compared.
Different file sizes are detected without reading the file contents.

|Binary contents
|Compares bytes like *Quick contents*, and classifies the result as binary.

|Modified date
|The modification dates are compared, within the *Date tolerance* set under *Options → Folder*.

|Modified date and size
|Both the dates and the sizes must match.

|Size
|Only the sizes are compared.
|===

For byte comparisons, files are read in chunks rather than loaded completely.
Files of different sizes can be identified without reading their contents.
A full text comparison may still need to load changed files into memory.

Use *Full contents* when text rules and ignored differences matter. Use *Quick contents* or
*Binary contents* for byte equality. Date and size methods are useful for an initial scan,
but matching metadata does not prove that the contents are identical.

=== Working with items

Select items with the mouse or the keyboard: the arrow keys, kbd:[PgUp], kbd:[PgDn],
kbd:[Home] and kbd:[End], with kbd:[Shift] to extend the selection and kbd:[Ctrl+A] to select all.
kbd:[Ctrl]+click adds an item to the selection or removes it.

* Double-click an item, or press kbd:[Enter], to compare it in its own tab.
  A folder opens in a separate folder comparison.
* Press kbd:[Space] for a *quick preview*: a colored diff of the selected file, without opening a
  tab.
  kbd:[↑] and kbd:[↓] move to the next item, kbd:[Enter] opens it, and kbd:[Space] or
  kbd:[Esc] closes the preview.
* kbd:[Alt+→] and kbd:[Alt+←] copy the selected items to the right or left.

Right-click an item for more:

* *Copy* to another side, and *Copy to folder...*, which copies the selected items of a side into
  another folder and keeps their relative paths;
* *Delete* from a side;
* *Open with associated application*;
* *Show in file manager*;
* *Copy full path*;
* *Select by name...*.

Under *Options → General*, use these settings to control file operations:

* *Confirm copy operations* asks before copying selected items.
* *Use the recycle bin when deleting* moves deleted items to the system's recycle bin or trash.
  If an item cannot be moved there, it is not deleted.
* *Keep a .bak copy when saving over a file* keeps the previous contents before replacement.

Copy and delete operations affect files on disk. They do not wait for *Save* and are not
reversed by the text editor's *Undo* command. Review the selected items and destination first.

=== Automatically merging folders

In a 3-way folder compare, the middle folder is the common ancestor.
*Merge → Auto merge folders...* brings the changes of both sides into it:

* items changed, added or removed on one side only are copied or removed;
* identical changes on both sides are applied once;
* text files changed on both sides are merged line by line when the changes do not overlap.

Before you start, enable both *Include subfolders* and *Include unique subfolders contents*
under *Options → Folder*, and let the comparison finish.

OxideMerge displays the planned copies, deletions, merges and unresolved conflicts.
Review this plan before confirming. Files with incompatible edits, unsupported content,
symbolic links or read errors are left unchanged. If a file has changed since the comparison,
refresh the comparison before trying again.

IMPORTANT: Folder operations write to disk after confirmation; they do not wait for *Save*.
The middle folder receives the merged result. Use a separate working copy as the middle folder
if you need to keep the original base folder unchanged.

=== Archives

Archives are extracted and compared as folders: zip-based formats (`.zip`, `.jar`, `.apk`,
`.docx`, `.xlsx`, `.odt`, `.epub`, `.nupkg` and more), `.tar`, `.tar.gz` / `.tgz`,
`.tar.bz2` / `.tbz2`, `.tar.xz` / `.txz` and `.7z`.
Extracted archive contents are read-only. OxideMerge does not write changes back into archives.
Archives that would extract to more than 8 GB or 500,000 files are rejected. RAR is not supported.

[[all-differences]]
== All differences

.All differences
image::alldiffs.png[All differences]

*All differences*, on the folder compare toolbar or in *Compare → All differences*, shows every
changed text file of the folder compare in one tab.
The filters and *Show* settings of the folder compare apply.

* The list on the left has every file, with its number of differences.
  *Filter files...* (kbd:[Ctrl+F]) narrows it down, and clicking a file scrolls to it.
* Each file is a card with its differences side by side.
  The arrow in a card header collapses or expands it, and the toolbar collapses or expands all of
  them.
* kbd:[Alt+↓] and kbd:[Alt+↑] step through the differences across files.
* The arrows next to a difference copy it to another side.
  In a 2-way compare the buttons in a card header copy the whole file.
* *Undo* reverses the last change.
  *Save* writes the changed files, and the folder compare refreshes afterwards.
* The button at the right of a card header opens the file in its own tab.

Copying from a side where a file is missing deletes the file when you save, along with folders
left empty.
If a file changes on disk after it was loaded, saving that card is blocked. The card offers
to discard your edits and reload the current file. Keep a copy of any edits you need before
choosing this action.

With backups enabled, a deleted file is retained as `.bak`, so its folder may remain.
Unedited cards reload when their files change on disk. *Refresh* (kbd:[F5]) also reloads
comparison rules and options. Reopen *All differences* to include newly detected changed files;
resolve or save existing edits first.

== Text comparison

.A 2-way text compare
image::text.png[Text compare]

Each side has a header with its file name and folder, the *encoding* and the *end of line* style
used when saving, and a lock button that makes the side read-only.
Choosing another encoding reloads the file using that encoding.
Check the text after changing the encoding, especially before editing or saving.

The *location pane* on the left is an overview of the whole file.
Click it to jump to that place.
Differences are colored: changed lines in amber, and lines only on one side in blue.
Within changed lines, the changed words or characters are highlighted.

=== Moving between differences

[cols="1,2"]
|===
|Keys |Action

|kbd:[Alt+↓], kbd:[Alt+↑]
|Next or previous difference

|kbd:[Alt+Home], kbd:[Alt+End]
|First or last difference

|kbd:[Alt+PgDn], kbd:[Alt+PgUp]
|Next or previous conflict, in a 3-way compare

|kbd:[Ctrl+G]
|Go to line
|===

When a file was opened from a folder compare, going past the last or first difference opens the
next or previous file with differences.

=== Copying changes and saving

Copying a text difference updates the destination pane. The file on disk changes only when
you save it. Check the active pane and the direction of the arrow before copying.

* The arrows on the divider between the sides copy the hovered or current difference.
* kbd:[Alt+→] and kbd:[Alt+←] copy the current difference, or the selected lines, to the
  right or left.
* kbd:[Ctrl+Alt+→] and kbd:[Ctrl+Alt+←] copy all differences.
* kbd:[Ctrl+Z] undoes and kbd:[Ctrl+Y] or kbd:[Ctrl+Shift+Z] redoes.
* kbd:[Ctrl+S] saves the current file and kbd:[Ctrl+Shift+S] saves all of them.
  *File → Save as* saves one side under another name.

For ordinary files, OxideMerge writes to a temporary file in the destination folder, then
replaces the destination. If staging or replacement fails, it reports an error rather than
writing directly over the original. The destination folder must allow temporary-file creation
and file replacement, even when the destination file itself is writable.

Enable *Keep a .bak copy when saving over a file* under *Options → General* to preserve the
previous contents as `<name>.bak`. A later save replaces that backup; it is not a version history.

=== Editing

Each writable pane supports line-based editing.

* Double-click a line, or press kbd:[F2] or kbd:[Enter], to edit it.
* Select lines by dragging, with kbd:[Shift]+click, or with kbd:[Shift+↑] and kbd:[Shift+↓].
* kbd:[Ctrl+C] copies the selected lines, and kbd:[Ctrl+V] pastes below the current line or over
  the selected lines.
* kbd:[Ctrl+\]] and kbd:[Ctrl+[] indent and unindent the selected lines.

Right-click a line to edit it, insert a line below it, delete it, copy its text, set a bookmark,
or add a compare rule built from it (see <<add-rule>>).

Edit markers in the gutter show which lines changed since the files were opened.
When another program changes a file, OxideMerge notices it as soon as the window gets the focus
again: files without unsaved changes reload automatically. Files with unsaved changes show a
notification with a reload option. Reloading replaces your edits with the version on disk.

=== Find and replace

* kbd:[Ctrl+F] opens the find bar.
  kbd:[F3] and kbd:[Shift+F3] find the next and previous match, and kbd:[Esc] closes the bar.
* kbd:[Ctrl+H] (kbd:[Cmd+Alt+F] on macOS) finds and replaces.
* The options are *Match case*, *Whole word* and *Regular expression*.
  With a regular expression, `$1` in the replacement is the first captured group.
* *Replace all* is a single undo step.

=== Bookmarks

* kbd:[Ctrl+F2] sets or removes a bookmark on the current line.
* kbd:[F4] and kbd:[Shift+F4] jump to the next and previous bookmark.
* *Edit → Bookmarks → Bookmark comment...* attaches a comment.
  The comment shows when you hover over the gutter, and in HTML reports.
* *Edit → Bookmarks → Clear bookmarks* removes all of them.

Bookmarks are marked in the gutter and in the location pane.

[[sync-points]]
=== Synchronization points

When the compare pairs the wrong lines, for example after a function was rewritten and moved,
tell it which lines belong together:

. Put the cursor on a line of one side and choose *Merge → Set synchronization point*
  (kbd:[Alt+S]), or right-click the line.
. Pick the matching line on the other side (and on the third side in a three-way compare) the
  same way.

Those lines are shown on one row, and the text before and after them is compared separately.
Add as many points as needed; a point that would cross another one is refused.
Synchronization points are marked in the gutter, follow their lines through edits, undo and
reloads, and are kept in saved comparisons. Choose the command again on a picked line to cancel
the pick, on a point's line to remove the point, or *Merge → Clear synchronization points* to
remove them all.

=== View options

*View → Text compare* has:

* *Location pane* and *Line detail pane*.
  The line detail pane shows the current line of every side, one above the other and wrapped, to
  spot small differences in long lines.
* *Line numbers*, *Edit markers*, *View whitespace* and *Syntax highlighting*.
* *Collapse unchanged lines* (kbd:[Alt+C]) folds unchanged lines into a bar, keeping three lines
  around each difference.
  Click the bar to show them.
* *Word wrap* (kbd:[Alt+Z]).

*View → Zoom* (kbd:[Ctrl+{plus}], kbd:[Ctrl+-] and kbd:[Ctrl+0]) changes the text size.
For CSV and TSV files, the toolbar has a *Table view* that shows the columns aligned.

[[three-way-merge]]
=== Three-way comparison and merge

.A three-way comparison
image::three.png[Three-way text comparison]

Place the files in this order: *your version, common ancestor (base), other version*.
OxideMerge compares the left and right versions with the base and combines changes into the
middle pane.

==== Choose the output before merging

By default, saving the middle pane overwrites the base file you opened. To preserve that file,
start with a separate output path:

[source,sh]
----
oxidemerge mine.txt base.txt theirs.txt -o merged.txt
----

The middle pane starts with the base contents; saving writes the result to `merged.txt`.
You can also use *File → Save as* to choose another path. Mark the left and right panes
read-only if they are only sources for the merge.

==== Merge and review conflicts

. Choose *Merge → Auto merge*. This copies changes made on only one side, and identical
  changes made on both sides, into the middle pane.
. Review the remaining conflicts with kbd:[Alt+PgDn] and kbd:[Alt+PgUp].
. Copy the required change from the left or right into the middle, or edit the middle directly.
. To keep both changes, right-click the difference and choose *Take left, then right* or
  *Take right, then left*. Review the combined text for duplicate or incompatible content.
. Save the result and check that the destination path is correct.

Automatic merging resolves text differences, but it does not verify the meaning of the result.
Review the output and run any checks required by the project before using it.

[[conflict-files]]
=== Resolving conflict files

.A conflict file opened in the 3-way view
image::conflict.png[Conflict file]

A file with version control conflict markers (`<<<<<<<`, `|||||||`, `=======` and `>>>>>>>`)
can be resolved in the 3-way view.
Open it with *File → Open conflict file...*, *Open conflict file* on the start page, or
`oxidemerge conflict.txt`.

The left side is *Mine*, the right side is *Theirs*, and the middle is the *Merged result*.
Resolve each conflict and save the middle pane to write the result back to the conflict file.
This workflow differs from opening three separate files: the original conflict file is the
output destination.

=== Comparing with a Git revision

*File → Compare with Git revision...* compares a file or folder with how it was in a Git
revision: `HEAD`, a branch, a tag or a commit.
The dialog lists recent commits to pick from.
The selected revision appears read-only on the left; the current file or folder appears on the right.
Git must be installed and available in `PATH`, and the selected path must belong to a Git repository.

From the command line, use `--git-rev`:

[source,sh]
----
oxidemerge --git-rev HEAD~1 src/main.rs
----

[[saved-comparisons]]
=== Saving a comparison for review

*File → Save comparison...* saves the text of every side, with its bookmarks and comments and the
synchronization points, in one `.oxmcmp` file.
Open it later, or send it to another reviewer, to inspect the saved text and notes.
The comparison opens read-only and does not depend on the original files being present.
It is a text snapshot, not a project that reloads current files from their paths.

NOTE: A saved comparison contains the full text of each side. An HTML report contains the
exported differences and context. Check either file for sensitive content before sharing it.

=== Patches

*File → Export → Generate patch...* writes the differences between two files or folders as a
patch in *Normal*, *Context* or *Unified* format, with the number of context lines you choose.
Patches can be made from 2-way compares only.

*File → Apply patch...* applies a unified diff, including the output of `git diff` and
`svn diff`.
OxideMerge finds each hunk even when lines have moved, and opens every patched file next to its
original so you can review the result and save it.
A hunk is one block of changes in the patch. Hunks that cannot be applied are reported;
review these messages and the resulting comparisons before saving. Applying a patch in this
workflow does not automatically approve or save all results.

== Binary comparison

.A binary compare
image::binary.png[Binary compare]

Binary files open in a side-by-side hexadecimal view. Highlighting identifies differing bytes.
The sides scroll together.

* kbd:[Alt+↓] and kbd:[Alt+↑] step through the differences.
* kbd:[Ctrl+F] finds hex bytes, such as `DE AD BE EF`, or text.
* kbd:[Ctrl+G] goes to an offset, written as `0x1F00`, `1F00h` or a decimal number.
* Differences can be copied to the other side and saved, like in a text compare.

The number of bytes per line is set under *Options → Image / Binary / Web*.

== Image comparison

.An image compare
image::image.png[Image compare]

Choose a view mode to inspect image differences:

Side by side:: The images next to each other.
Overlay:: One image over the other, with an adjustable *Opacity*.
Swipe:: One image left of a divider and the other right of it.
Drag the divider to move it.
Blink:: Alternates the images to make small changes easier to see.
Difference:: The pixel differences.

* *Highlight differences* marks the differing regions.
  *Color distance threshold* sets how different two pixels must be to count, and *Block size*
  sets the size of the marked blocks.
* Zoom with the buttons, the mouse wheel or a pinch, around the pointer.
  *Fit* fits the images to the window and *1:1* shows them at their real size.
* Drag, or scroll with two fingers, to move all the images together.
* Click a differing region to select it.
  kbd:[Alt+↓] and kbd:[Alt+↑] step through the regions, and kbd:[Alt+→] and
  kbd:[Alt+←] copy the current region to the other image.
  *Undo* reverses the copy, and kbd:[Ctrl+S] saves the changed image.

== Web page comparison

Compare two or three `http://` or `https://` addresses, or local HTML files compared with
*Compare as → Web page* (`-t web` on the command line).
Use the mode selector at the top of the tab. OxideMerge remembers the last selected mode:

Text:: The text you see on each page, one block per line: each heading, paragraph, list item,
table cell, form field value and line of preformatted text is one line, and hidden elements are
left out. It opens in the text compare, so changed words are highlighted within each line, and
the comparison options, filters and reports all apply. This is the default mode.
Full page:: A screenshot of each whole page, from top to bottom, in the image view. With
*Highlight differences* on, the text that differs between the pages is highlighted on the page
itself before the screenshot: changed blocks in yellow and the changed words in them in orange,
like WinMerge's *View Differences*. Because text is compared rather than pixels, a change that
moves the rest of the page down does not mark everything below it. Pages taller than 16384
pixels are cut.
Screenshot (visible area):: The same, for the top of each page only (the screenshot width and
height).
HTML source:: The page's HTML after its scripts have run, with long minified lines split between
tags, in the text compare.
Resource tree:: Downloads each page with its stylesheets, scripts, images, frames and media, and
compares the downloaded files in the folder compare.

Text, HTML source and the screenshots come from a Chromium-based browser that runs without a
window (Edge, Chrome, Chromium and Brave are detected automatically), so they show each page
after its scripts have run, as you would see it. The pages load at the same time, each in its own
tab, and are taken as they are after 45 seconds. Without a browser, or with *Render pages in the
browser for text and HTML* turned off, Text and HTML source use the HTML as downloaded instead:
scripts do not run, and content they add is missing. If the browser fails, they fall back to the
HTML as downloaded too, and the status bar says why.
The console compare (`--cli -t web`) compares the same text, or HTML with the HTML source mode.
On macOS and Linux OxideMerge talks to the browser over a private pipe; on Windows, over a port
that only this computer can reach, open while the pages load.

Pages are decoded as browsers do: a byte order mark comes first, then the charset of the HTTP
`Content-Type` header, then a `<meta>` charset, then a guess from the content.
HTTP status codes other than 2xx are shown in the pane header, and the page that came with them
is compared.
A page that cannot be reached, times out after 30 seconds, sends a malformed response or is larger
than 50 MB is reported with its address.

The resource tree reads the resources named in each page itself, at most 400 per page and 20 MB
each; it does not follow the links in stylesheets or scripts.
Resources that cannot be downloaded are counted in the status bar, and the rest are still compared.
A web page may not load local files, and only a page on this computer or a private network
(such as `localhost` or `192.168.x.x`) may load resources from one, or be redirected to one;
other such resources are skipped and counted.
The addresses you enter are always loaded.
The screenshot size and the browser are set under *Options → Image / Binary / Web*.
Leave the browser path empty to detect a supported browser automatically.
Switching modes loads the pages again; use *Reload* (kbd:[F5]) after a page changes.
Local HTML files require `-t web` or an explicit *Compare as → Web page* selection; otherwise,
they normally open as text.

NOTE: The resource tree compares the HTML as delivered by the server; the other modes run page
scripts when a browser is used. Authenticated sessions are not supported; a page that requires a
login may show its login page. Pages rendered by the browser load everything they ask for, so the
resource tree limits do not apply to them. No mode saves changes back to a web server.

== Controlling which differences are shown

Use *filters* to select files and folders. Use *comparison options* and *comparison rules*
to control which differences within text count. These settings affect comparison results;
they do not rewrite the source files.

If a change appears to be missing, review these settings before concluding that the files
are identical.

[[compare-options]]
=== Comparison options

Use *Compare → Compare options* for common settings. All comparison options are available
under *Options → Compare*:

Whitespace::
*Compare* treats whitespace as significant. *Ignore changes* ignores differences in the amount
of whitespace. *Ignore all* ignores whitespace completely.
Ignore blank lines:: Extra blank lines do not count as differences.
Ignore case:: Uppercase and lowercase letters are treated as equal.
Ignore carriage return differences (Windows/Unix/Mac):: `CRLF`, `LF` and `CR` line endings are
equal.
Ignore numbers:: Digits are ignored.
Ignore code page differences:: Files in different encodings with the same text are equal.
Ignore comment changes:: Changes limited to comments do not count, for languages whose comment syntax
is known (C-like languages, scripts, SQL, HTML/XML, CSS, Lua, Haskell and more).
Format JSON and XML before comparing:: Re-indents JSON and XML and sorts JSON keys to reduce
formatting differences. The formatted view is read-only. Turn this option off to edit or merge.
Detect moved lines:: Blocks of lines that moved are shown as moves.
Diff algorithm:: *Myers*, *Patience* or *LCS*.
Inline differences:: *Off*, *Word level* or *Character level*.
Treat numbers as equal within:: Numbers at most this far apart, for example `0.001`, count as
equal.
Useful for measurements and generated data.

These options also apply to text files in folder comparisons using *Full contents*.
Quick, binary, date and size methods do not use text comparison rules.

[[compare-rules]]
=== Comparison rules

A comparison rules file (`.oxrules`) can contain three kinds of rules:

Ignore lines matching:: One regular expression per line.
Differences made up only of matching lines are ignored.
Substitutions:: One rule per line, written `+regex => replacement+`.
They are applied to both sides before comparing, so text that differs in an expected way
compares equal.
Ignore blocks between start and end lines:: One block per line, written
`+start regex => end regex+`.
Differences inside a block, such as a generated section or a license header, are ignored.

Patterns are regular expressions in the syntax of the Rust `regex` crate.

.Options → Compare rules
image::rules.png[Compare rules options]

*Options → Compare rules* manages the files:

* Choose *None* or a rules file.
  The selected file is the default for comparisons that do not select a different rules file.
* *Edit* changes a file in the rules editor, and *Delete* removes it.
* *New rules file* creates one.
* *Open rules folder* shows the folder in the file manager, and *Reload* reads it again after you
  change files there.
* *Import...* adds rules files shared by others, and *Export* saves one file, or all of them to a
  folder.

A folder compare can use a different file: pick it from *Rules* on its toolbar, or from
*Compare → Compare rules*.
*Refresh* (kbd:[F5]) reads the rules file again.

Dropping a single `.oxrules` file on the window imports it too, as does dropping any number of
them on the options; dropping two on the window compares them instead.
When rules files are imported:

* a file with the same name and rules as one already there is skipped;
* a file named like an existing one but with other rules is added under a numbered name;
* a file with the same rules under another name is added as it is.

The files live in the `Rules` folder next to the settings file (see <<configuration>>).
A `Rules` folder next to the program is read too.
A rules file is plain JSON, and its name is the file name without `.oxrules`:

.Build logs.oxrules
[source,json]
----
{
  "description": "Timestamps and generated headers in build logs",
  "ignore_lines": ["^\\[\\d{2}:\\d{2}:\\d{2}\\]", "^// Generated on .*$"],
  "substitutions": [{ "find": "\\b0x[0-9a-fA-F]{8,}\\b", "replace": "0xADDR" }],
  "ignore_blocks": [{ "start": "^/\\* BEGIN LICENSE", "end": "END LICENSE \\*/$" }]
}
----

[[add-rule]]
=== Adding a rule from a text compare

Right-click a line in a text compare and choose *Add compare rule*, then the kind of rule:

Ignore lines like this:: A pattern matching the line, or every side of a changed line.
Substitute:: A substitution that turns the text of one side into the other.
Ignore block:: A block starting at the line.

The dialog suggests a pattern built from the line, which you can change.
Choose the *Rules file* to add it to, or give a *File name* to create a new one.
The current comparison applies the rule immediately.
Other folder compares that use the same file pick up the change when refreshed (kbd:[F5]).

[[filters]]
=== Filters

Filters decide which files and folders a folder compare includes.
Choose one from *Filter* on the folder compare toolbar, or manage them in *Tools → Filters...*.

A filter mask is a list of wildcards separated by `;`.
A leading `!` excludes matches, and a trailing `\` or `/` matches folders:

----
*.rs;*.toml;!target\
----

WinMerge `.flt` filter files in the `Filters` folder of the configuration folder are listed too.
*Tools → Filters...* shows them, opens the filters folder, and creates new ones.

[[unpackers]]
=== Unpacker plugins

Unpacker plugins convert files to text before comparison. Use them for document formats that
need an external conversion tool. Install the conversion program separately and make it
available to the configured command.
Add them under *Options → Plugins*: a *File pattern*, such as `*.docx`, and a *Command line* in
which `${file}` is replaced by the path of the file, already quoted.
OxideMerge compares the command's standard output as text. For example, with Pandoc installed:

----
pandoc -t plain ${file}
----

[[reports]]
== Reports, statistics and projects

=== Creating and sharing an HTML report

. Open a text or folder comparison and confirm that it has finished.
. Check the active options, rules and folder filters; these affect the reported differences.
. Choose *Export HTML* and select the output file.
. Open the report and check its scope before sharing it.

Exporting a report does not save edits back to the compared source files.

*Export HTML* on the toolbar of a text or folder compare, or *File → Export → Export HTML
report...* (kbd:[Ctrl+Shift+E]), saves a report and opens it in the browser.
The suggested file name uses the compared names, with spaces replaced by `_`.

The report is a single self-contained page.
It lists every difference as a card with line numbers, three lines of context and changed words
highlighted.
It has summary cards, an index, side-by-side or unified view, light and dark themes, and file
filters and search.
kbd:[N] and kbd:[P] step through the differences.
It identifies the comparison rules file and counts ignored differences.
The recipient can open the report in a browser without installing OxideMerge.

A folder report includes the differences of every changed text file.
Turn off *File → Export → Open reports in the browser after saving* to only save it.

=== Folder summaries and detailed reports

* *File → Export → Generate report...* writes a folder report as HTML, CSV, plain text or XML,
  and a text compare report as HTML or XML, by the file type chosen.
* *File → Export → Generate report with file differences...* adds the differences of every
  changed text file to an HTML folder report.

=== Slideshows

*File → Export → Generate slideshow report...* saves an HTML page that shows one difference at a
time, for walking others through a change in a meeting or a review.
A title slide names the compared sides and counts the differences; then each difference has a
slide of its own, with its lines, the lines around it, changed words highlighted and any bookmark
comments. A folder compare's slideshow has a slide for each difference of every changed text file,
and ends with a list of the files that differ in other ways, such as binary files or files on one
side only. Ignored differences are left out.

In the browser, the arrow keys, kbd:[Space], kbd:[PgUp] and kbd:[PgDn] move between slides,
kbd:[Home] and kbd:[End] go to the first and last, and kbd:[F] switches to full screen.
Each slide has its own address (`#3` for the third), so you can link to it.
Printing the page prints one slide per page.

=== XML reports

An XML report is for other programs: scripts, review tools or a build that checks what changed.
Choose the `.xml` type when generating a report, or give `--report <name>.xml` on the command line.
A text compare report lists every difference with its kind (`changed`, `added`, `removed`, or for
three-way compares `left-only`, `right-only`, `both-same`, `conflict`), whether it is ignored,
and the lines of each side with their numbers, then the bookmarks with their comments.
A folder report lists every file and folder with its status, and its date and size on each side.

[source,xml]
----
<comparison format="1" tool="OxideMerge" version="0.9.6" type="text" created="…">
  <side index="0" role="left" name="a.txt"/>
  <side index="1" role="right" name="b.txt"/>
  <statistics differences="1" ignored="0" identical-lines="1" changed-lines="1" added-lines="0" removed-lines="0"/>
  <differences>
    <difference index="1" kind="changed" ignored="false">
      <lines side="0" start="2" count="1"><line number="2">two</line></lines>
      <lines side="1" start="2" count="1"><line number="2">TWO</line></lines>
    </difference>
  </differences>
</comparison>
----

Line numbers start at 1. A side with no lines in a difference has `count="0"`, and `start` is
the line the text would go before. `format` changes only when the layout changes in a way that
could break a program reading it.

=== Viewing statistics

*Tools → Statistics...* shows:

* for a folder compare, the numbers of identical, different and unique files, errors, and the
  total size of each side;
* for a text compare, the identical, changed, added, removed and ignored lines, for each pair of
  sides.

[[command-line]]
== Command-line reference

=== Opening comparisons

Run `oxidemerge` without arguments to open the start page. Use two or three paths for a
comparison, or one path for a conflict file, project or saved comparison.
Quote paths that contain spaces. The following examples use POSIX shell syntax; on Windows,
use Git Bash for these examples or adapt them to your shell.

[source,sh]
----
oxidemerge left.txt right.txt                   # 2-way text compare
oxidemerge mine.txt base.txt theirs.txt         # 3-way compare (middle = base)
oxidemerge -r old-folder new-folder            # include subfolders
oxidemerge -r -f "*.rs;!target/" old new        # folder compare with a filter
oxidemerge conflict.txt                         # resolve a file with conflict markers
oxidemerge -t image a.png b.png                 # force the compare type
oxidemerge https://example.com https://example.org   # web page compare
oxidemerge left.txt right.txt -o merged.txt     # Save writes the right pane to merged.txt
oxidemerge release.oxmproj                      # open a saved project
oxidemerge -r old.tar.gz new.tar.gz             # compare archives as folders
oxidemerge --git-rev HEAD~1 src/main.rs         # compare with an earlier Git revision
oxidemerge review.oxmcmp                        # open a saved comparison
----

=== Scripting

`--cli`, `--report` and `--patch` run without opening a window. They return these exit codes:

* `0`: the compared content is identical under the active options and rules;
* `1`: differences were found, including when a report or patch was written successfully;
* `2`: an error occurred.

Scripts must treat `1` as a comparison result rather than a program failure. The command-line
comparison also uses saved options unless you override them. For isolated runs, set
`OXIDEMERGE_CONFIG_DIR` to a dedicated folder (see <<configuration>>).
Reports are supported for text and folder comparisons. A binary or image comparison does not
produce an HTML report; the program prints a diagnostic message instead.

[source,sh]
----
# Compare without a window; differences are also printed
oxidemerge --cli -r dirA dirB

# HTML report of a folder compare, with the differences of every changed file
oxidemerge -r dirA dirB --report report.html --report-diffs

# HTML report of two files, ignoring comment changes
oxidemerge old.c new.c --ignore-comments --report diff.html

# Unified diff with 5 lines of context
oxidemerge old.c new.c --patch changes.patch --context 5

# Use a compare rules file
oxidemerge --cli -r build1 build2 --rules "Build logs"
----

To handle differences correctly in a shell that uses `set -e`, capture the result explicitly:

[source,sh]
----
result=0
oxidemerge --cli -r old-folder new-folder || result=$?
case "$result" in
  0) echo "No differences" ;;
  1) echo "Differences found" ;;
  *) echo "Comparison failed" >&2; exit "$result" ;;
esac
----

=== Git integration

Install Git and make `oxidemerge` available in `PATH`. Run these commands in a POSIX-compatible
shell, such as Bash or Git Bash. They set the diff and merge tools for your user account:

[source,sh]
----
git config --global diff.tool oxidemerge
git config --global difftool.oxidemerge.cmd 'oxidemerge "$LOCAL" "$REMOTE"'
git config --global merge.tool oxidemerge
git config --global mergetool.oxidemerge.cmd \
  'oxidemerge "$LOCAL" "$BASE" "$REMOTE" -o "$MERGED" --dl Local --dr Remote --wl --wr'
git config --global mergetool.oxidemerge.trustExitCode false
----

* `git difftool` opens each changed file.
  `git difftool --dir-diff` opens one folder compare of all of them, and kbd:[Alt+↓] past the
  last difference moves on to the next changed file.
* `git mergetool` opens a 3-way merge with the common ancestor in the middle.
  Auto merge, or copy differences into the middle, then save: the middle is written to the merged
  file, never to the base.
  With `trustExitCode false`, Git checks whether the output changed and may ask you to
  confirm success if it appears unchanged.
  Confirm success only after saving and reviewing the result; closing the window alone does
  not indicate a successful merge.
* On macOS, use the full path `/Applications/OxideMerge.app/Contents/MacOS/oxidemerge`, unless you
  linked it into your `PATH`.
  On Windows, use the path of `oxidemerge.exe`.

[[file-manager]]
== File manager integration

The *Tools* menu, or `oxidemerge --register-shell`, adds OxideMerge to the file manager:

Windows:: *Tools → Add to Explorer context menu* adds an *OxideMerge* submenu for files, folders,
drives and folder backgrounds.
On Windows 11 it is under *Show more options*.
macOS:: *Tools → Add Finder Quick Actions* adds *OxideMerge: Compare*, *OxideMerge: Select Left*
and *OxideMerge: Select Middle* to the Quick Actions and Services menus of Finder.
Linux:: *Tools → Add to file manager context menu* adds the same entries to Nautilus, Nemo and
Dolphin.

The entries work like this:

* *Compare* compares the two or three selected files or folders.
  With one item selected, it compares the item with the side chosen earlier, or opens the
  *Select files or folders* dialog with the item filled in.
* *Select Left* and *Select Middle* remember an item, for example in another folder.
  *Compare* then reads *Compare to "name"*.
* *Compare as* (Windows, files only) compares as text, binary, image or web page.

The entries refer to the executable used for registration. Register again if you move it.
Use the corresponding *Tools* command, or `oxidemerge --unregister-shell`, to remove the entries.

== Configuration

Application options are stored as JSON in the user configuration folder:

[cols="1,3"]
|===
|System |Settings file

|Windows |`%APPDATA%\OxideMerge\config.json`
|macOS |`~/Library/Application Support/OxideMerge/config.json`

* `Filters`: WinMerge `.flt` filter files;

Portable use:: Create an empty `oxidemerge.json` next to the executable.
OxideMerge stores application options in that file. The executable folder must be writable.

Separate configuration:: Set `OXIDEMERGE_CONFIG_DIR` to a folder to use its `config.json`.
This setting takes precedence over portable mode and the default configuration folder.
It is useful for scripts, testing and separate work environments.

Languages:: To add or change a language, copy `lang/en.json` from the source code to
`<code>.json`, translate the values, keeping every `{placeholder}` as it is, and put the file in a
`Languages` folder next to the program or in the configuration folder.
Missing messages, and translations with missing or additional placeholders, are displayed in English.

== Troubleshooting

Read the error message first and note the affected path. Before repeating a merge or save,
check the destination, available disk space, permissions and whether another program changed
the file.

A web screenshot mode reports that no browser was found::
The screenshot modes need Edge, Chrome, Chromium or Brave.
Set the browser under *Options → Image / Binary / Web*.

A pane cannot be edited::
It is read-only: the lock in its header is closed, it was opened with `--wl`, `--wm` or `--wr`,
it was extracted from an archive, or it is JSON or XML shown formatted.
Turn off *Format JSON and XML before comparing* to edit and merge those files.

A file cannot be saved because of its encoding::
The selected encoding cannot represent some characters in the edited text.
Preserve your edits in another location before changing the encoding, because selecting an
encoding reloads the source file. Alternatively, undo the unsupported characters and save again.

A save or copy fails although the file is writable::
Replacing a file also requires permission to create a temporary file and replace entries in
its destination folder. Check folder permissions, free space and locks held by other programs.
OxideMerge reports staging and replacement failures instead of directly overwriting the original.
Keep the comparison open until you have saved the edited contents successfully.

Files look identical even though their bytes differ::
Review whitespace, case, line-ending, encoding and comment options, and the active comparison
rules. A text comparison may intentionally ignore these differences. Use a binary comparison
or the *Binary contents* folder method when byte-for-byte equality is required.

Expected files are missing from a folder comparison::
Check the file filter, hidden-file options, *Include subfolders*, and the *Show* settings.
*Find by name* also limits visible rows. *All differences* uses the folder comparison's filters
and display settings; it does not automatically include hidden results.

macOS refuses to open the app::
Try to open it once, then choose *Open Anyway* in *System Settings → Privacy & Security*.
Or clear the download flag in Terminal:
`xattr -dr com.apple.quarantine /Applications/OxideMerge.app`.

macOS asks for access to a folder, or a compare shows files as errors::
macOS asks once before OxideMerge reads Desktop, Documents, Downloads, removable or network
volumes; allow it, or turn it on later in *System Settings → Privacy & Security → Files and
Folders*.
On any system, a file that cannot be read is shown as an error, and the message names the file.
Check its permissions.

The AppImage does not start::
Make it executable with `chmod +x`.
If the message mentions FUSE, start it with `--appimage-extract-and-run`.

The window stays blank or does not open on Linux::
OxideMerge draws with OpenGL.
Without a working graphics driver (in a virtual machine, for example), start it with
`LIBGL_ALWAYS_SOFTWARE=1 oxidemerge` to use Mesa's software renderer.

File dialogs do not open on Linux::
They use the XDG desktop portal.
Install `xdg-desktop-portal` and the one for your desktop, such as `xdg-desktop-portal-gtk` or
`xdg-desktop-portal-kde`.

The file manager entries are missing::
On Windows 11 they are under *Show more options*.
They point at the program that added them, so after moving or updating it to another folder, add
them again from the new copy.
On Linux, restart the file manager (`nautilus -q`, for example) to see new entries.

Application settings are not saved::
OxideMerge reports the reason when it cannot save settings.
Check that the configuration folder (see <<configuration>>) can be written and that the disk
is not full.

Automatic folder merging does not start, or skips files::
Let the comparison finish with both *Include subfolders* and *Include unique subfolders contents*
enabled. Files that changed after comparison are skipped and listed. Refresh the comparison
and review the merge plan again.

A web comparison is missing content shown in the browser::
Check that a browser is found and *Render pages in the browser for text and HTML* is on; without
them, Text and HTML source use the HTML delivered by the server, and miss content added by
scripts. The resource tree always uses the delivered HTML. Content inside frames is not included.
Resources that could not be downloaded, or were skipped as being on this computer or a private
network, are counted in the status bar.

Large files are slow or use a lot of memory::
Text comparisons keep decoded text, comparison data and editing history in memory.
Memory use depends on the content and operations; binary and image views also load complete files.
Compare files of several hundred MB as binary, or compare folders by size and date instead of
contents (see <<compare-methods>>).

== Known limitations

* Archive support covers ZIP-based formats, TAR (plain, gzip, bzip2 and xz) and 7z. RAR is not
  supported. Extracted archive contents are read-only.
* Text editing is line-based and intended for reviewing and merging changes.
* Unpacker plugins use external commands. WinMerge plugin DLLs and scripts are not supported.
* Web page compare does not support cookies or logins; a page behind a login shows its login page.
  Without a Chromium-based browser, page scripts do not run, so content they add is missing.
  Content inside frames is not compared. A page rendered by the browser loads everything it asks
  for, without the resource tree's limits.
* Machine-assisted translations have not been reviewed by native speakers.
