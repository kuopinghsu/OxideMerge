[.lead]
OxideMerge 是一套圖形化的檔案與資料夾比較及合併工具，可在 Windows、macOS 與 Linux 上執行。
您可以用它檢查變更、整合不同版本的修改，以及解決合併衝突，
也能比較二進位檔、影像與網頁。
OxideMerge 以 Rust 撰寫，設計參考 WinMerge。

本指南另有 xref:user-guide.adoc[英文版]。

[[introduction]]
== 簡介

=== OxideMerge 能做什麼

* 比較兩個或三個資料夾（包括壓縮檔），並複製、刪除或合併其中的項目。
* 比較與編輯文字檔，在版本之間複製變更，以及解決版本控制產生的衝突。
* 比較二進位檔的位元組、影像的像素與網頁的內容。
* 透過比較選項與可重複使用的比較規則，略過不重要的差異。
* 匯出報告與修補檔，或儲存專案與比較結果，方便日後檢閱。
* 從指令碼執行比較，或將 OxideMerge 設為 Git 的比較與合併工具。

介面提供英文、繁體中文、簡體中文、日文、韓文、德文、法文、西班牙文、俄文、巴西葡萄牙文與義大利文。

=== 如何使用本指南

建議先閱讀 <<first-comparison>>，熟悉基本操作，再依需要的比較類型查閱對應章節。
最後幾章為參考資料，包括命令列、選項、鍵盤快速鍵與疑難排解。

本指南使用下列慣例：

* 「」括住的文字是程式中顯示的名稱，例如按鈕或選單命令。
* 「檔案 → 開啟...」這類寫法表示：先開啟「檔案」選單，再選擇「開啟...」。
* 命令列範例假設 `oxidemerge` 已在 `PATH` 環境變數中；若不在，請改用程式的完整路徑。
* 範例中的路徑（例如 `old-folder`）請換成您實際的路徑。

[NOTE]
====
*macOS 的快速鍵。* 本指南使用 Windows 與 Linux 的按鍵名稱。
在 macOS 上，請以 Command 鍵（kbd:[⌘]）取代 kbd:[Ctrl]，以 Option 鍵（kbd:[⌥]）取代 kbd:[Alt]。
唯一的例外是 kbd:[Ctrl+Tab]：在 macOS 上同樣使用 Control 鍵。
選單與工具提示一律顯示您所用系統的快速鍵。
====

=== 常用術語

側:: 比較中的一個版本，分為左側、中間與右側。
窗格:: 視窗中顯示某一側內容的區域。
差異:: 各版本之間不相同的地方。在文字比較中，一個差異可能包含好幾行。
基底（共同祖先版本）:: 兩份修改版本共同的原始版本。在三方比較中，基底位於中間。
衝突:: 兩份修改版本以不同方式變更了同一段文字，需要由您選擇或編輯結果。
合併:: 將變更複製或整合到目標版本。
篩選器:: 決定資料夾比較要包含哪些檔案與資料夾的條件。
比較規則:: 決定哪些文字差異要計入的規則，不會修改檔案本身。

IMPORTANT: 合併會變更目標內容。
複製或儲存前，請先確認來源、目標與輸出路徑。
只需要檢視的版本，建議設為唯讀。

== 安裝

請從 https://github.com/kuopinghsu/OxideMerge/releases[GitHub 發行頁面] 下載適合您系統與處理器的套件。
每個版本也附有本指南的英文與繁體中文 PDF 檔。
發行頁面會列出每個下載檔案的 SHA-256 摘要值，可用來確認檔案完整。

[cols="1,3"]
|===
|系統 |套件

|Windows 10 或 11，x64 或 Arm64
|`oxidemerge-<version>-windows-x64.zip` 或 `oxidemerge-<version>-windows-arm64.zip`

|macOS 11 或更新版本
|`oxidemerge-<version>-macos-universal.dmg`，適用於 Apple 晶片與 Intel 處理器

|Linux x64 或 Arm64
|AppImage（適用於 Ubuntu 20.04、RHEL 8、Debian 10 及更新版本）或 TAR.GZ 壓縮檔。
Intel 與 AMD 處理器請選 `linux-x64`，64 位元 Arm 處理器請選 `linux-arm64`。
|===

=== Windows

解壓縮 ZIP 檔後，直接執行 `oxidemerge.exe` 即可，不需要安裝。

=== macOS

. 開啟 DMG 檔，將「OxideMerge」拖移到「應用程式」檔案夾。
. 啟動 OxideMerge。
  本程式採用臨時簽署，未經 Apple 公證，因此 macOS 可能會阻擋第一次啟動。
  若遭到阻擋，請到「系統設定 → 隱私權與安全性」中選擇「強制打開」。
  在 macOS 14 及更早版本中，也可以按住 Control 鍵並按一下應用程式，再選擇「打開」。

若要從「終端機」啟動，請使用程式的完整路徑。
若想直接輸入 `oxidemerge`，請在 `PATH` 中的某個資料夾建立連結，例如：

[source,sh]
----
sudo ln -s /Applications/OxideMerge.app/Contents/MacOS/oxidemerge /usr/local/bin/oxidemerge
----

=== Linux

* 請在使用 X11 或 Wayland 的桌面環境中執行。
* 啟動 AppImage 前，請先讓它可以執行：`chmod +x oxidemerge-*.AppImage`。
* 若系統沒有 FUSE，請加上 `--appimage-extract-and-run` 啟動 AppImage。
* 檔案對話框需要 `xdg-desktop-portal`，大多數桌面環境已內建。
* 若要顯示中文、日文與韓文，請安裝 Noto Sans CJK 等中日韓字型。

=== 從原始碼建置

. 從 https://rustup.rs/ 安裝 Rust 工具鏈。
. 在儲存庫資料夾中執行 `cargo build --release --locked`。

建置完成的程式位於 `target/release/oxidemerge`（Windows 為 `target/release/oxidemerge.exe`）。
建置需求與檢查方式，請參閱 xref:../README_zh-TW.md#開發[讀我檔案的「開發」一節]。

== 快速入門

=== 起始頁

不指定任何比較就啟動 OxideMerge 時，會顯示起始頁。

.起始頁
image::start.png[起始頁]

起始頁包含下列部分：

比較檔案或資料夾:: 輸入「左側」與「右側」的路徑。
您可以直接輸入或貼上路徑，也可以按欄位旁的檔案與資料夾按鈕選擇。
按「三方」可加入「中間」路徑。
按「更多選項…」會開啟「選擇檔案或資料夾」對話框，並帶入這些路徑。
開啟衝突檔案:: 解決含有衝突標記的檔案，請參閱 <<conflict-files>>。
版本摘要／比較基準:: 將兩個資料夾或已儲存的審閱當作兩個版本來比較，請參閱 <<baselines>>。
最近使用:: 以卡片列出最近的比較。
+
--
* 按一下卡片，即可再次執行該比較。
* 在卡片上按右鍵，可「變更路徑...」或「從最近使用中移除」。
* 按「最近使用」標題右側的「清除」，可清空整份清單。
  「檔案 → 開啟最近使用 → 清除最近使用」的效果相同。
  清除後出現的訊息會在幾秒內提供「復原」。
--

最近使用清單是空的時候（例如第一次啟動），起始頁會顯示「開啟範例」。
按下後會開啟兩個小型範例資料夾，讓您了解比較如何運作。
範例資料夾是暫時性的：關閉分頁時 OxideMerge 就會刪除它們，也不會將範例加入最近使用清單。

[[first-comparison]]
=== 第一次比較

. 在起始頁中，將較舊的檔案填入「左側」，較新的檔案填入「右側」。
. 按「比較」。
  若要避免某一側被修改，請改按「更多選項…」，並開啟該側的「唯讀」。
. 按 kbd:[Alt+↓] 移到下一個差異。
. 若要複製某個差異，請先確認哪個窗格是目標，再按指向該窗格的箭頭。
. 檢查結果。
  若要另存成新檔，請選擇「檔案 → 另存新檔」；若要更新窗格中的檔案，請選擇「儲存」。

如果只想檢視而不修改，請將兩側都設為唯讀。
若要分享檢閱結果但不傳送原始檔案，可以匯出 HTML 報告（請參閱 <<reports>>）。

=== 主視窗

視窗包含下列部分：

選單列:: 「檔案」、「編輯」、「檢視」、「比較」、「合併」、「工具」與「說明」。
不適用於目前分頁的命令無法選取。
標題列:: 右側依序為「搜尋命令」（開啟命令面板）、「開啟」、淺色與深色主題切換、「選項」以及「說明與快速鍵」。
視窗較窄時，搜尋欄位會縮成圖示，放不下的按鈕會隱藏；選單中仍有相同的命令。
分頁:: 每個比較都在自己的分頁中開啟。
兩側檔名相同時，分頁只顯示一次檔名，後面接著不同的資料夾。
關閉按鈕的位置顯示圓點時，表示該分頁有尚未儲存的變更；將指標移到圓點上即可關閉分頁。
狀態列:: 顯示兩側是否不同，以及目前的行號或位移；最右側顯示介面語言。
差異與項目的數量則顯示在工具列與資料夾的篩選標籤上。

分頁操作：

* kbd:[Ctrl+Tab] 與 kbd:[Ctrl+Shift+Tab] 切換到下一個與上一個分頁。
* kbd:[Ctrl+W] 或 kbd:[Esc] 關閉目前的分頁。
  若有開啟中的對話框、搜尋列、預覽或編輯狀態，kbd:[Esc] 會先關閉它們。
  分頁有尚未儲存的變更時，OxideMerge 會先詢問再關閉。
* 在分頁上按右鍵，可關閉該分頁、其他分頁、右側的分頁或全部分頁。

若要變更介面語言，請使用「選項 → 一般」，或以 `--lang` 參數啟動 OxideMerge。

若要查看版本，請按一下應用程式標誌，或選擇「說明 → 關於 OxideMerge」。
對話框也會顯示建置識別碼：

* 開發版本會顯示 Git 的簡短雜湊值；
  已追蹤的檔案或 Git 索引有未提交的變更時，會加上 `-dirty`。
* 依發行標籤建置、且沒有任何修改的最佳化版本，會顯示建置日期（UTC）。

執行 `oxidemerge --version` 也會顯示相同的識別碼。

=== 開啟比較

開始比較的方式有好幾種：

* 在起始頁的「比較檔案或資料夾」中輸入路徑，再按「比較」。
* 選擇「檔案 → 開啟...」（kbd:[Ctrl+O]），或按起始頁的「更多選項…」，開啟「選擇檔案或資料夾」對話框。
* 將兩個或三個檔案或資料夾拖放到視窗上。
  只拖放一個項目時，會開啟對話框並帶入該項目。
* 從起始頁、「檔案 → 開啟最近使用」或命令面板選擇最近使用的比較。
* 從命令列（請參閱 <<command-line>>）或檔案管理員（請參閱 <<file-manager>>）啟動 OxideMerge。

「選擇檔案或資料夾」對話框的用法：

.「選擇檔案或資料夾」對話框
image::dialog.png[選擇檔案或資料夾對話框]

. 輸入或瀏覽「左側」與「右側」的路徑。
  路徑可以是檔案、資料夾，或以 `http://`、`https://` 開頭的網址。
  若要比較三個版本，請開啟「三方比較」並輸入「中間」的路徑。
. 開啟某一側旁的「唯讀」，可避免它被修改。
  「左右互換」會對調兩側。
. 比較資料夾時，可選擇「包含子資料夾」、「篩選器」與「比較方法」。
. 在「比較方式」中選擇比較類型：文字、二進位、影像或網頁。
  選擇「自動」時，由程式判斷類型（請參閱 <<compare-types>>）。
. 按「比較」。

TIP: 若要比較不在檔案中的文字，請選擇「檔案 → 新增文字比較」（kbd:[Ctrl+N]），開啟兩個空白的窗格。
可按 kbd:[Ctrl+V] 貼上文字，或按兩下某一行開始輸入。

[[compare-types]]
=== 比較類型

OxideMerge 提供五種比較類型：

[cols="1,4"]
|===
|類型 |顯示內容

|文字
|並排顯示各行，並醒目標示變更的字詞。
您可以編輯與合併文字；比較選項與比較規則決定哪些變更算是差異。
適用於原始碼、設定檔、CSV 檔與其他可閱讀的文字。

|二進位
|以十六進位檢視顯示位元組。
差異可以複製與儲存，但各行不會對齊。
例如在開頭附近插入一個位元組，其後的所有位元組都會跟著位移。

|影像
|以並排、疊加、滑動分隔線、閃爍或差異影像等方式顯示像素。
有差異的區域可以從一張影像複製到另一張。

|資料夾
|比較兩個或三個資料夾中的項目。
您可以複製、刪除與合併項目，也可以在個別的比較中開啟每個檔案。

|網頁
|比較兩個或三個網頁：可見文字、格式化的 Markdown、截圖、HTML 原始碼或下載的資源。
網頁為唯讀，OxideMerge 不會將任何內容存回網頁伺服器。
|===

「比較方式」設為「自動」時，OxideMerge 會依序檢查下列條件，並採用第一個符合的條件：

. 任一側為 `http://` 或 `https://` 網址：網頁比較。
. 每一側都是 HTML 檔案（`.html` 或 `.htm`）：網頁比較。
  除非您先前選過其他模式，否則使用格式化模式。
  例外：指定輸出檔（`-o`）的合併，或在主控台產生修補檔（`--patch`）時，會以文字比較。
. 每一側都是資料夾：資料夾比較。
. 每一側都是壓縮檔：解壓縮後以資料夾比較。
. 所有檔案的副檔名都是影像格式（例如 `.png`、`.jpg`、`.gif`、`.bmp`、`.tif` 或 `.webp`）：影像比較。
. 檔案的前 8 KB 含有零位元組：二進位比較。
  例外：解譯器外掛程式能將檔案轉換為文字時（請參閱 <<unpackers>>），以及帶有位元組順序標記的 UTF-16 文字，仍視為文字。
. 其他情況：文字比較。

若要自行指定類型，請使用對話框中的「比較方式」、已開啟分頁中的「比較 → 比較方式」，或命令列的 `-t` 參數。

=== 文字比較視窗

每一側都有標題列與頁尾：

* 標題列顯示檔案名稱與所在資料夾；鎖頭按鈕可將該側設為唯讀。
* 頁尾顯示儲存時使用的換行格式與編碼，以及目前行號與總行數。

在頁尾選擇其他編碼時，OxideMerge 會以該編碼重新讀取檔案。
變更編碼後請檢查文字是否正確，在編輯或儲存前尤其要確認。

差異以顏色標示：

* 變更的行為藍色。
* 雙向比較時，只在一側的行為綠色。
* 三方比較時，尚未解決的衝突為紅色。
* 變更的行中，有變更的字詞或字元會醒目標示。

在「選項 → 一般」中開啟「色盲友善的差異顏色」後，變更的行改為紫色，只在一側的行改為藍色。

兩個窗格之間的連接線會將每個差異的兩側連起來，目前的差異會醒目標示。
差異成為目前的差異，或指標移到它上方時，才會顯示它的複製箭頭。

工具列分成四組按鈕：

* 「差異」：移到下一個、上一個、第一個或最後一個差異。
* 「複製」（三方比較時為「合併」）：在各側之間複製差異。
* 「編輯」：復原與重做。
* 「檢視」：尋找、摺疊未變更的行與自動換行。

視窗夠寬時，工具列會顯示各組的名稱。
差異編號旁的 +/− 數字分別是新增與刪除的行數。

右側的位置窗格是整個檔案的概覽，按一下即可跳到該位置。
二進位比較與網頁比較的格式化模式也有位置窗格。

=== 在差異之間移動

[cols="1,2"]
|===
|按鍵 |動作

|kbd:[Alt+↓]、kbd:[Alt+↑]
|移到下一個或上一個差異

|kbd:[Alt+Home]、kbd:[Alt+End]
|移到第一個或最後一個差異

|kbd:[Alt+PgDn]、kbd:[Alt+PgUp]
|移到下一個或上一個衝突（三方比較）

|kbd:[Ctrl+G]
|跳至指定行號
|===

從資料夾比較開啟的檔案，可以接著切換到其他檔案：
在最後一個差異按 kbd:[Alt+↓]，會開啟下一個有差異的檔案；
在第一個差異按 kbd:[Alt+↑]，則會開啟上一個有差異的檔案。

=== 複製差異

複製差異時，OxideMerge 會修改目標窗格中的文字；要等到儲存後，磁碟上的檔案才會變更。
複製前，請先確認目前作用中的窗格與箭頭的方向。

* 按兩個窗格之間分隔線上的箭頭，可複製目前的差異或指標所在的差異。
* kbd:[Alt+→] 與 kbd:[Alt+←] 將目前的差異或選取的行複製到右側或左側。
* kbd:[Ctrl+Alt+→] 與 kbd:[Ctrl+Alt+←] 將所有差異複製到右側或左側。
* kbd:[Ctrl+Z] 復原變更，kbd:[Ctrl+Y] 或 kbd:[Ctrl+Shift+Z] 重做。

=== 儲存檔案

* kbd:[Ctrl+S] 儲存目前分頁中所有已修改的窗格。
* kbd:[Ctrl+Shift+S] 儲存所有分頁中已修改的窗格。
* 「檔案 → 另存新檔」以其他名稱儲存某一側。

OxideMerge 以安全的方式儲存檔案：

. 先將新內容寫入同一資料夾中的暫存檔。
. 再以暫存檔取代原始檔案。

任一步驟失敗時，OxideMerge 會顯示錯誤，絕不會直接覆寫原始檔案。
因此，即使檔案本身可以寫入，所在資料夾仍必須允許建立與取代檔案。

若要保留檔案先前的內容，請在「選項 → 一般」中開啟「覆寫檔案時保留 .bak 備份」，
OxideMerge 會將舊內容保留為 `<name>.bak`。
下次儲存時會取代這份備份，因此它並不是版本紀錄。

=== 編輯文字

非唯讀的窗格都可以編輯，編輯以行為單位。

* 若要編輯某一行，請按兩下該行，或按 kbd:[F2] 或 kbd:[Enter]。
* 若要選取多行，請拖曳、按住 kbd:[Shift] 再按一下，或按 kbd:[Shift+↑] 與 kbd:[Shift+↓]。
* kbd:[Ctrl+C] 複製選取的行；kbd:[Ctrl+V] 貼到目前這一行的下方，或取代選取的行。
* kbd:[Ctrl+\]] 增加選取行的縮排，kbd:[Ctrl+[] 減少縮排。

在某一行上按右鍵，可編輯該行、在下方插入一行、刪除該行、複製其文字、設定書籤，或依該行建立比較規則（請參閱 <<add-rule>>）。

行號區中的編輯標記，會標示開啟檔案後變更過的行。

其他程式修改了檔案時，OxideMerge 會在視窗重新成為作用中視窗時偵測到：

* 沒有未儲存變更的檔案會自動重新載入。
* 有未儲存變更的檔案會顯示訊息，並提供重新載入的選項。
  重新載入會以磁碟上的檔案取代您的編輯。

=== 尋找與取代

* kbd:[Ctrl+F] 開啟尋找列。
  kbd:[F3] 與 kbd:[Shift+F3] 尋找下一個與上一個符合項目，kbd:[Esc] 關閉尋找列。
* kbd:[Ctrl+H]（macOS 為 kbd:[Cmd+Alt+F]）開啟尋找與取代。
* 搜尋選項有「大小寫須相符」、「全字拼寫須符合」與「規則運算式」。
  使用規則運算式時，取代文字中的 `$1` 代表第一個擷取群組。
* 「全部取代」可以一次復原。

=== 書籤

* kbd:[Ctrl+F2] 在目前這一行設定或移除書籤。
* kbd:[F4] 與 kbd:[Shift+F4] 移到下一個與上一個書籤。
* 「編輯 → 書籤 → 書籤註解...」可為書籤加上註解。
  將指標移到行號區時會顯示註解，HTML 報告中也會列出。
* 「編輯 → 書籤 → 清除所有書籤」移除全部書籤。

書籤會標示在行號區與位置窗格中。

[[sync-points]]
=== 同步點

比較有時會把不相關的行配對在一起，例如某個函式改寫後又搬到其他位置。
這時可以用同步點告訴 OxideMerge 哪些行應該對齊：

. 將游標移到某一側的某一行，選擇「合併 → 設定同步點」（kbd:[Alt+S]），或在該行按右鍵。
. 以相同方式選擇另一側中對應的行；三方比較時，第三側也要選擇。

這些行會顯示在同一列，前後的文字則分開比較。

* 可以加入任意數量的同步點，但與其他同步點交叉的同步點會被拒絕。
* 同步點會標示在行號區；編輯、復原或重新載入時，同步點會跟著對應的行移動，也會一併存入已儲存的比較。
* 若要取消已選取的行，請在該行再執行一次此命令。
* 若要移除某個同步點，請在其中一行再執行一次此命令。
* 若要移除所有同步點，請選擇「合併 → 清除同步點」。

=== 檢視選項

「檢視 → 文字比較」提供下列選項：

* 「位置窗格」與「行詳細資料窗格」。
  行詳細資料窗格會將各側的目前這一行上下排列並自動換行，方便找出長行中的細微差異。
* 「行號」、「編輯標記」、「顯示空白字元」與「語法醒目提示」。
* 「摺疊未變更的行」（kbd:[Alt+C]）：將未變更的行收合成一列，每個差異前後保留三行。
  按一下該列即可展開。
* 「自動換行」（kbd:[Alt+Z]）。

「檢視 → 縮放」（kbd:[Ctrl+{plus}]、kbd:[Ctrl+-] 與 kbd:[Ctrl+0]）可調整文字大小。

「文字排列」位於「檢視 → 文字比較」與「選項 → 一般」中：

緊密排列:: 預設值。每一側只顯示自己的行，不留空白。
對齊差異:: 在新增或刪除行的另一側留白，讓後面的行維持左右對齊。

此設定會套用到所有已開啟的雙向與三方文字比較，並保留到下次使用。
切換排列方式不會變更檔案內容或比較規則。

[[inline-view]]
==== 內嵌檢視

雙向比較時，「自動換行」旁的「內嵌檢視」按鈕會以單欄顯示差異；命令面板中也有相同的命令。

.內嵌檢視
image::inline.png[內嵌檢視]

* 先列出刪除的行，再列出取代它們的行，每一行都附上舊行號與新行號。
* 開啟「摺疊未變更的行」時，未變更的行會收合，按一下即可展開。
* 差異之間的移動與複製照常運作；方向鍵可逐行移動，kbd:[Ctrl+C] 複製目前這一行。
* 若要編輯或選取多行，請切換回並排檢視。

=== CSV 與 TSV 檔案

CSV 與 TSV 檔案的工具列提供「表格檢視」，以記錄而非行為單位比較，因此引號內的欄位可以包含換行。

.兩個 CSV 檔案的表格檢視
image::csv.png[表格檢視]

* 拖曳欄位邊界可調整欄寬。
* 若要編輯儲存格，請按兩下它，或按右鍵選擇「編輯儲存格」；也可以選取後按 kbd:[F2] 或 kbd:[Enter]。
  儲存格可以包含多行文字。
* 若要將某個欄位複製到另一側的對應記錄，請在儲存格上按右鍵並選擇「複製儲存格」。兩筆記錄都必須有該欄。
* 方向鍵可在記錄與欄位之間移動；
  kbd:[PgUp] 與 kbd:[PgDn] 逐頁移動記錄，kbd:[Ctrl+Home] 與 kbd:[Ctrl+End] 選取第一筆與最後一筆記錄。
* 「跳至行」使用檔案中的實際行號。

編輯儲存格時，OxideMerge 會保留該欄位以外的引號與換行格式，並可復原與重做。
經過轉換或唯讀的文件無法編輯。

在表格檢視中複製差異時，只會變更所選的行。
若這樣會破壞 CSV 的引號格式，OxideMerge 會拒絕複製，文件維持不變；
此時請改為複製儲存格，或切換到文字檢視處理。
含引號的記錄格式不正確時，表格會顯示錯誤，請切換到文字檢視修正。
目前不支援依索引鍵欄位配對記錄。

[[git-revision]]
=== 與 Git 修訂版本比較

「檔案 → 與 Git 修訂版本比較...」會將檔案或資料夾與 Git 中較早的版本比較。
版本可以是 `HEAD`、分支、標籤或某次提交；對話框會列出最近的提交供您選擇。

Git 中的版本以唯讀方式顯示在左側，目前的檔案或資料夾顯示在右側。
必須先安裝 Git 並加入 `PATH`，而且路徑必須位於 Git 儲存庫中。

在命令列中使用 `--git-rev`：

[source,sh]
----
oxidemerge --git-rev HEAD~1 src/main.rs
----

[[merging]]
== 合併檔案與解決衝突

[[three-way-merge]]
=== 三方合併

.三方比較
image::three.png[三方文字比較]

三方合併會整合同一個檔案的兩份修改版本。
請依序開啟：您的版本、基底、另一份版本。
OxideMerge 會分別比較左右兩側與基底，並將變更整合到中間窗格。

==== 步驟一：選擇輸出檔案

預設情況下，儲存中間窗格會覆寫基底檔案。
若要保留基底檔案，請在啟動時另外指定輸出檔案：

[source,sh]
----
oxidemerge mine.txt base.txt theirs.txt -o merged.txt
----

中間窗格一開始顯示基底檔案的內容，儲存時會將結果寫入 `merged.txt`。
您也可以選擇「檔案 → 另存新檔」，將結果存到其他檔案。

若左右兩側只當作合併來源，建議將它們設為唯讀。

==== 步驟二：合併並解決衝突

窗格上方的合併列會顯示剩餘的衝突數，並提供下列按鈕：

* 「下一個衝突」。
* 「採用左側」、「採用兩側」與「採用右側」：處理目前的衝突。
* 「標記為已解決」：用於您手動編輯過的衝突，會保留中間的文字並將該衝突計為已解決。
* 「儲存結果」：位於最右側，儲存中間窗格；沒有剩餘衝突時，它會成為主要按鈕。

合併步驟：

. 選擇「合併 → 自動合併」。
  這會將兩類變更複製到中間窗格：只在一側出現的變更，以及兩側完全相同的變更。
. 以 kbd:[Alt+PgDn] 與 kbd:[Alt+PgUp] 逐一檢查剩餘的衝突。
. 從左側或右側複製需要的變更，或直接編輯中間窗格。
. 若要同時保留兩側的變更，請在差異上按右鍵，選擇「採用左側，再採用右側」或「採用右側，再採用左側」，
  再檢查結果是否有重複或互相矛盾的內容。
. 儲存結果，並確認目標路徑正確。

IMPORTANT: 自動合併只處理文字，不會檢查結果是否正確。
使用合併結果前，請先檢查內容，並執行專案所需的驗證。

[[conflict-files]]
=== 解決衝突檔案

.以三方檢視開啟的衝突檔案
image::conflict.png[衝突檔案]

衝突檔案是含有版本控制衝突標記的檔案，標記包括
`<<<<<<<`、`|||||||`、`=======` 與 `>>>>>>>`。
OxideMerge 會以三方檢視開啟這類檔案。

開啟衝突檔案的方式：

* 「檔案 → 開啟衝突檔案...」。
* 起始頁的「開啟衝突檔案」。
* 命令列：`oxidemerge conflict.txt`。

左側是「我的」，右側是「他們的」，中間是「合併結果」。
解決每個衝突後儲存中間窗格，OxideMerge 會將結果寫回衝突檔案。

NOTE: 這與開啟三個獨立檔案不同：解決衝突檔案時，原本的檔案就是輸出目標。

[[folder-comparison]]
== 比較資料夾

.資料夾比較
image::folder.png[資料夾比較]

資料夾比較會列出兩個或三個資料夾中的項目，以及每個項目的比較結果。
結果會在比較進行中陸續顯示：OxideMerge 在掃描資料夾時就會比較檔案，一發現差異就立即列出。
若視窗在背景時完成了耗時較久的比較，OxideMerge 會提醒您。

=== 資料夾清單

每一列顯示下列欄位：

* 「名稱」。
* 「資料夾」：項目所在的資料夾，只在平面清單中顯示。
* 「比較結果」。
* 「修改時間」：各側中最新的日期。
  日期不同時，日期後面會標示較新的一側；將指標移到日期上，可查看每一側的日期。
* 各側的檔案大小。
* 「副檔名」。

按一下欄位標題即可依該欄排序，再按一次可反轉順序。
列左緣的彩色線條，標示有差異或只在一側的項目。

比較結果為下列其中之一：

[cols="1,2"]
|===
|結果 |意義

|「相同」、「不同」
|檔案相同或不同；二進位檔另標示「二進位」。

|例如「3 個不同 · 1 個僅在左側」
|有差異的資料夾，文字說明其中哪些項目不同。

|「僅左側有」、「僅中間有」、「僅右側有」
|項目只在某一側。

|「左側不同」、「中間不同」、「右側不同」
|三方比較：某一側與另外兩側不同。

|「左側不存在」、「中間不存在」、「右側不存在」
|三方比較：項目只在另外兩側。

|「錯誤」
|OxideMerge 無法讀取該項目。
|===

將指標移到比較結果上，可查看完整說明，例如「文字檔案不同」。

路徑下方的篩選標籤會統計項目數量：「全部」、「不同」、「僅在左側」、「僅在右側」、「僅在中間」（僅三方比較）與「相同」。
按一下標籤即可隱藏或顯示該類項目。
關於計數的幾點說明：

* 三方比較中，只缺少一側的項目算作「不同」。
* 空資料夾與未掃描的資料夾，依其顯示的結果計數。
* 關閉「包含子資料夾」時不會比較子資料夾；這些子資料夾只計入「全部」，也不會被任何標籤隱藏。

狀態列會顯示比較所花的時間。

=== 顯示選項

「檢視 → 資料夾清單」提供下列選項：

樹狀模式:: 以樹狀結構顯示子資料夾，關閉後改為平面清單。
kbd:[→] 與 kbd:[←] 展開與摺疊資料夾，工具列也有「全部展開」與「全部摺疊」。
顯示:: 顯示或隱藏「相同」、「不同」、「僅左側」、「僅中間」與「僅右側」的項目。
資料夾清單下方顯示檔案比較:: 在清單下方直接顯示所選檔案的差異，不必開啟分頁。
工具列上的窗格按鈕或 kbd:[Alt+P] 可顯示或隱藏此窗格。

.資料夾清單下方的檔案比較
image::docked.png[含檔案比較窗格的資料夾比較]

顯示此窗格與否，會影響下列按鍵的作用：

[cols="1,2,2"]
|===
|按鍵 |顯示檔案比較窗格時 |未顯示窗格時

|kbd:[Alt+↓]、kbd:[Alt+↑]
|移到檔案中的下一個或上一個差異。
超過最後或第一個差異時，切換到下一個或上一個有差異的檔案。
|選取下一個或上一個有差異的檔案。

|kbd:[Alt+Home]、kbd:[Alt+End]
|移到檔案中的第一個或最後一個差異。
|選取第一個或最後一個有差異的檔案。
|===

窗格上的箭頭按鈕與 kbd:[Alt+↓]、kbd:[Alt+↑] 的作用相同。
檔案仍在載入時按下按鍵，OxideMerge 會等檔案載入完成，不會略過任何差異。
使用審閱篩選時，這些按鍵只會在篩選所列出的檔案之間切換。

=== 工具列

由左至右依序為：

* 「重新整理」（kbd:[F5]）：重新比較資料夾。
* 「全部展開」與「全部摺疊」：樹狀模式下使用。
* 「資料夾清單下方顯示檔案比較」（kbd:[Alt+P]）：顯示或隱藏檔案比較窗格。
* 「複製到右側」與「複製到左側」：複製選取的項目。
  三方比較時，這些按鈕改為「從左側複製到中間」、「從右側複製到中間」與「自動合併資料夾...」。
* 「依名稱選取...」：選取名稱符合萬用字元（例如 `*.c; *.h`）的項目。
* 「所有差異」：在一個分頁中開啟所有已變更的文字檔（請參閱 <<all-differences>>）。
* 「匯出 HTML」：儲存 HTML 報告（請參閱 <<reports>>）。
* 「篩選器」：決定要比較哪些檔案與資料夾（請參閱 <<filters>>）。
* 「規則」：選擇此比較使用的比較規則檔（請參閱 <<compare-rules>>）。
* 「比較方法」：選擇比較檔案的方式（請參閱 <<compare-methods>>）。
* 「依名稱尋找」（kbd:[Ctrl+F]）：只顯示名稱含有所輸入文字的項目。
* 「側邊面板」：位於最右側，開啟包含審閱、驗證與基準面板的側邊抽屜（請參閱 <<analysis>>）。

視窗較窄時，「所有差異」與「匯出 HTML」會縮成圖示，篩選標籤也只顯示數字。

[[compare-methods]]
=== 比較方法

[cols="1,3"]
|===
|方法 |比較檔案的方式

|完整內容
|逐行比較文字檔，並套用比較選項與比較規則。
只有被忽略的部分不同的檔案，視為相同。

|快速內容
|比較位元組。
大小不同的檔案不必讀取即可判定為不同。

|二進位內容
|與「快速內容」一樣比較位元組，並將結果標示為二進位。

|修改日期
|比較修改日期。
「選項 → 資料夾」中的「日期容許誤差（秒）」決定兩個日期可以相差多少。

|修改日期與大小
|日期與大小都必須相同。

|大小
|只比較大小。
|===

如何選擇：

* 需要套用比較規則或忽略某些差異時，請用「完整內容」。
* 需要確認檔案完全相同時，請用「快速內容」或「二進位內容」。
* 需要快速初步檢查時，可用日期或大小相關的方法。
  請注意，日期與大小相同，並不代表內容相同。

位元組比較會分段讀取檔案，因此大型檔案不必整個載入記憶體。
完整的文字比較仍可能將有變更的檔案載入記憶體。

=== 選取與開啟項目

可以用滑鼠或鍵盤選取項目：

* 方向鍵、kbd:[PgUp]、kbd:[PgDn]、kbd:[Home] 與 kbd:[End] 移動選取位置；按住 kbd:[Shift] 可擴大選取範圍。
* 按住 kbd:[Ctrl] 再按一下，可將項目加入或移出選取範圍。
* kbd:[Ctrl+A] 選取所有項目。

開啟項目：

* 按兩下項目或按 kbd:[Enter]，可在獨立分頁中比較它。
  在樹狀模式中，這個動作會改為展開或摺疊資料夾。
  若要以獨立的資料夾比較開啟某個資料夾，請使用平面清單，或在資料夾上按右鍵並選擇「比較」。
* 按 kbd:[Space] 開啟「快速預覽」：不必開啟新分頁，即可看到所選檔案以顏色標示的差異。
  在預覽中，kbd:[↑] 與 kbd:[↓] 切換項目，kbd:[Enter] 開啟項目，kbd:[Space] 或 kbd:[Esc] 關閉預覽。

=== 複製與刪除項目

* kbd:[Alt+→] 與 kbd:[Alt+←] 將選取的項目複製到右側或左側。
* 在項目上按右鍵可使用更多命令：
** 「複製」到另一側。
** 「複製到資料夾...」：將某一側選取的項目複製到另一個資料夾，並保留相對路徑。
** 從某一側「刪除」。
** 「以關聯的應用程式開啟」。
** 「在檔案總管中顯示」。
** 「複製完整路徑」。
** 「依名稱選取...」。

「選項 → 一般」中的下列設定會影響檔案操作：

* 「複製前先確認」：複製項目前先詢問；刪除項目前一律會詢問。
* 「刪除時使用資源回收筒」：刪除的項目會移到資源回收筒或垃圾桶。
  無法移入的項目，OxideMerge 不會刪除。
* 「覆寫檔案時保留 .bak 備份」：取代檔案時保留舊內容。

IMPORTANT: 複製與刪除會立即變更磁碟上的檔案，
不會等到「儲存」，也無法以文字編輯的「復原」命令還原。
操作前請先確認選取的項目與目標位置。

[[all-differences]]
=== 檢查所有差異

.所有差異
image::alldiffs.png[所有差異]

「所有差異」會在一個分頁中顯示資料夾比較裡所有已變更的文字檔。
請按資料夾比較工具列上的按鈕，或選擇「比較 → 所有差異」。
資料夾比較的篩選器與「顯示」設定同樣適用。

* 左側清單列出每個檔案及其差異數量。
  「篩選檔案…」（kbd:[Ctrl+F]）可縮短清單；按一下檔案即可捲動到該檔案。
* 每個檔案以一張卡片並排顯示其差異。
  按卡片標題中的箭頭可摺疊或展開卡片，工具列則可摺疊或展開全部卡片。
* kbd:[Alt+↓] 與 kbd:[Alt+↑] 依序瀏覽所有檔案的差異。
* 差異旁的箭頭會將它複製到另一側。
  雙向比較時，卡片標題中的按鈕可複製整個檔案。
* 「復原」取消上一個變更。
* 「儲存」寫入已變更的檔案，之後資料夾比較會重新整理。
* 卡片標題最右側的按鈕會在獨立分頁中開啟該檔案。

補充說明：

* 從檔案不存在的一側複製時，儲存後會刪除該檔案，因此變空的資料夾也會一併刪除。
  若已開啟備份，刪除的檔案會保留為 `.bak`，所在資料夾也就會保留。
* 檔案在載入後於磁碟上有變更時，無法儲存該卡片。
  卡片會提供捨棄編輯並重新載入檔案的選項；選擇前，請先另外保留需要的編輯內容。
* 沒有編輯過的卡片，會在檔案變更時自動重新載入。
* 「重新整理」（kbd:[F5]）也會重新載入比較規則與選項。
* 若要納入開啟「所有差異」之後才變更的檔案，請先儲存或捨棄目前的編輯，再重新開啟「所有差異」。

[[folder-merge]]
=== 自動合併資料夾

在三方資料夾比較中，中間的資料夾是基底。
「合併 → 自動合併資料夾...」會將兩側的變更帶入中間資料夾：

* 只在某一側變更、新增或刪除的項目，會被複製或刪除。
* 兩側完全相同的變更只套用一次。
* 兩側都有變更的文字檔，若變更沒有重疊，會逐行合併。

==== 開始之前

. 在「選項 → 資料夾」中，開啟「包含子資料夾」與「包含唯一子資料夾的內容」。
. 等待比較完成。

IMPORTANT: 合併結果會寫入中間資料夾。
若要保留原本的基底資料夾，請先複製一份，再以複本作為中間資料夾。

==== 檢查合併計畫

OxideMerge 會先列出計畫：預計複製、刪除與合併的項目，以及無法自動解決的衝突。
確認前請先仔細檢查。

下列檔案不會被變更：修改互相衝突的檔案、內容無法合併的檔案、符號連結，以及無法讀取的檔案。
若檔案在比較後又有變更，請重新整理比較後再試一次。

==== 合併如何保護您的檔案

合併只有兩種結果：所有變更全部完成，或中間資料夾完全維持原狀。

* _合併前_，OxideMerge 會檢查每個項目。
  若有項目在計畫產生後又有變更、會寫到中間資料夾之外，或其備份檔會取代比較中的檔案，就不會合併任何項目，並列出這些項目。
* _合併期間_，OxideMerge 會在寫入每個檔案前再檢查一次。
  若其他程式變更了檔案，合併會停止。您也可以按「停止」中止合併。
* _合併停止或失敗時_（例如資料夾唯讀或磁碟已滿），OxideMerge 會復原到目前為止的所有變更。
  中間資料夾會恢復原狀，被移除的資料夾也會恢復原本的權限。
  合併時移到垃圾桶的檔案會從副本還原，因此垃圾桶中也會保留一份。

為了能夠復原，OxideMerge 會將原始檔案的副本放在中間資料夾最上層的 `.oxidemerge-undo-…` 資料夾中。
若無法在該處建立此資料夾，則改用系統的暫存資料夾。
資料夾比較不會列出這個資料夾。
被刪除的檔案只是移到這個資料夾，復原時再移回原處。

若 OxideMerge 無法將某個檔案放回原處，會保留這個復原資料夾並顯示其位置。
資料夾中的 `index.txt` 列出每個副本的原始路徑，方便您手動還原。

[[archives]]
=== 壓縮檔

OxideMerge 會將壓縮檔解壓縮後，以資料夾的方式比較。支援下列格式：

* ZIP 類格式：`.zip`、`.jar`、`.apk`、`.docx`、`.xlsx`、`.odt`、`.epub`、`.nupkg` 等。
* `.tar`、`.tar.gz` / `.tgz`、`.tar.bz2` / `.tbz2` 與 `.tar.xz` / `.txz`。
* `.7z`。

解壓縮後的檔案為唯讀，OxideMerge 不會將變更寫回壓縮檔。
解壓縮後超過 8 GB 或 500,000 個檔案的壓縮檔不會開啟。
不支援 RAR 格式。

== 比較二進位檔

.二進位比較
image::binary.png[二進位比較]

二進位檔會以並排的十六進位檢視開啟。
不同的位元組會醒目標示，兩側會同步捲動。

[[image-comparison]]
== 比較影像

.影像比較
image::image.png[影像比較]

請選擇檢視模式：

並排:: 兩張影像左右並排。
疊加:: 一張影像疊在另一張上，「不透明度」決定上層影像的透明程度。
滑動:: 分隔線左邊顯示一張影像，右邊顯示另一張；拖曳分隔線即可移動。
閃爍:: 交替顯示兩張影像，方便看出細微的變化。
差異:: 只顯示像素的差異。

找出與複製差異：

* 「標示差異」會標出不同的區域。
** 「色彩距離門檻」決定兩個像素要相差多少才算不同。
** 「區塊大小」決定標示區塊的大小。
* 按一下某個區域即可選取它。
  kbd:[Alt+↓] 與 kbd:[Alt+↑] 移到下一個與上一個區域。
* kbd:[Alt+→] 與 kbd:[Alt+←] 將目前的區域複製到另一張影像。
  「復原」可取消複製，kbd:[Ctrl+S] 儲存變更後的影像。

縮放與平移：

* 可用按鈕、滑鼠滾輪或雙指縮放手勢縮放，縮放時以指標位置為中心。
* 「符合視窗」讓影像符合視窗大小，「1:1」以實際大小顯示。
* 拖曳或以雙指捲動，可一起平移所有影像。

狀態列會顯示有多少像素不同，以及分布在幾個區域。

[[web-comparison]]
== 比較網頁

您可以比較兩個或三個網址（`http://` 或 `https://`），或本機的 HTML 檔案。
本機 `.html` 與 `.htm` 檔案預設就會以網頁比較開啟。
若要將其他類型的檔案當作網頁比較，請選擇「比較方式 → 網頁」，或在命令列使用 `-t web`。

=== 比較模式

請在分頁上方的模式選擇器中選擇模式；OxideMerge 會記住您上次使用的模式。

[cols="1,3"]
|===
|模式 |比較的內容

|文字
|每個網頁上看得到的文字，以文字比較開啟。
每個標題、段落、清單項目、表格儲存格與表單欄位值各占一行，預先格式化文字的每一行也各占一行。
隱藏的元素不列入比較。
變更的字詞會醒目標示，比較選項、篩選器與報告也都適用。

|格式化
|預設模式。將每個網頁轉換成 Markdown，並排顯示格式化的結果。
請參閱 <<web-formatted>>。

|整頁
|每個網頁從上到下的完整截圖，以影像檢視比較。
請參閱 <<web-screenshots>>。

|螢幕截圖（可見區域）
|只擷取每個網頁的頂端，大小為選項中設定的截圖寬度與高度。

|HTML 原始碼
|每個網頁執行指令碼之後的 HTML，以文字比較開啟。
經過壓縮的長行會在標籤之間斷開。

|資源樹
|下載每個網頁及其樣式表、指令碼、影像、框架與媒體，再以資料夾比較來比較這些下載的檔案。
|===

切換到其他模式時，會重新載入網頁。
網頁有變更後，請按「重新載入網頁」（kbd:[F5]）。

若要逐行比較本機檔案的 HTML 原始碼，請使用 HTML 原始碼模式，或選擇「比較方式 → 文字」（`-t text`）。

[[web-formatted]]
=== 格式化模式

格式化模式會保留標題、段落、強調、連結、清單、引言、程式碼區塊與表格的樣式；影像則以連結顯示。

.以格式化模式比較兩個網頁
image::web.png[格式化模式的網頁比較]

OxideMerge 以區塊為單位比較網頁。
區塊是指一個標題、段落、清單項目、表格、引言或程式碼區塊。

* 不同的區塊會醒目標示，並與其他網頁上同類型的變更區塊對齊。
* 只在一個網頁出現的區塊，對面會留白。
* 在變更的區塊中，變更的字詞或字元會以較深的顏色標示；與文字比較相同，由「行內差異」選項控制。
* 表格會以框線畫出儲存格，各列也會對齊。
  不同的列中會醒目標示變更的字詞；另一個網頁缺少的列或欄，整個儲存格都會醒目標示。
* 每個變更的區塊各算一個差異，即使緊接在另一個變更的區塊之後也一樣。

若要在差異之間移動，請使用網頁上方的按鈕，或與文字比較相同的按鍵。

* 目前的差異會以較深的顏色標示，正在比較的區塊在每個網頁上都會加上外框；
  您最後點選的網頁，外框最明顯。
* 按一下某個區塊，即可將它設為目前的區塊，之後的下一個與上一個差異就從該處找起。
* 只有在差異不在畫面中時，網頁才會捲動，並將差異顯示在距離頂端約三分之一的位置。

網頁右側的位置窗格會顯示所有差異：目前的差異以強調色顯示，網頁目前可見的部分會加上外框。
在位置窗格中按一下或拖曳，即可前往該處。
若要顯示或隱藏位置窗格，請選擇「檢視 → 文字比較 → 位置窗格」。

網頁隱藏的內容不列入比較：

* 由瀏覽器轉譯時，瀏覽器沒有顯示的內容都不列入，包括樣式表隱藏的內容。
* 使用下載的原始 HTML 時，略過帶有 `hidden`、`aria-hidden` 屬性，或以行內 `display: none` 樣式隱藏的元素。

[[web-screenshots]]
=== 截圖模式

整頁與螢幕截圖（可見區域）模式會以影像檢視顯示截圖。

開啟「醒目提示差異」時，OxideMerge 會先在網頁上直接標示不同的文字，再進行截圖：

* 變更的區塊為黃色。
* 區塊中變更的字詞為橘色。

這與 WinMerge 標示網頁差異的方式類似。
由於比較的是文字而不是像素，即使某處的變更讓後面的內容往下移，也不會把下方全部標成差異。
高度超過 16384 像素的網頁會被截斷。

=== 網頁的載入方式

文字、格式化、HTML 原始碼與截圖模式，都使用 Chromium 系列瀏覽器載入網頁。
OxideMerge 會自動尋找 Edge、Chrome、Chromium 與 Brave。
瀏覽器在背景執行，不會顯示視窗；它會執行每個網頁的指令碼，因此您看到的就是網頁在瀏覽器中的樣子。

* 所有網頁同時載入，各自在獨立的瀏覽器分頁中。
* 45 秒後，OxideMerge 會以每個網頁當時的狀態進行比較。
* 網頁開啟的對話框（例如 `alert`）會自動關閉。
* 網頁載入後才重新導向時，以重新導向後的網頁為準。
* 在 macOS 與 Linux 上，OxideMerge 透過私有管道與瀏覽器溝通；
  在 Windows 上則使用只有本機能連線的網路連接埠，而且只在載入網頁時開啟。

在下列情況下，文字、格式化與 HTML 原始碼模式會改用下載的原始 HTML，不經過瀏覽器；
此時網頁的指令碼不會執行，指令碼加入的內容也就不會出現：

* 找不到瀏覽器。
* 已關閉「文字與 HTML 模式使用瀏覽器轉譯頁面（會執行頁面指令碼）」。
* 瀏覽器發生錯誤，狀態列會說明原因。
* 瀏覽器無法載入網頁：無法連線、未能及時載入，或分頁當掉。
  在截圖模式中，該網頁會顯示為空白，窗格標題列會顯示錯誤，其他網頁仍會照常比較。

OxideMerge 解碼網頁的方式與瀏覽器相同，依序採用第一個找到的資訊：
位元組順序標記、HTTP `Content-Type` 標頭中的字元集、`<meta>` 中的字元集，最後才依內容推測。

* 伺服器傳回非 2xx 的狀態碼時，窗格標題列會顯示該狀態碼，並比較隨之傳回的網頁。
* 網頁無法連線、超過 30 秒未回應、回應格式不正確或大於 50 MB 時，OxideMerge 會連同網址一併回報。

=== 資源樹的限制

資源樹模式只下載每個網頁本身列出的資源，不會再追蹤樣式表或指令碼中的連結。

* 每個網頁最多 400 個資源，每個資源最大 20 MB。
* 無法下載的資源會在狀態列中計數，其餘資源仍會照常比較。
* 為了安全起見，網頁不得載入本機檔案。
  只有位於本機或私人網路（例如 `localhost` 或 `192.168.x.x`）的網頁，才能從這類位址載入資源或被重新導向到這類位址；
  其他這類資源會被略過，並在狀態列中計數。
* 您自行輸入的網址一律會載入。

由瀏覽器轉譯的網頁不受這些限制：瀏覽器會載入網頁要求的所有內容。

=== 網頁比較設定

下列設定位於「選項 → 影像 / 二進位 / 網頁」：

* 「用於轉譯頁面的瀏覽器」：留白時會自動尋找支援的瀏覽器。
* 「文字與 HTML 模式使用瀏覽器轉譯頁面（會執行頁面指令碼）」。
* 「截圖寬度」與「截圖高度」：所有模式所用的瀏覽器視窗大小。

主控台比較（以 `--cli` 比較 HTML 檔案，或指定 `-t web` 時）會沿用您在視窗中最後選擇的模式：

* 格式化模式（預設）逐行比較網頁的 Markdown。
* HTML 原始碼模式比較 HTML。
* 其他模式比較可見文字。

NOTE: 資源樹模式比較伺服器傳回的原始 HTML；使用瀏覽器時，其他模式會執行網頁的指令碼。
不支援登入，因此需要登入的網頁可能只顯示登入畫面。
所有模式都不會將變更存回網頁伺服器。

[[differences-shown]]
== 控制要顯示的差異

有三類設定會決定 OxideMerge 將哪些內容顯示為差異：

* 篩選器：選擇資料夾比較要包含哪些檔案與資料夾。
* 比較選項：決定哪些文字變更要計入，例如空白字元或大小寫。
* 比較規則：忽略或取代符合樣式的文字。

這些設定只會改變比較結果，絕不會修改檔案。

TIP: 若預期中的變更沒有顯示，請先檢查這些設定，再判斷檔案是否相同。

[[compare-options]]
=== 比較選項

「比較 → 比較選項」提供最常用的選項，「選項 → 比較」則包含全部選項：

空白字元::
「比較」：空白字元列入比較。
「忽略變更」：空白字元的數量不同時不算差異。
「全部忽略」：完全忽略空白字元。
忽略空白行:: 多出來的空白行不算差異。
忽略大小寫:: 大寫與小寫字母視為相同。
忽略換行字元差異（Windows/Unix/Mac）:: `CRLF`、`LF` 與 `CR` 三種換行字元視為相同。
忽略數字:: 忽略所有數字。
忽略字碼頁差異:: 編碼不同但文字相同的檔案視為相同。
忽略註解變更:: 只有註解的變更不算差異。
適用於已知註解語法的語言：C 類語言、指令碼語言、SQL、HTML、XML、CSS、Lua、Haskell 等。
比較前格式化 JSON 與 XML:: 重新縮排 JSON 與 XML，並排序 JSON 的鍵，避免排版變更被當成差異。
格式化後的檢視為唯讀；若要編輯或合併，請關閉此選項。
偵測移動的行:: 被搬移的整段行會標示為移動。
差異演算法:: 「Myers」、「Patience」或「LCS」。
行內差異:: 行內變更的標示方式：「關閉」、「單字層級」或「字元層級」。
數字差距在此範圍內視為相同:: 差距不超過此值（例如 `0.001`）的數字視為相同，適合比較量測值或自動產生的資料。

在資料夾比較中，只有比較方法為「完整內容」時，這些選項才會套用到文字檔；其他方法不使用這些選項。

[[compare-rules]]
=== 比較規則

比較規則檔（`.oxrules`）包含三類規則：

忽略符合的行:: 每行一個規則運算式。
只由符合的行組成的差異會被忽略。
取代規則:: 每行一條規則，寫成 `+規則運算式 => 取代文字+`。
OxideMerge 會在比較前將取代規則套用到兩側，適合處理預期中就會不同的文字。
忽略起始行與結束行之間的區塊:: 每行一個區塊，寫成 `+起始規則運算式 => 結束規則運算式+`。
區塊內的差異會被忽略，適合處理自動產生的段落或授權聲明。

規則運算式採用 Rust `regex` 套件的語法。

==== 管理規則檔

.選項 → 比較規則
image::rules.png[比較規則選項]

在「選項 → 比較規則」中管理規則檔：

* 選擇「無」或某個規則檔。
  沒有另外指定規則檔的比較，會預設使用這個檔案。
* 「新增規則檔」建立新檔案，「編輯」以規則編輯器開啟檔案，「刪除」移除檔案。
* 「開啟規則資料夾」在檔案管理員中顯示該資料夾；在其中變更檔案後，請按「重新載入」。
* 「匯入...」加入其他人分享的規則檔；
  「匯出」可匯出單一檔案，或以「所有規則檔到資料夾...」將全部檔案匯出到資料夾。

資料夾比較可以使用不同的規則檔，請從工具列的「規則」或「比較 → 比較規則」中選擇。
「重新整理」（kbd:[F5]）會重新讀取規則檔。

也可以用拖放的方式匯入規則檔：

* 將一個 `.oxrules` 檔案拖放到視窗上即可匯入；拖放兩個時，OxideMerge 會改為比較它們。
* 將任意數量的 `.oxrules` 檔案拖放到選項對話框上，即可一次匯入。

匯入規則檔時：

* 已有名稱與規則都相同的檔案時，略過新檔案。
* 已有名稱相同但規則不同的檔案時，新檔案的名稱會加上編號。
* 已有規則相同但名稱不同的檔案時，新檔案以自己的名稱加入。

==== 規則檔格式

規則檔存放在設定檔旁的 `Rules` 資料夾中（請參閱 <<configuration>>）。
OxideMerge 也會讀取程式旁的 `Rules` 資料夾。

規則檔是 JSON 檔案，規則的名稱就是去掉 `.oxrules` 的檔名：

.Build logs.oxrules
[source,json]
----
{
  "description": "忽略建置紀錄中的時間戳記與自動產生的標頭",
  "ignore_lines": ["^\\[\\d{2}:\\d{2}:\\d{2}\\]", "^// Generated on .*$"],
  "substitutions": [{ "find": "\\b0x[0-9a-fA-F]{8,}\\b", "replace": "0xADDR" }],
  "ignore_blocks": [{ "start": "^/\\* BEGIN LICENSE", "end": "END LICENSE \\*/$" }]
}
----

[[add-rule]]
=== 從文字比較建立規則

. 在文字比較中的某一行上按右鍵，選擇「新增比較規則」。
. 選擇規則的類型：
+
--
忽略類似的行:: 符合該行（或變更行的每一側）的樣式。
取代:: 將一側文字轉換成另一側文字的取代規則。
忽略區塊:: 從該行開始的區塊。
--
. 檢查 OxideMerge 建議的樣式，視需要修改。
. 選擇要加入的「規則檔」，或輸入「檔案名稱」建立新檔案。

目前的比較會立即套用新規則；
其他使用相同規則檔的資料夾比較，會在重新整理（kbd:[F5]）後套用。

[[filters]]
=== 篩選器

篩選器決定資料夾比較要包含哪些檔案與資料夾。
請從資料夾比較工具列的「篩選器」中選擇；若要管理篩選器，請選擇「工具 → 篩選器...」。

篩選遮罩是以 `;` 分隔的萬用字元清單：

* 開頭加上 `!` 表示排除符合的項目。
* 結尾加上 `\` 或 `/` 表示符合資料夾。

例如，下列遮罩會包含 Rust 與 TOML 檔案，並排除 `target` 資料夾：

----
*.rs;*.toml;!target\
----

OxideMerge 也會列出 WinMerge 的 `.flt` 篩選器檔案，
來源為設定資料夾中的 `Filters` 資料夾，以及程式旁的 `Filters` 資料夾。
「工具 → 篩選器...」會列出這些篩選器，並可開啟篩選器資料夾及新增篩選器。

[[unpackers]]
=== 解譯器外掛程式

解譯器外掛程式會在比較前將檔案轉換為文字，
適合 PDF 或 Office 文件等需要外部轉換程式的格式。
OxideMerge 會比較轉換程式寫到標準輸出的文字。

新增外掛程式的步驟：

. 安裝轉換程式，並確認命令找得到它。
. 在「選項 → 外掛程式」中新增項目，填入「檔案樣式」（例如 `*.docx`）與「命令列」。
  命令列中的 `${file}` 會替換為已加上引號的檔案路徑。
. 啟用該項目。

預設按鈕可新增 PDF 文字（`pdftotext`）、Office 與 OpenDocument 文件（`pandoc`），以及一般文件擷取（`tika`）的項目；
這些項目新增後預設為停用。
將指標移到項目的核取方塊上，可查看它需要哪個程式。
這項檢查只看命令中的第一個程式名稱；若命令實際執行失敗，OxideMerge 會顯示轉換程式的輸出訊息。

以已安裝的 Pandoc 為例：

----
pandoc -t plain ${file}
----

凡是以文字比較檔案的地方都會使用轉換程式：單一檔案、以「完整內容」比較的資料夾、命令列、檔案比較窗格、「所有差異」，以及資料夾報告中的差異。
資料夾比較的大小、日期、快速內容與二進位方法，仍然比較原始檔案。

其他限制與規則：

* 擷取出的文字為唯讀，絕不會覆寫原始文件。
* 每次轉換最多執行 30 秒，每個輸出串流最多 16 MiB。
* 轉換程式以非零的結束代碼結束時，即使已輸出部分文字，仍視為錯誤。
* 停止資料夾掃描時，進行中的轉換也會一併停止。

[[projects]]
=== 專案

「檔案 → 另存為專案...」會將目前分頁所比較的內容存成 `.oxmproj` 檔案。專案會儲存：

* 路徑、說明文字與唯讀的側；
* 比較類型、篩選器、「包含子資料夾」與比較方法；
* 比較規則檔。

「檔案 → 開啟專案...」可再次開啟專案；OxideMerge 也能開啟 WinMerge 的專案檔（`.WinMerge`）。

路徑會以相對於專案檔的方式儲存，因此專案可以和檔案一起搬移。
位於不同 Windows 磁碟機的路徑會保留為絕對路徑，網址也不會變更。

專案不包含檔案本身；開啟專案時，OxideMerge 會載入這些路徑目前的檔案。
將專案搬到其他電腦時，請一併複製其中的檔案，以及專案使用的外部規則檔。
若要分享目前的文字與檢閱註記，請改為儲存比較。

[[saved-comparisons]]
=== 已儲存的比較

「檔案 → 儲存比較...」會將文字比較存成 `.oxmcmp` 檔案，
內容包括各側的文字、書籤與註解，以及同步點。

您可以日後再開啟，或傳送給其他檢閱者。
檔案會以唯讀方式開啟，不需要原始檔案。
它是文字當時的快照：與專案不同，不會依路徑載入目前的檔案。

[[folder-reviews]]
=== 資料夾審閱

資料夾比較完成後，「檔案 → 儲存比較...」會存成 `.oxmreview` 檔案。
這是一個可攜式的封裝檔，包含篩選器納入的所有項目。

* 若只要儲存部分項目，請選取檔案或資料夾，按右鍵並選擇「儲存所選資料夾審閱…」。
  選取的資料夾會包含其中已掃描的所有內容。
* 「顯示」設定與篩選標籤只會改變畫面上看到的項目，不會從完整的封裝檔中移除項目。
* 請先完成所有檔案操作；若檔案有變更，請重新整理比較後再儲存。

若要加上註記，請在檔案或資料夾上按右鍵，選擇「切換書籤」或「書籤註解」。
加上書籤的項目，名稱前會顯示 `*`；將指標移到項目上會顯示註解。
這些註記會存入封裝檔，也會出現在 HTML、XML 與純文字的資料夾報告中，但不會納入 CSV 摘要。
若在已開啟的封裝檔中修改註記，請再次儲存比較以保留變更。

開啟封裝檔的方式：

* 命令列：`oxidemerge review.oxmreview`；
* 將檔案拖放到視窗上；
* 「檔案 → 開啟專案...」。

封裝檔會以唯讀快照開啟，並沿用當時的比較選項。
它不需要原始檔案、具名篩選器或外部規則檔。
經轉換的文件會以擷取出的文字儲存，轉換命令則不會儲存，因此檢閱者不必安裝轉換程式。
在樹狀檢視中展開資料夾，即可查看其中的內容。

限制：

* 支援兩側或三側，最多 10,000 個項目與 256 MiB 未壓縮內容。
* 不接受符號連結、特殊檔案、在其他系統上不安全的路徑，以及比較後已變更的檔案。
* 封裝檔包含每個檔案的完整內容，二進位檔也不例外。

審閱工作區可在資料夾審閱中加入審閱決定，請參閱 <<review-workspace>>。

[[html-reports]]
=== HTML 報告

建立 HTML 報告的步驟：

. 開啟文字或資料夾比較，並等待比較完成。
. 檢查比較選項、比較規則與資料夾篩選器，這些設定會影響報告中的差異。
. 按工具列上的「匯出 HTML」，或選擇「檔案 → 匯出 → 匯出 HTML 報告...」（kbd:[Ctrl+Shift+E]）。
. 選擇輸出檔案。建議的檔名由比較項目的名稱組成，空格會換成 `_`。
. OxideMerge 會在瀏覽器中開啟報告。分享前請先確認內容。

報告是單一的 HTML 檔案，內含顯示所需的一切資源；
收件者可以用任何瀏覽器開啟，不需要安裝 OxideMerge。

* 每個差異以一張卡片呈現，附有行號、前後三行內容，並醒目標示變更的字詞。
* 報告包含摘要卡片、索引、並排或合併檢視、淺色與深色主題、檔案篩選與搜尋。
* kbd:[N] 與 kbd:[P] 移到下一個與上一個差異。
* 報告會列出使用的比較規則檔，並統計被忽略的差異數量。
* 資料夾報告會包含每個已變更文字檔的差異。

若只想儲存報告而不開啟，請關閉「檔案 → 匯出 → 儲存後在瀏覽器開啟報告」。

匯出報告絕不會將您的編輯存回比較的檔案。

[[other-reports]]
=== 其他報告

「檔案 → 匯出 → 產生報告...」會依您選擇的格式產生報告：

* 資料夾比較：HTML、CSV、純文字或 XML；
* 文字比較：HTML 或 XML。

「檔案 → 匯出 → 產生含檔案差異的報告...」會在 HTML 資料夾報告中加入每個已變更文字檔的差異。

「工具 → 統計資料...」會顯示目前比較的統計數字：

* 資料夾比較：相同、不同與唯一的檔案數量、錯誤數，以及各側的總大小；
* 文字比較：每一對窗格之間相同、變更、新增、刪除與忽略的行數。

==== XML 報告

XML 報告是給其他程式讀取的，例如指令碼、審閱工具，或檢查變更內容的建置流程。
產生報告時選擇 `.xml` 類型，或在命令列使用 `--report <名稱>.xml`。

* 文字比較報告會列出每個差異的種類、是否被忽略，以及各側的行與行號；最後列出書籤及其註解。
* 差異種類包括 `changed`、`added` 與 `removed`；
  三方比較另有 `left-only`、`right-only`、`both-same`、`compatible` 與 `conflict`。
* 資料夾報告會列出每個檔案與資料夾的狀態，以及在各側的日期與大小。

[source,xml]
----
<comparison format="1" tool="OxideMerge" version="0.9.8" type="text" created="…">
  <side index="0" role="left" name="a.txt"/>
  <side index="1" role="right" name="b.txt"/>
  <statistics differences="1" ignored="0" identical-lines="1" changed-lines="1" added-lines="0" removed-lines="0"/>
  <differences>
    <difference index="1" kind="changed" ignored="false">
      <lines side="0" start="2" count="1"><line number="2">two</line></lines>
      <lines side="1" start="2" count="1"><line number="2">TWO</line></lines>
    </difference>
  </differences>
</comparison>
----

* 行號從 1 開始。
* 某一側在差異中沒有任何行時，`count` 為 `0`，`start` 表示文字應插入在第幾行之前。
* 只有在格式的變更可能影響讀取程式時，`format` 的值才會改變。

[[slideshows]]
=== 投影片

「檔案 → 匯出 → 產生投影片報告...」會儲存一個一次顯示一個差異的 HTML 網頁，
適合在會議或審閱時逐一說明變更。

* 標題投影片列出比較的各側與差異數量。
* 接著每個差異各有一張投影片，顯示差異的行、前後幾行、變更的字詞，以及書籤註解。
* 資料夾比較會為每個已變更文字檔的每個差異各建立一張投影片；
  最後一張列出以其他方式不同的檔案，例如二進位檔或只在一側的檔案。
* 被忽略的差異不會列出。

在瀏覽器中：

* kbd:[→]、kbd:[←]、kbd:[Space]、kbd:[PgUp] 與 kbd:[PgDn] 切換投影片。
* kbd:[Home] 與 kbd:[End] 跳到第一張與最後一張。
* kbd:[F] 切換全螢幕。
* 每張投影片都有自己的網址（例如第三張為 `#3`），可以直接連結。
* 列印時，每張投影片各印成一頁。

[[patches]]
=== 修補檔

「檔案 → 匯出 → 產生修補檔...」會將兩個檔案或資料夾之間的差異寫成修補檔。
您可以選擇格式（「一般」、「上下文」或「統一」）與前後文的行數。

* 只能從雙向比較產生修補檔。
* 匯出哪些差異，仍由目前的忽略選項決定。
* 支援 UTF-8 檔案（不論有無位元組順序標記）、LF、CRLF 或混合的換行字元，以及結尾沒有換行字元的檔案。
* 其他編碼或只使用 CR 換行的檔案，必須先轉換。
  遇到這類檔案時，OxideMerge 會顯示錯誤，而不會產生無法正確還原變更的修補檔。

「檔案 → 套用修補檔...」可套用統一格式的差異，包括 `git diff` 與 `svn diff` 的輸出。

* 即使行的位置已經移動，OxideMerge 仍能找到每個修補區塊。修補區塊是修補檔中的一組變更。
* 每個修補後的檔案會與原始檔案並排開啟，方便您檢查後再儲存。
* 無法套用的修補區塊會列在訊息中。
  儲存前請先閱讀這些訊息並檢查比較結果；套用修補檔不會自動儲存任何結果。

== 分析工具

OxideMerge 提供幾項選用的工具，協助您檢查合併結果與審閱大量變更：

* <<merge-verification>>：預覽合併並檢查已儲存的結果。
* <<semantic>>：依結構比較 JSON、XML、TOML 與 YAML 檔案。

[[merge-verification]]
=== 合併驗證

==== 文字檔

在三方文字比較中，開啟「合併驗證」分頁。

.執行「預覽合併」後的合併驗證
image::verify.png[合併驗證]

* 「預覽合併」會以「唯讀預覽」顯示合併的結果，不會變更中間窗格。
  預覽中的衝突處保留基底的文字，必須由您自行解決。
* 「驗證已儲存的結果」會重新讀取已儲存的結果檔，
  並將其位元組、編碼、位元組順序標記、換行字元與檔案結尾換行與預覽比較。
* 編輯文字後，畫面上顯示的驗證狀態就不再有效。

對於沒有衝突、但值得仔細檢查的合併，預覽也會提出警告：

* 兩側編輯的行相距不超過兩行；
* 兩側在不同位置變更了同一個設定，例如 `name = value`、`name: value` 或 `"name": value`。

警告不會讓檢查判定為失敗。

IMPORTANT: 這些檢查只比較文字與位元組，無法證明合併結果正確無誤。

==== 資料夾

`--merge-plan` 會列出資料夾合併的各項操作與衝突，但不會實際執行。

`--validate-merge` 會依計畫檢查合併結果：
檢查計畫中的複製、合併與刪除，以及應維持不變的檔案，並再次確認來源檔案沒有變更。
結果可以放在另一個資料夾中：

[source,sh]
----
oxidemerge --validate-merge result-folder left-folder base-folder right-folder
----

建議的順序：先預覽合併，再執行合併，最後依計畫驗證結果。

[[semantic]]
=== 語意比較

比較 JSON、XML、TOML 與 YAML 檔案時，可選擇「語意」，依資料結構而非逐行比較。
語意檢視絕不會寫入檔案。
若 OxideMerge 無法讀取檔案，檢視會說明原因，按一下即可返回文字檢視。

.兩個 JSON 檔案的語意比較
image::semantic.png[語意比較]

==== 哪些變更會計入

JSON::
* 物件鍵的順序不計。
* 陣列元素的順序要計。
* 缺少的值與 `null` 視為不同。
* 重複的鍵視為錯誤。
XML::
* 屬性的順序不計。
* 名稱連同完整的命名空間一起比較。
* 子元素的順序、文字中的空白、混合內容與註解都要計。
* 不支援 DTD、宣告或未知的實體，以及 XML 1.1；支援內建的字元參照。
TOML 與 YAML::
* 比較方式與 JSON 相同：表格與對應的順序不計。
* 數字依數值比較，整數與小數之間也是如此。
  例如 `1` 等於 `1.0`，TOML 中的 `8_080` 等於 `8080`。
* 註解與排版不計。
* TOML 中含時區的日期時間，依所代表的時刻比較。
  例如 `10:00+02:00` 等於 `08:00Z`。
* YAML 採用 YAML 1.2 核心結構描述，因此 `yes` 與 `on` 都是文字。
  鍵也依值比較，因此 `0x10:` 與 `16:` 是同一個鍵。

限制：

* TOML 或 YAML 檔案最大 4 MiB。
* YAML 檔案只能包含一份文件，且不得使用別名、複合鍵或自訂標籤；
  `!!int` 這類核心標籤必須與其值相符。

文字比較的比較規則，不會當作語意檢視的篩選條件。

==== 解讀結果

變更會依路徑以樹狀顯示，每個分支會標出其中包含的變更數量。
按變更的來源按鈕，即可跳到檔案中對應的行。

陣列需要特別注意：

* 陣列以新的順序保有相同的元素時，被移動的元素會列為「移動」，並註明原本的位置。
* 若要依某個成員而非位置來配對陣列中的物件，請在「陣列配對鍵」中輸入成員名稱，例如 `id`（適用於 JSON、TOML 與 YAML）。
  這樣一來，插入或重新排序會顯示為新增與移動的元素，而不是之後每個位置都有變更。
* 若無法以該鍵配對某個陣列（某個元素沒有可唯一識別的簡單值），變更清單上方會說明原因，該陣列則改依位置比較。

若陣列元素不是單純依路徑配對，每項變更都會註明配對方式：
依陣列配對鍵、依完全相同的重新排序，或在長度不同的陣列中依位置配對。

若另一種解讀也同樣說得通，該變更會標示為「有歧義」，請自行確認。例如：

* 兩個元素互換位置時，任一個都可能是被移動的元素。
* 被移動的元素有重複。
* 插入元素讓後面的元素錯位，而該變更是依位置找到的。

報告會記錄每項變更的 `confidence`（`parser_exact`、`array_key`、`reordered` 或 `position`）、
有標示時的 `ambiguous`，以及 `notes`。

=== 審閱工作區

資料夾比較的「審閱工作區」分頁會記錄您的審閱內容：

* 每個檔案與每個差異區塊的狀態；
* 「審閱註解」、「判斷理由」與選填的「標籤（以逗號分隔）」；
* 「審閱者（自行填寫的名稱）」：只是自由填寫的文字，並非經過驗證的身分。

.審閱工作區
image::review.png[審閱工作區]

「下一個未審閱項目」會移到下一個尚待審閱的檔案。
若要審閱個別差異區塊，請從資料夾比較中開啟該檔案。

若要保留審閱決定與目前位置，請儲存資料夾審閱（請參閱 <<folder-reviews>>）。
OxideMerge 會等到比較、檔案操作與先前決定的檢查都完成後才儲存；
若比較已停止或失敗，則拒絕儲存。

==== 更新審閱

「更新審閱來源…」可選擇新的資料夾，並與先前的審閱決定對照。
它會保留所選的比較規則、以唯讀方式開啟資料夾，並標示不再相符的決定。

* 檔案只改名而內容未變時，審閱決定會跟著檔案，並註明原本的名稱。
* 若有多個新檔案的內容相同，每個檔案都會標示為需要重新審閱。
* 轉換後的內容、轉換程式或規則有變更時，先前的決定可能失效。
* 過期的決定一律列為「需要處理」，絕不會視為「已接受」。
* 差異區塊的前後文重複或無法明確對應時，必須手動審閱。

==== 檔案版本與安全性

* OxideMerge 以第 2 版格式儲存 `.oxmreview` 檔案。
  開啟第 1 版檔案時，所有項目都會設為尚未審閱；無法識別的版本則會被拒絕。
* 開啟封裝檔時，OxideMerge 會檢查所儲存檔案的摘要值。
* 下列封裝檔會被拒絕：路徑指向封裝檔以外、項目缺少、未列出或為連結，或由較新版本的 OxideMerge 儲存。

[[baselines]]
=== 版本基準

「版本摘要／比較基準」面板用來比較兩個版本，
位於起始頁，以及資料夾比較的側邊抽屜中。

.開啟「潛在影響」的版本摘要
image::baseline.png[版本摘要]

請直接選擇每一側的來源，不必先比較兩個資料夾。來源可以是：

[cols="1,2"]
|===
|來源 |意義

|`folder:路徑`
|資料夾目前的內容。

|`git:修訂版本:路徑`
|Git 修訂版本中的路徑。
OxideMerge 只解析一次修訂版本，並記錄其提交識別碼；不包含尚未提交的變更。

|`review:側:路徑`
|已儲存資料夾審閱中的某一側，第一側為 `0`。
|===

使用 Git 來源時，與 <<git-revision,Git 修訂版本比較>> 相同，您的 Git 設定與篩選器必須是可信任的。

==== 摘要

摘要會統計下列變更：

* 新增、刪除、修改與未變更的檔案；
* 內容完全相同的唯一檔案的移動；
* 疑似重新命名並修改的檔案；
* 二進位內容變更與檔案類型變更；
* JSON、XML、TOML 與 YAML 檔案的語意變更；
* 被排除的檔案。

摘要也會顯示每一側的擷取時間。

* 清單上方的計數可當作篩選條件，按一個或多個類別即可只顯示這些變更。
* 「高優先」只顯示有風險標記的變更：符合重要路徑，或檔案中仍留有衝突標記。這些變更也會排在最前面。
* 選取某一列，即可以唯讀方式開啟擷取的檔案。
  這些檔案來自基準，即使來源在擷取後有變更也不受影響。

==== 重新命名

同時符合下列條件時，OxideMerge 會判定為疑似重新命名並修改：

* 一個刪除的檔案與一個新增的檔案，都是同類型的文字檔。
* 兩者至少有一半、且至少三行相同。
* 兩者明確是彼此最相符的對象。

該列會顯示舊名稱，以及相同行數所占的比例。

* 按「不是重新命名」，可將兩個檔案維持為刪除與新增。
  在命令列中使用 `--split-rename 路徑`；若該路徑不是新增的檔案，OxideMerge 會提出警告。
* 按「重新偵測重新命名」可恢復判定。

==== 重要路徑

重要路徑是您想特別留意的文字，例如 `config/` 或 `api`。
包含這段文字的變更路徑會標示為高優先；從這類路徑移動或重新命名的檔案也會標示。
請在「重要路徑片段（以 ; 分隔）」中輸入；在命令列中則使用 `--important-path 文字`。

`--important-path` 與 `--split-rename` 都可以重複指定，
並需搭配 `--impact`、`--release-report` 或 `--baseline-left`。

NOTE: 重要路徑只是協助您決定審閱的先後順序，並不保證相容性。

[[impact]]
=== 影響分析

開啟「潛在影響」，即可列出變更的檔案可能在哪些地方被使用。
每項發現都會顯示檔案、行號、內容摘要值與一段摘錄。

==== 確切發現

匯入陳述式明確指向某個變更、刪除或重新命名的檔案時，該發現標示為「確切」。
OxideMerge 能辨識下列匯入方式：

* JavaScript 與 TypeScript：相對路徑的匯入、重新匯出與 `require`。
  匯入 `./util.js` 時，也會找到變更的 `util.ts`。
* Python 的匯入。
* C 與 C++ 的 `#include "…"`，以及 Objective-C 的 `#import "…"`。
* CSS 的 `@import`。
* Rust 的 `mod name;`，以及以 `crate::`、`super::` 或 `self::` 開頭的 `use` 路徑。
* JSON 的 `$ref` 檔案參照。

JavaScript、TypeScript、Python、C、C++ 與 Rust 檔案的匯入，是從 Tree-sitter 產生的語法樹中讀取；
`.h` 標頭檔以 C 剖析，只有在只能以 C++ 剖析時才視為 C++。
其他檔案則依程式碼的語法單位辨識；Vue 與 Svelte 元件只讀取其中的 `<script>` 區塊。
因此匯入可以跨越多行，而註解或字串中的文字不會被當成匯入。
若剖析器無法讀取檔案的某些部分，該檔案會列為部分評估，因為其中的匯入與定義可能被遺漏。

OxideMerge 也會比較變更的 JavaScript、TypeScript、Python、C、C++ 與 Rust 檔案中最上層的函式、型別與常數，
但不包括 C 與 C++ 的全域變數。
`#[derive(…)]` 這類 Rust 屬性，視為其後定義的一部分。

若某個檔案依名稱匯入了變更或移除的定義，會在第一次使用該名稱處產生「確切」發現，
並說明該定義是變更還是移除；以其他名稱匯入時也一樣。
這類匯入的例子：

* `import { parse } from "./parser"`
* `from .parser import parse`
* `use crate::parser::parse`

==== 推測發現

推測發現是可能的使用位置，需要您自行確認：

* 在同一語言的其他檔案中，第一次使用變更的定義名稱之處；
* 文字中以獨立字詞出現的變更檔案名稱或路徑；
* 變更的 JSON、TOML 與 YAML 鍵，也包括 `db.timeout` 這類以點連接的路徑。

大範圍的變更若產生超過 500 個名稱與鍵的相符處，只會列出前 500 個，
發現清單上方會註明其餘的數量；其他類型的發現則一律完整列出。

==== 影響分析找不到的項目

* 條件式、自動產生或由巨集建立的匯入。
* 方法，以及經由命名空間使用的名稱，例如 `ns.parse`。

OxideMerge 絕不會執行儲存庫的建置、測試或指令碼。

==== 處理發現

* 按「略過此發現」可隱藏該發現，不會修改檔案。
* 在資料夾比較中，按「審閱」可在審閱工作區開啟該發現所在的檔案。
* 沒有結果時，面板會說明尚未評估影響。
* 變更來源時，舊的發現會被清除。
* 取消分析時，不會顯示部分結果。

[[analysis-limits]]
=== 限制

* 每個檔案最大 16 MiB。
* 每個基準最多 10,000 個項目與 256 MiB 的擷取內容。
* 結構化檔案最多 64 層巢狀結構與 100,000 個節點。
* 影響分析的發現超過 2,000 個時會失敗，並要求您縮小範圍；只有名稱與鍵的相符處會被截斷。
* 超過限制的檔案會被拒絕或列為排除，絕不會被判定為相同。

耗時較久的分析會顯示進度，也可以取消。
某些步驟（例如剖析或合併單一檔案）只在開始前與結束後檢查是否取消，因此取消時可能要等該步驟完成。
這些限制不影響一般的比較。

[[analysis-command-line]]
=== 從命令列執行分析

[source,shell]
----
oxidemerge --merge-plan left.txt base.txt right.txt --report merge-plan.json
oxidemerge --validate-merge merged.txt left.txt base.txt right.txt --report validation.json
oxidemerge --semantic --format json old.json new.json --report semantic.html
oxidemerge --semantic --array-key id old.yaml new.yaml
oxidemerge --review-summary review.oxmreview --report review-summary.json
oxidemerge --baseline-left git:v1.0:/repo --baseline-right git:v1.1:/repo --release-report release.html
oxidemerge --impact old-folder new-folder --report impact.json
----

輸出：

* 未指定報告路徑時，分析會將附有版本編號的 JSON 輸出到標準輸出。
* `.xml` 報告與大多數分析的 `.html` 報告都包含這份 JSON，其格式與一般比較報告分開。
* 版本基準的 `.html` 報告是易讀的摘要，列出計數、高優先的變更以及每項變更的段落，並附上 JSON。
* 報告不得覆寫任何輸入檔案，也不得位於所選的輸入資料夾中。

結束代碼：

[cols="1,3"]
|===
|代碼 |意義

|`0`
|相同，或已成功產生計畫或摘要。

|`1`
|不同、有警告、計畫中仍有衝突，或審閱摘要中有過期的決定。

|`2`
|發生錯誤，或基準範圍不完整。
被篩選器刻意排除的檔案屬於範圍之外，不算錯誤。

|`3`
|僅 `--validate-merge`：檢查失敗。
|===

其他說明：

* `--format` 可為 `json`、`xml`、`toml` 或 `yaml`；預設依第一個檔案的副檔名判斷。
* 每次執行只能使用一個分析選項。
* OxideMerge 無法將結構化的變更寫回檔案，請在文字比較中編輯。
* 語意結果中的來源位置，是解碼後 UTF-8 文字的位元組範圍與檔案中的行號，
  而不是 UTF-16 或舊式編碼檔案中的位元組位置。

[[command-line]]
== 命令列

=== 開啟比較

不加任何參數執行 `oxidemerge`，會開啟起始頁。
指定兩個或三個路徑即可比較；指定一個路徑則可開啟衝突檔案、專案或已儲存的比較。
路徑包含空格時，請加上引號。

範例使用 POSIX 命令殼層語法。
在 Windows 上，請使用 Git Bash，或依您使用的命令殼層調整。

[source,sh]
----
oxidemerge left.txt right.txt                   # 雙向文字比較
oxidemerge mine.txt base.txt theirs.txt         # 三方比較（中間為基底）
oxidemerge -r old-folder new-folder             # 包含子資料夾
oxidemerge -r -f "*.rs;!target/" old new        # 套用篩選器的資料夾比較
oxidemerge conflict.txt                         # 解決含有衝突標記的檔案
oxidemerge -t image a.png b.png                 # 指定比較類型
oxidemerge https://example.com https://example.org   # 網頁比較
oxidemerge left.txt right.txt -o merged.txt     # 「儲存」會將右側窗格寫入 merged.txt
oxidemerge release.oxmproj                      # 開啟已儲存的專案
oxidemerge -r old.tar.gz new.tar.gz             # 將壓縮檔當作資料夾比較
oxidemerge --git-rev HEAD~1 src/main.rs         # 與較早的 Git 修訂版本比較
oxidemerge review.oxmcmp                        # 開啟已儲存的比較
----

=== 選項

.路徑與各側
[cols="2,3"]
|===
|選項 |說明

|`PATHS...`
|兩個或三個檔案、資料夾或網址；或是一個衝突檔案、專案檔或已儲存的比較。

|`-t`、`--compare-as <T>`
|比較類型：`text`、`binary`、`image` 或 `web`。

|`-o`、`--output <PATH>`
|「儲存」寫入結果的位置：雙向比較為右側窗格，三方比較為中間窗格。

|`--dl`、`--dm`、`--dr <TEXT>`
|取代左側、中間與右側路徑顯示的說明文字。

|`--wl`、`--wm`、`--wr`
|以唯讀方式開啟左側、中間或右側。

|`--git-rev <REV>`
|將指定的單一路徑，與它在 Git 修訂版本中的內容比較。
|===

.資料夾比較
[cols="2,3"]
|===
|選項 |說明

|`-r`、`--recursive`
|包含子資料夾。

|`-f`、`--filter <MASK>`
|篩選遮罩，例如 `*.c;*.h` 或 `!*.bak`；或以 `"[F] 名稱"` 指定具名篩選器。

|`-m`、`--method <M>`
|比較方法：`full`、`quick`、`binary`、`date`、`datesize` 或 `size`。
|===

.比較選項
[cols="2,3"]
|===
|選項 |說明

|`--ignore-ws <MODE>`
|空白字元：`compare`、`change` 或 `all`。

|`--ignore-case`、`--ignore-blank`、`--ignore-eol`、`--ignore-numbers`
|忽略大小寫、空白行、換行字元差異或數字。

|`--ignore-comments`
|忽略註解的變更。

|`--prettify`
|比較前格式化 JSON 與 XML。

|`--numeric-tolerance <AMOUNT>`
|差距不超過此值的數字視為相同。

|`--rules <NAME>`
|比較規則檔：規則資料夾中的名稱，或 `.oxrules` 檔案的路徑。
`""` 表示不使用規則檔。
|===

.報告與修補檔
[cols="2,3"]
|===
|選項 |說明

|`--cli`
|不開啟視窗進行比較。結束代碼請參閱 <<scripting>>。

|`--report <FILE>`
|產生報告。資料夾比較：`.html`、`.csv`、`.txt` 或 `.xml`；文字比較：`.html` 或 `.xml`。

|`--report-diffs`
|在 HTML 資料夾報告中加入每個已變更文字檔的差異。

|`--slideshow`
|將 `.html` 報告寫成投影片，每張投影片一個差異。

|`--patch <FILE>`
|為兩個檔案或資料夾產生修補檔。

|`--patch-style <S>`
|`normal`、`context` 或 `unified`（預設）。

|`--context <N>`
|上下文與統一格式修補檔中的前後文行數，預設為 3。
|===

.分析
[cols="2,3"]
|===
|選項 |說明

|`--merge-plan`
|為三個檔案或資料夾（左側、基底、右側）產生唯讀的合併計畫。

|`--validate-merge <RESULT>`
|對照三個檔案或資料夾（左側、基底、右側）檢查合併結果。

|`--semantic`
|依結構比較兩個 JSON、XML、TOML 或 YAML 檔案。

|`--format <FORMAT>`
|語意比較的格式：`json`、`xml`、`toml` 或 `yaml`。需搭配 `--semantic`。

|`--array-key <MEMBER>`
|依此成員配對陣列中的物件。需搭配 `--semantic`。

|`--review-summary <SNAPSHOT>`
|摘要已儲存的 `.oxmreview` 資料夾審閱中的決定。

|`--impact`
|列出兩個資料夾或基準中，變更的檔案可能在哪些地方被使用。

|`--baseline-left <SPEC>`、`--baseline-right <SPEC>`
|版本基準：`folder:路徑`、`git:修訂版本:路徑` 或 `review:側:路徑`。
兩者都要指定，用來取代路徑參數。

|`--release-report <FILE>`
|以 `.json`、`.html` 或 `.xml` 產生版本基準報告。

|`--important-path <TEXT>`
|將包含此文字的變更路徑標示為重要，可重複指定。
需搭配 `--impact`、`--release-report` 或 `--baseline-left`。

|`--split-rename <PATH>`
|將此新增的路徑維持為新增，而不視為疑似重新命名，可重複指定。
需搭配 `--impact`、`--release-report` 或 `--baseline-left`。
|===

每次執行只能使用一個分析選項，
且分析選項不能與 `-o`、`--patch`、`--git-rev`、`--slideshow` 或 `--report-diffs` 一起使用。

.其他選項
[cols="2,3"]
|===
|選項 |說明

|`--lang <CODE>`
|介面語言，例如 `ja` 或 `zh-TW`。

|`--list-languages`
|列出可用的語言。

|`--register-shell`、`--unregister-shell`
|加入或移除檔案管理員中的項目（請參閱 <<file-manager>>）。

|`--select-left <PATH>`、`--select-middle <PATH>`
|記住某一側，供之後的 `--compare-to` 使用。

|`--compare-to <PATH>`
|將路徑與記住的左側（及中間）比較。

|`-V`、`--version`
|顯示版本。
|===

在 Windows 上，也可以使用 WinMerge 風格的參數，例如 `/r`、`/f`、`/o`、`/dl`、`/dr`、`/wl` 與 `/wr`。
部分 WinMerge 參數會被忽略或不支援，使用既有的指令碼前請先測試。

[[scripting]]
=== 撰寫指令碼與結束代碼

`--cli`、`--report` 與 `--patch` 都不會開啟視窗，並傳回下列結束代碼：

[cols="1,4"]
|===
|代碼 |意義

|`0`
|套用目前的選項與規則後，內容相同。

|`1`
|找到差異。即使已成功產生報告或修補檔，也會傳回此代碼。

|`2`
|發生錯誤。
|===

IMPORTANT: 結束代碼 `1` 是比較結果，不是錯誤，請確認您的指令碼以這種方式處理。

* 命令列會使用您已儲存的選項，除非以參數另外指定。
  若要讓執行結果不受個人設定影響，請將 `OXIDEMERGE_CONFIG_DIR` 指向一個專用資料夾（請參閱 <<configuration>>）。
* 報告支援文字與資料夾比較。
  二進位或影像比較不會產生 HTML 報告，OxideMerge 會改為顯示說明訊息。

[source,sh]
----
# 不開啟視窗進行比較，同時輸出差異
oxidemerge --cli -r dirA dirB

# 資料夾比較的 HTML 報告，並附上每個已變更檔案的差異
oxidemerge -r dirA dirB --report report.html --report-diffs

# 兩個檔案的 HTML 報告，忽略註解的變更
oxidemerge old.c new.c --ignore-comments --report diff.html

# 含 5 行前後文的統一格式差異
oxidemerge old.c new.c --patch changes.patch --context 5

# 使用比較規則檔
oxidemerge --cli -r build1 build2 --rules "Build logs"
----

若命令殼層啟用了 `set -e`，請先將結束代碼存入變數，以免有差異時指令碼就中止：

[source,sh]
----
result=0
oxidemerge --cli -r old-folder new-folder || result=$?
case "$result" in
  0) echo "沒有差異" ;;
  1) echo "找到差異" ;;
  *) echo "比較失敗" >&2; exit "$result" ;;
esac
----

[[integration]]
== 與其他工具整合

[[git]]
=== Git

請先安裝 Git，並確認 `oxidemerge` 在 `PATH` 中。
接著在 Bash 或 Git Bash 等 POSIX 命令殼層中執行下列命令，
將 OxideMerge 設為目前使用者的比較工具與合併工具：

[source,sh]
----
git config --global diff.tool oxidemerge
git config --global difftool.oxidemerge.cmd 'oxidemerge "$LOCAL" "$REMOTE"'
git config --global merge.tool oxidemerge
git config --global mergetool.oxidemerge.cmd \
  'oxidemerge "$LOCAL" "$BASE" "$REMOTE" -o "$MERGED" --dl Local --dr Remote --wl --wr'
git config --global mergetool.oxidemerge.trustExitCode false
----

在 macOS 上，除非已將程式連結到 `PATH`，否則請使用完整路徑 `/Applications/OxideMerge.app/Contents/MacOS/oxidemerge`。
在 Windows 上，請使用 `oxidemerge.exe` 的路徑。

`git difftool`:: 逐一開啟每個已變更的檔案。
`git difftool --dir-diff` 則以一個資料夾比較開啟所有已變更的檔案；
在檔案中的最後一個差異按 kbd:[Alt+↓]，會開啟下一個已變更的檔案。
`git mergetool`:: 開啟三方合併，中間為基底。
請使用「自動合併」，或將差異複製到中間，然後儲存。
中間窗格的內容會寫入合併結果檔，絕不會寫入基底。
+
設定 `trustExitCode false` 時，Git 會檢查輸出檔案是否有變更；
若看起來沒有變更，Git 可能會詢問合併是否成功。
請在儲存並檢查結果後，才回答成功。
只是關閉視窗，並不代表合併成功。

[[file-manager]]
=== 檔案管理員

透過「工具」選單或執行 `oxidemerge --register-shell`，可將 OxideMerge 加入檔案管理員：

Windows:: 「工具 → 加入檔案總管右鍵選單」會為檔案、資料夾、磁碟機與資料夾背景加入「OxideMerge」子選單。
在 Windows 11 上，這些項目位於「顯示其他選項」中。
macOS:: 「工具 → 加入 Finder 快速動作」會在 Finder 的「快速動作」與「服務」選單中，
加入「OxideMerge: 比較」、「OxideMerge: 選為左側」與「OxideMerge: 選為中間」。
Linux:: 「工具 → 加入檔案管理員右鍵選單」會在 Nautilus、Nemo 與 Dolphin 中加入相同的項目。

這些項目的用法如下：

* 「比較」會比較選取的兩個或三個檔案或資料夾。
  只選取一個項目時，會將它與您先前選擇的一側比較；
  若尚未選擇任何一側，則開啟「選擇檔案或資料夾」對話框並帶入該項目。
* 「選為左側」與「選為中間」會記住一個項目，例如位於其他資料夾中的項目。
  之後「比較」會顯示為「與「名稱」比較」。
* 「比較方式」（僅限 Windows 的檔案）可指定以文字、二進位、影像或網頁比較。

這些項目會指向加入它們的程式；搬移程式後，請重新加入。
若要移除，請使用「工具」中對應的命令，或執行 `oxidemerge --unregister-shell`。

|===

「說明與快速鍵」會顯示設定檔的位置。
若 OxideMerge 無法讀取設定檔，會將它另存為 `config.json.bad` 並改用預設值；您可以修正該檔案後再放回原處。

設定資料夾中也包含下列資料夾：

* `Rules`：比較規則檔。
* `Filters`：WinMerge 的 `.flt` 篩選器檔案。
* `Languages`：新增或修改過的語言套件。

=== 可攜式與獨立設定

可攜式使用:: 在程式所在的資料夾中建立一個名為 `oxidemerge.json` 的空白檔案。
OxideMerge 便會將選項存放在這個檔案中，`Rules` 資料夾也會位於程式旁。
程式所在的資料夾必須可以寫入。
獨立設定:: 將環境變數 `OXIDEMERGE_CONFIG_DIR` 設為某個資料夾，OxideMerge 便會使用該資料夾中的 `config.json`。
此設定優先於可攜式使用與預設的設定資料夾，
適合用於指令碼、測試，或區隔不同的工作環境。

=== 新增語言

. 將原始碼中的 `lang/en.json` 複製為 `<code>.json`，例如 `nl.json`。
. 翻譯其中的值，所有 `{placeholder}` 都必須維持原樣。
. 將檔案放到程式旁或設定資料夾中的 `Languages` 資料夾。

缺少的訊息，以及少了或多了預留位置的翻譯，都會改以英文顯示。

[[troubleshooting]]
== 疑難排解

請先閱讀錯誤訊息，並記下其中提到的路徑。
重新合併或儲存之前，請檢查目標位置、磁碟可用空間、存取權限，以及是否有其他程式修改了檔案。

=== 安裝與啟動

macOS 拒絕開啟應用程式::
請先嘗試開啟一次，再到「系統設定 → 隱私權與安全性」中選擇「強制打開」。
或在「終端機」中清除下載標記：
`xattr -dr com.apple.quarantine /Applications/OxideMerge.app`。

macOS 要求存取資料夾::
OxideMerge 第一次讀取「桌面」、「文件」、「下載項目」、卸除式磁碟區或網路磁碟區時，macOS 會詢問一次。
請允許存取，或之後在「系統設定 → 隱私權與安全性 → 檔案和資料夾」中開啟。

AppImage 無法啟動::
請先以 `chmod +x` 讓它可以執行。
若訊息提到 FUSE，請加上 `--appimage-extract-and-run` 啟動。

在 Linux 上視窗一片空白或無法開啟::
OxideMerge 以 OpenGL 繪製畫面。
若沒有可用的顯示卡驅動程式（例如在虛擬機器中），請以 `LIBGL_ALWAYS_SOFTWARE=1 oxidemerge` 啟動，改用 Mesa 的軟體繪圖。

在 Linux 上無法開啟檔案對話框::
檔案對話框使用 XDG 桌面入口服務。
請安裝 `xdg-desktop-portal`，以及適用於您桌面環境的套件，例如 `xdg-desktop-portal-gtk` 或 `xdg-desktop-portal-kde`。

檔案管理員中沒有 OxideMerge 的項目::
在 Windows 11 上，這些項目位於「顯示其他選項」中。
項目會指向加入它們的程式；若將程式移動或更新到其他資料夾，請從新的程式重新加入。
在 Linux 上，請重新啟動檔案管理員（例如執行 `nautilus -q`）才會看到新項目。

設定沒有儲存::
OxideMerge 無法儲存設定時，會顯示原因。
請確認設定資料夾（請參閱 <<configuration>>）可以寫入，且磁碟沒有滿。

=== 編輯與儲存

某個窗格無法編輯::
該窗格因下列原因之一而為唯讀：
+
--
* 標題列上的鎖頭已鎖上。
* 以 `--wl`、`--wm` 或 `--wr` 開啟。
* 是從壓縮檔解壓縮出來的。
* 是以格式化方式顯示的 JSON 或 XML 檔案。
  請關閉「比較前格式化 JSON 與 XML」，即可編輯與合併。
--

檔案因編碼問題而無法儲存::
所選的編碼無法表示編輯內容中的某些字元。
請復原加入這些字元的變更後再儲存。
若改選其他編碼，OxideMerge 會重新讀取檔案，因此請先將您的編輯另外保留一份。

檔案可以寫入，但儲存或複製仍失敗::
取代檔案時，OxideMerge 還需要能在檔案所在的資料夾中建立暫存檔並取代檔案。
請檢查資料夾權限、磁碟可用空間，以及是否有其他程式鎖定該檔案。
OxideMerge 會回報失敗，絕不會直接覆寫原始檔案。
在成功儲存編輯內容之前，請不要關閉比較。

=== 比較結果

檔案看起來相同，但位元組內容不同::
請檢查空白字元、大小寫、換行字元、編碼與註解相關的選項，以及比較規則。
文字比較可能依設定刻意忽略這些差異。
若要確認檔案完全相同，請使用二進位比較，或資料夾比較的「二進位內容」方法。

資料夾比較中缺少某些檔案::
請檢查篩選器、「略過隱藏的檔案與資料夾」、「包含子資料夾」與「顯示」設定。
「依名稱尋找」也會隱藏部分項目。
「所有差異」沿用資料夾比較的篩選器與顯示設定，不會包含被隱藏的結果。

檔案顯示為錯誤::
OxideMerge 無法讀取該檔案，訊息中會指出是哪個檔案。
請檢查檔案的權限；在 macOS 上，也請一併檢查上述的資料夾存取權限。

資料夾自動合併無法開始，或沒有合併任何項目::
請開啟「包含子資料夾」與「包含唯一子資料夾的內容」，並等待比較完成。
若有檔案在比較後又有變更，就不會合併任何項目，並會列出該檔案。
若合併途中某項變更失敗，到目前為止的所有變更都會復原。
請重新整理比較後，再次檢查合併計畫。

=== 網頁

截圖模式顯示找不到瀏覽器::
截圖模式需要 Edge、Chrome、Chromium 或 Brave。
請在「選項 → 影像 / 二進位 / 網頁」中設定瀏覽器。

網頁比較缺少瀏覽器中看得到的內容::
請確認已找到瀏覽器，且已開啟「文字與 HTML 模式使用瀏覽器轉譯頁面（會執行頁面指令碼）」。
否則文字、格式化與 HTML 原始碼模式會使用伺服器傳回的 HTML，看不到指令碼加入的內容。
資源樹模式一律使用伺服器傳回的 HTML。
框架中的內容不列入比較。
無法下載的資源，以及因位於本機或私人網路而被略過的資源，都會在狀態列中計數。

=== 效能

大型檔案比較緩慢或占用大量記憶體::
文字比較會在記憶體中保留解碼後的文字、比較資料與編輯紀錄，實際用量取決於內容與您的操作。
二進位與影像檢視也會載入完整的檔案。
+
--
* 16 MiB 以上的有效 UTF-8 檔案會分段載入；
  UTF-16 與舊式編碼的檔案則會整個解碼。
  文字仍可編輯，比較規則也照常運作。
* 超過 50,000 行或 16 MiB 的解碼文字時，會關閉語法醒目提示。
* 編輯、復原、自動換行與特殊的比較規則，仍可能增加記憶體用量。
--
+
若要減少記憶體用量，可使用二進位比較，或改以大小與日期而非內容比較資料夾（請參閱 <<compare-methods>>）。

[[limitations]]
== 已知限制

* 壓縮檔：支援 ZIP 類格式、TAR（未壓縮、gzip、bzip2 與 xz）與 7z，不支援 RAR。解壓縮後的內容為唯讀。
* 文字編輯以行為單位，主要用於檢查與合併變更。
* 解譯器外掛程式使用外部命令，不支援 WinMerge 的外掛程式動態連結程式庫與指令碼。
* 網頁比較不支援 Cookie 或登入，需要登入的網頁會顯示其登入畫面。
  沒有 Chromium 系列瀏覽器時，網頁的指令碼不會執行，因此看不到指令碼加入的內容。
  框架中的內容不列入比較。
* 語意比較無法將變更寫回檔案。
* 介面翻譯由機器輔助完成，尚未經過母語人士審閱。
