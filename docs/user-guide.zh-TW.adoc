[.lead]
OxideMerge 是適用於 Windows、macOS 與 Linux 的圖形化比較與合併工具。
您可以檢查檔案與資料夾的變更、整合修改內容，以及解決合併衝突。
也能比較二進位檔、影像與網頁。程式以 Rust 開發，設計參考 WinMerge。

本指南另提供 xref:user-guide.adoc[英文版]。

[NOTE]
====
*macOS 快速鍵。* 本指南採用 Windows 與 Linux 的按鍵名稱。
在 macOS 上，kbd:[Ctrl] 請改用 Command 鍵（kbd:[⌘]）；但 kbd:[Ctrl+Tab] 仍使用 Control 鍵。
kbd:[Alt] 請改用 Option 鍵（kbd:[⌥]）。選單與工具提示會依平台顯示適用的快速鍵。
====

== 關於本指南

本指南說明日常比較與合併的操作方式。建議先閱讀 <<first-comparison>>，
再依工作類型查閱對應章節。
「檔案 → 開啟...」這類寫法表示要依序選擇的選單與指令。
指令列範例假設 `oxidemerge` 已加入 `PATH` 環境變數；若尚未加入，請使用執行檔的完整路徑。
範例中的檔案與資料夾路徑，請替換為實際路徑。

=== 主要功能

* 比較兩個或三個資料夾，包括支援的壓縮檔，並複製、刪除或合併項目。
* 比較與編輯文字、在版本之間複製變更，以及解決版本控制衝突。
* 比較二進位檔的位元組、影像像素與網頁內容。
* 透過比較選項與可重複使用的比較規則，排除不需要檢查的差異。
* 匯出報告與修補檔，或儲存專案及文字比較，供日後檢閱。
* 透過指令碼執行比較，或搭配 Git 使用。

介面提供英文、繁體中文、簡體中文、日文、韓文、德文、法文、西班牙文、俄文與巴西葡萄牙文。

=== 常用術語

側與窗格:: 「側」代表比較中的一個版本，分為左側、中間與右側；「窗格」是顯示該版本的區域。
差異:: 版本之間的變更。在文字比較中，一個差異可能包含多行。
共同祖先版本:: 兩份修改版本所依據的原始版本。進行三方比較時，請將它放在中間。
衝突:: 同一區域出現不同修改，需要自行選擇或編輯合併結果。
合併:: 將變更複製或整合到目標版本。
篩選器:: 決定要包含哪些檔案與資料夾的條件。
比較規則:: 決定哪些文字變更算是差異，不會直接修改原始檔案。

IMPORTANT: 合併會變更目標內容。複製或儲存前，請確認來源、目標與輸出路徑。
只需要檢閱的版本，建議設為唯讀。

== 安裝

請從 https://github.com/kuopinghsu/OxideMerge/releases[GitHub 發行頁面] 下載適合系統與處理器的套件。
每個版本也提供英文與繁體中文 PDF 指南，以及用來驗證下載檔案的 `SHA256SUMS.txt`。

[cols="1,3"]
|===
|平台 |套件

|Windows 10 或 11，x64／Arm64
|`oxidemerge-<version>-windows-x64.exe` 或 `oxidemerge-<version>-windows-arm64.exe`。
可直接執行，或解壓縮對應的 ZIP 套件。

|Linux x64 / Arm64
|AppImage（Ubuntu 20.04、RHEL 8、Debian 10 及更新版本）、Debian 套件（Ubuntu 22.04 及更新版本），
或 TAR.GZ 壓縮檔。Intel／AMD 處理器請選 `linux-x64`，64 位元 Arm 請選 `linux-arm64`。

|macOS 11 以上
|`oxidemerge-<version>-macos-universal.dmg`（Apple 晶片與 Intel），或包含相同應用程式的 `.zip`。
|===

Linux::
請在使用 X11 或 Wayland 的桌面環境中執行。
啟動 AppImage 前，請先執行 `chmod +x oxidemerge-*.AppImage`。
若系統沒有 FUSE，請加上 `--appimage-extract-and-run` 啟動。
以 `sudo apt install ./oxidemerge-*.deb` 安裝 Debian 套件。
檔案對話框需要 `xdg-desktop-portal`，一般桌面環境通常已提供。
若要顯示中文、日文與韓文，請安裝 Noto Sans CJK 等適用字型。

macOS::
開啟磁碟映像檔，將「OxideMerge」拖移至「應用程式」。
程式採臨時簽署，尚未經過 Apple 公證，因此首次啟動時可能遭到 macOS 阻擋。
請先嘗試開啟一次，再到「系統設定 → 隱私權與安全性」中選擇「強制打開」。
在 macOS 14 及更早版本，也可以按住 Control 鍵點選應用程式，再選擇「打開」。
您可以在終端機中使用執行檔的完整路徑。若要直接使用 `oxidemerge` 指令，
可在 `PATH` 已包含且存在的目錄中建立連結，例如：
+
[source,sh]
----
sudo ln -s /Applications/OxideMerge.app/Contents/MacOS/oxidemerge /usr/local/bin/oxidemerge
----

從原始碼建置::
透過 https://rustup.rs/ 安裝 Rust 工具鏈，在儲存庫根目錄執行 `cargo build --release --locked`。
執行檔位於 `target/release/oxidemerge`，Windows 則為 `target/release/oxidemerge.exe`。
建置需求與檢查方式請參閱 xref:../README_zh-TW.md#開發[讀我文件的開發章節]。

== 快速入門

[[first-comparison]]
=== 第一次比較

. 在起始頁選擇「比較檔案或資料夾」。
. 將較舊的檔案設為「左側」，較新的檔案設為「右側」。
. 勾選不希望修改的一側旁的「唯讀」，再按「比較」。
. 按 kbd:[Alt+↓] 移至下一個差異。
. 若要合併差異，請先確認目標窗格，再使用指向該窗格的箭頭。
. 檢查結果。使用「檔案 → 另存新檔」指定另一個輸出檔案，或使用「儲存」更新目前窗格的檔案。

如果只需檢查而不修改，請將兩側都設為唯讀。
若要分享檢閱結果而不傳送原始檔案，可以匯出 HTML 報告。

=== 選擇工作流程

檢查兩個版本:: 開啟兩個檔案或資料夾。不需要修改的一側可設為唯讀。
整合兩份修改:: 依序開啟左側版本、共同祖先版本與右側版本。
輸出位置與衝突處理請參閱 <<three-way-merge>>。
解決衝突檔案:: 開啟含有衝突標記的單一檔案，請參閱 <<conflict-files>>。
檢查多個變更檔案:: 先執行資料夾比較，再開啟「所有差異」。
日後重複比較:: 儲存為專案；若要保留當下的文字與檢閱註記，請儲存比較。
請參閱 <<projects>> 與 <<saved-comparisons>>。

=== 主視窗

.起始頁
image::start.png[起始頁]

視窗包含下列部分：

選單列:: 「檔案」、「編輯」、「檢視」、「比較」、「合併」、「工具」與「說明」。
在目前分頁中不適用的命令會以灰色顯示。
右上角的按鈕:: 「開啟」、主題選擇、「選項」、「命令面板」與「說明與快速鍵」。
分頁:: 每個比較都在自己的分頁中開啟。
在分頁上按右鍵，可關閉該分頁、其他分頁、右側的分頁或全部分頁。
kbd:[Ctrl+Tab] 與 kbd:[Ctrl+Shift+Tab] 切換分頁，kbd:[Ctrl+W] 關閉目前的分頁。
狀態列:: 顯示差異數量、目前的行或位移，最右側則顯示介面語言。
可在「選項 → 一般」中變更語言，或以 `--lang` 啟動 OxideMerge。

不帶任何比較啟動 OxideMerge 時會顯示起始頁。
起始頁有「比較檔案或資料夾」、「開啟衝突檔案」，以及最近使用的比較清單。
在最近使用的比較上按右鍵，可「變更路徑...」或「從最近使用中移除」。

=== 開啟比較

有幾種方式可以開始比較：

* 「檔案 → 開啟...」（kbd:[Ctrl+O]）或起始頁的「比較檔案或資料夾」會開啟「選擇檔案或資料夾」對話框。
* 將兩個或三個檔案或資料夾拖放到視窗上。
  只拖放一個項目時，會開啟已填入該項目的對話框。
* 從起始頁、「檔案 → 開啟最近使用」或命令面板選擇最近使用的比較。
* 從指令列（請參閱 <<command-line>>）或檔案總管（請參閱 <<file-manager>>）啟動 OxideMerge。

在「選擇檔案或資料夾」對話框中：

. 輸入或瀏覽「左側」與「右側」的路徑。
  路徑可以是檔案、資料夾，或 `http://`、`https://` 網址。
  勾選「三方比較」可加入「中間」的路徑。
. 勾選某一側旁的「唯讀」可避免它被修改。
  「左右互換」會交換兩側。
. 比較資料夾時，可選擇「包含子資料夾」、「篩選器」與「比較方法」。
. 「比較方式」可強制以文字、二進位、影像或網頁比較。
  「自動」會依路徑、副檔名與檔案內容決定，請參閱 <<compare-types>>。
. 按一下「比較」。

TIP: 「檔案 → 新增文字比較」（kbd:[Ctrl+N]）會開啟兩個空白窗格。
按 kbd:[Ctrl+V] 貼上文字，或按兩下某一行開始輸入。

[[compare-types]]
=== 比較類型

「比較方式」設為「自動」時，OxideMerge 會依下列順序，從路徑決定比較類型：

. 任一側為 `http://` 或 `https://` 網址時，開啟網頁比較。
. 每一側都是資料夾時，開啟資料夾比較。
. 每一側都是壓縮檔時，解壓縮後以資料夾比較。
. 所有檔案的副檔名都是影像格式（`.png`、`.jpg`、`.gif`、`.bmp`、`.tif`、`.webp` 等）時，開啟影像比較。
. 檔案的前 8 KB 中含有零位元組時，開啟二進位比較，除非有解譯器外掛程式將它轉換為文字（請參閱 <<unpackers>>）。
  帶有位元組順序標記的 UTF-16 文字仍視為文字。
. 其他情況一律開啟文字比較。

對話框中的「比較方式」、已開啟分頁中的「比較 → 比較方式」，或指令列的 `-t`，都可以覆寫這項選擇。
各種比較類型顯示的內容與可變更的對象如下：

文字:: 並排顯示各行，並醒目標示變更的字詞。
可在允許編輯的窗格中修改與合併文字，由比較選項與規則決定哪些變更算是差異。
適用於原始碼、設定檔、CSV 及其他可閱讀的文字。
二進位:: 以十六進位檢視顯示位元組。
差異可以複製與儲存，但不會對齊：在開頭附近插入一個位元組，其後的所有內容都會跟著位移。
影像:: 以並排、疊加、滑動、閃爍或差異模式顯示像素。
有差異的區域可以在影像之間複製。
資料夾:: 依所選的比較方法，比較兩個或三個資料夾中的項目。
可在這裡複製、刪除與合併項目，每個檔案也可以在各自的比較中開啟。
網頁:: 以可見文字、醒目提示文字差異的整頁或可見區域截圖、HTML 原始碼或下載的資源比較兩個或三個網頁。
網頁為唯讀，不會將任何內容存回伺服器。

以下各章會分別說明每種比較類型。

=== 取得說明

* 「說明 → 說明與快速鍵」（kbd:[F1] 或 kbd:[?]）依檢視列出所有鍵盤快速鍵與滑鼠操作，並顯示設定檔的位置。
* 「說明 → 命令面板」（kbd:[Ctrl+K] 或 kbd:[Ctrl+Shift+P]）可搜尋命令、最近的比較和設定。
  輸入名稱的一部分後按 kbd:[Enter]。
  可開關的設定會顯示目前是否「已開啟」。

== 資料夾比較

.資料夾比較
image::folder.png[資料夾比較]

資料夾比較會列出兩個或三個資料夾中的項目及其比較結果。
結果在比較進行中就會顯示：檔案在掃描資料夾時即進行比較，找到差異或唯一的項目後會立即列出。
若視窗在背景時完成了耗時較久的比較，OxideMerge 會提醒您。

=== 資料夾清單

每一列顯示「名稱」、所在的「資料夾」、「比較結果」、各側的日期與大小，以及「副檔名」。
按一下欄位標題即可依該欄排序。

比較結果為下列其中之一：

* 「文字檔案相同」或「文字檔案不同」；
* 「二進位檔案相同」或「二進位檔案不同」；
* 「資料夾相同」或「資料夾不同」；
* 「僅左側有」、「僅右側有」或「僅中間有」：只在某一側找到的項目；
* 「左側不同」、「中間不同」或「右側不同」：三方比較時；
* 「錯誤」：無法讀取的項目。

狀態列會統計相同、不同、唯一的項目數量與錯誤數。

「檢視 → 資料夾清單」中有：

* 「樹狀模式」：以樹狀結構顯示子資料夾，關閉後改為平面清單。
  kbd:[→] 與 kbd:[←] 展開及摺疊資料夾，工具列也有「全部展開」與「全部摺疊」。
* 「顯示」：顯示或隱藏「相同」、「不同」、「僅左側」、「僅中間」與「僅右側」的項目。
* 「資料夾清單下方顯示檔案比較」：在清單下方直接顯示所選檔案的差異，不必開啟分頁。

=== 工具列

由左至右：

* 「重新整理」（kbd:[F5]）：重新比較。
* 「全部展開」與「全部摺疊」：樹狀模式下使用。
* 「複製到右側」與「複製到左側」：複製選取的項目。
* 「依名稱選取...」：選取名稱符合萬用字元（例如 `*.c; *.h`）的項目。
* 「所有差異」：在一個分頁中開啟所有已變更的文字檔（請參閱 <<all-differences>>）。
* 「匯出 HTML」：儲存 HTML 報告（請參閱 <<reports>>）。
* 「篩選器」：決定要比較哪些檔案與資料夾（請參閱 <<filters>>）。
* 「規則」：選擇此比較使用的比較規則檔（請參閱 <<compare-rules>>）。
* 「比較方法」：選擇比較檔案的方式。
* 「依名稱尋找」（kbd:[Ctrl+F]）：只顯示名稱含有該文字的項目。

[[compare-methods]]
=== 比較方法

[cols="1,3"]
|===
|方法 |比較檔案的方式

|完整內容
|逐行比較文字檔，並套用比較選項與規則。
只有被忽略的差異的檔案視為相同。

|快速內容
|比較位元組。
大小不同的檔案不必讀取即可判定為不同。

|二進位內容
|與「快速內容」一樣比較位元組，並將結果歸類為二進位檔案。

|修改日期
|比較修改日期，容許「選項 → 資料夾」中設定的「日期容許誤差（秒）」。

|修改日期與大小
|日期與大小都必須相同。

|大小
|只比較大小。
|===

進行位元組比較時，會分段讀取檔案，不必載入完整內容；檔案大小不同時，也能直接判定有差異。
完整的文字比較仍可能需要將有變更的檔案載入記憶體。

需要套用文字規則與忽略選項時，請用「完整內容」。需要確認位元組完全相同時，請用「快速內容」或
「二進位內容」。日期與大小適合初步檢查，但中繼資料相同不代表內容完全相同。

=== 操作項目

可以用滑鼠或鍵盤選取項目：方向鍵、kbd:[PgUp]、kbd:[PgDn]、kbd:[Home] 與 kbd:[End]，按住 kbd:[Shift] 可擴充選取範圍，kbd:[Ctrl+A] 全選。
按住 kbd:[Ctrl] 並按一下可將項目加入或移出選取範圍。

* 按兩下項目或按 kbd:[Enter]，即可在獨立分頁中比較它。
  資料夾會開啟自己的資料夾比較。
* 按 kbd:[Space] 開啟「快速預覽」：不必開啟分頁即可看到所選檔案的彩色差異。
  kbd:[↑] 與 kbd:[↓] 切換項目，kbd:[Enter] 開啟，kbd:[Space] 或 kbd:[Esc] 關閉預覽。
* kbd:[Alt+→] 與 kbd:[Alt+←] 將選取的項目複製到右側或左側。

在項目上按右鍵可使用更多功能：

* 複製到另一側，以及「複製到資料夾...」：將某一側選取的項目複製到另一個資料夾，並保留相對路徑；
* 從某一側「刪除」；
* 「以關聯的應用程式開啟」；
* 「在檔案總管中顯示」；
* 「複製完整路徑」；
* 「依名稱選取...」。

「選項 → 一般」提供下列檔案操作設定：

* 「複製前先確認」：複製選取項目前先顯示確認提示。
* 「刪除時使用資源回收筒」：將刪除的項目移至系統的資源回收筒或垃圾桶。
  無法移入的項目不會被刪除。
* 「覆寫檔案時保留 .bak 備份」：取代檔案前保留先前的內容。

複製與刪除會直接變更磁碟上的檔案，不會等待「儲存」，也無法使用文字編輯的「復原」撤銷。
操作前請確認選取項目與目標位置。

=== 自動合併資料夾

在三方資料夾比較中，中間的資料夾是共同的祖先版本。
「合併 → 自動合併資料夾...」會將兩側的變更帶入中間資料夾：

* 只在某一側變更、新增或刪除的項目會被複製或刪除；
* 兩側相同的變更只會套用一次；
* 兩側都有變更的文字檔，若變更不重疊，會逐行合併。

開始前，請在「選項 → 資料夾」中啟用「包含子資料夾」與「包含唯一子資料夾的內容」，並等待比較完成。

OxideMerge 會列出預計複製、刪除、合併的項目與未解決的衝突，確認前請先檢查。
修改不相容、內容不支援、符號連結或讀取失敗的檔案會維持原狀。
若檔案在比較後又有變更，請先重新整理再嘗試合併。

IMPORTANT: 資料夾操作會在確認後寫入磁碟，不會等待「儲存」。合併結果會寫入中間的資料夾。
若要保留原始祖先資料夾，請先複製一份作為中間的工作資料夾。

=== 壓縮檔

壓縮檔會解壓縮後以資料夾比較：zip 類格式（`.zip`、`.jar`、`.apk`、`.docx`、`.xlsx`、`.odt`、`.epub`、`.nupkg` 等）、`.tar`、`.tar.gz` / `.tgz`、`.tar.bz2` / `.tbz2`、`.tar.xz` / `.txz` 與 `.7z`。
解壓縮後的內容為唯讀，無法將變更寫回壓縮檔。
解壓縮後超過 8 GB 或 500,000 個檔案的壓縮檔不會開啟。不支援 RAR。

[[all-differences]]
== 所有差異

.所有差異
image::alldiffs.png[所有差異]

資料夾比較工具列上的「所有差異」，或「比較 → 所有差異」，會在一個分頁中顯示資料夾比較裡所有已變更的文字檔。
資料夾比較的篩選器與「顯示」設定同樣適用。

* 左側清單列出每個檔案及其差異數量。
  「篩選檔案...」（kbd:[Ctrl+F]）可縮小範圍，按一下檔案即可捲動到該檔案。
* 每個檔案是一張卡片，並排顯示其差異。
  卡片標題的箭頭可摺疊或展開卡片，工具列可摺疊或展開全部卡片。
* kbd:[Alt+↓] 與 kbd:[Alt+↑] 跨檔案逐一切換差異。
* 差異旁的箭頭會將它複製到另一側。
  雙向比較時，卡片標題上的按鈕可複製整個檔案。
* 「復原」可取消上一個變更。
  「儲存」會寫入已變更的檔案，之後資料夾比較會重新整理。
* 卡片標題最右側的按鈕會「在單獨的分頁中開啟」該檔案。

若從檔案不存在的一側複製，儲存時會刪除該檔案，以及因此變空的資料夾。
若檔案在載入後於磁碟上發生變更，會停止儲存該卡片，並提供捨棄編輯、重新載入的選項。
選擇重新載入前，請先另外保留需要的編輯內容。

啟用備份時，刪除的檔案會保留為 `.bak`，因此所在資料夾可能不會移除。
未編輯的卡片會在檔案變更時重新載入。「重新整理」（kbd:[F5]）也會重新載入比較規則與選項。
若要加入新發現的變更檔案，請先儲存或處理目前的編輯，再重新開啟「所有差異」。

== 文字比較

.雙向文字比較
image::text.png[文字比較]

每一側的標題列顯示檔案名稱與所在資料夾、「編碼」、儲存時使用的「換行格式」，以及可將該側設為唯讀的鎖頭按鈕。
選擇其他編碼會以該編碼重新載入檔案，請在編輯與儲存前確認文字顯示正確。

左側的「位置窗格」是整個檔案的概覽。
按一下即可跳到該位置。
差異會以顏色標示：變更的行為琥珀色，只在一側的行為藍色。
變更的行中，有變更的單字或字元會醒目標示。

=== 在差異之間移動

[cols="1,2"]
|===
|按鍵 |動作

|kbd:[Alt+↓]、kbd:[Alt+↑]
|下一個或上一個差異

|kbd:[Alt+Home]、kbd:[Alt+End]
|第一個或最後一個差異

|kbd:[Alt+PgDn]、kbd:[Alt+PgUp]
|下一個或上一個衝突（三方比較）

|kbd:[Ctrl+G]
|跳至行
|===

從資料夾比較開啟的檔案，越過最後或第一個差異時，會開啟下一個或上一個有差異的檔案。

=== 複製變更與儲存

複製文字差異會更新目標窗格，儲存後才會變更磁碟上的檔案。
複製前請先確認目前作用中的窗格與箭頭方向。

* 兩側之間分隔線上的箭頭會複製滑鼠所在或目前的差異。
* kbd:[Alt+→] 與 kbd:[Alt+←] 將目前的差異或選取的行複製到右側或左側。
* kbd:[Ctrl+Alt+→] 與 kbd:[Ctrl+Alt+←] 複製所有差異。
* kbd:[Ctrl+Z] 復原，kbd:[Ctrl+Y] 或 kbd:[Ctrl+Shift+Z] 重做。
* kbd:[Ctrl+S] 儲存目前的檔案，kbd:[Ctrl+Shift+S] 全部儲存。
  「檔案 → 另存新檔」可將某一側以其他名稱儲存。

儲存一般檔案時，程式會先在目標資料夾建立暫存檔，再取代目標檔案。
若無法建立暫存檔或取代檔案，會回報錯誤，不會改為直接覆寫原檔。
即使目標檔案本身可寫入，目標資料夾仍須允許建立暫存檔與取代檔案。

啟用「選項 → 一般 → 覆寫檔案時保留 .bak 備份」，可將先前的內容保留為 `<name>.bak`。
後續儲存會取代這份備份，因此備份不等同於完整的版本紀錄。

=== 編輯

不是唯讀的每一側都可以逐行編輯。

* 按兩下某一行，或按 kbd:[F2] 或 kbd:[Enter] 即可編輯。
* 拖曳、按住 kbd:[Shift] 並按一下，或按 kbd:[Shift+↑] 與 kbd:[Shift+↓] 可選取多行。
* kbd:[Ctrl+C] 複製選取的行，kbd:[Ctrl+V] 貼到目前這一行下方，或取代選取的行。
* kbd:[Ctrl+\]] 與 kbd:[Ctrl+[] 增加或減少選取行的縮排。

在某一行上按右鍵，可編輯行、在下方插入行、刪除行、複製該行文字、加入書籤，或依該行新增比較規則（請參閱 <<add-rule>>）。

行號旁的編輯標記會顯示開啟檔案後變更過的行。
當其他程式修改了檔案，OxideMerge 會在視窗重新取得焦點時偵測到：沒有未儲存變更的檔案會自動重新載入，有未儲存變更的檔案則會顯示提示列，讓您決定是否重新載入。
重新載入會以磁碟上的版本取代尚未儲存的編輯內容。

=== 尋找與取代

* kbd:[Ctrl+F] 開啟尋找列。
  kbd:[F3] 與 kbd:[Shift+F3] 尋找下一個與上一個，kbd:[Esc] 關閉尋找列。
* kbd:[Ctrl+H]（macOS 為 kbd:[Cmd+Alt+F]）尋找並取代。
* 選項有「大小寫須相符」、「全字拼寫須符合」與「規則運算式」。
  使用規則運算式時，取代文字中的 `$1` 代表第一個擷取群組。
* 「全部取代」可一次復原。

=== 書籤

* kbd:[Ctrl+F2] 在目前這一行設定或移除書籤。
* kbd:[F4] 與 kbd:[Shift+F4] 跳到下一個與上一個書籤。
* 「編輯 → 書籤 → 書籤註解...」可加上註解。
  滑鼠移到行號區時會顯示註解，HTML 報告中也會列出。
* 「編輯 → 書籤 → 清除所有書籤」會移除全部書籤。

書籤會標示在行號區與位置窗格中。

=== 檢視選項

「檢視 → 文字比較」中有：

* 「位置窗格」與「行詳細資料窗格」。
  行詳細資料窗格會將各側的目前這一行上下排列並自動換行，方便找出長行中的細微差異。
* 「行號」、「編輯標記」、「顯示空白字元」與「語法醒目提示」。
* 「摺疊未變更的行」（kbd:[Alt+C]）：將未變更的行摺疊成一列，每個差異前後保留三行。
  按一下該列即可展開。
* 「自動換行」（kbd:[Alt+Z]）。

「檢視 → 縮放」（kbd:[Ctrl+{plus}]、kbd:[Ctrl+-] 與 kbd:[Ctrl+0]）調整文字大小。
CSV 與 TSV 檔案的工具列有「表格檢視」，會將各欄對齊顯示。

[[three-way-merge]]
=== 三方比較與合併

.三方文字比較
image::three.png[三方文字比較]

請依序開啟「您的版本、共同祖先版本、另一份版本」。
OxideMerge 會將左右兩側與祖先版本比較，並將變更合併至中間窗格。

==== 合併前先選擇輸出位置

預設情況下，儲存中間窗格會覆寫開啟的祖先檔案。若要保留祖先檔案，請在啟動時指定另一個輸出路徑：

[source,sh]
----
oxidemerge mine.txt base.txt theirs.txt -o merged.txt
----

中間窗格一開始顯示祖先檔案的內容，儲存時會將結果寫入 `merged.txt`。
也可以使用「檔案 → 另存新檔」選擇其他路徑。
若左右兩側只作為合併來源，建議將它們設為唯讀。

==== 合併與檢查衝突

. 選擇「合併 → 自動合併」，將只在一側出現的變更，以及兩側相同的變更複製至中間窗格。
. 使用 kbd:[Alt+PgDn] 與 kbd:[Alt+PgUp] 檢查剩餘衝突。
. 將需要的變更從左側或右側複製至中間，或直接編輯中間窗格。
. 若要保留兩側的變更，在差異上按右鍵，選擇「採用左側，再採用右側」或「採用右側，再採用左側」。
  檢查結果是否出現重複或不相容的內容。
. 確認目標路徑正確後儲存。

自動合併只處理文字差異，不會驗證結果的意義或邏輯。
使用合併結果前，請先檢查內容並執行專案所需的驗證。

[[conflict-files]]
=== 解決衝突檔案

.以三方檢視開啟的衝突檔案
image::conflict.png[衝突檔案]

含有版本控制衝突標記（`<<<<<<<`、`|||||||`、`=======` 與 `>>>>>>>`）的檔案可以在三方檢視中解決。
以「檔案 → 開啟衝突檔案...」、起始頁的「開啟衝突檔案」，或 `oxidemerge conflict.txt` 開啟。

左側是「我的」，右側是「他們的」，中間是「合併結果」。
解決各項衝突後儲存中間窗格，結果會寫回衝突檔案。
這與開啟三個獨立檔案的流程不同：原本的衝突檔案就是輸出目標。

=== 與 Git 修訂版本比較

「檔案 → 與 Git 修訂版本比較...」會將檔案或資料夾與其在 Git 修訂版本（`HEAD`、分支、標籤或提交）中的內容比較。
對話框會列出最近的提交供您選擇。
選取的修訂版本以唯讀方式顯示在左側，目前的檔案或資料夾顯示在右側。
必須先安裝 Git 並加入 `PATH`，選取的路徑也必須位於 Git 儲存庫中。

在指令列中使用 `--git-rev`：

[source,sh]
----
oxidemerge --git-rev HEAD~1 src/main.rs
----

[[saved-comparisons]]
=== 儲存比較供日後檢閱

「檔案 → 儲存比較...」會將各側的文字連同書籤與註解存成一個 `.oxmcmp` 檔案。
日後開啟或傳送給其他檢閱者，即可查看儲存的文字與註記。
比較會以唯讀方式開啟，不需要原始檔案仍存在。這是當時文字內容的快照，
並非依路徑重新載入目前檔案的專案。

NOTE: 儲存的比較包含每一側的完整文字；HTML 報告則包含匯出的差異與前後文。
分享前請先確認沒有不宜公開的內容。

=== 修補檔

「檔案 → 匯出 → 產生修補檔...」會將兩個檔案或資料夾之間的差異寫成「一般」、「前後文」或「統一」格式的修補檔，並可指定前後文行數。
只能從雙向比較產生修補檔。

「檔案 → 套用修補檔...」可套用統一格式的差異，包括 `git diff` 與 `svn diff` 的輸出。
即使行的位置已移動，OxideMerge 也能找到每個區塊，並將每個修補後的檔案與原始檔案並排開啟，供您檢查後儲存。
修補區塊是修補檔中的一組變更。無法套用的區塊會列在訊息中，
儲存前請先檢查訊息與產生的比較結果。套用修補檔不會自動確認或儲存全部結果。

== 二進位比較

.二進位比較
image::binary.png[二進位比較]

二進位檔會以並排的十六進位檢視開啟，不同的位元組會醒目標示。
兩側會同步捲動。

* kbd:[Alt+↓] 與 kbd:[Alt+↑] 逐一切換差異。
* kbd:[Ctrl+F] 尋找十六進位位元組（例如 `DE AD BE EF`）或文字。
* kbd:[Ctrl+G] 跳至位移，可寫成 `0x1F00`、`1F00h` 或十進位數字。
* 與文字比較一樣，可將差異複製到另一側並儲存。

每行位元組數可在「選項 → 影像 / 二進位 / 網頁」中設定。

== 影像比較

.影像比較
image::image.png[影像比較]

可選擇下列檢視模式檢查影像差異：

並排:: 兩張影像並排顯示。
疊加:: 一張影像疊在另一張上，可調整「不透明度」。
滑動:: 分隔線左邊顯示一張影像，右邊顯示另一張。
拖曳分隔線即可移動。
閃爍:: 交替顯示兩張影像，方便看出細微變化。
差異:: 顯示像素的差異。

* 「標示差異」會標出不同的區域。
  「色彩距離門檻」決定兩個像素要差多少才算不同，「區塊大小」決定標示區塊的大小。
* 可用按鈕、滑鼠滾輪或雙指縮放，以指標為中心縮放。
  「符合視窗」讓影像符合視窗大小，「1:1」以實際大小顯示。
* 拖曳或雙指滑動可一起平移所有影像。
* 按一下不同的區域即可選取它。
  kbd:[Alt+↓] 與 kbd:[Alt+↑] 逐一切換區域，kbd:[Alt+→] 與 kbd:[Alt+←] 將目前的區域複製到另一張影像。
  「復原」可取消複製，kbd:[Ctrl+S] 儲存變更後的影像。

狀態列會顯示有多少像素不同，以及分布在幾個區域。

== 網頁比較

可比較兩個或三個 `http://`、`https://` 網址，或以「比較方式 → 網頁」（指令列為 `-t web`）比較本機 HTML 檔案。
分頁上方的列用來選擇模式，並會記住上次使用的模式：

文字:: 網頁上看得到的文字，每個區塊一行：標題、段落、清單項目、表格儲存格、表單欄位值與預先格式化文字的每一行各佔一行，隱藏的元素不列入。
以文字比較開啟，因此每行內變更的字詞會醒目提示，比較選項、篩選器與報告也都適用。這是預設模式。
整頁:: 以影像檢視比較每個網頁從上到下的完整截圖。
開啟「醒目提示差異」時，會先在網頁本身醒目提示頁面之間不同的文字再截圖：變更的區塊為黃色，其中變更的字詞為橘色，如同 WinMerge 的「View Differences」。
由於比較的是文字而非像素，某處變更使後面的內容往下移時，不會把下方全部標成差異。高度超過 16384 像素的網頁會被截斷。
螢幕截圖（可見區域）:: 同上，但只擷取每個網頁的頂端（截圖寬度與高度）。
HTML 原始碼:: 網頁執行指令碼後的 HTML，經壓縮的長行會在標籤之間斷開，於文字比較中開啟。
資源樹:: 下載每個網頁及其樣式表、指令碼、影像、框架與媒體，並在資料夾比較中比較下載的檔案。

文字、HTML 原始碼與截圖都來自不顯示視窗的 Chromium 系列瀏覽器（可自動偵測 Edge、Chrome、Chromium 與 Brave），因此呈現的是網頁執行指令碼後、您實際看到的樣子。
各網頁在各自的分頁中同時載入，45 秒後即以當時的狀態處理。
沒有瀏覽器，或關閉「文字與 HTML 模式使用瀏覽器轉譯頁面」時，文字與 HTML 原始碼改用下載的原始 HTML：不會執行指令碼，也不包含指令碼加入的內容。

網頁的解碼方式與瀏覽器相同：先看位元組順序標記，其次是 HTTP `Content-Type` 標頭中的字元集，再來是 `<meta>` 中的字元集，最後才依內容推測。
非 2xx 的 HTTP 狀態碼會顯示在窗格標題中，並比較隨之傳回的網頁。
無法連線、超過 30 秒逾時、回應格式錯誤或大於 50 MB 的網頁，會連同其網址一併回報。

資源樹只讀取每個網頁本身列出的資源，每個網頁最多 400 個，每個最多 20 MB；不會再追蹤樣式表或指令碼中的連結。
無法下載的資源會在狀態列中計數，其餘資源照常比較。
網頁不得載入本機檔案；只有位於本機或私人網路（例如 `localhost` 或 `192.168.x.x`）的網頁，才能從這類位址載入資源或被重新導向到這類位址，其他這類資源會略過並計數。
您輸入的網址則一律會載入。
截圖大小與瀏覽器可在「選項 → 影像 / 二進位 / 網頁」中設定。
瀏覽器路徑留白時會自動偵測。變更網頁或切換模式後，可使用「重新載入」。
本機 HTML 檔案需指定 `-t web` 或「比較方式 → 網頁」，否則通常會以文字比較開啟。

NOTE: 資源樹比較伺服器傳回的原始 HTML；使用瀏覽器時，其他模式會執行網頁指令碼。
不支援已登入的瀏覽階段，因此需要登入的網頁可能只顯示登入畫面。
由瀏覽器轉譯的網頁會載入它要求的所有內容，不受資源樹的資源限制影響。所有模式都不會將變更寫回網頁伺服器。

== 控制要顯示的差異

使用「篩選器」選擇要比較的檔案與資料夾；使用「比較選項」與「比較規則」決定哪些文字變更算是差異。
這些設定影響比較結果，不會改寫原始檔案。

若預期的變更沒有顯示，請先檢查這些設定，再判斷檔案是否相同。

[[compare-options]]
=== 比較選項

「比較 → 比較選項」可快速切換常用選項，「選項 → 比較」則包含全部選項：

空白字元::
「比較」會比較所有空白，「忽略變更」忽略空白數量的變更，「全部忽略」完全忽略空白。
忽略空白行:: 只在一側出現的空白行不算差異。
忽略大小寫:: 大寫與小寫字母視為相同。
忽略換行字元差異（Windows/Unix/Mac）:: `CRLF`、`LF` 與 `CR` 換行視為相同。
忽略數字:: 忽略數字。
忽略字碼頁差異:: 編碼不同但文字相同的檔案視為相同。
忽略註解變更:: 對於已知註解語法的語言（C 類語言、指令碼、SQL、HTML/XML、CSS、Lua、Haskell 等），只有註解的變更不算差異。
比較前格式化 JSON 與 XML:: 重新縮排 JSON 與 XML，並排序 JSON 鍵，減少格式差異。
格式化檢視為唯讀；若要編輯或合併，請關閉此選項。
偵測移動的行:: 移動過的行區塊會標示為移動。
差異演算法:: 「Myers」、「Patience」或「LCS」。
行內差異:: 「關閉」、「單字層級」或「字元層級」。
數字差距在此範圍內視為相同:: 差距不超過此值（例如 `0.001`）的數字視為相同，適合比較量測值或產生的資料。

使用「完整內容」時，這些選項也適用於資料夾比較中的文字檔。
快速、二進位、日期與大小比較不使用文字比較規則。

[[compare-rules]]
=== 比較規則

比較規則檔（`.oxrules`）包含三種規則：

忽略符合的行:: 每行一個規則運算式。
僅由符合行組成的差異將被忽略。
取代規則:: 每行一條規則，寫成 `+規則運算式 => 取代文字+`。
比較前會套用到兩側，讓預期中會不同的文字視為相同。
忽略起始行與結束行之間的區塊:: 每行一個區塊，寫成 `+起始規則運算式 => 結束規則運算式+`。
區塊內的差異（例如自動產生的區段或授權標頭）將被忽略。

規則運算式採用 Rust `regex` 套件支援的語法。

.選項 → 比較規則
image::rules.png[比較規則選項]

在「選項 → 比較規則」中管理規則檔：

* 選擇「無」或某個規則檔。
  未另行指定規則檔的比較，會預設使用所選檔案。
* 「編輯」以規則編輯器修改檔案，「刪除」移除檔案。
* 「新增規則檔」建立新檔案。
* 「開啟規則資料夾」在檔案總管中顯示該資料夾；在其中變更檔案後，按「重新載入」重新讀取。
* 「匯入...」加入他人分享的規則檔，「匯出」可儲存一個檔案，或將「所有規則檔到資料夾...」。

資料夾比較可以使用不同的規則檔：從其工具列的「規則」或「比較 → 比較規則」中選擇。
「重新整理」（kbd:[F5]）會重新讀取規則檔。

將單一 `.oxrules` 檔案拖放到視窗上也會匯入它，拖放到選項對話框上則可一次匯入多個；拖放兩個到視窗上則會比較它們。
匯入規則檔時：

* 名稱與規則都和現有檔案相同的檔案會略過；
* 名稱和現有檔案相同但規則不同的檔案，會以加上編號的名稱加入；
* 規則相同但名稱不同的檔案會照原樣加入。

規則檔存放在設定檔旁的 `Rules` 資料夾中（請參閱 <<configuration>>）。
程式旁的 `Rules` 資料夾也會被讀取。
規則檔是純 JSON 格式，其名稱就是去掉 `.oxrules` 的檔案名稱：

.Build logs.oxrules
[source,json]
----
{
  "description": "忽略建置紀錄中的時間戳記與自動產生的標頭",
  "ignore_lines": ["^\\[\\d{2}:\\d{2}:\\d{2}\\]", "^// Generated on .*$"],
  "substitutions": [{ "find": "\\b0x[0-9a-fA-F]{8,}\\b", "replace": "0xADDR" }],
  "ignore_blocks": [{ "start": "^/\\* BEGIN LICENSE", "end": "END LICENSE \\*/$" }]
}
----

[[add-rule]]
=== 從文字比較新增規則

在文字比較中的某一行上按右鍵，選擇「新增比較規則」，再選擇規則種類：

忽略類似的行:: 符合該行（或變更行的各側）的樣式。
取代:: 將一側文字轉換成另一側文字的取代規則。
忽略區塊:: 從該行開始的區塊。

對話框會依該行建議一個樣式，您可以加以修改。
選擇要加入的「規則檔」，或輸入「檔案名稱」建立新的規則檔。
此比較會立即使用該規則。
其他使用相同規則檔的資料夾比較，在重新整理（kbd:[F5]）後套用變更。

[[filters]]
=== 篩選器

篩選器決定資料夾比較要包含哪些檔案與資料夾。
從資料夾比較工具列的「篩選器」中選擇，或在「工具 → 篩選器...」中管理。

篩選遮罩是以 `;` 分隔的萬用字元清單。
開頭的 `!` 表示排除符合的項目，結尾的 `\` 或 `/` 表示符合資料夾：

----
*.rs;*.toml;!target\
----

設定資料夾的 `Filters` 資料夾中的 WinMerge `.flt` 篩選器檔案也會列出。
「工具 → 篩選器...」會列出它們，並可開啟篩選器資料夾及新增篩選器。

[[unpackers]]
=== 解譯器外掛程式

解譯器外掛程式會在比較前將檔案轉換為文字，適合需要外部轉換工具的文件格式。
請先另外安裝轉換程式，並確認設定的指令可以執行。
在「選項 → 外掛程式」中新增：「檔案樣式」（例如 `*.docx`）與「指令列」，其中的 `${file}` 會替換為已加上引號的檔案路徑。
OxideMerge 會將指令的標準輸出當作文字比較。以下以已安裝的 Pandoc 為例：

----
pandoc -t plain ${file}
----

== 報告、統計資料與專案

=== 產生與分享 HTML 報告

. 開啟文字或資料夾比較，確認比較已完成。
. 檢查目前的比較選項、規則與資料夾篩選器；這些設定會影響報告中的差異。
. 選擇「匯出 HTML」，指定輸出檔案。
. 開啟報告並確認涵蓋範圍，再分享給其他人。

匯出報告不會將編輯內容儲存回比較來源檔案。


文字或資料夾比較工具列上的「匯出 HTML」，或「檔案 → 匯出 → 匯出 HTML 報告...」（kbd:[Ctrl+Shift+E]），會儲存報告並在瀏覽器中開啟。
建議的檔名由比較項目的名稱組成，空格會換成 `_`。

報告是單一網頁檔，內含顯示報告所需的資源。
每個差異都是一張卡片，附有行號、前後三行前後文，並醒目標示變更的單字。
報告包含摘要卡片、索引、並排或合併檢視、淺色與深色主題，以及檔案篩選與搜尋。
kbd:[N] 與 kbd:[P] 逐一切換差異。
報告會列出比較規則檔，並統計忽略的差異數量。
收件者可直接使用瀏覽器開啟，不需要安裝 OxideMerge。

資料夾報告會包含每個已變更文字檔的差異。
關閉「檔案 → 匯出 → 儲存後在瀏覽器開啟報告」即可只儲存而不開啟。

=== 資料夾摘要與詳細報告

* 「檔案 → 匯出 → 產生報告...」將資料夾報告寫成 HTML、CSV 或純文字。
* 「檔案 → 匯出 → 產生含檔案差異的報告...」在 HTML 資料夾報告中加入每個已變更文字檔的差異。

=== 查看統計資料

「工具 → 統計資料...」會顯示：

* 資料夾比較：相同、不同、唯一的檔案數量、錯誤數，以及各側的總大小；
* 文字比較：每一對窗格之間相同、變更、新增、移除與忽略的行數。

=== 儲存專案

「檔案 → 另存為專案...」會將目前分頁的比較內容存成 `.oxmproj` 檔案：路徑、說明、唯讀的窗格、比較類型、篩選器、子資料夾、比較方法與比較規則檔。
「檔案 → 開啟專案...」可再次開啟。
路徑以相對於專案檔的方式儲存，因此專案可以隨著比較的檔案一起搬移。

== 指令列參考

=== 開啟比較

不帶參數執行 `oxidemerge` 會開啟起始頁。指定兩個或三個路徑可開啟比較，
指定一個路徑則可開啟衝突檔案、專案或已儲存的比較。
路徑包含空格時，請加上引號。以下範例使用相容於 POSIX 的命令殼層語法；
Windows 可使用 Git Bash，或依使用的命令殼層調整。

[source,sh]
----
oxidemerge left.txt right.txt                   # 雙向文字比較
oxidemerge mine.txt base.txt theirs.txt         # 三方比較，中間為共同祖先版本
oxidemerge -r old-folder new-folder            # 包含子資料夾
oxidemerge -r -f "*.rs;!target/" old new        # 套用篩選器的資料夾比較
oxidemerge conflict.txt                         # 解決含衝突標記的檔案
oxidemerge -t image a.png b.png                 # 強制指定比較類型
oxidemerge https://example.com https://example.org   # 網頁比較
oxidemerge left.txt right.txt -o merged.txt     # 儲存時將右側窗格寫入 merged.txt
oxidemerge release.oxmproj                      # 開啟已儲存的專案
oxidemerge -r old.tar.gz new.tar.gz             # 將壓縮檔當作資料夾比較
oxidemerge --git-rev HEAD~1 src/main.rs         # 與較早的 Git 修訂版本比較
oxidemerge review.oxmcmp                        # 開啟已儲存的比較
----

|===
|選項 |說明

|`-t`、`--compare-as <T>` |強制以 `text`、`binary`、`image` 或 `web` 比較
|`-o`、`--output <PATH>` |儲存目標：雙向比較為右側窗格，三方比較為中間窗格
|`--dl`、`--dm`、`--dr <TEXT>` |取代左側、中間、右側路徑顯示的說明文字
|`--wl`、`--wm`、`--wr` |以唯讀方式開啟左側、中間或右側

|`--ignore-case`、`--ignore-blank`、`--ignore-eol`、`--ignore-numbers` |忽略選項
|`--ignore-comments` |忽略註解的變更
|`--prettify` |比較前重新格式化 JSON 與 XML
|`--numeric-tolerance <AMOUNT>` |差距不超過此值的數字視為相同
|`--rules <NAME>` |比較規則檔：規則資料夾中的名稱，或 `.oxrules` 檔案的路徑；`""` 表示不使用
|`--git-rev <REV>` |將指定的單一路徑與其在 Git 修訂版本中的內容比較
|`--report <FILE>` |產生報告：資料夾比較可為 `.html`、`.csv` 或 `.txt`，文字比較為 `.html`
|`--report-diffs` |在 HTML 資料夾報告中加入每個已變更文字檔的差異
|`--patch <FILE>` |為兩個檔案或資料夾產生修補檔
|`--patch-style <S>` |`normal`、`context` 或 `unified`（預設）
|`--context <N>` |修補檔的前後文行數（預設 3）
|`--cli` |不開啟視窗執行；結束代碼 0 = 相同，1 = 不同，2 = 錯誤
|`--lang <CODE>` |介面語言，例如 `ja` 或 `zh-TW`
|`--list-languages` |列出可用的語言
|`--register-shell`、`--unregister-shell` |加入或移除檔案總管的右鍵選單項目
|`--select-left <PATH>`、`--select-middle <PATH>` |記住一側，供之後的 `--compare-to` 使用
|`--compare-to <PATH>` |將路徑與記住的左側（及中間）比較
|===

在 Windows 上也接受 WinMerge 風格的參數，例如 `/r`、`/f`、`/o`、`/dl`、`/dr`、`/wl` 與 `/wr`，部分 WinMerge 參數會被忽略或不受支援，使用既有指令碼前請先驗證相容性。

=== 撰寫指令碼

`--cli`、`--report` 與 `--patch` 都不會開啟視窗，結束代碼如下：

* `0`：套用目前選項與規則後，內容相同。
* `1`：找到差異；即使報告或修補檔已成功產生，也可能傳回此代碼。
* `2`：發生錯誤。

指令碼應將 `1` 視為比較結果，而非程式執行失敗。
指令列比較也會使用已儲存的選項，除非另以參數指定。若要隔離設定，請將 `OXIDEMERGE_CONFIG_DIR`
指向專用資料夾，詳見 <<configuration>>。
報告支援文字與資料夾比較；二進位或影像比較不會產生 HTML 報告，而是顯示診斷訊息。

[source,sh]
----
# 不開啟視窗比較，同時輸出差異
oxidemerge --cli -r dirA dirB

# 資料夾比較的 HTML 報告，並附上每個已變更檔案的差異
oxidemerge -r dirA dirB --report report.html --report-diffs

# 兩個檔案的 HTML 報告，忽略註解的變更
oxidemerge old.c new.c --ignore-comments --report diff.html

# 含 5 行前後文的統一格式差異
oxidemerge old.c new.c --patch changes.patch --context 5

# 使用比較規則檔
oxidemerge --cli -r build1 build2 --rules "Build logs"
----

若命令殼層啟用了 `set -e`，請明確擷取結束代碼，以免將有差異誤判為執行失敗：

[source,sh]
----
result=0
oxidemerge --cli -r old-folder new-folder || result=$?
case "$result" in
  0) echo "沒有差異" ;;
  1) echo "找到差異" ;;
  *) echo "比較失敗" >&2; exit "$result" ;;
esac
----

=== 與 Git 整合

請先安裝 Git，並將 `oxidemerge` 加入 `PATH`。
在 Bash 或 Git Bash 等相容於 POSIX 的命令殼層中執行下列指令，設定目前使用者的比較與合併工具：

[source,sh]
----
git config --global diff.tool oxidemerge
git config --global difftool.oxidemerge.cmd 'oxidemerge "$LOCAL" "$REMOTE"'
git config --global merge.tool oxidemerge
git config --global mergetool.oxidemerge.cmd \
  'oxidemerge "$LOCAL" "$BASE" "$REMOTE" -o "$MERGED" --dl Local --dr Remote --wl --wr'
git config --global mergetool.oxidemerge.trustExitCode false
----

* `git difftool` 會逐一開啟每個已變更的檔案。
  `git difftool --dir-diff` 會以一個資料夾比較開啟全部檔案，在最後一個差異之後按 kbd:[Alt+↓] 會切換到下一個已變更的檔案。
* `git mergetool` 會開啟三方合併，中間是共同的祖先版本。
  自動合併或將差異複製到中間後儲存：中間內容會寫入合併結果檔案，不會修改祖先版本。
  設定 `trustExitCode false` 時，Git 會檢查輸出檔案是否變更；若看起來未變更，可能要求確認是否成功。
  請在儲存並檢查結果後才確認成功，單純關閉視窗並不代表合併成功。
* 在 macOS 上，除非已將程式連結到 `PATH`，否則請使用完整路徑 `/Applications/OxideMerge.app/Contents/MacOS/oxidemerge`。
  在 Windows 上，請使用 `oxidemerge.exe` 的路徑。

== 檔案管理員整合

透過「工具」選單或執行 `oxidemerge --register-shell`，可啟用檔案管理員整合：

Windows:: 「工具 → 加入檔案總管右鍵選單」會為檔案、資料夾、磁碟機與資料夾背景加入「OxideMerge」子選單。
在 Windows 11 上，這些項目位於「顯示其他選項」中。
macOS:: 「工具 → 加入 Finder 快速動作」會在 Finder 的「快速動作」與「服務」選單中，
加入比較、選為左側與選為中間的操作項目。
Linux:: 「工具 → 加入檔案管理員右鍵選單」會在 Nautilus、Nemo 與 Dolphin 中加入相同的項目。

這些項目的用法如下：

* 「比較」會比較選取的兩個或三個檔案或資料夾。
  只選取一個項目時，會將它與先前選擇的一側比較，或開啟已填入該項目的「選擇檔案或資料夾」對話框。
* 「選為左側」與「選為中間」會記住一個項目，例如位於其他資料夾中的項目。
  之後「比較」會顯示為「與「名稱」比較」。
* 「比較方式」（僅 Windows，限檔案）以文字、二進位、影像或網頁比較。

這些項目會指向註冊時使用的執行檔。搬移程式後，請重新註冊。
若要移除，請使用「工具」中的對應指令，或執行 `oxidemerge --unregister-shell`。

[[configuration]]
== 設定

選項以 JSON 格式存放在設定資料夾中：

[cols="1,3"]
|===
|系統 |設定檔

|Windows |`%APPDATA%\OxideMerge\config.json`
|macOS |`~/Library/Application Support/OxideMerge/config.json`
|Linux |`~/.config/OxideMerge/config.json`
|===

「說明與快速鍵」會顯示設定檔的位置。無法讀取的設定檔會先保留為 `config.json.bad`，再改用預設值，修正後即可放回。

設定資料夾中也包含：

* `Rules`：比較規則檔；
* `Filters`：WinMerge `.flt` 篩選器檔案；
* `Languages`：額外或修改過的語言套件。

可攜式使用:: 在執行檔所在的資料夾中建立空白的 `oxidemerge.json`。
程式會將選項儲存在該檔案中，執行檔所在的資料夾必須允許寫入。

獨立設定:: 將 `OXIDEMERGE_CONFIG_DIR` 設為指定資料夾，使用其中的 `config.json`。
此設定優先於可攜式模式與預設設定資料夾，適合指令碼、測試或不同工作環境。

語言:: 若要新增或修改語言，請將原始碼中的 `lang/en.json` 複製為 `<code>.json`，翻譯其中的值（所有 `{placeholder}` 須保持不變），再將檔案放到程式旁或設定資料夾中的 `Languages` 資料夾。
檔案中缺少的訊息，以及刪除或增加了預留位置的翻譯，都會改以英文顯示。

== 疑難排解

請先閱讀錯誤訊息並確認受影響的路徑。重新合併或儲存前，請檢查目標位置、磁碟可用空間、
存取權限，以及是否有其他程式修改了檔案。

網頁截圖模式顯示找不到瀏覽器::
截圖模式需要 Edge、Chrome、Chromium 或 Brave。
請在「選項 → 影像 / 二進位 / 網頁」中設定瀏覽器。

某一側無法編輯::
它是唯讀的：標題列的鎖頭已鎖上、以 `--wl`、`--wm` 或 `--wr` 開啟、從壓縮檔解壓縮而來，或是以格式化方式顯示的 JSON 或 XML。
關閉「比較前格式化 JSON 與 XML」即可編輯與合併這些檔案。

檔案因編碼問題而無法儲存::
選取的編碼無法表示編輯內容中的某些字元。變更編碼會重新載入來源檔案，請先另外保留需要的編輯內容。
也可以復原不支援的字元，再重新儲存。

檔案可寫入，但儲存或複製仍失敗::
取代檔案也需要在目標資料夾建立暫存檔與取代目錄項目的權限。
請檢查資料夾權限、磁碟可用空間，以及其他程式是否鎖定檔案。
無法建立暫存檔或取代檔案時，OxideMerge 會回報錯誤，不會直接覆寫原檔。
編輯內容成功儲存前，請先保留比較視窗。

檔案看起來相同，但位元組內容不同::
檢查空白字元、大小寫、換行格式、編碼、註解與目前的比較規則。
文字比較可能依設定忽略這些差異。若需要確認位元組完全一致，請使用二進位比較，
或資料夾比較中的「二進位內容」。

資料夾比較中缺少預期的檔案::
檢查篩選器、隱藏檔案選項、「包含子資料夾」與「顯示」設定。「依名稱尋找」也會限制顯示的項目。
「所有差異」會沿用資料夾比較的篩選器與顯示設定，不會自動包含隱藏的結果。

macOS 拒絕開啟應用程式::
請先嘗試開啟一次，再到「系統設定 → 隱私權與安全性」中選擇「強制打開」。
或在終端機中清除下載標記：
`xattr -dr com.apple.quarantine /Applications/OxideMerge.app`。

macOS 要求存取資料夾，或比較時檔案顯示為錯誤::
OxideMerge 第一次讀取「桌面」、「文件」、「下載項目」、卸除式或網路磁碟區時，macOS 會詢問一次；請允許，或之後在「系統設定 → 隱私權與安全性 → 檔案和資料夾」中開啟。
在任何系統上，無法讀取的檔案都會顯示為錯誤，訊息中會指出是哪個檔案。
請檢查該檔案的權限。

AppImage 無法啟動::
請先以 `chmod +x` 讓它可以執行。
若訊息提到 FUSE，請加上 `--appimage-extract-and-run` 啟動。

在 Linux 上視窗一片空白或無法開啟::
OxideMerge 以 OpenGL 繪製畫面。
若沒有可用的顯示卡驅動程式（例如在虛擬機器中），請以 `LIBGL_ALWAYS_SOFTWARE=1 oxidemerge` 啟動，改用 Mesa 的軟體繪圖。

在 Linux 上檔案對話框無法開啟::
檔案對話框使用桌面環境提供的 XDG 入口服務。
請安裝 `xdg-desktop-portal` 及適用於您桌面環境的套件，例如 `xdg-desktop-portal-gtk` 或 `xdg-desktop-portal-kde`。

檔案管理員中沒有 OxideMerge 項目::
在 Windows 11 上，這些項目位於「顯示其他選項」之下。
項目指向加入它們的程式，因此把程式移動或更新到其他資料夾後，請從新的程式再加入一次。
在 Linux 上，請重新啟動檔案管理員（例如 `nautilus -q`）才會看到新項目。

設定沒有保留::
OxideMerge 無法儲存設定時會顯示訊息並說明原因。
請確認設定資料夾（請參閱 <<configuration>>）可以寫入，且磁碟沒有滿。

資料夾自動合併無法開始，或略過了某些檔案::
請啟用「包含子資料夾」與「包含唯一子資料夾的內容」，並等待比較完成。
比較後又有變更的檔案會略過並列出，請重新整理後再次檢查合併計畫。

網頁比較顯示的內容比瀏覽器少::
請確認已找到瀏覽器，且已開啟「文字與 HTML 模式使用瀏覽器轉譯頁面」；否則文字與 HTML 原始碼會使用伺服器傳回的 HTML，
看不到指令碼加入的內容。資源樹一律使用傳回的 HTML。框架中的內容不列入比較。
無法下載的資源，以及因位於本機或私人網路而略過的資源，都會在狀態列中計數。

大型檔案比較緩慢或佔用大量記憶體::
文字比較會在記憶體保留解碼後的文字、比較資料與編輯紀錄，實際用量取決於內容與操作。
二進位與影像檢視也會載入完整檔案。
數百 MB 的檔案請以二進位方式比較，或改以大小與日期比較資料夾，而非比較內容（請參閱 <<compare-methods>>）。

== 已知限制

* 支援 ZIP 類格式、TAR（未壓縮、gzip、bzip2 與 xz）與 7z，不支援 RAR。解壓縮後的內容為唯讀。
* 文字編輯以行為單位，主要用於檢查與合併變更。
* 解譯器外掛程式使用外部指令，不支援 WinMerge 的外掛動態連結程式庫或指令碼。
* 網頁比較不支援瀏覽器的登入資訊；需要登入的網頁可能只顯示登入畫面。
沒有 Chromium 系列瀏覽器時不會執行網頁指令碼，因此看不到指令碼加入的內容。框架中的內容不列入比較。
由瀏覽器轉譯的網頁會載入它要求的所有內容，不受資源樹的限制。
* 由機器輔助完成的翻譯尚未經母語人士審閱。
