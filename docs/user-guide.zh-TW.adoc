[.lead]
OxideMerge 是一套圖形化的檔案與資料夾比較及合併工具，可在 Windows、macOS 與 Linux 上執行。
您可以用它檢查變更、整合不同版本的修改，以及解決合併衝突，
也能比較二進位檔、影像與網頁。
OxideMerge 以 Rust 撰寫。

本指南另有 xref:user-guide.adoc[英文版]。

[[introduction]]
== 簡介

=== OxideMerge 能做什麼

* 比較兩個或三個資料夾（包括壓縮檔），並複製、刪除或合併其中的項目。
* 比較與編輯文字檔，在版本之間複製變更，以及解決版本控制產生的衝突。
* 比較二進位檔的位元組、影像的像素與網頁的內容。
* 透過比較選項與可重複使用的比較規則，略過不重要的差異。
* 匯出報告與修補檔，或儲存專案與比較結果，方便日後檢閱。
* 從指令碼執行比較，或將 OxideMerge 設為 Git 的比較與合併工具。

介面提供英文、繁體中文、簡體中文、日文、韓文、德文、法文、西班牙文、俄文、巴西葡萄牙文與義大利文。

=== 如何使用本指南

建議先閱讀 <<first-comparison>>，熟悉基本操作，再依需要的比較類型查閱對應章節。
最後幾章為參考資料，包括命令列、選項、鍵盤快速鍵與疑難排解。

本指南使用下列慣例：

* 「」括住的文字是程式中顯示的名稱，例如按鈕或選單命令。
* 「檔案 → 開啟...」這類寫法表示：先開啟「檔案」選單，再選擇「開啟...」。
* 命令列範例假設 `oxidemerge` 已在 `PATH` 環境變數中；若不在，請改用程式的完整路徑。
* 範例中的路徑（例如 `old-folder`）請換成您實際的路徑。

NOTE: *macOS 的快速鍵。* 本指南使用 Windows 與 Linux 的按鍵名稱。
在 macOS 上，請以 Command 鍵（kbd:[⌘]）取代 kbd:[Ctrl]，以 Option 鍵（kbd:[⌥]）取代 kbd:[Alt]。
唯一的例外是 kbd:[Ctrl+Tab]：在 macOS 上同樣使用 Control 鍵。
選單與工具提示一律顯示您所用系統的快速鍵。

=== 常用術語

側:: 比較中的一個版本，分為左側、中間與右側。
窗格:: 視窗中顯示某一側內容的區域。
差異:: 各版本之間不相同的地方。在文字比較中，一個差異可能包含好幾行。
基底（共同祖先版本）:: 兩份修改版本共同的原始版本。在三方比較中，基底位於中間。
衝突:: 兩份修改版本以不同方式變更了同一段文字，需要由您選擇或編輯結果。
合併:: 將變更複製或整合到目標版本。
篩選器:: 決定資料夾比較要包含哪些檔案與資料夾的條件。
比較規則:: 決定哪些文字差異要計入的規則，不會修改檔案本身。

IMPORTANT: 合併會變更目標內容。
複製或儲存前，請先確認來源、目標與輸出路徑。
只需要檢視的版本，建議設為唯讀。

== 安裝

請從 https://github.com/kuopinghsu/OxideMerge/releases[GitHub 發行頁面] 下載適合您系統與處理器的套
件。
每個版本也附有本指南的英文與繁體中文 PDF 檔。
發行頁面會列出每個下載檔案的 SHA-256 摘要值，可用來確認檔案完整。

[cols="1,3"]
|===
|系統 |套件

|Windows 10 或 11，x64 或 Arm64
|`oxidemerge-<version>-windows-x64.zip` 或 `oxidemerge-<version>-windows-arm64.zip`

|macOS 11 或更新版本
|`oxidemerge-<version>-macos-universal.dmg`，適用於 Apple 晶片與 Intel 處理器

|Linux x64 或 Arm64
|AppImage（適用於 Ubuntu 20.04、RHEL 8、Debian 10 及更新版本）或 TAR.GZ 壓縮檔。
Intel 與 AMD 處理器請選 `linux-x64`，64 位元 Arm 處理器請選 `linux-arm64`。
|===

=== Windows

解壓縮 ZIP 檔後，直接執行 `oxidemerge.exe` 即可，不需要安裝。

=== macOS

. 開啟 DMG 檔，將「OxideMerge」拖移到「應用程式」檔案夾。
. 啟動 OxideMerge。
  本程式採用臨時簽署，未經 Apple 公證，因此 macOS 可能會阻擋第一次啟動。
  若遭到阻擋，請到「系統設定 → 隱私權與安全性」中選擇「強制打開」。
  在 macOS 14 及更早版本中，也可以按住 Control 鍵並按一下應用程式，再選擇「打開」。

若要從「終端機」啟動，請使用程式的完整路徑。
若想直接輸入 `oxidemerge`，請在 `PATH` 中的某個資料夾建立連結，例如：

[source,sh]
----
sudo ln -s /Applications/OxideMerge.app/Contents/MacOS/oxidemerge /usr/local/bin/oxidemerge
----

=== Linux

* 請在使用 X11 或 Wayland 的桌面環境中執行。
* 啟動 AppImage 前，請先讓它可以執行：`chmod +x oxidemerge-*.AppImage`。
* 若系統沒有 FUSE，請加上 `--appimage-extract-and-run` 啟動 AppImage。
* 檔案對話框需要 `xdg-desktop-portal`，大多數桌面環境已內建。
* 若要顯示中文、日文與韓文，請安裝 Noto Sans CJK 等中日韓字型。

=== 從原始碼建置

. 從 https://rustup.rs/ 安裝 Rust 工具鏈。
. 在儲存庫資料夾中執行 `cargo build --release --locked`。

建置完成的程式位於 `target/release/oxidemerge`（Windows 為 `target/release/oxidemerge.exe`）。
建置需求與檢查方式，請參閱 xref:development.zh-TW.md[開發指南]。

== 快速入門

=== 起始頁

不指定任何比較就啟動 OxideMerge 時，會顯示起始頁。

.起始頁
image::start.png[起始頁]

起始頁包含下列部分：

比較檔案或資料夾:: 輸入「左側」與「右側」的路徑。
您可以直接輸入或貼上路徑，也可以按欄位旁的檔案與資料夾按鈕選擇。
按「三方」可加入「中間」路徑。
按「更多選項…」會開啟「選擇檔案或資料夾」對話框，並帶入這些路徑。
開啟衝突檔案:: 解決含有衝突標記的檔案，請參閱 <<conflict-files>>。
版本摘要／比較基準:: 將兩個資料夾或已儲存的審閱當作兩個版本來比較，請參閱 <<baselines>>。
最近使用:: 以卡片列出最近的比較。
+
--
* 按一下卡片，即可再次執行該比較。
* 在卡片上按右鍵，可「變更路徑...」或「從最近使用中移除」。
* 按「最近使用」標題右側的「清除」，可清空整份清單。
  「檔案 → 開啟最近的比較 → 清除最近的比較」的效果相同。
  清除後出現的訊息會在幾秒內提供「復原」。
--

最近使用清單是空的時候（例如第一次啟動），起始頁會顯示「開啟範例」。
按下後會開啟兩個小型範例資料夾，讓您了解比較如何運作。
範例資料夾是暫時性的：關閉分頁時 OxideMerge 就會刪除它們，也不會將範例加入最近使用清單。

[[first-comparison]]
=== 第一次比較

. 在起始頁中，將較舊的檔案填入「左側」，較新的檔案填入「右側」。
. 按「比較」。
  若要避免某一側被修改，請改按「更多選項…」，並開啟該側的「唯讀」。
. 按 kbd:[Alt+↓] 移到下一個差異。
. 若要複製某個差異，請先確認哪個窗格是目標，再按指向該窗格的箭頭。
. 檢查結果。
  若要另存成新檔，請選擇「檔案 → 另存新檔」；若要更新窗格中的檔案，請選擇「儲存」。

如果只想檢視而不修改，請將兩側都設為唯讀。
若要分享檢閱結果但不傳送原始檔案，可以匯出 HTML 報告（請參閱 <<reports>>）。

=== 主視窗

視窗包含下列部分：

選單列:: 「檔案」、「編輯」、「檢視」、「比較」、「合併」、「工具」與「說明」。
不適用於目前分頁的命令無法選取。
標題列:: 右側依序為「搜尋命令」（開啟命令面板）、「開啟」、淺色與深色主題切換、「選項」以及「說明與
快速鍵」。
視窗較窄時，搜尋欄位會縮成圖示，放不下的按鈕會隱藏；選單中仍有相同的命令。
分頁:: 每個比較都在自己的分頁中開啟。
兩側檔名相同時，分頁只顯示一次檔名，後面接著不同的資料夾。
關閉按鈕的位置顯示圓點時，表示該分頁有尚未儲存的變更；將指標移到圓點上即可關閉分頁。
狀態列:: 顯示兩側是否不同，以及目前的行號或位移；最右側顯示介面語言。
差異與項目的數量則顯示在工具列與資料夾的篩選標籤上。

分頁操作：

* kbd:[Ctrl+Tab] 與 kbd:[Ctrl+Shift+Tab] 切換到下一個與上一個分頁。
* kbd:[Ctrl+W] 或 kbd:[Esc] 關閉目前的分頁。
  若有開啟中的對話框、搜尋列、預覽或編輯狀態，kbd:[Esc] 會先關閉它們。
  分頁有尚未儲存的變更時，OxideMerge 會先詢問再關閉。
* 在分頁上按右鍵，可關閉該分頁、其他分頁、右側的分頁或全部分頁。

若要變更介面語言，請使用「選項 → 一般」，或以 `--lang` 參數啟動 OxideMerge。

若要查看版本，請按一下應用程式標誌，或選擇「說明 → 關於 OxideMerge」。
對話框也會顯示建置識別碼：

* 開發版本會顯示 Git 的簡短雜湊值；
  已追蹤的檔案或 Git 索引有未提交的變更時，會加上 `-dirty`。
* 依發行標籤建置、且沒有任何修改的最佳化版本，會顯示建置日期（UTC）。

執行 `oxidemerge --version` 也會顯示相同的識別碼。

=== 開啟比較

開始比較的方式有好幾種：

* 在起始頁的「比較檔案或資料夾」中輸入路徑，再按「比較」。
* 選擇「檔案 → 開啟...」（kbd:[Ctrl+O]），或按起始頁的「更多選項…」，開啟「選擇檔案或資料夾」對話框。
* 將兩個或三個檔案或資料夾拖放到視窗上。
  只拖放一個項目時，會開啟對話框並帶入該項目。
* 從起始頁、「檔案 → 開啟最近的比較」或命令面板選擇最近使用的比較。
* 從命令列（請參閱 <<command-line>>）或檔案管理員（請參閱 <<file-manager>>）啟動 OxideMerge。
* 選擇「檔案 → 透過 SFTP/FTP 比較...」，或按一下起始頁或「選擇檔案或資料夾」對話框中路徑旁的
  地球圖示按鈕，先透過 SFTP、FTPS 或 FTP 從伺服器取得檔案或資料夾。請參閱 <<remote-sftp>>。

「選擇檔案或資料夾」對話框的用法：

.「選擇檔案或資料夾」對話框
image::dialog.png[選擇檔案或資料夾對話框]

. 輸入或瀏覽「左側」與「右側」的路徑。
  路徑可以是檔案、資料夾，或以 `http://`、`https://` 開頭的網址。
  若要比較三個版本，請開啟「三方比較」並輸入「中間」的路徑。
. 開啟某一側旁的「唯讀」，可避免它被修改。
  「左右互換」會對調兩側。
. 比較資料夾時，可選擇「包含子資料夾」、「篩選器」與「比較方法」。
. 在「比較方式」中選擇比較類型：文字、二進位、影像或網頁。
  選擇「自動」時，由程式判斷類型（請參閱 <<compare-types>>）。
. 按「比較」。

TIP: 若要比較不在檔案中的文字，請選擇「檔案 → 新增文字比較」（kbd:[Ctrl+N]），開啟兩個空白的窗格。
可按 kbd:[Ctrl+V] 貼上文字，或按兩下某一行開始輸入。

TIP: 若要將剪貼簿中的文字與即將貼上的文字比較，請選擇「檔案 → 比較剪貼簿」。
這會開啟一個文字比較，左側是剪貼簿目前的文字，右側是空白且可編輯的窗格；
按 kbd:[Ctrl+V] 貼上第二份文字即可。
「儲存」的用法與其他尚未存檔的比較相同，因為沒有原始檔案可寫回。

[[remote-sftp]]
=== 透過 SFTP 或 FTP 比較

「檔案 → 透過 SFTP/FTP 比較...」，以及起始頁或「選擇檔案或資料夾」對話框中路徑旁的地球圖示
按鈕，可連線到伺服器取得要比較的檔案或資料夾，而不必瀏覽本機磁碟。

. 選擇「通訊協定」：「SFTP（透過 SSH）」；「FTPS（明確 TLS）」，連到 FTP 埠號（21）並在登入前
  切換為 TLS；「FTPS（隱含 TLS，連接埠 990）」，適用於一開始就要求 TLS 的伺服器；或「FTP（未加密）」。
  變更通訊協定時，「埠號」會改為該通訊協定的慣用埠號，除非您自行輸入了其他埠號。
. 輸入伺服器的「主機」、「埠號」與「使用者」。使用 SFTP 時，主機可以是 `~/.ssh/config` 中的 `Host`
  別名，使用者也可以留空，與 `ssh` 相同（請參閱 <<remote-ssh-config>>）。
. 使用 SFTP 時，選擇登入方式：「密碼」、「私密金鑰」（可另外設定「金鑰密碼」），或「SSH 代理程式」，
  使用 `ssh-agent`（Windows 上為 Pageant）持有的金鑰，以及 `~/.ssh/config` 指定的金鑰，這裡不需輸入
  任何內容。FTP 與 FTPS 以密碼登入。
. 如有需要，可展開「進階」設定代理伺服器、FTP 主動模式或 FTPS 用戶端憑證（請參閱 <<remote-advanced>>）。
. 輸入要取得的檔案或資料夾的「遠端路徑」，或按一下旁邊的資料夾按鈕，從伺服器的資料夾與檔案清單
  中選擇。
. 按一下「連線」。

資料夾按鈕會連線並列出「遠端路徑」所在的資料夾；若「遠端路徑」是空的，則列出您在伺服器上的
主資料夾。清單先列資料夾，再列檔案及其大小；名稱以點開頭的隱藏項目排在各組最後。
按一下資料夾即可開啟，按一下檔案即可選取：「遠端路徑」會隨著您按的項目更新，因此「連線」會取得
您所在的資料夾或選取的檔案。按兩下檔案則會立即取得。向上箭頭按鈕會開啟上一層資料夾，重新整理
按鈕會再次列出「遠端路徑」，包括您自行輸入的路徑。不存在的路徑會列出其上方最近的現有資料夾。
清單顯示期間會保持連線，因此切換資料夾時不必每次重新登入；關閉對話框，或變更主機、埠號、
使用者、密碼或金鑰時，清單就會關閉。每個資料夾最多顯示前 10,000 個項目。

取得的路徑會填入「左側」、「中間」或「右側」路徑，用法與本機路徑相同。
再連線一次以取得另一側，即可比較兩個遠端位置；
或讓另一側維持本機路徑，以比較遠端路徑與本機路徑。
對話框會記住上次成功連線的主機、埠號、使用者與金鑰路徑，
方便從同一台伺服器取得第二個路徑；但密碼或金鑰的密碼短語不會被記住。

取得的**檔案**可編輯：編輯後按「儲存」，會在背景透過一個新的連線將檔案上傳回伺服器，並提供
「取消」按鈕。上傳會直接更新原檔，以保留其擁有者、群組及存取權限。若伺服器上的路徑是連結，
會更新它指向的檔案。開始寫入之前可以取消；若寫入途中連線中斷，伺服器可能只收到部分內容，
訊息會說明這點，再按一次「儲存」即可完成寫入。
若取得檔案後，伺服器上的檔案已被修改或刪除，上傳會在寫入之前被拒絕。您的編輯仍保留在分頁中，
可與伺服器上的版本比較。在上傳成功之前，分頁視為
尚未儲存，因此關閉分頁或結束程式時會先詢問，而「儲存」會再試一次。在關閉分頁時選擇「儲存」，
會等上傳完成後才關閉。

取得的**資料夾**同樣可寫入。在資料夾比較中複製或刪除檔案，或從中開啟檔案並編輯，按「儲存」就會把
變更寫回伺服器：新增或內容有變更的檔案會上傳，新增的資料夾會建立，已移除的檔案與資料夾會在伺服器上
刪除。未變更的檔案不會再次傳送。每次上傳或刪除之前，OxideMerge 都會確認伺服器上的檔案仍是當初取得的
那一份：取得後在伺服器上被修改的檔案不會被覆寫或刪除，取得後才在伺服器上建立的同名新檔案也不會被
覆寫。取得前幾秒內才修改過的檔案也會比對其內容，因為同一秒內的第二次修改不會改變其大小與時間。
儲存後的訊息會列出這些檔案；您的副本仍保留在分頁中，可與伺服器上的版本比較後再儲存一次。
其餘變更照常寫入。在所有變更都寫入之前，分頁視為尚未儲存。若資料夾的本機副本已不存在，或其中有部分
無法讀取，則不會寫入任何內容，因此無法讀取的檔案絕不會在伺服器上被刪除。

檔案會先上傳，再刪除已移除的檔案，因此移到其他資料夾的檔案，要等新的副本已在伺服器上，才會從原位置
刪除：若該上傳失敗，舊的副本會保留。取得的副本中的符號連結或特殊檔案，或不是有效 Unicode 的名稱，
絕不會上傳，也絕不視為已移除；伺服器上的檔案維持原樣，儲存後的訊息會列出它。

每次取得限制在 4 GiB、50,000 個檔案與資料夾，以及 64 層巢狀資料夾以內，避免不小心取得過大的
資料夾。無法在本機作為檔名的名稱會被略過；本機無法區分的兩個名稱（例如在不分大小寫的檔案系統上的
`A.txt` 與 `a.txt`），第二個也會被略過。取得的副本中不會建立 `.bak` 備份，因為儲存時會一併上傳。

「檔案 → 從伺服器重新載入」會透過新的連線，再次取得目前分頁中遠端檔案或資料夾在伺服器上的副本，
並取代先前取得的副本。若這樣會取代尚未儲存到伺服器的變更，會先詢問；同意後，遠端檔案的編輯會被取代
（可用「復原」找回），本機那一側的編輯則會保留。

使用 FTP 與 FTPS 時，OxideMerge 依伺服器回報的檔案大小與修改時間判斷檔案是否在伺服器上被修改；
伺服器未回報修改時間時，則讀取檔案並比對其內容。
無法以標準機器可讀格式（`MLSD`）列出資料夾的伺服器，改從一般清單讀取；連結會依其指向的檔案或
資料夾處理。除非勾選「主動模式」（請參閱 <<remote-advanced>>），傳輸使用被動模式，而且一律連到登入時
所連的伺服器。

使用 FTPS 時，若下載的連線在沒有 TLS 結束訊息的情況下中斷（中間的任何人都能造成這種情況），會與
伺服器回報的大小比對，不足時拒絕。許多 FTPS 伺服器（例如 ProFTPD 與 vsftpd）要求每次傳輸沿用登入時的
TLS 工作階段；伺服器為此提供的每個工作階段票證只能用於一次傳輸，因此用完時，OxideMerge 會在下一次傳輸
之前重新登入。

IMPORTANT: 一般 FTP 會以不加密的方式傳送密碼與檔案：在您與伺服器之間網路上的任何人都能讀取，
對話框也會如此提醒。只要伺服器支援，請改用 FTPS 或 SFTP。

連線資訊（包括密碼或金鑰的密碼短語）只會保留在記憶體中，直到分頁關閉為止；不再需要時，密碼會
在記憶體中被覆寫。這些資訊絕不會寫入設定檔。顯示取得之檔案或資料夾的分頁，不會列入已儲存的工作區
（請參閱 <<workspaces>>）、OxideMerge 啟動時自動重新開啟的工作階段，以及最近使用的路徑，因為
程式關閉後，它們的暫存副本就不存在了：若要比較同一個遠端路徑，請重新連線。

在送出密碼或金鑰之前，OxideMerge 會先檢查伺服器的主機金鑰。它會先以 `ssh` 的方式讀取您自己的
SSH `~/.ssh/known_hosts`：`*.example.com`、`!host.example.com` 這類主機樣式（不分大小寫）與
`ssh-keygen -H` 雜湊過的名稱都能比對，連接埠不是 22 的伺服器以 `[主機]:埠號` 查找。若伺服器列在其中且金鑰
相同，且也符合 OxideMerge 已記錄的金鑰（若有），即予以信任。若列在其中的是同類型但不同的金鑰，
或該金鑰在其中標記為 `@revoked`，則與
`ssh` 一樣拒絕連線：若伺服器已重新安裝，請以 `ssh-keygen -R 主機`（或
`ssh-keygen -R "[主機]:埠號"`）移除舊金鑰後再重新連線。OxideMerge 也會檢查設定檔旁它自己的
`known_hosts` 檔案。第一次連線到兩者都沒有記錄的伺服器時，OxideMerge 會顯示金鑰的類型與指紋
（`SHA256:...`，與 `ssh` 顯示的格式相同），並詢問是否信任：請先與伺服器管理員提供的指紋比對，
再按「信任並連線」。若您的 `~/.ssh/known_hosts` 為該伺服器只記錄了其他類型的金鑰，會顯示警告。

伺服器也可以用主機憑證證明身分，由您的 `~/.ssh/known_hosts` 以 `@cert-authority` 行指定的憑證授權
單位簽署，例如 `@cert-authority *.example.com ssh-ed25519 AAAA...`。OxideMerge 只向有這類行指定的
伺服器要求憑證；若憑證由該授權單位簽署、主體（principals）中列有該伺服器（或其 `HostKeyAlias`）、
目前在有效期間內，且沒有關鍵選項（critical options），就直接信任，不會先詢問您。不符合其中任何一項的
憑證會被拒絕；授權單位或金鑰標記為 `@revoked` 的也會被拒絕。可檢查以 Ed25519、ECDSA（P-256 或
P-384）或採用 SHA-2 的 RSA 簽署的憑證；使用其他演算法的授權單位（例如採用 SHA-1 的 RSA 或 ECDSA
P-521）會被拒絕。沒有指定授權單位的伺服器若提供憑證，則以其一般金鑰檢查。

之後每次連線，都會比對記錄的金鑰：若金鑰不再相符，OxideMerge 會拒絕連線，而不是信任一台可能
不是您預期的伺服器。這通常表示伺服器已經重建或重新安裝；若您確定是這種情況，可從 OxideMerge
的 `known_hosts` 檔案中移除該伺服器的舊記錄（格式為「主機:埠號」加上其
金鑰），再重新連線。若任一個 `known_hosts` 檔案存在卻無法讀取，或含有無法解讀的行（它自己檔案中的
任何一行，或 `~/.ssh/known_hosts` 中它會檢查的金鑰類型的行），OxideMerge
在能讀取之前不會連線到任何伺服器。

FTPS 伺服器的檢查方式與網頁瀏覽器檢查網站相同：憑證必須對該主機名稱有效，並由知名的憑證授權單位
擔保。許多 FTP 伺服器使用的是自我簽署的憑證。第一次連線到這類伺服器時，OxideMerge 會顯示憑證的指紋
並詢問是否信任，與未知的 SSH 主機金鑰相同；信任後，憑證會記錄在設定檔旁的 `known_certs` 檔案中
（可攜式使用時為 `oxidemerge-known_certs`），之後若連線時出現不同的憑證，會拒絕連線。若伺服器的
憑證已更新，請從該檔案中移除該伺服器的那一行（「主機:埠號」加上憑證）。兩種情況下都會在送出密碼
之前檢查憑證；不提供 TLS 的伺服器在 FTPS 下會被拒絕，而不會在沒有 TLS 的情況下登入。

[[remote-ssh-config]]
==== SSH 設定、跳板主機與登入問題

連線到 SFTP 伺服器的方式與 `ssh` 相同，依照您的 `~/.ssh/config`（以及系統的 `/etc/ssh/ssh_config`）。
「主機」可以是其中的別名（例如 `prod`），其區塊可設定 `HostName`、`User`、`Port`、`IdentityFile`
（以及 `IdentitiesOnly`）、`HostKeyAlias`（查找與認證其金鑰時使用的名稱）與 `UserKnownHostsFile`。
位於字首的 `#` 表示註解。`Include` 會就地讀取，但略過名稱以點開頭的檔案，除非樣式的檔名也以點開頭；
依 `host`（與 `ssh` 相同，為目前已設定的 `HostName`）、`originalhost`、`user`、`localuser` 或 `all`
條件的 `Match` 區塊也會套用；`Match exec` 絕不會執行。與 `ssh` 相同，先找到的值優先，而在對話框中輸入
的使用者，或 22 以外的埠號，優先於設定檔；命令列的位址中寫明的任何埠號都優先，包括 `:22`。未指定
使用者時，使用設定檔的 `User`，或您自己的使用者名稱。

需經由跳板主機連線的伺服器（`ProxyJump bastion` 或 `ProxyJump user@hop1,hop2:2222`），會與
`ssh -J` 一樣依序經過每一台（最多 8 台）連線；跳板主機以 SSH 代理程式的金鑰及其區塊指定的金鑰登入，
且在送出任何內容之前，會像伺服器一樣檢查其金鑰。`ProxyCommand` 與 `ssh` 一樣交由 shell 執行，
並代入 `%h`、`%p`、`%r` 與 `%n`，連線會經由它進行。與 OpenSSH 相同，主機或使用者名稱若含有
shell 會解讀的字元（引號、`$`、`;`、`|`、空白等），或以 `-` 開頭，會在執行任何命令之前被拒絕。

伺服器在登入時可能提出問題（*鍵盤互動式*登入）：一次性密碼、第二道驗證、新密碼等。OxideMerge 會在
標示伺服器名稱的「登入問題」視窗中顯示這些問題；除非伺服器表示答案可以顯示，否則答案會隱藏；
「取消」則表示拒絕回答。伺服器若只詢問一次密碼，會自動以您提供的密碼回答。未提供金鑰密碼的加密
私密金鑰，也會以同樣方式詢問其密碼；若旁邊有其 `.pub` 檔，則要等伺服器表示接受該金鑰後才會詢問。
伺服器拒絕過的密碼不會再次送出。登入方式會從您選擇的那一種開始依序嘗試，以支援需要多種方式
登入的伺服器。

[[remote-advanced]]
==== 代理伺服器、主動模式與用戶端憑證

連線對話框中的「進階」包含大多數伺服器用不到的設定：

* 「代理伺服器」：經由 SOCKS5 代理伺服器（`socks5://host:1080`，或 `socks5://user@host:1080` 並填寫
  「代理伺服器密碼」）或允許 `CONNECT` 的 HTTP 代理伺服器（`http://host:8080`）連線。輸入在位址中的
  密碼，會在離開該欄位時移到會隱藏內容的「代理伺服器密碼」。SFTP 與 FTP 都會
  使用，包括每一條 FTP 資料連線。對於 `~/.ssh/config` 中設有跳板主機或 `ProxyCommand` 的伺服器，改用
  後者；第一台跳板主機則經由代理伺服器連線。
* 「主動模式」（FTP）：每次傳輸時由伺服器反向連線到這台電腦（使用 `EPRT`，伺服器不支援時改用
  `PORT`），適用於拒絕被動模式的伺服器。資料連線只接受來自伺服器位址的連線。主動模式無法經由代理
  伺服器使用，在位址轉譯（NAT）路由器或阻擋連入連線的防火牆後方通常也無法使用。
* 「用戶端憑證」與「憑證金鑰」（FTPS）：提供給要求憑證之伺服器的 PEM 憑證，其私密金鑰可放在同一個
  檔案或金鑰檔中。金鑰不可加密。

對話框會連同上次成功的連線，記住代理伺服器位址、主動模式與憑證檔案，但絕不記住代理伺服器密碼。

[[remote-command-line]]
==== 命令列與工作中的伺服器路徑

在命令列與工作檔中（請參閱 <<jobs>>），路徑也可以是伺服器上的檔案或資料夾，以位址表示：

[source,sh]
----
oxidemerge sftp://ann@build.example.com/var/www/site ./site     # SFTP，埠號 22
oxidemerge ftpes://ann@ftp.example.com/public/index.html index.html  # 明確 FTPS，埠號 21
oxidemerge ftps://ann@ftp.example.com:990/public ./public -r    # 隱含 FTPS
oxidemerge --cli ftp://ftp.example.com/pub/README README         # 匿名的一般 FTP
oxidemerge sftp://ann@host/~/notes.txt notes.txt                # 在 ann 的主資料夾中
----

位址的格式為 `scheme://[使用者@]主機[:埠號]/路徑`。IPv6 位址要加上方括號，例如
`sftp://ann@[2001:db8::1]/srv`。以 `/~/` 開頭的路徑位於使用者在伺服器上的主資料夾，
其他字元可寫成 `%XX`。SFTP 的主機可以是 `~/.ssh/config` 中的別名（請參閱 <<remote-ssh-config>>），
未指定使用者名稱時，使用其 `User` 或您自己的使用者名稱；FTP 未指定時以 `anonymous` 登入，密碼為
`anonymous@`，絕不使用 `OXIDEMERGE_REMOTE_PASSWORD` 中的密碼。

密碼絕不放在位址中，否則任何看得到命令列或工作檔的人都能讀到；位址中含有密碼會被拒絕。請改為設定在
環境變數 `OXIDEMERGE_REMOTE_PASSWORD` 中。SFTP 在指定 `--ssh-key 檔案` 時以該金鑰登入（此時環境變數
存放金鑰密碼，若有的話），否則使用環境變數中的密碼，再否則使用 `ssh-agent` 與 `~/.ssh/config` 指定
的金鑰。FTP 與 FTPS 需要密碼，以 `anonymous` 登入時除外。OxideMerge 啟動時會移除這個環境變數，因此它
所執行的程式（例如外部工具）不會繼承它。伺服器在登入時提出的問題，以及未提供密碼之加密金鑰的密碼，
會在終端機上詢問，輸入時不顯示（此時按 *Ctrl+C* 會在結束程式時恢復顯示輸入）；沒有終端機時則拒絕
回答。

`--proxy URL` 經由代理伺服器連線，作用同對話框中的「代理伺服器」；代理伺服器密碼從環境變數
`OXIDEMERGE_PROXY_PASSWORD` 讀取（啟動時同樣會移除），位址中含有密碼會被拒絕。`--ftp-active` 使用 FTP
的主動模式。`--client-cert 檔案` 提供 FTPS 用戶端憑證，金鑰不在同一個檔案時以 `--client-key 檔案`
指定。

伺服器的檢查方式與程式中相同，使用同樣的 `known_hosts` 與 `known_certs` 檔案。尚未信任的伺服器
會被拒絕，錯誤訊息會顯示其指紋。請與管理員提供的指紋比對，再加上 `--trust-fingerprint SHA256:...`
重新執行以信任它；之後就會記住，與按「信任並連線」相同。金鑰或憑證已變更的伺服器會被拒絕。

每個伺服器路徑都會在比較前取得為暫存副本，再像本機路徑一樣開啟。在視窗中，「儲存」會如上所述將
變更寫回伺服器。不開啟視窗時，執行過程對取得之副本所做的變更（例如 `sync` 工作對目的地所做的變更），
會在執行後以相同的檢查寫回伺服器；在伺服器上已被修改的檔案會回報為錯誤（結束代碼 2）。同步中途停止
且未能復原所有變更時（結束代碼 5），會改為在取得的副本中復原這些變更，且不寫回任何內容。以
`--sync-plan` 製作的同步計畫會以位址識別伺服器上的資料夾，因此 `--sync-apply` 會將它套用到該次執行
取得的副本；與本機資料夾相同，若計畫要變更的檔案已與規劃時不同，就會被拒絕。

[[compare-types]]
=== 比較類型

OxideMerge 提供五種比較類型：

[cols="1,4"]
|===
|類型 |顯示內容

|文字
|並排顯示各行，並醒目標示變更的字詞。
您可以編輯與合併文字；比較選項與比較規則決定哪些變更算是差異。
適用於原始碼、設定檔、CSV 檔與其他可閱讀的文字。

|二進位
|以十六進位檢視顯示位元組。
差異可以複製與儲存，但各行不會對齊。
例如在開頭附近插入一個位元組，其後的所有位元組都會跟著位移。

|影像
|以並排、疊加、滑動分隔線、閃爍或差異影像等方式顯示像素。
有差異的區域可以從一張影像複製到另一張。

|資料夾
|比較兩個或三個資料夾中的項目。
您可以複製、刪除與合併項目，也可以在個別的比較中開啟每個檔案。

|網頁
|比較兩個或三個網頁：可見文字、格式化的 Markdown、HTML 原始碼或下載的資源。
網頁為唯讀，OxideMerge 不會將任何內容存回網頁伺服器。
|===

文件、試算表與程式是以 OxideMerge 從中讀取到的文字進行比較，屬於文字或表格比較，
而非獨立的比較類型。Word 文件、活頁簿與加上標籤的 PDF 也能以*格式化*顯示，包含標題、清單與表格；
請參閱 <<documents>>。

「比較方式」設為「自動」時，OxideMerge 會依序檢查下列條件，並採用第一個符合的條件：

. 任一側為 `http://` 或 `https://` 網址：網頁比較。
. 每一側都是 HTML 檔案（`.html` 或 `.htm`）：網頁比較。
  除非您先前選過其他模式，否則使用格式化模式。
  例外：指定輸出檔（`-o`）的合併，或在主控台產生修補檔（`--patch`）時，會以文字比較。
. 每一側都是資料夾：資料夾比較。
. 所有檔案都是 OxideMerge 能讀取為文字的類型 —— 文件、試算表或 ELF 程式（請參閱 <<documents>>）——
  或可由解譯器外掛程式轉換（請參閱 <<unpackers>>）：以讀取到的文字進行比較，且為唯讀。
  由 OxideMerge 自行讀取、且只有一個工作表的試算表會以表格比較開啟。
  這一條在壓縮檔與二進位規則之前，因此 `.docx`、`.xlsx` 與 `.odt` 會以其中的文字開啟，
  而非視為實際的 zip 壓縮檔。在「選項 → 外掛」中取消「將文件、試算表與 ELF 檔讀取為文字」，
  這些檔案就會交由下列規則處理。
. 每一側都是壓縮檔：解壓縮後以資料夾比較。
. 所有檔案的副檔名都是影像格式（例如 `.png`、`.jpg`、`.gif`、`.bmp`、`.tif` 或 `.webp`）：影像比較。
. 檔案的前 8 KB 含有零位元組：二進位比較。
  例外：帶有位元組順序標記的 UTF-16 文字仍視為文字。
. 其他情況：文字比較。

若要自行指定類型，請使用對話框中的「比較方式」、已開啟分頁中的「比較 → 比較方式」，或命令列的 `-t`
參數。

=== 文字比較視窗

每一側都有標題列與頁尾：

* 標題列顯示檔案名稱與所在資料夾；鎖頭按鈕可將該側設為唯讀。
* 頁尾顯示儲存時使用的換行格式與編碼，以及目前行號與總行數。

在頁尾選擇其他編碼時，OxideMerge 會以該編碼重新讀取檔案。
變更編碼後請檢查文字是否正確，在編輯或儲存前尤其要確認。

差異以顏色標示：

* 變更的行為藍色。
* 雙向比較時，只在一側的行為綠色。
* 三方比較時，尚未解決的衝突為紅色。
* 變更的行中，有變更的字詞或字元會醒目標示。

在「選項 → 一般」中開啟「色盲友善的差異顏色」後，變更的行改為紫色，只在一側的行改為藍色。

兩個窗格之間的連接線會將每個差異的兩側連起來，目前的差異會醒目標示。
差異成為目前的差異，或指標移到它上方時，才會顯示它的複製箭頭。

工具列分成四組按鈕：

* 「差異」：移到下一個、上一個、第一個或最後一個差異。
* 「複製」（三方比較時為「合併」）：在各側之間複製差異。
* 「編輯」：復原與重做。
* 「檢視」：尋找、摺疊未變更的行與自動換行。

視窗夠寬時，工具列會顯示各組的名稱。
差異編號旁的 +/− 數字分別是新增與刪除的行數。

右側的位置窗格是整個檔案的概覽，按一下即可跳到該位置。
二進位比較、網頁比較的格式化模式與文件的格式化檢視也有位置窗格。

=== 在差異之間移動

[cols="1,2"]
|===
|按鍵 |動作

|kbd:[Alt+↓]、kbd:[Alt+↑]
|移到下一個或上一個差異

|kbd:[Alt+Home]、kbd:[Alt+End]
|移到第一個或最後一個差異

|kbd:[Alt+PgDn]、kbd:[Alt+PgUp]
|移到下一個或上一個衝突（三方比較）

|kbd:[Ctrl+G]
|跳至指定行號
|===

從資料夾比較開啟的檔案，可以接著切換到其他檔案：
在最後一個差異按 kbd:[Alt+↓]，會開啟下一個有差異的檔案；
在第一個差異按 kbd:[Alt+↑]，則會開啟上一個有差異的檔案，並停在它的最後一個差異。
在三方資料夾比較中，kbd:[Alt+PgDn] 與 kbd:[Alt+PgUp] 也會以相同方式，前往下一個或上一個仍有未解決衝
突的檔案。

將指標停在導覽按鈕上，可看到它會走過哪些項目、對應的按鍵，以及到結尾即停止、不會從頭再開始。

[[folder-navigation]]
==== 在資料夾的差異之間移動

在資料夾比較中，同樣的按鍵可用於資料夾清單下方顯示的檔案，以及資料夾中的其他檔案：

* kbd:[Alt+↓] 前往該檔案的下一個差異；過了最後一個差異，會選取下一個有差異的檔案，並前往它的第一個差
  異。
* kbd:[Alt+↑] 方向相反：在第一個差異之前，會前往上一個檔案的最後一個差異。
* kbd:[Alt+Home] 與 kbd:[Alt+End] 前往第一個檔案的第一個差異，以及最後一個檔案的最後一個差異。
* 狀態列會顯示目前位置，例如「檔案 2 / 5 · 差異 3 / 7」。

這些檔案是資料夾清單中顯示為不同的檔案，依清單順序排列；包含二進位檔，但不包含無法讀取的檔案。
到達最後一個檔案的最後一個差異時，OxideMerge 會加以說明，不會從頭再開始。

若檔案仍在載入時按下按鍵，OxideMerge 會記住，等檔案顯示後再移動，因此不會略過任何差異。
若檔案無法讀取，窗格會加以說明，並提供「重試」與「略過」。資料夾仍在比較時，後面可能還有其他檔案，
訊息會如此說明，而不會直接結束。若比較已被停止，結尾的訊息會說明它只涵蓋已比較的檔案。

比較後又變更的檔案，會以目前的內容顯示；若已不再有差異，下一步會接著前往下一個檔案。
清單下方顯示的檔案若在磁碟上變更，會重新載入並停在同一個差異。

在三方資料夾比較中，kbd:[Alt+PgDn] 與 kbd:[Alt+PgUp] 會逐一走過兩側都有變更之檔案中的未解決衝突。
變更可以無衝突合併的檔案，載入後會被略過；只有一側變更的檔案則不會前往。kbd:[Alt+↓] 仍會停在每個有變
更的檔案。

=== 複製差異

複製差異時，OxideMerge 會修改目標窗格中的文字；要等到儲存後，磁碟上的檔案才會變更。
複製前，請先確認目前作用中的窗格與箭頭的方向。

* 按兩個窗格之間分隔線上的箭頭，可複製目前的差異或指標所在的差異。
* kbd:[Alt+→] 與 kbd:[Alt+←] 將目前的差異或選取的行複製到右側或左側。
* kbd:[Ctrl+Alt+→] 與 kbd:[Ctrl+Alt+←] 將所有差異複製到右側或左側。
* 三方比較時，工具列的「合併」群組可將目前的差異或所有差異，從左側或右側複製到中間。
  在差異上按右鍵，可將它從左側或右側複製到中間，或從中間複製到左側或右側。
* kbd:[Ctrl+Z] 復原變更，kbd:[Ctrl+Y] 或 kbd:[Ctrl+Shift+Z] 重做。

[[saving-files]]
=== 儲存檔案

* kbd:[Ctrl+S] 儲存目前分頁中所有已修改的窗格。
* kbd:[Ctrl+Shift+S] 儲存所有分頁中已修改的窗格。
* 「檔案 → 另存新檔」以其他名稱儲存某一側。

OxideMerge 以安全的方式儲存檔案：

. 先將新內容寫入同一資料夾中的暫存檔。
. 再以暫存檔取代原始檔案。

任一步驟失敗時，OxideMerge 會顯示錯誤，絕不會直接覆寫原始檔案。
因此，即使檔案本身可以寫入，所在資料夾仍必須允許建立與取代檔案。

若要保留檔案先前的內容，請在「選項 → 一般」中開啟「覆寫檔案時保留 .bak 備份」，
OxideMerge 會將舊內容保留為 `<name>.bak`。
下次儲存時會取代這份備份，因此它並不是版本紀錄。

=== 編輯文字

非唯讀的窗格都可以編輯。

在文字中按一下即可將游標放在該處並直接輸入，就像一般的文字編輯器。

* kbd:[Enter] 會開始新的一行，並沿用上一行的縮排。
  kbd:[Backspace] 與 kbd:[Delete] 會刪除一個字元，或將一行與相鄰的行合併。
* kbd:[Ctrl+V] 會在游標處貼上，可一次貼上多行。
* 若要選取文字，請拖曳、按住 kbd:[Shift] 再按一下，或按住 kbd:[Shift] 移動游標。
  按兩下會選取一個字，按三下會選取整行（含換行），kbd:[Ctrl+A] 會選取整個檔案。
  拖曳超過窗格頂端或底部時，窗格會捲動並繼續選取。
  輸入或貼上的內容會取代選取的文字。
* kbd:[Ctrl+C] 複製選取的文字，kbd:[Ctrl+X] 剪下。
  沒有選取時，會複製或剪下整行。
* 方向鍵、kbd:[Home]、kbd:[End]、kbd:[PgUp] 與 kbd:[PgDn] 可移動游標。
  kbd:[Ctrl+Home] 與 kbd:[Ctrl+End] 移到檔案開頭與結尾。
  在 macOS 上，kbd:[Cmd+←] 與 kbd:[Cmd+→] 移到行首與行尾。
  開啟自動換行時，上下方向鍵、kbd:[PgUp] 與 kbd:[PgDn] 以顯示行移動，長的一行需按數次；
  kbd:[Home] 與 kbd:[End]（kbd:[Cmd+←] 與 kbd:[Cmd+→]）先移到該顯示行的開頭或結尾，再按一次才移到整
  行的開頭或結尾。
  按住 kbd:[Shift] 時，這些按鍵都會延伸同一個選取範圍。
* kbd:[Tab] 輸入定位字元；選取範圍跨越多行或為整行時，則增加這些行的縮排。
  kbd:[Shift+Tab] 減少選取行（或游標所在行）的縮排。
  游標在窗格中時，kbd:[Ctrl+\]] 與 kbd:[Ctrl+[] 的作用相同。
  以定位字元縮排的行多於以空格縮排的檔案，會以定位字元縮排；其他檔案則以「Tab 寬度」個空格縮排。
  空白行不會增加縮排；減少縮排時移除一個定位字元，或最多為「Tab 寬度」個空格。
  選取範圍結束於某行開頭時，該行不受影響；選取範圍會隨文字移動，因此在 kbd:[Tab] 之後立即按
  kbd:[Shift+Tab]，會還原相同的文字與選取範圍。每次操作皆為一個復原步驟。
* kbd:[Ctrl+←] 與 kbd:[Ctrl+→]（macOS 上為 kbd:[Option+←] 與 kbd:[Option+→]）以單字移動，
  按住 kbd:[Shift] 時則以單字選取。
  以單字移動會移到下一個單字的結尾，或前一個單字的開頭；在行尾或行首時會移到下一行或上一行。
  字母、數字與 `_` 組成一個單字（`snake_case` 與 `camelCase` 都是一個單字），
  連續的標點符號自成一個單字（`x.len` 是三個），每個中文、日文或韓文字也各是一個單字。
* kbd:[Ctrl+Backspace] 與 kbd:[Ctrl+Delete]（macOS 上為 kbd:[Option+Backspace] 與
  kbd:[Option+Delete]）會刪除游標前或後的單字；有選取時則刪除選取的文字。
  按一次 kbd:[Ctrl+Z] 即可復原該單字。
* 在 macOS 上，游標在文字中時，kbd:[Option+←] 與 kbd:[Option+→] 會以單字移動，而不是複製差異；
  請按 kbd:[Esc] 離開文字，或使用複製按鈕。
  kbd:[Option] 加上字母、數字或符號會輸入對應的字元（kbd:[Option+S] 輸入 ß），因此
  kbd:[Alt+C]、kbd:[Alt+Z]、kbd:[Alt+P] 與 kbd:[Alt+S] 要等游標離開文字後才有作用；這些命令仍可從選
  單執行。
* 每按一次 kbd:[Esc] 只做一件事，依序取第一項適用的：
. 關閉開啟中的選單。
. 關閉對話框，或正在輸入的欄位。
. 關閉搜尋列。
. 從多個游標回到一個。
. 結束選取（游標留在原處）。
. 移除游標，方向鍵便恢復逐列移動。
. 關閉分頁。
* 輸入法可在游標處使用，因此可以輸入中文、日文或韓文。
* 在非常大的檔案中，在一行內輸入仍然流暢：OxideMerge 會在您稍停片刻後，或在其他按鍵、按一下或命令之
  前重新比較，
  因此正在輸入的那一行，其顏色可能稍晚更新。新增一行、貼上或復原則會立即重新比較。
* 跨多行的選取也會選取這些列，因此複製按鈕以及 kbd:[Alt+→] 與 kbd:[Alt+←] 可將這些行複製到另一側。
* kbd:[Ctrl+\]] 增加選取行的縮排，kbd:[Ctrl+[] 減少縮排（使用文字游標時，也可用 kbd:[Tab] 與
  kbd:[Shift+Tab]，見上文）。
* kbd:[Ctrl+D] 會在選取的行（或游標所在的行）下方放一份複本，並選取該複本。
  kbd:[Alt+Shift+↑] 與 kbd:[Alt+Shift+↓] 會將這些行連同選取範圍越過相鄰的一行上移或下移。
  與 kbd:[Tab] 相同，它們作用於文字選取範圍所在的行（結束於某行開頭的選取不包含該行）；
  沒有文字游標時，則作用於使用中窗格在所選列中的行。每個動作都是一個復原步驟，也可從「編輯」選單執
  行。
  不按 kbd:[Shift] 時，kbd:[Alt+↓] 與 kbd:[Alt+↑] 仍是前往下一個與上一個差異。
* 沒有游標時，按 kbd:[F2] 或 kbd:[Enter] 會將游標放在目前這一行的結尾。

[[multiple-cursors]]
==== 多個游標

若要在同一窗格的多個位置輸入相同內容，可以使用多個文字游標：

* 按住 kbd:[Ctrl] 按一下（macOS 上為 kbd:[Cmd]）會在該處新增游標，或移除該處的游標。
  按住 kbd:[Ctrl] 按兩下或按三下則新增單字或整行的選取。
* kbd:[Ctrl+Alt+↑] 與 kbd:[Ctrl+Alt+↓]（macOS 上為 kbd:[Cmd+Option+↑] 與 kbd:[Cmd+Option+↓]）
  會在第一個游標的上一行或最後一個游標的下一行、相同欄位處新增游標。部分 Linux 桌面以這些按鍵切換工
  作區；
  按住 kbd:[Ctrl] 按一下則在各處都可使用。

之後輸入、刪除、kbd:[Enter]、方向鍵、kbd:[Home] 與 kbd:[End] 會在每個游標處作用；相遇的游標會合而為
一。
每次編輯對所有游標而言是一個復原步驟，復原時游標也會回到原處。貼上的行數與游標數相同時，每個游標各貼
一行；
其他文字則貼到每個游標處。複製時，各選取範圍依文字順序每段一行。kbd:[Tab]、kbd:[Shift+Tab]、
「複製行」與「移動行」作用於所有游標所在的行，每行一次。唯讀窗格會拒絕在所有游標處的編輯。

最後新增的游標是畫面跟隨的游標，輸入法也在該處顯示組字。kbd:[Esc] 會先回到這一個游標；
不按 kbd:[Ctrl] 按一下也一樣。欄選取（kbd:[Alt]+拖曳）與此分開：建立欄選取會移除多出的游標。

有游標的窗格，其標題列下方會有一條彩色線。可輸入文字時，游標是一條實心的豎線；
在唯讀窗格中、搜尋列等欄位取得鍵盤時，以及視窗位於背景時，游標會變細變淡。
在唯讀窗格中輸入不會變更任何內容，狀態列會說明是哪一側，以及如何解除鎖定。

游標可在並排檢視中使用。
在內嵌檢視中，按兩下某一行，或按 kbd:[Enter] 或 kbd:[F2]，即可在並排檢視中編輯該行（見
<<inline-view>>）；在表格檢視中，請按兩下儲存格來編輯。

每個窗格下方的列會顯示是否可以編輯：

* 「可寫入」：可以編輯並儲存檔案。
* 「唯讀」：窗格已鎖定（例如以標題列中的鎖定按鈕），不接受編輯。
* 「磁碟上為唯讀」：可以編輯，但檔案標示為唯讀，因此「儲存」不會取代它，並保留您的編輯：請以其他名稱
  儲存，或清除唯讀標示後再儲存。
* 「僅供比較」：窗格顯示的是 OxideMerge 從檔案讀取的文字，而不是檔案本身，例如文件、試算表、PDF、程
  式、網頁，或 JSON 與 XML 的格式化副本。
  這類窗格無法解除鎖定、編輯或存回。若要編輯這些文字，請以「檔案 → 另存新檔」存成一般檔案（例如
  `.txt` 檔），窗格之後就會編輯該檔案；無論選項如何設定，都不會存到本身是以這種方式讀取的檔案上。
* 檔案有尚未儲存的變更時，會顯示「已修改」。

視窗底部的狀態列也會顯示目前作用中窗格的這些狀態。
樹狀檢視、格式化檢視，以及以 Markdown 顯示的網頁，也會在狀態列顯示「僅供比較」。

若要選取一欄文字，請按住 kbd:[Alt]（macOS 為 kbd:[Option]）並拖曳。
選取範圍在經過的每一行都涵蓋相同的欄。
自動換行或表格檢視中無法使用。

* 輸入文字會取代每一行選取的欄。
  寬度為零的選取範圍就是每一行各有一個游標，輸入的文字會插入到每一行。
* kbd:[Backspace] 與 kbd:[Delete] 會移除選取的欄，或在每一行各移除一個字元。
* kbd:[Ctrl+C] 複製這些欄（每列一行），kbd:[Ctrl+X] 剪下。
* kbd:[Ctrl+V] 貼上。
  單行文字會貼到每一個選取的行。
  多行文字會逐行貼上，超出選取範圍的行會貼到下方的行。
* 按 kbd:[Esc] 或按一下即結束欄選取。

欄依各行的顯示方式計算：Tab 會延伸到下一個定位點。
貼到較短行尾端之後的文字會以空格補齊，以便對齊。
顯示得較寬的字元（例如中文字）仍算一欄，因此跨過這類字元的欄選取看起來可能不整齊。

每次編輯、貼上、剪下或刪除都是一個復原步驟；在同一行中連續輸入，在游標移動之前算一個步驟。
儲存時會保留各檔案的行尾、編碼與位元組順序標記。

在某一行上按右鍵，可編輯該行、在下方插入一行、刪除該行、複製其文字、設定書籤，或依該行建立比較規則
（請參閱 <<add-rule>>）。
在選取的文字上按右鍵會保留選取範圍，此時「複製文字」只會複製選取的文字；在其他位置按右鍵，則會先將游
標移到該處。

行號區中的編輯標記，會標示開啟檔案後變更過的行。

其他程式修改了檔案時，OxideMerge 會在視窗重新成為作用中視窗時偵測到：

* 沒有未儲存變更的檔案會自動重新載入。
* 有未儲存變更的檔案會顯示訊息，並提供重新載入的選項。
  重新載入會以磁碟上的檔案取代您的編輯。

=== 尋找與取代

* kbd:[Ctrl+F] 開啟尋找列。
  kbd:[F3] 與 kbd:[Shift+F3] 尋找下一個與上一個符合項目，kbd:[Esc] 關閉尋找列。
* kbd:[Ctrl+H]（macOS 為 kbd:[Cmd+Alt+F]）開啟尋找與取代。
* 搜尋選項有「大小寫須相符」、「全字拼寫須符合」與「規則運算式」。
  使用規則運算式時，取代文字中的 `$1` 代表第一個擷取群組。
* 「全部取代」可以一次復原。

=== 書籤

* kbd:[Ctrl+F2] 在目前這一行設定或移除書籤。
* kbd:[F4] 與 kbd:[Shift+F4] 移到下一個與上一個書籤。
* 「編輯 → 書籤 → 書籤註解...」可為書籤加上註解。
  將指標移到行號區時會顯示註解，HTML 報告中也會列出。
* 「編輯 → 書籤 → 清除所有書籤」移除全部書籤。

書籤會標示在行號區與位置窗格中。

[[sync-points]]
=== 同步點

比較有時會把不相關的行配對在一起，例如某個函式改寫後又搬到其他位置。
這時可以用同步點告訴 OxideMerge 哪些行應該對齊：

. 將游標移到某一側的某一行，選擇「合併 → 設定同步點」（kbd:[Alt+S]），或在該行按右鍵。
. 以相同方式選擇另一側中對應的行；三方比較時，第三側也要選擇。

這些行會顯示在同一列，前後的文字則分開比較。

* 可以加入任意數量的同步點，但與其他同步點交叉的同步點會被拒絕。
* 同步點會標示在行號區；編輯、復原或重新載入時，同步點會跟著對應的行移動，也會一併存入已儲存的比較。
* 若要取消已選取的行，請在該行再執行一次此命令。
* 若要移除某個同步點，請在其中一行再執行一次此命令。
* 若要移除所有同步點，請選擇「合併 → 清除同步點」。

=== 檢視選項

「檢視 → 文字比較」提供下列選項：

* 「位置窗格」與「行詳細資料窗格」。
  行詳細資料窗格會將各側的目前這一行上下排列並自動換行，方便找出長行中的細微差異。
* 「行號」、「編輯標記」、「顯示空白字元」與「語法醒目提示」。
* 「摺疊未變更的行」（kbd:[Alt+C]）：將未變更的行收合成一列，每個差異前後保留三行。
  按一下該列即可展開。
* 「自動換行」（kbd:[Alt+Z]）。

「檢視 → 縮放」（kbd:[Ctrl+{plus}]、kbd:[Ctrl+-] 與 kbd:[Ctrl+0]）可調整文字大小。

「文字排列」位於「檢視 → 文字比較」與「選項 → 一般」中：

緊密排列:: 預設值。每一側只顯示自己的行，不留空白。
對齊排列:: 在新增或刪除行的另一側留白，讓後面的行維持左右對齊。

此設定會套用到所有已開啟的雙向與三方文字比較，並保留到下次使用。
切換排列方式不會變更檔案內容或比較規則。

==== 內嵌檢視

雙向比較時，「自動換行」旁的「內嵌檢視」按鈕會以單欄顯示差異；命令面板中也有相同的命令。

.內嵌檢視
image::inline.png[內嵌檢視]

* 先列出刪除的行，再列出取代它們的行，每一行都附上舊行號與新行號。
* 開啟「摺疊未變更的行」時，未變更的行會收合，按一下即可展開。
* 差異之間的移動與複製照常運作，復原與取消復原也可使用；方向鍵可逐行移動，kbd:[Ctrl+C] 複製目前這一
  行。
* 內嵌檢視僅顯示檔案：上方的列會說明這一點，輸入、貼上、增加縮排與「取代」在此都沒有作用。
  若要編輯，請按該列上的「在並排檢視中編輯」、按兩下某一行，或按 kbd:[Enter] 或 kbd:[F2]：
  並排檢視會開啟，文字游標位於目前這一行的開頭。

  時即可繼續。

=== CSV 與 TSV 檔案

CSV 與 TSV 檔案的工具列提供「表格檢視」，以記錄而非行為單位比較，因此引號內的欄位可以包含換行。

.兩個 CSV 檔案的表格檢視
image::csv.png[表格檢視]

* 拖曳欄位邊界可調整欄寬。
* 若要編輯儲存格，請按兩下它，或按右鍵選擇「編輯儲存格」；也可以選取後按 kbd:[F2] 或 kbd:[Enter]。
  儲存格可以包含多行文字。
* 若要將某個欄位複製到另一側的對應記錄，請在儲存格上按右鍵並選擇「複製儲存格」。兩筆記錄都必須有該
  欄。
* 方向鍵可在記錄與欄位之間移動；
  kbd:[PgUp] 與 kbd:[PgDn] 逐頁移動記錄，kbd:[Ctrl+Home] 與 kbd:[Ctrl+End] 選取第一筆與最後一筆記錄。
* 「跳至行」使用檔案中的實際行號。

編輯儲存格時，OxideMerge 會保留該欄位以外的引號與換行格式，並可復原與重做。
經過轉換或唯讀的文件無法編輯。

在表格檢視中複製差異時，只會變更所選的行。
若這樣會破壞 CSV 的引號格式，OxideMerge 會拒絕複製，文件維持不變；
此時請改為複製儲存格，或切換到文字檢視處理。
含引號的記錄格式不正確時，表格會顯示錯誤，請切換到文字檢視修正。

[[table-keys]]
==== 依鍵配對列

表格檢視預設依位置配對記錄，就像逐行比較一樣。若記錄的排序不同，或有新增、刪除的記錄，請改為依鍵配
對。
雙向比較時，表格上方的列提供下列設定：

「列配對方式」:: 「位置」（預設）或「鍵欄」。
「鍵」:: 用來識別記錄的欄，例如 `id`；可選擇一欄或多欄。
「第一列為標題」:: 以第一列作為欄名，不列入比較。
「欄配對方式」:: 依「位置」或「標題名稱」配對欄，即使欄的順序改變也能對上。
「忽略列順序」:: 只移動過的記錄不算差異：上一個與下一個差異會略過它，但仍保留 `↕` 標記。
「數值容差」:: 相差在此範圍內的數字視為相等。`0.01` 表示差值，`1%` 表示較大數字的比例；留空則精確比
較。
「列順序」:: 「左側順序」（預設）依左側表格的順序列出，只在右側的記錄會排在它前一筆記錄之後；「右側
順序」依右側表格的順序；
「鍵順序」依鍵排序：數字依數值排序並排在文字之前，沒有鍵的列排在最後。

摘要會顯示新增、刪除、修改、順序變動與不明確的記錄數。列標記為：`+` 新增、`−` 刪除、`~` 修改、`↕` 移
動、`?` 不明確。

* 「下一個差異」與「上一個差異」會逐一走過不同的記錄。
* 「複製儲存格」會複製到對應記錄中配對的欄。複製整筆記錄會取代對應記錄的儲存格，或新增、刪除該記錄。
* 鍵為空白，或有多筆記錄使用同一個鍵時，該記錄為「不明確」。不明確的記錄絕不會被複製；「下一個不明確
  的列」可找到它們。
* 若某一側缺少鍵欄，OxideMerge 會改依位置配對並說明原因。

兩側合計超過 100,000 筆記錄的表格會在背景配對，上方的列會顯示已處理的記錄數，並提供「取消」。
取消後，列會改依位置配對，按「依鍵配對」可重新開始。

依鍵配對之表格的 HTML 與 XML 報告，會記錄列的配對方式：鍵、標題列、欄的配對方式、列順序、容差、各項
計數與警告。
XML 報告將這些資訊放在 `<table-match>` 元素中。

這些設定會儲存在專案中；較舊的專案開啟時會依位置配對。

[[git-revision]]
=== 與修訂版本比較

「檔案 → 與修訂版本比較...」會將檔案或資料夾與 Git、Subversion 或 Mercurial 中較早的版本比較。
路徑上方最近的工作複本決定使用哪一種。
對話框會列出最近變更過該路徑的修訂版本供您選擇。

WARNING: 與 Subversion 或 Mercurial 修訂版本比較屬於實驗性功能，尚未完整測試：
僅在 macOS 上以本機儲存庫試過。

在 Git 中，版本可以是 `HEAD`、分支、標籤或某次提交；留空即為 `HEAD`。
在 Subversion 中，可以是 `BASE`（工作複本更新到的修訂版本）、`PREV`、`HEAD`、
`1234` 或 `r1234` 這類編號，或 `{2026-11-01}` 這類日期；留空即為 `BASE`。
在 Mercurial 中，可以是 `.`（工作複本的父修訂版本）、`.^`、`tip`、編號、雜湊值、標籤、書籤或其他
revset；
留空即為 `.`。

較早的版本以唯讀方式顯示在左側，目前的檔案或資料夾顯示在右側。
必須先安裝 Git、Subversion 或 Mercurial 並加入 `PATH`。
Git 與 Mercurial 從本機儲存庫讀取修訂版本。
Subversion 從工作複本讀取 `BASE`；其他修訂版本與最近修訂版本清單則來自儲存庫伺服器，
伺服器可能要求 OxideMerge 無法提供的登入，請先用 `svn` 本身登入。
修訂版本在背景讀取；伺服器緩慢或沒有回應時，按 *取消* 即可停止，並回到對話框。
按下 *比較* 時，Mercurial 會讀取儲存庫本身的 `.hg/hgrc`，如同會套用 Git 的篩選器；
輸入路徑時讀取的最近修訂版本清單則會略過它（Mercurial 5.4 或更新版本）。
比較工作複本的最上層資料夾時，`.git`、`.svn` 或 `.hg` 資料夾只會列在右側；
「Exclude Source Control」篩選器可將其隱藏。
匯出修訂版本的資料夾若會超過 8 GB 或 500,000 個檔案，就會被拒絕，
這與<<archives,解壓縮壓縮檔>>相同的限制，以免誤觸或過大的修訂版本把磁碟空間耗盡。

在命令列中使用 `--rev`（或同一選項 `--git-rev`）：

[source,sh]
----
oxidemerge --rev HEAD~1 src/main.rs
oxidemerge --rev PREV src/main.c
oxidemerge --rev .^ docs
----

另請參閱 <<integration>>：OxideMerge 也可以設定為 Git、Subversion、Mercurial 或 Perforce
自己叫用的差異與合併工具，而非從 OxideMerge 內開啟某個修訂版本。

[[merging]]
== 合併檔案與解決衝突

[[three-way-merge]]
=== 三方合併

.三方比較
image::three.png[三方文字比較]

三方合併會整合同一個檔案的兩份修改版本。
請依序開啟：您的版本、基底、另一份版本。
OxideMerge 會分別比較左右兩側與基底，並將變更整合到中間窗格。

==== 步驟一：選擇輸出檔案

預設情況下，儲存中間窗格會覆寫基底檔案。
若要保留基底檔案，請在啟動時另外指定輸出檔案：

[source,sh]
----
oxidemerge mine.txt base.txt theirs.txt -o merged.txt
----

中間窗格一開始顯示基底檔案的內容，儲存時會將結果寫入 `merged.txt`。
您也可以選擇「檔案 → 另存新檔」，將結果存到其他檔案。

若左右兩側只當作合併來源，建議將它們設為唯讀。

==== 步驟二：合併並解決衝突

窗格上方的合併列會顯示剩餘的衝突數，並提供下列按鈕：

* 「下一個衝突」。
* 「採用左側」、「採用兩側」與「採用右側」：處理目前的衝突。
* 「標記為已解決」：用於您手動編輯過的衝突，會保留中間的文字並將該衝突計為已解決。
* 「儲存結果」：位於最右側，儲存中間窗格；沒有剩餘衝突時，它會成為主要按鈕。

合併步驟：

. 選擇「合併 → 自動合併」。
  這會將兩類變更複製到中間窗格：只在一側出現的變更，以及兩側完全相同的變更。
. 以 kbd:[Alt+PgDn] 與 kbd:[Alt+PgUp] 逐一檢查剩餘的衝突。
. 從左側或右側複製需要的變更，或直接編輯中間窗格。
. 若要同時保留兩側的變更，請在差異上按右鍵，選擇「採用左側，再採用右側」或「採用右側，再採用左側」，
  再檢查結果是否有重複或互相矛盾的內容。
. 儲存結果，並確認目標路徑正確。

IMPORTANT: 自動合併只處理文字，不會檢查結果是否正確。
使用合併結果前，請先檢查內容，並執行專案所需的驗證。

[[conflict-files]]
=== 解決衝突檔案

.以三方檢視開啟的衝突檔案
image::conflict.png[衝突檔案]

衝突檔案是含有版本控制衝突標記的檔案，標記包括
`<<<<<<<`、`|||||||`、`=======` 與 `>>>>>>>`。
OxideMerge 會以三方檢視開啟這類檔案。

開啟衝突檔案的方式：

* 「檔案 → 開啟衝突檔案...」。
* 起始頁的「開啟衝突檔案」。
* 命令列：`oxidemerge conflict.txt`。

左側是「我的」，右側是「他們的」，中間是「合併結果」。
解決每個衝突後儲存中間窗格，OxideMerge 會將結果寫回衝突檔案。

NOTE: 這與開啟三個獨立檔案不同：解決衝突檔案時，原本的檔案就是輸出目標。

== 比較資料夾

.資料夾比較
image::folder.png[資料夾比較]

資料夾比較會列出兩個或三個資料夾中的項目，以及每個項目的比較結果。
結果會在比較進行中陸續顯示：OxideMerge 在掃描資料夾時就會比較檔案，一發現差異就立即列出。
若視窗在背景時完成了耗時較久的比較，OxideMerge 會提醒您。

=== 資料夾清單

每一列顯示下列欄位：

* 「名稱」。
* 「資料夾」：項目所在的資料夾，只在平面清單中顯示。
* 「比較結果」。
* 「修改時間」：各側中最新的日期。
  日期不同時，日期後面會標示較新的一側；將指標移到日期上，可查看每一側的日期。
* 各側的檔案大小。
* 「副檔名」。

按一下欄位標題即可依該欄排序，再按一次可反轉順序。
列左緣的彩色線條，標示有差異或只在一側的項目。

比較結果為下列其中之一：

[cols="1,2"]
|===
|結果 |意義

|「相同」、「不同」
|檔案相同或不同；二進位檔另標示「二進位」。

|例如「3 個不同 · 1 個僅在左側」
|有差異的資料夾，文字說明其中哪些項目不同。

|「僅左側有」、「僅中間有」、「僅右側有」
|項目只在某一側。

|「左側不同」、「中間不同」、「右側不同」
|三方比較：某一側與另外兩側不同。

|「左側不存在」、「中間不存在」、「右側不存在」
|三方比較：項目只在另外兩側。

|「錯誤」
|OxideMerge 無法讀取該項目。
|===

將指標移到比較結果上，可查看完整說明，例如「文字檔案不同」。

路徑下方的篩選標籤會統計項目數量：「全部」、「不同」、「僅在左側」、「僅在右側」、「僅在中間」（僅三
方比較）與「相同」。
按一下標籤即可隱藏或顯示該類項目。
關於計數的幾點說明：

* 三方比較中，只缺少一側的項目算作「不同」。
* 空資料夾與未掃描的資料夾，依其顯示的結果計數。
* 關閉「包含子資料夾」時不會比較子資料夾；這些子資料夾只計入「全部」，也不會被任何標籤隱藏。

狀態列會顯示比較所花的時間。

=== 顯示選項

「檢視 → 資料夾清單」提供下列選項：

樹狀模式:: 以樹狀結構顯示子資料夾，關閉後改為平面清單。
kbd:[→] 與 kbd:[←] 展開與摺疊資料夾，工具列也有「全部展開」與「全部摺疊」。
顯示:: 顯示或隱藏「相同」、「不同」、「僅左側」、「僅中間」與「僅右側」的項目。
資料夾清單下方顯示檔案比較:: 在清單下方直接顯示所選檔案的差異，不必開啟分頁。
工具列上的窗格按鈕或 kbd:[Alt+P] 可顯示或隱藏此窗格。

.資料夾清單下方的檔案比較
image::docked.png[含檔案比較窗格的資料夾比較]

顯示此窗格與否，會影響下列按鍵的作用：

[cols="1,2,2"]
|===
|按鍵 |顯示檔案比較窗格時 |未顯示窗格時

|kbd:[Alt+↓]、kbd:[Alt+↑]
|移到檔案中的下一個或上一個差異。
超過最後或第一個差異時，切換到下一個或上一個有差異的檔案。
|選取下一個或上一個有差異的檔案。

|kbd:[Alt+Home]、kbd:[Alt+End]
|移到檔案中的第一個或最後一個差異。
|選取第一個或最後一個有差異的檔案。
|===

窗格上的箭頭按鈕與 kbd:[Alt+↓]、kbd:[Alt+↑] 的作用相同。
檔案仍在載入時按下按鍵，OxideMerge 會等檔案載入完成，不會略過任何差異。
使用審閱篩選時，這些按鍵只會在篩選所列出的檔案之間切換。

=== 工具列

由左至右依序為：

* 「重新整理」（kbd:[F5]）：重新比較資料夾。
* 「全部展開」與「全部摺疊」：樹狀模式下使用。
* 「資料夾清單下方顯示檔案比較」（kbd:[Alt+P]）：顯示或隱藏檔案比較窗格。
* 「複製到右側」與「複製到左側」：複製選取的項目。
  三方比較時，這些按鈕改為「從左側複製到中間」、「從右側複製到中間」與「自動合併資料夾...」。
* 「同步資料夾...」：雙向比較時，預覽並套用同步（請參閱 <<folder-sync>>）。
* 「依名稱選取...」：選取名稱符合萬用字元（例如 `*.c; *.h`）的項目。
* 「所有差異」：在一個分頁中開啟所有已變更的文字檔（請參閱 <<all-differences>>）。
* 「匯出 HTML」：儲存 HTML 報告（請參閱 <<reports>>）。
* 「篩選器」：決定要比較哪些檔案與資料夾（請參閱 <<filters>>）。
* 「規則」：選擇此比較使用的比較規則檔（請參閱 <<compare-rules>>）。
* 「比較方法」：選擇比較檔案的方式（請參閱 <<compare-methods>>）。
* 「依名稱尋找」（kbd:[Ctrl+F]）：只顯示名稱含有所輸入文字的項目。
* 「側邊面板」：位於最右側，開啟包含審閱、驗證與基準面板的側邊抽屜（請參閱 <<analysis>>）。

視窗較窄時，「所有差異」與「匯出 HTML」會縮成圖示，篩選標籤也只顯示數字。

[[compare-methods]]
=== 比較方法

[cols="1,3"]
|===
|方法 |比較檔案的方式

|完整內容
|逐行比較文字檔，並套用比較選項與比較規則。
只有被忽略的部分不同的檔案，視為相同。

|快速內容
|比較位元組。
大小不同的檔案不必讀取即可判定為不同。

|二進位內容
|與「快速內容」一樣比較位元組，並將結果標示為二進位。

|修改日期
|比較修改日期。
「選項 → 資料夾」中的「日期容許誤差（秒）」決定兩個日期可以相差多少。

|修改日期與大小
|日期與大小都必須相同。

|大小
|只比較大小。
|===

如何選擇：

* 需要套用比較規則或忽略某些差異時，請用「完整內容」。
* 需要確認檔案完全相同時，請用「快速內容」或「二進位內容」。
* 需要快速初步檢查時，可用日期或大小相關的方法。
  請注意，日期與大小相同，並不代表內容相同。

位元組比較會分段讀取檔案，因此大型檔案不必整個載入記憶體。
完整的文字比較仍可能將有變更的檔案載入記憶體。

=== 選取與開啟項目

可以用滑鼠或鍵盤選取項目：

* 方向鍵、kbd:[PgUp]、kbd:[PgDn]、kbd:[Home] 與 kbd:[End] 移動選取位置；按住 kbd:[Shift] 可擴大選取
  範圍。
* 按住 kbd:[Ctrl] 再按一下，可將項目加入或移出選取範圍。
* kbd:[Ctrl+A] 選取所有項目。

開啟項目：

* 按兩下項目或按 kbd:[Enter]，可在獨立分頁中比較它。
  在樹狀模式中，這個動作會改為展開或摺疊資料夾。
  若要以獨立的資料夾比較開啟某個資料夾，請使用平面清單，或在資料夾上按右鍵並選擇「比較」。
* 按 kbd:[Space] 開啟「快速預覽」：不必開啟新分頁，即可看到所選檔案以顏色標示的差異。
  在預覽中，kbd:[↑] 與 kbd:[↓] 切換項目，kbd:[Enter] 開啟項目，kbd:[Space] 或 kbd:[Esc] 關閉預覽。

=== 複製與刪除項目

* kbd:[Alt+→] 與 kbd:[Alt+←] 將選取的項目複製到右側或左側。
* 在項目上按右鍵可使用更多命令：
** 「複製」到另一側。
** 「複製到資料夾...」：將某一側選取的項目複製到另一個資料夾，並保留相對路徑。
** 從某一側「刪除」。
** 「以關聯的應用程式開啟」。
** 「在檔案管理員中顯示」。
** 「複製完整路徑」。
** 「依名稱選取...」。

「選項 → 一般」中的下列設定會影響檔案操作：

* 「複製前先確認」：複製項目前先詢問；刪除項目前一律會詢問。
* 「刪除時使用資源回收筒」：刪除的項目會移到資源回收筒或垃圾桶。
  無法移入的項目，OxideMerge 不會刪除。
* 「覆寫檔案時保留 .bak 備份」：取代檔案時保留舊內容。

IMPORTANT: 複製與刪除會立即變更磁碟上的檔案，
不會等到「儲存」，也無法以文字編輯的「復原」命令還原。
操作前請先確認選取的項目與目標位置。

[[all-differences]]
=== 檢查所有差異

.所有差異
image::alldiffs.png[所有差異]

「所有差異」會在一個分頁中顯示資料夾比較裡所有已變更的文字檔。
請按資料夾比較工具列上的按鈕，或選擇「比較 → 所有差異」。
資料夾比較的篩選器與「顯示」設定同樣適用。

* 左側清單列出每個檔案及其差異數量。
  「篩選檔案…」（kbd:[Ctrl+F]）可縮短清單；按一下檔案即可捲動到該檔案。
* 每個檔案以一張卡片並排顯示其差異。
  按卡片標題中的箭頭可摺疊或展開卡片，工具列則可摺疊或展開全部卡片。
* kbd:[Alt+↓] 與 kbd:[Alt+↑] 依序瀏覽所有檔案的差異。
  從資料夾比較開啟「所有差異」時，會從那裡選取的差異開始。仍在載入的卡片會等候，不會被略過。
  狀態列會顯示目前位置，與 <<folder-navigation>> 相同。
* 差異旁的箭頭會將它複製到另一側。
  雙向比較時，卡片標題中的按鈕可複製整個檔案。
* 「復原」取消上一個變更。
* 「儲存」寫入已變更的檔案，之後資料夾比較會重新整理。
* 卡片標題最右側的按鈕會在獨立分頁中開啟該檔案。

補充說明：

* 從檔案不存在的一側複製時，儲存後會刪除該檔案，因此變空的資料夾也會一併刪除。
  若已開啟備份，刪除的檔案會保留為 `.bak`，所在資料夾也就會保留。
* 檔案在載入後於磁碟上有變更時，無法儲存該卡片。
  卡片會提供捨棄編輯並重新載入檔案的選項；選擇前，請先另外保留需要的編輯內容。
* 磁碟上標示為唯讀的檔案不會被儲存、取代或刪除；其卡片會保留您的編輯。
* 沒有編輯過的卡片，會在檔案變更時自動重新載入。
* 「重新整理」（kbd:[F5]）也會重新載入比較規則與選項。
* 若要納入開啟「所有差異」之後才變更的檔案，請先儲存或捨棄目前的編輯，再重新開啟「所有差異」。

[[folder-merge]]
=== 自動合併資料夾

在三方資料夾比較中，中間的資料夾是基底。
「合併 → 自動合併資料夾...」會將兩側的變更帶入中間資料夾：

* 只在某一側變更、新增或刪除的項目，會被複製或刪除。
* 兩側完全相同的變更只套用一次。
* 兩側都有變更的文字檔，若變更沒有重疊，會逐行合併。

==== 開始之前

. 在「選項 → 資料夾」中，開啟「包含子資料夾」與「包含僅一側子資料夾的內容」。
. 等待比較完成。

IMPORTANT: 合併結果會寫入中間資料夾。
若要保留原本的基底資料夾，請先複製一份，再以複本作為中間資料夾。

==== 檢查合併計畫

OxideMerge 會先列出計畫：預計複製、刪除與合併的項目，以及無法自動解決的衝突。
確認前請先仔細檢查。

下列檔案不會被變更：修改互相衝突的檔案、內容無法合併的檔案、符號連結，以及無法讀取的檔案。
若檔案在比較後又有變更，請重新整理比較後再試一次。

==== 合併如何保護您的檔案

合併只有兩種結果：所有變更全部完成，或中間資料夾完全維持原狀。

* _合併前_，OxideMerge 會檢查每個項目。
  若有項目在計畫產生後又有變更、會寫到中間資料夾之外，或其備份檔會取代比較中的檔案，就不會合併任何項
  目，並列出這些項目。
* _合併期間_，OxideMerge 會在寫入每個檔案前再檢查一次。
  若其他程式變更了檔案，合併會停止。您也可以按「停止」中止合併。
* _合併停止或失敗時_（例如資料夾唯讀或磁碟已滿），OxideMerge 會復原到目前為止的所有變更。
  中間資料夾會恢復原狀，被移除的資料夾也會恢復原本的權限。
  合併時移到垃圾桶的檔案會從副本還原，因此垃圾桶中也會保留一份。

為了能夠復原，OxideMerge 會將原始檔案的副本放在中間資料夾最上層的 `.oxidemerge-undo-…` 資料夾中。
若無法在該處建立此資料夾，則改用系統的暫存資料夾。
資料夾比較不會列出這個資料夾。
被刪除的檔案只是移到這個資料夾，復原時再移回原處。

若 OxideMerge 無法將某個檔案放回原處，會保留這個復原資料夾並顯示其位置。
資料夾中的 `index.txt` 列出每個副本的原始路徑，方便您手動還原。

[[folder-sync]]
=== 同步兩個資料夾

在雙向資料夾比較中，「同步資料夾...」（位於工具列與「合併」選單）會讓一個資料夾（「目的地」）與另一
個（「來源」）一致。
您會先看到計畫，套用之前不會變更任何檔案。

image::sync.png[同步資料夾預覽]

==== 模式

「鏡像 左 → 右」、「鏡像 右 → 左」::
目的地最後會擁有來源的檔案：複製新增與變更的檔案，並刪除只有目的地才有的檔案與資料夾。
「以左側更新右側」、「以右側更新左側」::
複製新增與變更的檔案，不刪除任何項目。

唯讀的一側（例如 Git 修訂版本）不能作為目的地。
OxideMerge 依內容（SHA-256）判斷，絕不會只因修改時間較新就覆寫。比較結果相同、但大小或時間不同的檔
案，會讀取內容再確認。

==== 開始之前

. 在「選項 → 資料夾」中，開啟「包含子資料夾」與「包含僅一側子資料夾的內容」。
. 等比較完成。已停止的比較無法同步。

兩個資料夾必須是不同的資料夾，且任一個都不能位於另一個之中。

==== 預覽

預覽為唯讀，會列出每個項目的動作與原因：

[cols="1,3"]
|===
|動作 |意義

|建立資料夾、複製
|項目只在來源中。

|取代
|內容不同，目的地的檔案會被覆寫。

|刪除、移除資料夾
|項目只在目的地中（僅限鏡像）。資料夾只有在之後變成空的時才會移除。

|略過
|項目只在目的地中，且模式為更新。

|衝突
|無法安全判斷，OxideMerge 不會變更該項目。
|===

衝突包括：無法讀取的項目、符號連結（絕不跟隨或複製）、裝置、一側是檔案另一側是資料夾、
名稱與另一個只差在大小寫或拉丁字母重音寫法（組合或分解），以及比較後又變更的項目。
若某個檔案在兩側的名稱只差在大小寫或上述重音寫法，且兩側內容相同，鏡像時不算衝突，而會重新命名（見下
文）。

在 macOS 與 Linux 上，勾選 *將符號連結以連結本身複製* 即可同步連結，而不是略過它們。此時連結會被當作
連結本身，
絕不當作它所指向的內容：

* 只在來源中的連結，會以相同的目標文字建立在目的地。
* 目標文字不同的連結會被取代。
* 鏡像時，只在目的地中的連結會被刪除；更新則會保留。
* 與同名檔案或資料夾對應的連結仍算衝突。

連結所指向的內容絕不會被讀取、寫入或刪除，即使它位於兩個資料夾之外；變更過的連結也會像檔案一樣記錄在
復原日誌中，
因此復原時會將它們放回原處。

按一下項目可查看詳細資料：兩側的大小與 SHA-256 開頭，以及該動作是向目的地新增，還是會覆寫或刪除目的
地的內容。

若某個複製的內容與計畫要刪除的檔案相同，代表該檔案在來源中被重新命名或移動過。
「重新命名」會以「舊名稱 → 新名稱」列出這些配對，複製與刪除項目也會顯示對方的名稱。
套用重新命名時，會在目的地中移動該檔案，因此不需複製，也不會在日誌中保留副本：
檔案會先改成日誌所記錄的暫存名稱，再改成新名稱。只改變名稱大小寫或重音寫法的重新命名也以相同方式進
行，
即使檔案系統把兩個名稱視為同一個（例如 Windows 與 macOS 的檔案系統）也一樣。
若新舊位置位於不同磁碟，則會先複製再刪除舊檔案。只差在大小寫的資料夾重新命名，以及只差在大小寫且內容
也變更的檔案，
仍不會被變更。

清單上方會顯示警告：

* 若篩選器或隱藏檔案設定排除了某些項目，鏡像不會刪除它們，因此目的地可能不是完全一致的鏡像；仍含有這
  類項目的資料夾會保留。
* 大量刪除會被標示，並需要再確認一次。

「匯出計畫...」會將計畫儲存為 JSON，內含版本編號與相對於資料夾的路徑，不含資料夾的絕對路徑。
計畫會記錄篩選條件，以及兩個資料夾路徑的 SHA-256，因此只會套用到製作計畫時的資料夾。

==== 套用計畫

「套用變更...」會要求確認並指出目的地。若要刪除的項目很多，還必須勾選一個註明數量的核取方塊。

接著 OxideMerge 依下列順序處理：建立資料夾、複製與取代檔案、刪除檔案，最後移除空的資料夾。
對話框會顯示已完成的數量與正在變更的項目。
每個項目都會先確認來源與目的地仍與預覽時相同。每個檔案會先複製到目的地旁的暫存檔，與計畫中的 SHA-256
核對後，
再改名放到定位；重新命名的檔案則改為移動。最後會再檢查一次所有複製與移動的檔案。

若有檔案在預覽後被變更（即使大小與修改時間相同），就不會套用任何變更，並會指出該檔案。

目前無法讀取的檔案會如實回報，而不會說成已變更：在 Windows 上，若有其他程式開著某個檔案且不允許共用，
同步會在變更任何檔案之前停止，並指出該檔案。請關閉該程式後重新預覽。

在 Windows 上，超過舊有 260 字元限制的路徑，也會與其他路徑一樣複製與刪除。

若新增與取代的檔案，或被取代與刪除檔案的日誌副本，超出所在磁碟的可用空間，也不會套用任何變更。
訊息會指出該磁碟、所需空間與可用空間。只在目的地內移動的檔案不計入。此檢查僅在 macOS 與 Linux
上進行，Windows 不會測量可用空間。若磁碟仍在中途寫滿，該次寫入會失敗，並復原已做的變更。

==== 發生問題時

取代或刪除檔案之前，OxideMerge 會先將它複製到設定資料夾中 `sync-recovery` 資料夾內的復原日誌，絕不會
放在被同步的資料夾裡。

* 若某項變更失敗，或您按下「停止」，OxideMerge 會從最後一項開始復原已完成的變更。
* 若某個檔案在這期間又被變更，OxideMerge 不會覆寫它，而是顯示「部分套用 — 需要復原」，並保留含有副本
  的日誌。
* 若 OxideMerge 在同步完成前結束，下次啟動時會詢問要復原這些變更，還是保持資料夾現狀。在處理之前，這
  些資料夾無法再次同步。

IMPORTANT: 對多個檔案的套用並非單一的不可分割操作。每個檔案都是以不可分割的方式取代，但其他程式可能
會看到部分檔案已變更。
不會使用資源回收筒。

[[documents]]
=== 文件、試算表與程式

有些檔案本身不是文字，卻含有文字。OxideMerge 會自行讀取這些檔案，不需另外安裝程式：

[cols="1,3"]
|===
|檔案 |比較的內容

|`.pdf`
|每一頁的文字，依繪製順序排列，頁與頁之間以空行分隔，也包含頁面所繪製之表單（Form）中的文字。
字元取自檔案為各字型所附的 `ToUnicode` 對照表，或取自字型所指定的編碼。加密的檔案會明確回報，而非讀取為空白。
若檔案有部分內容無法讀取（例如採用 OxideMerge 不支援之壓縮方式的串流，或字型沒有字形對應字元的對照表），
結尾會以一行說明文字並不完整及其原因；若完全讀不出任何文字，則會明確回報。

|`.docx`、`.odt`、`.rtf`
|文件的文字，每個段落或標題一行。表格的儲存格以 Tab 分隔，每列一行。標示為已刪除的文字與功能變數代碼不會列入。

|`.xlsx`、`.xlsm`、`.ods`
|每個工作表，每列一行、儲存格以逗號分隔。資料列之間的空白列會保留，使各列維持原本的位置；
最後一列之後的空白列則不列入。只有一個工作表的活頁簿會以<<table-compare,表格比較>>開啟：
欄位、排序與「配對依據 → 索引鍵欄位」皆可使用。若活頁簿有多個工作表，每個工作表的資料前會標示其名稱，
並以文字比較，因為這些工作表並非同一個表格。

|ELF 程式、共用程式庫與目的檔
|標頭（類別、位元組順序、種類、機器、ABI、進入點與各項數量），接著是程式標頭，
每個區段（segment）一行，含類型、位移、虛擬與實體位址、檔案中與記憶體中的大小、對齊與 `R`、`W`、`E` 旗標
（動態連結的程式還會列出所需的解譯器），然後是區段表，每個區段一行，含名稱、類型、位址、位移、大小、對齊與旗標。
最後是各符號表（`.symtab`、`.dynsym`）的符號，依名稱排序，每個符號一行，含位址、大小、類型、繫結、可見性與所在區段
（未定義為 `UND`，絕對值為 `ABS`）。因此兩次建置可逐一函式對照：變大或搬移的函式會顯示為變更的一行。
ARM 與 RISC-V 組譯器加入的對應符號（`$x`、`$d` 等）會略過，只列出數量；每個符號表最多列出 100,000 個符號。

|`.ipynb`
|Jupyter notebook，逐一儲存格比較：每個儲存格上方有一行標示它是程式碼儲存格、Markdown 儲存格或
原始（raw）儲存格，只比較該儲存格本身的原始內容。儲存格不編號，因此新增一個儲存格不會改變其後
每個儲存格的標示。執行後附加的輸出、執行次數等中繼資料都不會列入，因此未變更內容而重新執行的
notebook 會視為相同。較舊的 nbformat 3 notebook 也能讀取，其標題儲存格會讀成 Markdown 標題。
最多讀取 20,000 個儲存格，文字結尾會說明略過了多少個。無法以這種方式讀取的 notebook（例如已損毀
的檔案）會以其 JSON 文字比較。
|===

以這種方式讀取的檔案為*唯讀*：窗格會標示讀取的內容（例如 `report.docx [文件文字]`），
且無法編輯或覆寫原始檔案。這些文字是對檔案的解讀，而非檔案的複本，
因此版面、字型、公式等格式中的其他內容並不會被比較。

兩個或三個 `.docx` 檔案也可以選擇窗格上方的*格式化*來比較。文件會以 Markdown 逐一區塊並排顯示：
標題、含粗體、斜體與刪除線文字的段落、清單項目、連結與表格；不同的區塊會連同變更的文字一起標示。
表格以表格繪製，合併儲存格會橫跨其涵蓋的列與欄；在合併儲存格內新增的列會在其所在位置標示，
標題儲存格向下延伸到的列也屬於標題。圖片以其描述加上圖片內容的簡短指紋顯示，
因此即使描述相同，圖片變更了也會顯示為差異。*下一個差異*與*上一個差異*會在變更的區塊間移動。
與文字一樣，格式化檢視不包含頁首、頁尾、註腳與註解，追蹤修訂則以接受後的內容顯示。

活頁簿（`.xlsx`、`.xlsm`）無論只有一個或有多個工作表，也都能以*格式化*比較。每個工作表是一個標題加上
一個表格，
工作表依名稱對齊，因此新增或移除的工作表會整個顯示為差異。合併儲存格會橫跨其涵蓋的儲存格繪製。
數字以其數值格式顯示：日期與時間不論格式中的順序，一律以 ISO 形式顯示（`2026-09-30 18:00`），
金額則包含小數位數、千分位、貨幣符號與百分比符號。公式顯示儲存時的結果。
連續三列以上的空白列會顯示為一列並註明列數，因此往下移動一列的值仍會顯示為差異。
工作表上的每張圖片會列在表格之後，附上描述、所在儲存格與圖片內容的指紋，因此圖片變更或移動都會顯示為
差異。
填色、字型、框線、公式本身以及由資料繪製的圖表不會被比較。

加上標籤（tagged）的 PDF 檔案也能以*格式化*比較。多數文書處理程式匯出 PDF 時會加上標籤，
註明哪些文字是標題、段落、清單項目、表格儲存格或圖片，以及哪些儲存格橫跨多列或多欄；
格式化檢視依這些標籤讀取，因此由文件產生的 PDF 讀起來與文件本身大致相同。
以粗體或斜體字型繪製的文字會保留其格式，但整個段落或標題都是同一格式時，視為樣式而不標示。
圖片以其替代文字加上圖片內容的指紋顯示。頁首、頁尾與頁碼在檔案中標為非內容，因此不會顯示。
沒有標籤的 PDF（例如掃描檔，或由不加標籤的程式產生的檔案）會顯示說明；請改以文字比較。

每一側都是 `.docx` 檔案、都是活頁簿（`.xlsx`、`.xlsm`）或都是 `.pdf` 檔案，且由 OxideMerge 自行讀取
時，
窗格上方會出現*文字*／*格式化*切換。`.odt`、`.rtf` 與 `.ods` 檔案不提供此切換。
即使「選項 → 外掛程式」中為這些檔案設定了轉換工具，格式化檢視仍會自行讀取檔案。
區塊是否不同只取決於其文字；比較選項只決定變更區塊中醒目提示哪些字詞。檔案或選項變更時會重新產生檢
視。
顯示格式化檢視時，工具列上的差異計數仍是文字比較的差異數；*下一個差異*與*上一個差異*則在格式化檢視中
變更的區塊間移動。

其他限制與規則：

* PDF 或 RTF 檔案最大 256 MiB，因為這兩種格式需要整份讀取；超過的檔案會明確回報，而不會讀取。
* `.docx`、`.odt`、`.xlsx` 或 `.ods` 檔案中的每個組成部分最大 64 MiB。
  若有組成部分超過此大小或無法讀取，會明確回報，而不會略過該部分繼續比較。
* ELF 檔案沒有大小限制：只會讀取其標頭、區段表與符號表，每一部分最多 64 MiB。由於兩個不同的建置仍可
  能讀出相同的內容，
  以「完整內容」進行資料夾比較時，程式檔會依位元組比較。
* 一個 PDF 檔案解碼後的內容總計最多 1 GiB；需要更多的檔案會明確回報，而不會讀取。
* 每個檔案讀出的文字最多 16 MiB，「文字」與「格式化」模式皆然；其餘部分會略過，並在結尾以一行說明。
* 在「格式化」模式中，一個表格最多顯示 1,048,576 個儲存格與 1,024 欄；超過的列會略過，
  並在結尾以同樣的一行說明。元素超過 300 萬個的部分太大，無法以格式化顯示，會明確回報；
  「文字」模式仍可讀取。
* 若活頁簿所列的工作表在檔案中都找不到，會明確回報，而不會當作空白比較。

「選項 → 外掛」中設定的轉換指令會優先使用，因此隨時可以改用更合適的讀取方式 ——
例如 PDF 使用 `pdftotext`，或以 Pandoc、Tika 處理更多格式。轉換指令的輸出一律以文字比較，試算表也不
例外。
在該處取消「將文件、試算表與 ELF 檔讀取為文字」，則會改以封存檔或位元組的形式比較這些檔案。

NOTE: 目前尚未支援舊版 Word `.doc` 與舊版 Excel `.xls`；請在「選項 → 外掛」中設定轉換指令。
PDF 記錄的是字形的位置而非詞語，因此分欄、表格與連字可能無法完全還原；
版面較複雜的頁面，建議改用 `pdftotext -layout` 之類的轉換指令。

[[archives]]
=== 壓縮檔

OxideMerge 會將壓縮檔解壓縮後，以資料夾的方式比較。支援下列格式：

* ZIP 類格式：`.zip`、`.jar`、`.apk`、`.docx`、`.xlsx`、`.odt`、`.epub`、`.nupkg` 等。
* `.tar`、`.tar.gz` / `.tgz`、`.tar.bz2` / `.tbz2` 與 `.tar.xz` / `.txz`。
* `.7z`。

編輯解壓縮後的檔案並儲存，變更會寫回壓縮檔：複製、刪除、合併或編輯檔案後儲存，
會以新的壓縮檔取代原始檔案，並保留其權限。只有檔案有變更的壓縮檔才會寫入，而您未變更的項目
會完全維持原樣，包括日期、壓縮方式與順序；有變更的項目則使用目前時間。7z 會將項目一起封裝成
壓縮區塊：只含未變更項目的區塊會原樣複製，其他區塊則以 LZMA2 重新壓縮，其中的項目保留日期與
屬性。`.tar.xz` 會以 `xz` 的預設方式重新壓縮。大型的 `.tar.xz` 或 7z 壓縮需要一段時間，因此會在背景
寫入，同時以視窗顯示正在寫入哪個壓縮檔；上傳、關閉分頁與結束程式都會等它完成。若壓縮檔本身在解壓縮後
已在磁碟上被修改，或為唯讀，則會拒絕寫入，以免遺失那些變更。解壓縮後的壓縮檔內不會建立 `.bak`
備份。透過 SFTP 或 FTP 取得的壓縮檔，儲存後會再上傳回伺服器。

位於解壓縮壓縮檔內的壓縮檔也可以編輯：儲存時會一併寫入它所在的壓縮檔，一路寫到最外層；
已開啟的該壓縮檔比較也會重新比較。

下列壓縮檔仍為唯讀，因為沒有可寫回變更的原始檔案，或重新寫入會使其損壞：

* 以檢閱快照開啟的壓縮檔，或從網頁比較出的頁面樹狀結構；
* 已簽署的套件（`.apk`、`.ipa`、`.appx`、`.msix`、`.crx`、`.xpi`，以及含有 `META-INF` 簽章或
  `_xmlsignatures` 資料夾的 zip），因為重新寫入會使簽章失效；
* 位於上述壓縮檔內的壓縮檔。
解壓縮後超過 8 GB 或 500,000 個檔案的壓縮檔不會開啟。
不支援 RAR 格式。

== 比較二進位檔

.二進位比較
image::binary.png[二進位比較]

二進位檔會以並排的十六進位檢視開啟。
不同的位元組會醒目標示，兩側會同步捲動。

* kbd:[Alt+↓] 與 kbd:[Alt+↑] 移到下一個與上一個差異。
* kbd:[Ctrl+F] 尋找十六進位位元組（例如 `DE AD BE EF`）或文字。
* kbd:[Ctrl+G] 跳至指定位移，可寫成 `0x1F00`、`1F00h` 或十進位數字。
* 與文字比較相同，可以將差異複製到另一側並儲存。

若要變更每行顯示的位元組數，請使用「選項 → 影像 / 二進位」中的「每行位元組數（二進位）」。

=== 移動區塊

二進位工具列的「移動區塊」會在十六進位欄、文字欄與位置窗格中標示位於不同位移的相同區塊。
選取已標示的位元組後，按「前往相符區塊」可跳到另一側的對應位置，並保留在區塊內的相對位移。
也可以按 Tab 將焦點移到按鈕，再按 Enter。跳轉後焦點會回到位元組格，便於繼續使用方向鍵。
支援雙向與三向比較；三向比較會前往按鈕旁顯示的第一個相符側。取消勾選後僅顯示一般差異。
OxideMerge 會記住這個勾選狀態，下次開啟二進位比較時沿用。

偵測可找到兩種相同的位元組：

* _因插入或刪除而位移的資料_：位於編輯處附近、往前或往後移動最多 128 個位元組的資料，
  包括兩處編輯之間較短的資料段。
* _移到較遠處或交換順序的區塊_：至少 16 個位元組、且只在檔案中出現一次的資料。
  重複出現的資料（例如整段填充位元組）不會以這種方式配對。

標示只是額外資訊：差異範圍、複製差異、檔案內容與儲存的位元組都不會因此改變。

偵測在背景執行：開啟比較時執行一次，編輯、復原、重做或複製差異後，等輸入停止片刻再執行。
編輯或關閉比較會立即停止進行中的偵測，因此不會拖慢編輯，也不會額外占用記憶體。
大型檔案會取樣偵測，因此可能略過部分較短的相符區塊；每對檔案最多標示 1,024 個區塊。

=== 編輯位元組

. 在要修改的一側按一下位元組。
  按一下十六進位欄可輸入十六進位數字，按一下右側的文字欄則可輸入字元。
. 輸入新的值。
  在十六進位欄中，兩個數字構成一個位元組：第一個數字修改位元組的前半，第二個數字修改後半。
  在文字欄中，每個字元會取代一個位元組，且只能輸入 ASCII 字元。
. 按 kbd:[Ctrl+S] 儲存。

預設情況下，輸入的內容會取代游標處的位元組。若要改為插入位元組，請按 kbd:[Insert]，
或按一下工具列上的「插入」。在最後一個位元組之後輸入時，一律會新增位元組。

* 方向鍵、kbd:[PgUp]、kbd:[PgDn]、kbd:[Home] 與 kbd:[End] 可移動游標。
  kbd:[Ctrl+Home] 與 kbd:[Ctrl+End] 會移到檔案的開頭與結尾。
* kbd:[Delete] 刪除游標處的位元組，kbd:[Backspace] 刪除游標前的位元組。
* 在十六進位欄中貼上（kbd:[Ctrl+V]）會寫入 `DE AD BE EF` 這類十六進位位元組，其他文字則無法貼上。
  在文字欄中，文字會依原樣寫入。
* kbd:[Ctrl+Z] 可復原上次移動游標後輸入的內容，或一次貼上。

唯讀的一側無法修改。若要變更，請按一下該側上方的鎖頭圖示。

== 比較網頁

您可以比較兩個或三個網址（`http://` 或 `https://`），或本機的 HTML 檔案。
本機 `.html` 與 `.htm` 檔案預設就會以網頁比較開啟。
若要將其他類型的檔案當作網頁比較，請選擇「比較方式 → 網頁」，或在命令列使用 `-t web`。

=== 比較模式

請在分頁上方的模式選擇器中選擇模式；OxideMerge 會記住您上次使用的模式。

[cols="1,3"]
|===
|模式 |比較的內容

|文字
|每個網頁的文字，以文字比較開啟。
每個標題、段落與清單項目各占一行；表格的每一列占一行，儲存格之間以定位字元分隔。
隱藏的元素不列入比較。
變更的字詞會醒目標示，比較選項、篩選器與報告也都適用。

|格式化
|預設模式。將每個網頁轉換成 Markdown，並排顯示格式化的結果。
請參閱 <<web-formatted>>。

|HTML 原始碼
|每個網頁的 HTML，以文字比較開啟。
經過壓縮的長行會在標籤之間斷開。

|資源樹
|下載每個網頁及其樣式表、指令碼、影像、框架與媒體，再以資料夾比較來比較這些下載的檔案。
|===

切換到其他模式時，會重新載入網頁。
網頁有變更後，請按「重新載入網頁」（kbd:[F5]）。

若要逐行比較本機檔案的 HTML 原始碼，請使用 HTML 原始碼模式，或選擇「比較方式 → 文字」（`-t text`）。

[[web-formatted]]
=== 格式化模式

格式化模式會保留標題、段落、強調、連結、清單、引言、程式碼區塊與表格的樣式；影像則以連結顯示。

.以格式化模式比較兩個網頁
image::web.png[格式化模式的網頁比較]

OxideMerge 以區塊為單位比較網頁。
區塊是指一個標題、段落、清單項目、表格、引言或程式碼區塊。

* 不同的區塊會醒目標示，並與其他網頁上同類型的變更區塊對齊。
* 只在一個網頁出現的區塊，對面會留白。
* 在變更的區塊中，變更的字詞或字元會以較深的顏色標示；與文字比較相同，由「行內差異」選項控制。
* 表格會以框線畫出儲存格，各列也會對齊。
  不同的列中會醒目標示變更的字詞；另一個網頁缺少的列或欄，整個儲存格都會醒目標示。
* 橫跨多列或多欄的儲存格（`rowspan`、`colspan`）會畫過其涵蓋的儲存格，因此同列的其他儲存格仍留在各自
  的欄中。
* 每個變更的區塊各算一個差異，即使緊接在另一個變更的區塊之後也一樣。

若要在差異之間移動，請使用網頁上方的按鈕，或與文字比較相同的按鍵。

* 目前的差異會以較深的顏色標示，正在比較的區塊在每個網頁上都會加上外框；
  您最後點選的網頁，外框最明顯。
* 按一下某個區塊，即可將它設為目前的區塊，之後的下一個與上一個差異就從該處找起。
* 只有在差異不在畫面中時，網頁才會捲動，並將差異顯示在距離頂端約三分之一的位置。

網頁右側的位置窗格會顯示所有差異：目前的差異以強調色顯示，網頁目前可見的部分會加上外框。
在位置窗格中按一下或拖曳，即可前往該處。
若要顯示或隱藏位置窗格，請選擇「檢視 → 文字比較 → 位置窗格」。

=== 網頁的載入方式

所有模式都直接使用伺服器傳回或檔案中儲存的原始 HTML。
OxideMerge 不會在瀏覽器中開啟網頁，因此開啟得很快。
網頁的指令碼不會執行，指令碼加入的內容也不會出現。

文字與格式化模式會略過網頁隱藏的內容：帶有 `hidden`、`aria-hidden="true"` 屬性，
或以行內 `display: none`、`visibility: hidden` 樣式隱藏的元素。
只由樣式表隱藏的內容仍會比較。

OxideMerge 解碼網頁的方式與瀏覽器相同，依序採用第一個找到的資訊：
位元組順序標記、HTTP `Content-Type` 標頭中的字元集、`<meta>` 中的字元集，最後才依內容推測。

* 伺服器傳回非 2xx 的狀態碼時，窗格標題列會顯示該狀態碼，並比較隨之傳回的網頁。
* 網頁無法連線、超過 30 秒未回應、回應格式不正確或大於 50 MB 時，OxideMerge 會連同網址一併回報。

=== 資源樹的限制

資源樹模式只下載每個網頁本身列出的資源，不會再追蹤樣式表或指令碼中的連結。

* 每個網頁最多 400 個資源，每個資源最大 20 MB。
* 無法下載的資源會在狀態列中計數，其餘資源仍會照常比較。
* 為了安全起見，網頁不得載入本機檔案。
  只有位於本機或私人網路（例如 `localhost` 或 `192.168.x.x`）的網頁，才能從這類位址載入資源或被重新
  導向到這類位址；
  其他這類資源會被略過，並在狀態列中計數。
* 您自行輸入的網址一律會載入。

=== 在主控台比較網頁

主控台比較（以 `--cli` 比較 HTML 檔案，或指定 `-t web` 時）會沿用您在視窗中最後選擇的模式：

* 格式化模式（預設）逐行比較網頁的 Markdown。
* HTML 原始碼模式比較 HTML。
* 其他模式比較可見文字。

NOTE: 所有模式都不會執行網頁的指令碼。
不支援登入，因此需要登入的網頁可能只顯示登入畫面。
所有模式都不會將變更存回網頁伺服器。

[[differences-shown]]
== 控制要顯示的差異

有三類設定會決定 OxideMerge 將哪些內容顯示為差異：

* 篩選器：選擇資料夾比較要包含哪些檔案與資料夾。
* 比較選項：決定哪些文字變更要計入，例如空白字元或大小寫。
* 比較規則：忽略或取代符合樣式的文字。

這些設定只會改變比較結果，絕不會修改檔案。

TIP: 若預期中的變更沒有顯示，請先檢查這些設定，再判斷檔案是否相同。

=== 比較選項

「比較 → 比較選項」提供最常用的選項，「選項 → 比較」則包含全部選項：

空白字元::
「比較」：空白字元列入比較。
「忽略變更」：空白字元的數量不同時不算差異。
「全部忽略」：完全忽略空白字元。
忽略空白行:: 多出來的空白行不算差異。
忽略大小寫:: 大寫與小寫字母視為相同。
忽略換行字元差異（Windows/Unix/Mac）:: `CRLF`、`LF` 與 `CR` 三種換行字元視為相同。
忽略數字:: 忽略所有數字。
忽略字碼頁差異:: 編碼不同但文字相同的檔案視為相同。
忽略註解變更:: 只有註解的變更不算差異。
適用於已知註解語法的語言：C 類語言、指令碼語言、SQL、HTML、XML、CSS、Lua、Haskell 等。
比較前格式化 JSON 與 XML:: 重新縮排 JSON 與 XML，並排序 JSON 的鍵，避免排版變更被當成差異。
格式化後的檢視為唯讀；若要編輯或合併，請關閉此選項。
偵測移動的行:: 被搬移的整段行會標示為移動。
差異演算法:: 「Myers」、「Patience」或「LCS」。
行內差異:: 行內變更的標示方式：「關閉」、「單字層級」或「字元層級」。
數字差距在此範圍內視為相同:: 差距不超過此值（例如 `0.001`）的數字視為相同，適合比較量測值或自動產生
的資料。

在資料夾比較中，只有比較方法為「完整內容」時，這些選項才會套用到文字檔；其他方法不使用這些選項。

[[compare-rules]]
=== 比較規則

比較規則檔（`.oxrules`）包含三類規則：

忽略符合的行:: 每行一個規則運算式。
只由符合的行組成的差異會被忽略。
取代規則:: 每行一條規則，寫成 `+規則運算式 => 取代文字+`。
OxideMerge 會在比較前將取代規則依序套用到兩側，每條規則套用到前面的規則處理後的文字；行內有變更的
字詞也以同樣方式標示。適合處理預期中就會不同的文字。
忽略起始行與結束行之間的區塊:: 每行一個區塊，寫成 `+起始規則運算式 => 結束規則運算式+`。
區塊內的差異會被忽略，適合處理自動產生的段落或授權聲明。

規則運算式採用 Rust `regex` 套件的語法。

==== 管理規則檔

.選項 → 比較規則
image::rules.png[比較規則選項]

在「選項 → 比較規則」中管理規則檔：

* 選擇「無」或某個規則檔。
  沒有另外指定規則檔的比較，會預設使用這個檔案。
* 「新增規則檔」建立新檔案，「編輯」以規則編輯器開啟檔案，「刪除」移除檔案。
* 「開啟規則資料夾」在檔案管理員中顯示該資料夾；在其中變更檔案後，請按「重新載入」。
* 「匯入...」加入其他人分享的規則檔；
  「匯出」可匯出單一檔案，或以「所有規則檔到資料夾...」將全部檔案匯出到資料夾。

資料夾比較可以使用不同的規則檔，請從工具列的「規則」或「比較 → 比較規則」中選擇。
「重新整理」（kbd:[F5]）會重新讀取規則檔。

也可以用拖放的方式匯入規則檔：

* 將一個 `.oxrules` 檔案拖放到視窗上即可匯入；拖放兩個時，OxideMerge 會改為比較它們。
* 將任意數量的 `.oxrules` 檔案拖放到選項對話框上，即可一次匯入。

匯入規則檔時：

* 已有名稱與規則都相同的檔案時，略過新檔案。
* 已有名稱相同但規則不同的檔案時，新檔案的名稱會加上編號。
* 已有規則相同但名稱不同的檔案時，新檔案以自己的名稱加入。

==== 規則檔格式

規則檔存放在設定檔旁的 `Rules` 資料夾中（請參閱 <<configuration>>）。
OxideMerge 也會讀取程式旁的 `Rules` 資料夾。

規則檔是 JSON 檔案，規則的名稱就是去掉 `.oxrules` 的檔名：

.Build logs.oxrules
[source,json]
----
{
  "description": "忽略建置紀錄中的時間戳記與自動產生的標頭",
  "ignore_lines": ["^\\[\\d{2}:\\d{2}:\\d{2}\\]", "^// Generated on .*$"],
  "substitutions": [{ "find": "\\b0x[0-9a-fA-F]{8,}\\b", "replace": "0xADDR" }],
  "ignore_blocks": [{ "start": "^/\\* BEGIN LICENSE", "end": "END LICENSE \\*/$" }]
}
----

=== 從文字比較建立規則

. 在文字比較中的某一行上按右鍵，選擇「新增比較規則」。
. 選擇規則的類型：
+
--
忽略類似的行:: 符合該行（或變更行的每一側）的樣式。
取代:: 將一側文字轉換成另一側文字的取代規則。
忽略區塊:: 從該行開始的區塊。
--
. 檢查 OxideMerge 建議的樣式，視需要修改。
. 選擇要加入的「規則檔」，或輸入「檔案名稱」建立新檔案。

目前的比較會立即套用新規則；
其他使用相同規則檔的資料夾比較，會在重新整理（kbd:[F5]）後套用。

[[filters]]
=== 篩選器

篩選器決定資料夾比較要包含哪些檔案與資料夾。
請從資料夾比較工具列的「篩選器」中選擇；若要管理篩選器，請選擇「工具 → 篩選器...」。

篩選遮罩是以 `;` 分隔的萬用字元清單：

* 開頭加上 `!` 表示排除符合的項目。
* 結尾加上 `\` 或 `/` 表示符合資料夾。

例如，下列遮罩會包含 Rust 與 TOML 檔案，並排除 `target` 資料夾：

----
*.rs;*.toml;!target\
----

OxideMerge 也會列出 WinMerge 的 `.flt` 篩選器檔案，
來源為設定資料夾中的 `Filters` 資料夾，以及程式旁的 `Filters` 資料夾。
「工具 → 篩選器...」會列出這些篩選器，並可開啟篩選器資料夾及新增篩選器。

[[unpackers]]
=== 解譯器外掛程式

OxideMerge 本身即可讀取 PDF、`.docx`、`.odt`、`.rtf`、`.xlsx`、`.ods`、`.ipynb` 與 ELF 程式
（請參閱 <<documents>>），因此只有在遇到它尚未支援的格式（例如舊版 Word `.doc` 與 Excel `.xls`），
或想以更好的方式讀取上述格式時，才需要外掛程式。只要外掛程式的檔案樣式符合，就一律優先使用。

解譯器外掛程式會在比較前將檔案轉換為文字，
適合 PDF 或 Office 文件等需要外部轉換程式的格式。
OxideMerge 會比較轉換程式寫到標準輸出的文字。

新增外掛程式的步驟：

. 安裝轉換程式，並確認命令找得到它。
. 在「選項 → 外掛程式」中新增項目，填入「檔案樣式」（例如 `*.docx`）與「命令列」。
  命令列中的 `${file}` 會替換為已加上引號的檔案路徑。
. 啟用該項目。

預設按鈕可新增 PDF 文字（`pdftotext`）、Office 與 OpenDocument 文件（`pandoc`），以及一般文件擷取
（`tika`）的項目；
這些項目新增後預設為停用。
將指標移到項目的核取方塊上，可查看它需要哪個程式。
這項檢查只看命令中的第一個程式名稱；若命令實際執行失敗，OxideMerge 會顯示轉換程式的輸出訊息。

以已安裝的 Pandoc 為例：

----
pandoc -t plain ${file}
----

凡是以文字比較檔案的地方都會使用轉換程式：單一檔案、以「完整內容」比較的資料夾、命令列、檔案比較窗
格、「所有差異」，以及資料夾報告中的差異。
資料夾比較的大小、日期、快速內容與二進位方法，仍然比較原始檔案。

其他限制與規則：

* 擷取出的文字為唯讀，絕不會覆寫原始文件。
* 每次轉換最多執行 30 秒，每個輸出串流最多 16 MiB。
* 轉換程式以非零的結束代碼結束時，即使已輸出部分文字，仍視為錯誤。
* 停止資料夾掃描時，進行中的轉換也會一併停止。

分享前，請先確認其中沒有機密內容。

[[projects]]
=== 專案

「檔案 → 另存為專案...」會將目前分頁所比較的內容存成 `.oxmproj` 檔案。專案會儲存：

* 路徑、說明文字與唯讀的側；
* 比較類型、篩選器、「包含子資料夾」與比較方法；
* 比較規則檔。

「檔案 → 開啟專案...」可再次開啟專案；OxideMerge 也能開啟 WinMerge 的專案檔（`.WinMerge`）。

路徑會以相對於專案檔的方式儲存，因此專案可以和檔案一起搬移。
位於不同 Windows 磁碟機的路徑會保留為絕對路徑，網址也不會變更。

專案不包含檔案本身；開啟專案時，OxideMerge 會載入這些路徑目前的檔案。
將專案搬到其他電腦時，請一併複製其中的檔案，以及專案使用的外部規則檔。
若要分享目前的文字與檢閱註記，請改為儲存比較。

[[workspaces]]
=== 工作區

「檔案 → 工作區 → 另存為工作區...」會將所有擁有自己檔案的文字、二進位、影像、網頁與資料夾比較
分頁，以您指定的名稱（最多 80 個字元）儲存。名稱以及各分頁的路徑與設定都儲存在您的設定中，而非
另外存成檔案。沒有可重新開啟之自身內容的分頁不會列入，這與 OxideMerge 自動重新開啟的工作階段省略
它們的方式相同：「所有差異」與審閱分頁、剪貼簿，以及暫存副本的分頁，例如透過 SFTP 或 FTP 取得的
檔案或資料夾（請參閱 <<remote-sftp>>）、修訂版本，或從壓縮檔比較中開啟的檔案。儲存後的訊息會說明儲存了
多少個分頁、略過了多少個。若目前開啟的分頁都無法儲存，對話框會說明，且不會儲存任何內容。

名稱不分大小寫。以既有工作區的名稱儲存時，對話框會先說明，並在您按一下「取代」後才取代其分頁。

接著，「檔案 → 工作區」會列出已儲存的工作區（前 15 個；「管理工作區...」會列出全部）：選擇其中
之一，即可一次重新開啟它的所有分頁，與目前已開啟的分頁並存。檔案已不存在的分頁不會重新開啟，
訊息會說明有多少個無法開啟。「管理工作區...」會列出已儲存的工作區，供您開啟或刪除；刪除的工作區
可在隨後訊息中按「復原」找回。

工作區與 OxideMerge 啟動時自動重新開啟的那一個未命名工作階段不同：該工作階段會自動保留並
取代，而工作區只會依您指定的名稱保留與重新開啟。同時執行兩個 OxideMerge 視窗時，在其中一個儲存
或刪除的工作區，會在另一個儲存設定時保留下來。

[[saved-comparisons]]
=== 已儲存的比較

「檔案 → 儲存比較...」會將文字比較存成 `.oxmcmp` 檔案，
內容包括各側的文字、書籤與註解，以及同步點。

您可以日後再開啟，或傳送給其他檢閱者。
檔案會以唯讀方式開啟，不需要原始檔案。
它是文字當時的快照：與專案不同，不會依路徑載入目前的檔案。

[[folder-reviews]]
=== 資料夾審閱

資料夾比較完成後，「檔案 → 儲存比較...」會存成 `.oxmreview` 檔案。
這是一個可攜式的封裝檔，包含篩選器納入的所有項目。

* 若只要儲存部分項目，請選取檔案或資料夾，按右鍵並選擇「儲存所選資料夾審閱…」。
  選取的資料夾會包含其中已掃描的所有內容。
* 「顯示」設定與篩選標籤只會改變畫面上看到的項目，不會從完整的封裝檔中移除項目。
* 請先完成所有檔案操作；若檔案有變更，請重新整理比較後再儲存。

若要加上註記，請在檔案或資料夾上按右鍵，選擇「切換書籤」或「書籤註解」。
加上書籤的項目，名稱前會顯示 `*`；將指標移到項目上會顯示註解。
這些註記會存入封裝檔，也會出現在 HTML、XML 與純文字的資料夾報告中，但不會納入 CSV 摘要。
若在已開啟的封裝檔中修改註記，請再次儲存比較以保留變更。

開啟封裝檔的方式：

* 命令列：`oxidemerge review.oxmreview`；
* 將檔案拖放到視窗上；
* 「檔案 → 開啟專案...」。

封裝檔會以唯讀快照開啟，並沿用當時的比較選項。
它不需要原始檔案、具名篩選器或外部規則檔。
經轉換的文件會以擷取出的文字儲存，轉換命令則不會儲存，因此檢閱者不必安裝轉換程式。
在樹狀檢視中展開資料夾，即可查看其中的內容。

限制：

* 支援兩側或三側，最多 10,000 個項目與 256 MiB 未壓縮內容。
* 不接受符號連結、特殊檔案、在其他系統上不安全的路徑，以及比較後已變更的檔案。
* 封裝檔包含每個檔案的完整內容，二進位檔也不例外。

審閱工作區可在資料夾審閱中加入審閱決定，請參閱 <<review-workspace>>。

[[html-reports]]
=== HTML 報告

建立 HTML 報告的步驟：

. 開啟文字或資料夾比較，並等待比較完成。
. 檢查比較選項、比較規則與資料夾篩選器，這些設定會影響報告中的差異。
. 按工具列上的「匯出 HTML」，或選擇「檔案 → 匯出 → HTML 報告...」（kbd:[Ctrl+Shift+E]）。
. 選擇輸出檔案。建議的檔名由比較項目的名稱組成，空格會換成 `_`。
. OxideMerge 會在瀏覽器中開啟報告。分享前請先確認內容。

報告是單一的 HTML 檔案，內含顯示所需的一切資源；
收件者可以用任何瀏覽器開啟，不需要安裝 OxideMerge。

* 每個差異以一張卡片呈現，附有行號、前後三行內容，並醒目標示變更的字詞。
* 報告包含摘要卡片、索引、並排或統一檢視、淺色與深色主題、檔案篩選與搜尋。
* kbd:[N] 與 kbd:[P] 移到下一個與上一個差異，該差異會短暫閃動。
* 頁首帶有 OxideMerge 圖示，頁面開啟時會有動畫：各區塊淡入，摘要卡片中的數字逐步遞增。
  瀏覽器設定為減少動態效果時會顯示靜態頁面，列印時也是如此。
* 報告會列出使用的比較規則檔，並統計被忽略的差異數量。
* 資料夾報告會包含每個已變更文字檔的差異。

若只想儲存報告而不開啟，請關閉「檔案 → 匯出 → 儲存後在瀏覽器開啟報告」。

匯出報告絕不會將您的編輯存回比較的檔案。

[[other-reports]]
=== 其他報告

「檔案 → 匯出 → HTML 報告...」也能儲存其他格式：請在儲存對話方塊中選擇檔案類型。

* 資料夾比較：HTML（含每個已變更文字檔的差異）、CSV、純文字或 XML。CSV 與純文字會列出檔案及其狀態、
  大小與日期。
* 文字比較：HTML 或 XML。

「工具 → 統計資料...」會顯示目前比較的統計數字：

* 資料夾比較：相同、不同與僅一側的檔案數量、錯誤數，以及各側的總大小；
* 文字比較：每一對窗格之間相同、變更、新增、刪除與忽略的行數。

==== XML 報告

XML 報告是給其他程式讀取的，例如指令碼、審閱工具，或檢查變更內容的建置流程。
在「檔案 → 匯出 → HTML 報告...」的儲存對話方塊中選擇 XML 類型，或在命令列使用 `--report <名稱>.xml`。

* 文字比較報告會列出每個差異的種類、是否被忽略，以及各側的行與行號；最後列出書籤及其註解。
* 差異種類包括 `changed`、`added` 與 `removed`；
  三方比較另有 `left-only`、`right-only`、`both-same`、`compatible` 與 `conflict`。
* 資料夾報告會列出每個檔案與資料夾的狀態，以及在各側的日期與大小。

[source,xml]
----
<comparison format="1" tool="OxideMerge" version="0.9.8" type="text" created="…">
  <side index="0" role="left" name="a.txt"/>
  <side index="1" role="right" name="b.txt"/>
  <statistics differences="1" ignored="0" identical-lines="1" changed-lines="1" added-lines="0" removed-lines="0"/>
  <differences>
    <difference index="1" kind="changed" ignored="false">
      <lines side="0" start="2" count="1"><line number="2">two</line></lines>
      <lines side="1" start="2" count="1"><line number="2">TWO</line></lines>
    </difference>
  </differences>
</comparison>
----

* 行號從 1 開始。
* 某一側在差異中沒有任何行時，`count` 為 `0`，`start` 表示文字應插入在第幾行之前。
* 只有在格式的變更可能影響讀取程式時，`format` 的值才會改變。

[[slideshows]]
=== 投影片

「檔案 → 匯出 → 投影片報告...」會儲存一個一次顯示一個差異的 HTML 網頁，
適合在會議或審閱時逐一說明變更。

* 標題投影片列出比較的各側與差異數量。
* 接著每個差異各有一張投影片，顯示差異的行、前後幾行、變更的字詞，以及書籤註解。
* 資料夾比較會為每個已變更文字檔的每個差異各建立一張投影片；
  最後一張列出以其他方式不同的檔案，例如二進位檔或只在一側的檔案。
* 被忽略的差異不會列出。

在瀏覽器中：

* kbd:[→]、kbd:[←]、kbd:[Space]、kbd:[PgUp] 與 kbd:[PgDn] 切換投影片。
* kbd:[Home] 與 kbd:[End] 跳到第一張與最後一張。
* kbd:[F] 切換全螢幕。
* 每張投影片都有自己的網址（例如第三張為 `#3`），可以直接連結。
* 列印時，每張投影片各印成一頁。
* 頁首帶有 OxideMerge 圖示，可連到專案網頁；最後一張投影片也有此連結。

[[pdf-reports]]
=== PDF 報告與列印

*檔案 → 匯出 → PDF 報告...* 會將文字或資料夾比較的報告儲存為 PDF 檔案。
*檔案 → 列印...*（kbd:[Ctrl+P]）會把同樣的 PDF 寫入只有你能讀取的暫存檔，並以系統的 PDF 檢視器開啟，
再從檢視器列印。暫存檔會在 OxideMerge 關閉時刪除。整個過程不使用瀏覽器。

PDF 報告的內容與 HTML 報告相同：

* 比較的檔案、比較規則檔、差異數與新增、刪除、變更的行數，以及書籤註解。
* 每個差異及其前後三行、行號與標記的變更字詞，以並排方式顯示。開啟行內檢視時，
  雙向比較的報告改為單欄，刪除的行在新增的行上方，並使用直式頁面。
* 資料夾比較會列出檔案及其狀態、大小與日期，接著是每個已變更文字檔的差異、審閱附註與審閱摘要。
* 以鍵比對的表格會附上鍵比對的結果。

每頁的頁首有 OxideMerge 圖示與報告標題，頁尾有「第 n 頁，共 m 頁」與 *OxideMerge*，
後者連結到專案網頁（https://github.com/kuopinghsu/OxideMerge）。PDF 也為每個檔案與每個差異建立書籤。
OxideMerge 使用的字型會內嵌在檔案中，而且只包含報告需要的字元，
因此中文、日文與韓文會依照畫面上的樣子列印。每一欄都標示其所屬的一側；差異延續到下一頁時，
也會標示其檔案。資料夾報告的檔案清單表頭會在每一頁重複。

一份報告最多繪製 20,000 行比較文字（約 400 頁），所有檔案合計；折行的長行占幾行就計算幾次。
除非顯示整個檔案，每個差異最多顯示 400 列。差異被截斷時，變更上方最多保留 100 行未變更的內容，
因此一定會顯示變更本身，並以「…還有 1,200 行」之類的文字說明省略的部分。超過上限之後的差異只會計數。

每行由左至右閱讀，其中的希伯來文與阿拉伯文則由右至左，文中的數字與括號維持在正確位置（日期、電話號碼、
百分比與價格保持完整），阿拉伯與波斯字母也會連寫。
這比瀏覽器的排版簡單，因此以特殊方式混合兩種方向的行可能與瀏覽器顯示不同。程式字型不會把 `!=`
或 `->` 合成一個符號。希伯來文、阿拉伯文與泰文會使用已安裝、且授權允許嵌入子集的字型列印，例如
SF Hebrew、Geeza Pro、Tahoma、Segoe UI 或 Noto。所有字型都沒有的字元會印成 `?`；報告結尾（以及命令列
的標準錯誤輸出）
會附註以碼位列出這些字元。

顏色從不是唯一的提示，因此以黑白列印的報告仍能看出變更：

* 每個變更的行開頭都有符號：`-` 刪除、`+` 新增、`~` 變更、`!` 衝突、`=` 忽略。
* 變更的字詞除了醒目標示，也會加上底線。
* 某一側缺少的行，其位置以斜線網底表示。
* 在「選項 → 一般」中開啟「色盲友善的差異顏色」時，以藍色與橘色取代綠色與紅色，變更為紫色，衝突為黃
  色。

頁面為 A4 橫式。選取 *檔案 → 匯出 → PDF 報告使用 US Letter 紙張* 可改用 Letter 紙張。
在命令列中，可用 `--page-size`、`--portrait`、`--unified`、`--whole-file` 與 `--context` 設定版面
（請參閱 <<command-line>>）：

[source,sh]
----
oxidemerge old.c new.c --report changes.pdf
oxidemerge -r old new --report review.pdf --report-diffs --page-size letter
oxidemerge old.c new.c --report full.pdf --whole-file --unified --portrait
----

[[patches]]
=== 修補檔

「檔案 → 匯出 → 產生修補檔...」會將兩個檔案或資料夾之間的差異寫成修補檔。
您可以選擇格式（「一般」、「上下文」或「統一」）與前後文的行數。

* 只能從雙向比較產生修補檔。
* 匯出哪些差異，仍由目前的忽略選項決定。
* 支援 UTF-8 檔案（不論有無位元組順序標記）、LF、CRLF 或混合的換行字元，以及結尾沒有換行字元的檔案。
* 其他編碼或只使用 CR 換行的檔案，必須先轉換。
  遇到這類檔案時，OxideMerge 會顯示錯誤，而不會產生無法正確還原變更的修補檔。

「檔案 → 套用修補檔...」可套用統一格式的差異，包括 `git diff` 與 `svn diff` 的輸出。

* 即使行的位置已經移動，OxideMerge 仍能找到每個修補區塊。修補區塊是修補檔中的一組變更。
* 每個修補後的檔案會與原始檔案並排開啟，方便您檢查後再儲存。
* 無法套用的修補區塊會列在訊息中。
  儲存前請先閱讀這些訊息並檢查比較結果；套用修補檔不會自動儲存任何結果。

[[analysis]]

=== 合併驗證

==== 文字檔

在三方文字比較中，開啟「合併驗證」分頁。

.執行「預覽合併」後的合併驗證
image::verify.png[合併驗證]

* 「預覽合併」會以「唯讀預覽」顯示合併的結果，不會變更中間窗格。
  預覽中的衝突處保留基底的文字，必須由您自行解決。
* 「驗證已儲存的結果」會重新讀取已儲存的結果檔，
  並將其位元組、編碼、位元組順序標記、換行字元與檔案結尾換行與預覽比較。
* 編輯文字後，畫面上顯示的驗證狀態就不再有效。

對於沒有衝突、但值得仔細檢查的合併，預覽也會提出警告：

* 兩側編輯的行相距不超過兩行；
* 兩側在不同位置變更了同一個設定，例如 `name = value`、`name: value` 或 `"name": value`。

警告不會讓檢查判定為失敗。

IMPORTANT: 這些檢查只比較文字與位元組，無法證明合併結果正確無誤。

==== 資料夾

`--merge-plan` 會列出資料夾合併的各項操作與衝突，但不會實際執行。

`--validate-merge` 會依計畫檢查合併結果：
檢查計畫中的複製、合併與刪除，以及應維持不變的檔案，並再次確認來源檔案沒有變更。
結果可以放在另一個資料夾中：

[source,sh]
----
oxidemerge --validate-merge result-folder left-folder base-folder right-folder
----

建議的順序：先預覽合併，再執行合併，最後依計畫驗證結果。

[[semantic]]
=== 語意比較

比較 JSON、XML、TOML 與 YAML 檔案時，可選擇「語意」，依資料結構而非逐行比較。
比較本身絕不會寫入檔案；只有下文所述的複製按鈕會修改窗格。
若 OxideMerge 無法讀取檔案，檢視會說明原因，按一下即可返回文字檢視。

.兩個 JSON 檔案的語意比較
image::semantic.png[語意比較]

==== 哪些變更會計入

JSON::
* 物件鍵的順序不計。
* 陣列元素的順序要計。
* 缺少的值與 `null` 視為不同。
* 重複的鍵視為錯誤。
XML::
* 屬性的順序不計。
* 名稱連同完整的命名空間一起比較。
* 子元素的順序、文字中的空白、混合內容與註解都要計。
* 不支援 DTD、宣告或未知的實體，以及 XML 1.1；支援內建的字元參照。
TOML 與 YAML::
* 比較方式與 JSON 相同：表格與對應的順序不計。
* 數字依數值比較，整數與小數之間也是如此。
  例如 `1` 等於 `1.0`，TOML 中的 `8_080` 等於 `8080`。
* 註解與排版不計。
* TOML 中含時區的日期時間，依所代表的時刻比較。
  例如 `10:00+02:00` 等於 `08:00Z`。
* YAML 採用 YAML 1.2 核心結構描述，因此 `yes` 與 `on` 都是文字，`0777` 是數字 777，而不是 YAML 1.1
  所讀的八進位數字。
  鍵也依值比較，因此 `0x10:` 與 `16:` 是同一個鍵。

限制：

* TOML 或 YAML 檔案最大 4 MiB。
* YAML 檔案只能包含一份文件，且不得使用別名、複合鍵或自訂標籤；
  `!!int` 這類核心標籤必須與其值相符。

文字比較的比較規則，不會當作語意檢視的篩選條件。

==== 解讀結果

變更會依路徑以樹狀顯示，每個分支會標出其中包含的變更數量。
按變更的來源按鈕，即可跳到檔案中對應的行。

陣列需要特別注意：

* 陣列以新的順序保有相同的元素時，被移動的元素會列為「移動」，並註明原本的位置。
* 若要依某個成員而非位置來配對陣列中的物件，請在「陣列配對鍵」中輸入成員名稱，例如 `id`（適用於
  JSON、TOML 與 YAML）。
  這樣一來，插入或重新排序會顯示為新增與移動的元素，而不是之後每個位置都有變更。
* 若無法以該鍵配對某個陣列（某個元素沒有可唯一識別的簡單值），變更清單上方會說明原因，該陣列則改依位
  置比較。

若陣列元素不是單純依路徑配對，每項變更都會註明配對方式：
依陣列配對鍵、依完全相同的重新排序，或在長度不同的陣列中依位置配對。

若另一種解讀也同樣說得通，該變更會標示為「有歧義」，請自行確認。例如：

* 兩個元素互換位置時，任一個都可能是被移動的元素。
* 被移動的元素有重複。
* 插入元素讓後面的元素錯位，而該變更是依位置找到的。

報告會記錄每項變更的 `confidence`（`parser_exact`、`array_key`、`reordered` 或 `position`）、
有標示時的 `ambiguous`，以及 `notes`。

==== 複製值

每項變更都有「將值複製到左側」與「將值複製到右側」按鈕（唯讀的窗格除外）。
複製會取代另一側的值、將值加到它應在的位置，或在來源側沒有該值時將其移除。

* 只會修改寫有該值的文字，註解、排版與檔案的其餘部分都保持原樣。
* 保留複製結果前，會重新讀取編輯後的檔案。若結果與預期的結構不完全相同，就不做任何變更，並在檢視中說
  明原因。
  這類值請在文字檢視中編輯。
* 移動不會被複製，因為移動會改變整個陣列的順序。
* 每次複製都是「復原」的一個步驟。檔案只有在您儲存時才會寫入。

[[tree]]
==== 樹狀檢視

比較兩個 JSON、YAML、TOML 或 XML 檔案時，選擇「樹狀」會將兩份文件顯示為一棵對齊的樹。節點與其對應節
點位於同一列：
左側檔案在左、右側檔案在右，兩側一起捲動。只存在於一側的節點，另一側會顯示空白的占位列。
此檢視只讀取檔案。

image::xml-tree.png[樹狀檢視]

兩側之間的欄位以符號標示每一列，不只靠顏色：`+` 新增、`−` 移除、`~` 修改、`↕` 移動、
`•` 內含變更、`?` 不明確。收合且內含變更的節點會顯示數量，例如「3 項變更」。每一列顯示的內容依格式而
定：

* 「JSON、YAML 與 TOML」：索引鍵與其值，例如 `port: 8080`；物件或陣列及其成員數，例如 `env {2}` 或
  `ports [2]`；
  陣列元素則依其位置顯示，並附上 `id`、`name` 或 `key` 成員，例如 `[0] id="report"`。
* 「XML」：元素會顯示原始寫法的名稱，並以簡短標籤顯示 `id`、`name`、`key`、`ref` 屬性及有變更的屬性。
  展開元素即可看到其屬性、文字、註解與處理指令。

列會在已配對的父節點之下配對，因此節點不會顯示在其他父節點之下：

* 物件成員與 XML 屬性依其索引鍵或名稱配對，不論寫出的順序。
* 陣列元素與 XML 子節點依同層節點逐一配對：
. 依您指定的索引鍵規則；若陣列中的每個物件都有值各不相同的 `id`、`name` 或 `key` 成員，則依該成員
  （見下文「索引鍵規則」）；
. 依相同內容，並保持順序；
. 依順序不同的相同內容，且該內容在兩側各只出現一次：即「移動」列；
. 在已配對的列之間，依種類與名稱配對。

插入一個元素只算一項新增：其後的元素仍與其對應元素配對。語意檢視依位置比較，
因此對同樣的檔案可能列出較多變更。變更的認定方式與語意檢視相同：

* 「JSON、YAML 與 TOML」：索引鍵順序、註解、引號以及區塊或流式寫法都不計。在 YAML 與 TOML 中，
  數字的寫法（`8_080`、`0x1F90`、`1.0`）也不計；在 JSON 中，`1` 與 `1.0` 不同。型別改變的值（例如數
  字變成字串）會顯示為「型別變更」。
* 「XML」：屬性順序與命名空間前置詞不計，CDATA 視為文字，子節點順序、文字中的空白與註解都會比較。
  未變更且只有空白的文字列不會顯示；在新增或移除的元素旁新增或移除的空白（例如其縮排）屬於該元素。

「在變更之間移動」:: 上一個與下一個差異指令（`Alt+↑` 與 `Alt+↓`、`Alt+Home` 與 `Alt+End`）
以及樹狀上方的按鈕，會依樹狀順序走訪變更。收合節點內的變更不會被略過：其父節點會自動展開。
「變更 3 / 12」顯示目前位置。篩選條件只顯示並走訪新增、移除、修改、移動或不明確的變更，
收合列上的變更數量也會依篩選條件計算。

「鍵盤操作」:: 樹狀在 Tab 順序中只佔一站，這也是樹狀元件的慣例：按 `Tab` 直到樹狀出現外框，
或直接點選一列。之後即可用方向鍵移動：kbd:[↑] 與 kbd:[↓] 在列之間移動，kbd:[→] 展開一列，
kbd:[←] 收合該列或移到其父節點。再按 `Tab` 會離開樹狀，而不是跳到下一列；按 `Esc` 則放開樹狀。
樹狀取得鍵盤時，螢幕閱讀器會讀出選取列的狀態與兩側內容。無論樹狀是否取得鍵盤，每一列都在
無障礙樹中，可逐列朗讀。

「展開與收合」:: 「展開變更」（也是初始狀態）會展開所有內含變更的節點。「收合未變更」收合其餘節點，
「展開至層級」展開到指定深度，「重設展開」則回到初始狀態。

「詳細資料與原始碼」:: 樹狀下方會顯示選取列在兩側的路徑（例如 `$.server.port` 或
`/catalog/book[2]/@id`）、
配對方式、行號與欄號、值，以及檔案中寫有該節點的原始內容。「顯示原始碼」會在文字檢視中開啟該行。
文字游標位於某個節點（包括其索引鍵所在的行）時選擇「樹狀」，會選取該節點。

「搜尋」:: 輸入索引鍵、名稱或值，即可顯示符合的列及其父節點。在 JSON、YAML 與 TOML 中，以 `$` 開頭的
文字為路徑，
例如 `$.server.port`，會顯示該節點及其下的內容。在 XML 中，以 `/` 開頭的文字為 XPath 的小型子集：
由元素名稱或 `*`、`@name`、`text()` 與 `comment()` 組成的 `/` 與 `//` 步驟，可加上
`[@a]`、`[@a='value']` 與 `[n]` 條件，例如 `//book[@id='b102']/title`。其他 XPath 會顯示訊息並拒絕。

「索引鍵規則」:: 重複的節點預設依位置配對，除非可以區分它們。在 JSON、YAML 與 TOML 中，若陣列中的物
件在每一側都有值各不相同的
`id`、`name` 或 `key` 成員，不需規則即依其配對，工具列會顯示配對的數量，例如「3 個物件依其 id 成員配
對」。
否則可寫成 `name@key` 形式的規則。在 JSON、YAML 與 TOML 中，
`servers@name` 依 `name` 成員配對名為 `servers` 的陣列中的物件，`ports@name+protocol` 依兩個成員配
對，
`spec/ports@name` 則只套用於 `spec` 之下；`*@id` 涵蓋所有陣列，包括整個檔案就是一個陣列的情況，
以及直接位於另一個陣列中、沒有名稱的陣列。在 XML 中，
`book@id` 依 `id` 屬性配對 `book` 元素，`book@id+lang` 依兩個屬性配對，`catalog/book@id` 則只套用於
`catalog` 之下；
規則比對的是區域名稱，但絕不會配對不同命名空間的元素。多條規則以 `;` 分隔，停止輸入後即套用。
如此一來，互換位置的項目會顯示為一項移動加上變更的內容，而不是兩項取代。只有當規則涵蓋的節點
在兩側都有完整且唯一的索引鍵時，才會對該組同層節點使用規則；否則會顯示警告並列出重複與缺少的
索引鍵數量，這些節點會改以未套用規則的方式配對並標示為不明確。索引鍵規則只屬於此檢視：
不會改變語意檢視或 `--semantic` 報告。

「集合」:: 選取的列含有物件陣列或重複的 XML 元素時，「以集合檢視」會將它們列成表格：每個項目一列，
顯示狀態與兩側的值，每個只含單一值的成員，或每個屬性、每個只含文字的子元素及該子元素的每個屬性各一欄
（若只含文字，另有文字欄）。可選擇欄位並依狀態篩選；點選一列即可在樹狀中選取。含有更深層的物件、陣
列、
子元素或混合內容的項目會另行提示，因為表格不會顯示這些內容。
+
image::xml-collection.png[集合表格]

不明確的列:: 當另一種配對同樣合理時，該列會標示為不明確：一側有數個同名的同層節點而另一側較少、
索引鍵規則無法使用、新增的節點旁有相同的同層節點，或互換位置時兩個節點都可能是移動的那一個。
請自行確認這些列。

樹狀檢視會在背景建立，並顯示進度與「取消」，限制與語意檢視相同（100,000 個節點與 64 層）。
此檢視適用於兩個檔案；三向比較請使用語意檢視。

==== 三個檔案

在三向比較中，「語意」會將左側與右側檔案分別與中間的檔案比較。
每個不同的路徑只會列出一次，並以它在中間檔案中的路徑表示：

* 「僅左側不同」或「僅右側不同」：只有一側變更了它。
* 「兩側改法相同」：兩側做了相同的變更。
* 「衝突」：兩側的變更不同，或一側變更了另一側所變更之值內部的值。
  同一個物件中不同成員的變更不會衝突。
  若兩側都變更了一個元素可用多種方式配對的陣列（例如依位置配對、長度不同的陣列），整個陣列即為一個衝
  突。

可使用篩選器只顯示衝突。「採用左側」與「採用右側」會將該側的值複製到中間窗格，方式與複製值相同。
中間窗格會以目前的內容比較：採用某一側後，該路徑就不再與所採用的一側不同。

=== 審閱工作區

資料夾比較的「審閱工作區」分頁會記錄您的審閱內容：

* 每個檔案與每個差異區塊的狀態；
* 「審閱註解」、「判斷理由」與選填的「標籤（以逗號分隔）」；
* 「審閱者（自行填寫的名稱）」：只是自由填寫的文字，並非經過驗證的身分。

.審閱工作區
image::review.png[審閱工作區]

「下一個未審閱項目」會移到下一個尚待審閱的檔案。
若要審閱個別差異區塊，請從資料夾比較中開啟該檔案。

若要保留審閱決定與目前位置，請儲存資料夾審閱（請參閱 <<folder-reviews>>）。
OxideMerge 會等到比較、檔案操作與先前決定的檢查都完成後才儲存；
若比較已停止或失敗，則拒絕儲存。

==== 更新審閱

「更新審閱來源…」可選擇新的資料夾，並與先前的審閱決定對照。
它會保留所選的比較規則、以唯讀方式開啟資料夾，並標示不再相符的決定。

* 檔案只改名而內容未變時，審閱決定會跟著檔案，並註明原本的名稱。
* 若有多個新檔案的內容相同，每個檔案都會標示為需要重新審閱。
* 轉換後的內容、轉換程式或規則有變更時，先前的決定可能失效。
* 過期的決定一律列為「需要處理」，絕不會視為「已接受」。
* 編輯已審閱的檔案時，該檔案的決定會過期；差異區塊的決定只有在編輯改到其內容或前後兩行時才會過期，其
  他差異的決定保持不變。
* 差異區塊的前後文重複或無法明確對應時，必須手動審閱。

==== 檔案版本與安全性

* OxideMerge 以第 2 版格式儲存 `.oxmreview` 檔案。
  開啟第 1 版檔案時，所有項目都會設為尚未審閱；無法識別的版本則會被拒絕。
* 開啟封裝檔時，OxideMerge 會檢查所儲存檔案的摘要值。
* 下列封裝檔會被拒絕：路徑指向封裝檔以外、項目缺少、未列出或為連結，或由較新版本的 OxideMerge 儲存。

[[baselines]]
=== 版本摘要／比較基準

「版本摘要／比較基準」面板用來比較兩個版本，
位於起始頁，以及資料夾比較的側邊抽屜中。

.開啟「潛在影響」的版本摘要
image::baseline.png[版本摘要]

請直接選擇每一側的來源，不必先比較兩個資料夾。來源可以是：

[cols="1,2"]
|===
|來源 |意義

|`folder:路徑`
|資料夾目前的內容。

|`git:修訂版本:路徑`
|Git 修訂版本中的路徑。
OxideMerge 只解析一次修訂版本，並記錄其提交識別碼；不包含尚未提交的變更。

|`review:側:路徑`
|已儲存資料夾審閱中的某一側，第一側為 `0`。
|===

使用 Git 來源時，與 <<git-revision,Git 修訂版本比較>> 相同，您的 Git 設定與篩選器必須是可信任的。

==== 摘要

摘要會統計下列變更：

* 新增、刪除、修改與未變更的檔案；
* 內容完全相同的唯一檔案的移動；
* 疑似重新命名並修改的檔案；
* 二進位內容變更與檔案類型變更；
* JSON、XML、TOML 與 YAML 檔案的語意變更；
* 被排除的檔案。

摘要也會顯示每一側的擷取時間。

* 清單上方的計數可當作篩選條件，按一個或多個類別即可只顯示這些變更。
* 「高優先」只顯示有風險標記的變更：符合重要路徑，或檔案中仍留有衝突標記。這些變更也會排在最前面。
* 選取某一列，即可以唯讀方式開啟擷取的檔案。
  這些檔案來自基準，即使來源在擷取後有變更也不受影響。

==== 重新命名

同時符合下列條件時，OxideMerge 會判定為疑似重新命名並修改：

* 一個刪除的檔案與一個新增的檔案，都是同類型的文字檔。
* 兩者至少有一半、且至少三行相同。
* 兩者明確是彼此最相符的對象。

該列會顯示舊名稱，以及相同行數所占的比例。

* 按「不是重新命名」，可將兩個檔案維持為刪除與新增。
  在命令列中使用 `--split-rename 路徑`；若該路徑不是新增的檔案，OxideMerge 會提出警告。
* 按「重新偵測重新命名」可恢復判定。

==== 重要路徑

重要路徑是您想特別留意的文字，例如 `config/` 或 `api`。
包含這段文字的變更路徑會標示為高優先；從這類路徑移動或重新命名的檔案也會標示。
請在「重要路徑片段（以 ; 分隔）」中輸入；在命令列中則使用 `--important-path 文字`。

`--important-path` 與 `--split-rename` 都可以重複指定，
並需搭配 `--impact`、`--release-report` 或 `--baseline-left`。

NOTE: 重要路徑只是協助您決定審閱的先後順序，並不保證相容性。

[[impact]]
=== 潛在影響

開啟「潛在影響」，即可列出變更的檔案可能在哪些地方被使用。
每項發現都會顯示檔案、行號、內容摘要值與一段摘錄。

==== 確切發現

匯入陳述式明確指向某個變更、刪除或重新命名的檔案時，該發現標示為「確切」。
OxideMerge 能辨識下列匯入方式：

* JavaScript 與 TypeScript：相對路徑的匯入、重新匯出與 `require`。
  匯入 `./util.js` 時，也會找到變更的 `util.ts`。
* Python 的匯入。
* C 與 C++ 的 `#include "…"`，以及 Objective-C 的 `#import "…"`。
* CSS 的 `@import`。
* Rust 的 `mod name;`，以及以 `crate::`、`super::` 或 `self::` 開頭的 `use` 路徑。
* JSON 的 `$ref` 檔案參照。

JavaScript、TypeScript、Python、C、C++ 與 Rust 檔案的匯入，是從 Tree-sitter 產生的語法樹中讀取；
`.h` 標頭檔以 C 剖析，只有在只能以 C++ 剖析時才視為 C++。
其他檔案則依程式碼的語法單位辨識；Vue 與 Svelte 元件只讀取其中的 `<script>` 區塊。
因此匯入可以跨越多行，而註解或字串中的文字不會被當成匯入。
若剖析器無法讀取檔案的某些部分，該檔案會列為部分評估，因為其中的匯入與定義可能被遺漏。

OxideMerge 也會比較變更的 JavaScript、TypeScript、Python、C、C++ 與 Rust 檔案中最上層的函式、型別與
常數，
但不包括 C 與 C++ 的全域變數。
`#[derive(…)]` 這類 Rust 屬性，視為其後定義的一部分。

若某個檔案依名稱匯入了變更或移除的定義，會在第一次使用該名稱處產生「確切」發現，
並說明該定義是變更還是移除；以其他名稱匯入時也一樣。
這類匯入的例子：

* `import { parse } from "./parser"`
* `from .parser import parse`
* `use crate::parser::parse`

==== 推測發現

推測發現是可能的使用位置，需要您自行確認：

* 在同一語言的其他檔案中，第一次使用變更的定義名稱之處；
* 文字中以獨立字詞出現的變更檔案名稱或路徑；
* 變更的 JSON、TOML 與 YAML 鍵，也包括 `db.timeout` 這類以點連接的路徑。

大範圍的變更若產生超過 500 個名稱與鍵的相符處，只會列出前 500 個，
發現清單上方會註明其餘的數量；其他類型的發現則一律完整列出。

==== 影響分析找不到的項目

* 條件式、自動產生或由巨集建立的匯入。
* 方法，以及經由命名空間使用的名稱，例如 `ns.parse`。

OxideMerge 絕不會執行儲存庫的建置、測試或指令碼。

==== 處理發現

* 按「略過此發現」可隱藏該發現，不會修改檔案。
* 在資料夾比較中，按「審閱」可在審閱工作區開啟該發現所在的檔案。
* 沒有結果時，面板會說明尚未評估影響。
* 變更來源時，舊的發現會被清除。
* 取消分析時，不會顯示部分結果。

[[analysis-limits]]
=== 限制

* 每個檔案最大 16 MiB。
* 每個基準最多 10,000 個項目與 256 MiB 的擷取內容。
* 結構化檔案最多 64 層巢狀結構與 100,000 個節點。
* 影響分析的發現超過 2,000 個時會失敗，並要求您縮小範圍；只有名稱與鍵的相符處會被截斷。
* 超過限制的檔案會被拒絕或列為排除，絕不會被判定為相同。

耗時較久的分析會顯示進度，也可以取消。
某些步驟（例如剖析或合併單一檔案）只在開始前與結束後檢查是否取消，因此取消時可能要等該步驟完成。
這些限制不影響一般的比較。

[[analysis-command-line]]
=== 從命令列執行分析

[source,shell]
----
oxidemerge --merge-plan left.txt base.txt right.txt --report merge-plan.json
oxidemerge --validate-merge merged.txt left.txt base.txt right.txt --report validation.json
oxidemerge --semantic --format json old.json new.json --report semantic.html
oxidemerge --semantic --array-key id old.yaml new.yaml
oxidemerge --semantic left.yaml base.yaml right.yaml --report conflicts.json
oxidemerge --review-summary review.oxmreview --report review-summary.json
oxidemerge --baseline-left git:v1.0:/repo --baseline-right git:v1.1:/repo --release-report release.html
oxidemerge --impact old-folder new-folder --report impact.json
----

輸出：

* 未指定報告路徑時，分析會將附有版本編號的 JSON 輸出到標準輸出。
* `.xml` 報告與大多數分析的 `.html` 報告都包含這份 JSON，其格式與一般比較報告分開。
* 版本基準的 `.html` 報告是易讀的摘要，列出計數、高優先的變更以及每項變更的段落，並附上 JSON。
* 報告不得覆寫任何輸入檔案，也不得位於所選的輸入資料夾中。

結束代碼：

[cols="1,3"]
|===
|代碼 |意義

|`0`
|相同，或已成功產生計畫或摘要。

|`1`
|不同、有警告、計畫中仍有衝突，或審閱摘要中有過期的決定。

|`2`
|發生錯誤，或基準範圍不完整。
被篩選器刻意排除的檔案屬於範圍之外，不算錯誤。

|`3`
|僅 `--validate-merge`：檢查失敗。
|===

其他說明：

* `--format` 可為 `json`、`xml`、`toml` 或 `yaml`；預設依第一個檔案的副檔名判斷。
* 每次執行只能使用一個分析選項。
* `--semantic` 只產生報告。若要複製值，請開啟檔案並使用語意檢視（請參閱 <<semantic>>）。
* 三個檔案的 `--semantic` 報告會列出每個路徑的 `state`（`left`、`right`、`both` 或 `conflict`），
  以及每一側的變更。只要有任何路徑不同（包括衝突），結束代碼即為 `1`。
* 語意結果中的來源位置，是解碼後 UTF-8 文字的位元組範圍與檔案中的行號，
  而不是 UTF-16 或舊式編碼檔案中的位元組位置。

== 命令列

=== 開啟比較

不加任何參數執行 `oxidemerge`，會開啟起始頁。
指定兩個或三個路徑即可比較；指定一個路徑則可開啟衝突檔案、專案或已儲存的比較。
路徑包含空格時，請加上引號。

範例使用 POSIX 命令殼層語法。
在 Windows 上，請使用 Git Bash，或依您使用的命令殼層調整。

[source,sh]
----
oxidemerge left.txt right.txt                   # 雙向文字比較
oxidemerge mine.txt base.txt theirs.txt         # 三方比較（中間為基底）
oxidemerge -r old-folder new-folder             # 包含子資料夾
oxidemerge -r -f "*.rs;!target/" old new        # 套用篩選器的資料夾比較
oxidemerge conflict.txt                         # 解決含有衝突標記的檔案
oxidemerge -t image a.png b.png                 # 指定比較類型
oxidemerge https://example.com https://example.org   # 網頁比較
oxidemerge left.txt right.txt -o merged.txt     # 「儲存」會將右側窗格寫入 merged.txt
oxidemerge release.oxmproj                      # 開啟已儲存的專案
oxidemerge -r old.tar.gz new.tar.gz             # 將壓縮檔當作資料夾比較
oxidemerge --git-rev HEAD~1 src/main.rs         # 與較早的 Git 修訂版本比較
oxidemerge review.oxmcmp                        # 開啟已儲存的比較
----

|`--split-rename <PATH>`

|`--sync-plan <MODE>`
|產生同步兩個資料夾（來源、目的地）的唯讀計畫。`MODE` 為 `mirror` 或 `update`。
以 JSON 寫到標準輸出，或寫到 `--report` 指定的檔案。

|`--sync-links`

|`--sync-apply <PLAN>`
|將計畫套用到產生它的資料夾，資料夾須依相同順序指定。需搭配 `--yes`。

|`--yes`
|確認 `--sync-apply` 或 `--job` 的同步工作可以取代與刪除目的地中的檔案，
以及 `--job` 的工作可以在工作檔所在資料夾之外寫入報告與修補檔。

|`--sync-recover`
|復原未完成的資料夾同步。

|`--job <FILE>`
|依序執行工作檔中的工作並輸出 JSON 摘要（請參閱 <<jobs>>）。不接受路徑。
|===

每次執行只能使用一個分析選項，
且分析選項不能與 `-o`、`--patch`、`--git-rev`、`--slideshow` 或 `--report-diffs` 一起使用。

.其他選項
[cols="2,3"]
|===
|選項 |說明

|`--lang <CODE>`
|介面語言，例如 `ja` 或 `zh-TW`。

|`--list-languages`
|列出可用的語言。

|`--register-shell`、`--unregister-shell`
|加入或移除檔案管理員中的項目（請參閱 <<file-manager>>）。

|`--select-left <PATH>`、`--select-middle <PATH>`
|記住某一側，供之後的 `--compare-to` 使用。

|`--compare-to <PATH>`
|將路徑與記住的左側（及中間）比較。

|`-h`、`--help`
|列出所有選項；`-h` 只顯示摘要。

|`-V`、`--version`
|顯示版本。
|===

在 Windows 上，也可以使用 WinMerge 風格的參數，例如 `/r`、`/f`、`/o`、`/dl`、`/dr`、`/wl` 與 `/wr`。
部分 WinMerge 參數會被忽略或不支援，使用既有的指令碼前請先測試。

[[scripting]]
=== 撰寫指令碼與結束代碼

`--cli`、`--report` 與 `--patch` 都不會開啟視窗，並傳回下列結束代碼：

[cols="1,4"]
|===
|代碼 |意義

|`0`
|套用目前的選項與規則後，內容相同。

|`1`
|找到差異。即使已成功產生報告或修補檔，也會傳回此代碼。

|`2`
|發生錯誤。
|===

IMPORTANT: 結束代碼 `1` 是比較結果，不是錯誤，請確認您的指令碼以這種方式處理。

資料夾同步（請參閱 <<folder-sync>>）有自己的結束代碼：

[cols="1,4"]
|===
|代碼 |意義

|`0`
|`--sync-plan`：沒有需要做的事。`--sync-apply`：所有變更都已套用並檢查。`--sync-recover`：已全部復原。

|`1`
|`--sync-plan`：計畫中有變更或衝突。

|`2`
|發生錯誤，或計畫被拒絕且未變更任何檔案，例如有檔案在計畫產生後被變更。

|`4`
|`--sync-apply` 失敗或被停止，所有變更都已復原。

|`5`
|部分套用：有些變更無法復原，`--sync-recover` 也無法復原。輸出中列出的日誌保留了原始檔案。
|===

[source,sh]
----
oxidemerge --sync-plan mirror source destination --report plan.json
oxidemerge --sync-apply plan.json --yes source destination
----

`--sync-apply` 會重新比較資料夾，若計畫已與資料夾不符、以不同的篩選條件或為其他資料夾製作，或由較新
版本產生，就會拒絕套用。

`--sync-apply` 與 `--sync-recover` 會輸出 JSON 結果，其中 `status` 為 `applied`、`not_applied`、
`rolled_back`、`recovery_required` 或 `recovered`。結果不是單純成功時，還會有 `problem`：
`stale`（計畫製作後檔案或資料夾有變更）、`unsupported`、`read_failure`、`write_failure`
（例如沒有權限或可用空間不足）、`canceled` 或 `recovery_needed`。
這七個名稱在 OxideMerge 中是一致的：若某個檢視會先標示問題類型再說明細節，也會使用同樣的名稱，
讓相同情況在各處都有相同的說法（第七個是 `ambiguous`：輸入還有同樣可能的另一種解讀，
例如無法區分的重複項目）。

* 命令列會使用您已儲存的選項，除非以參數另外指定。
  若要讓執行結果不受個人設定影響，請將 `OXIDEMERGE_CONFIG_DIR` 指向一個專用資料夾（請參閱
  <<configuration>>）。
* 報告支援文字與資料夾比較。
  二進位或影像比較不會產生 HTML 報告，OxideMerge 會改為顯示說明訊息。

[source,sh]
----
# 不開啟視窗進行比較，同時輸出差異
oxidemerge --cli -r dirA dirB

# 資料夾比較的 HTML 報告，並附上每個已變更檔案的差異
oxidemerge -r dirA dirB --report report.html --report-diffs

# 兩個檔案的 HTML 報告，忽略註解的變更
oxidemerge old.c new.c --ignore-comments --report diff.html

# 含 5 行前後文的統一格式差異
oxidemerge old.c new.c --patch changes.patch --context 5

# 使用比較規則檔
oxidemerge --cli -r build1 build2 --rules "Build logs"
----

若命令殼層啟用了 `set -e`，請先將結束代碼存入變數，以免有差異時指令碼就中止：

[source,sh]
----
result=0
oxidemerge --cli -r old-folder new-folder || result=$?
case "$result" in
  0) echo "沒有差異" ;;
  1) echo "找到差異" ;;
  *) echo "比較失敗" >&2; exit "$result" ;;
esac
----

[[jobs]]
=== 工作

工作檔把一組執行集中在一處，讓每晚的報告或備份只需一個指令。工作檔是 JSON 檔案，副檔名通常為
`.oxjob`：

[source,json]
----
{
  "version": 1,
  "continue_on_error": false,
  "jobs": [
    {
      "name": "nightly report",
      "left": "a",
      "right": "b",
      "recursive": true,
      "report": "report.html"
    },
    {
      "name": "plan",
      "kind": "sync_plan",
      "source": "a",
      "destination": "${env:BACKUP}",
      "mode": "mirror",
      "report": "plan.json"
    },
    {
      "name": "backup",
      "kind": "sync",
      "source": "a",
      "destination": "${env:BACKUP}",
      "mode": "mirror",
      "apply": true
    }
  ]
}
----

[source,sh]
----
oxidemerge --job nightly.oxjob          # 執行前兩個工作，拒絕同步
oxidemerge --job nightly.oxjob --yes    # 執行全部三個工作
----

每個工作都會轉換成命令列選項，並以該命令列的方式執行，因此工作與其命令列的結果相同。
與命令列一樣，會套用您已儲存的選項。
`--job` 不接受路徑，除了 `--yes` 與 `--lang` 之外也不接受其他選項；每個工作的選項都寫在檔案中。

`version`:: 必填，值為 `1`。版本較新的檔案會被拒絕。
`continue_on_error`:: 為 `false`（預設）時，某個工作以錯誤結束（代碼 2 或以上）後，之後的工作不會執
行。
為 `true` 時，所有工作都會執行。
`jobs`:: 依序列出的工作。OxideMerge 不認識的欄位會視為錯誤，因此拼錯的名稱絕不會被忽略。

每個工作都有選用的 `name`（顯示在摘要與錯誤訊息中）以及 `kind`：

`compare`（預設）:: 必須指定 `left` 與 `right`（三方比較另需 `base`）。
選項：`recursive`、`report`、`report_diffs`、`slideshow`、`patch`、`patch_style`、`context`、
`compare_as`。
`sync_plan`:: 寫出同步計畫。必須指定 `source`、`destination`、`mode`（`mirror` 或 `update`）
與 `report`（計畫檔）。
`sync`:: 一次完成同步的規劃與套用。必須指定 `source`、`destination`、`mode` 與 `"apply": true`；
執行時還需要 `--yes`。會刪除大量項目的同步會被拒絕，除非工作中設定 `"allow_large_deletion": true`。
兩種同步工作都可以用 `"copy_links": true` 代替 `--sync-links`。

所有類型也接受 `filter`、`method`、`rules`、`whitespace`、`ignore_case`、`ignore_blank`、
`ignore_eol`、`ignore_numbers`、`ignore_comments`、`prettify`、`structured` 與 `numeric_tolerance`；
比較類型另接受用於 `.pdf` 報告的 `page_size`、`portrait`、`unified` 與 `whole_file`，
意義與同名的命令列選項相同。不符合類型的欄位（例如比較工作中的 `apply`）會視為錯誤。
針對伺服器路徑，所有類型都接受 `ssh_key`、`trust_fingerprint`、`proxy`、`ftp_active`、`client_cert`
與 `client_key`，作用同 `--ssh-key`、`--trust-fingerprint`、`--proxy`、`--ftp-active`、`--client-cert`
與 `--client-key`（請參閱 <<remote-command-line>>）；`destination` 為伺服器路徑的 `sync` 工作
會將變更寫回伺服器。

路徑（包括 `rules`）相對於工作檔所在的資料夾，絕對路徑、URL 與伺服器路徑除外。在路徑與 `rules` 中，
`${env:NAME}` 會換成環境變數 `NAME` 的值；未設定的變數會視為錯誤。不會展開其他內容，
工作檔也不會指定任何命令或命令殼層。比較由您的解包器讀取的檔案時（見 <<unpackers>>），
會如同任何比較一樣執行該解包器。

工作寫入報告或修補檔時，只會建立新檔案或覆寫一般檔案，絕不會經由符號連結寫入。
位於工作檔所在資料夾之外的報告或修補檔（例如 `../report.html` 或 `${env:HOME}` 底下的路徑）
只有在指定 `--yes` 時才會寫入，因此別人傳來的工作檔無法取代您的檔案。

`--job` 會輸出 JSON 摘要。其中 `exit_code` 是所有工作中最差的代碼，也是這次執行的結束代碼。
`jobs` 的每個項目包含 `name`、`kind`、`exit_code`，工作失敗時還有 `error`，同步工作則有與
`--sync-apply` 輸出相同的 `sync` 結果。`not_run` 列出因先前失敗而略過的工作；
在程式中停止執行時，`stopped` 為 `true`：

[source,json]
----
{
  "exit_code": 2,
  "jobs": [
    { "name": "nightly report", "kind": "compare", "exit_code": 1 },
    { "name": "plan", "kind": "sync_plan", "exit_code": 1 },
    { "name": "backup", "kind": "sync", "exit_code": 2,
      "error": "此工作會變更 …，僅在允許時執行：命令列中的 --yes" }
  ]
}
----

[[jobs-in-the-program]]
==== 在程式中儲存與執行工作

*檔案 → 另存為工作...* 會將目前的資料夾比較儲存為工作檔。工作會記下比較的資料夾、篩選器、比較方法、
比較規則檔，以及已開啟的比較選項，因此比較方式與分頁相同。請選擇工作內容：

* *比較並寫入報告*：報告檔案相對於工作檔，副檔名（`.html`、`.pdf`、`.csv`、`.txt` 或 `.xml`）決定格
  式。
* *規劃同步*：寫入 JSON 計畫，不變更任何內容。
* *同步*：一次完成規劃與套用，可選左到右或右到左，以及鏡像或更新。工作會含有 `"apply": true`；
  勾選 *允許刪除大量檔案* 會加上 `"allow_large_deletion": true`。

勾選 *以相對於工作檔的路徑儲存*，即可將工作與資料夾一起搬移。只有兩個資料夾的比較才能存成同步工作。
修訂版本、網頁或壓縮檔的比較是透過暫存副本進行，因此無法存成工作。

*檔案 → 執行工作...* 會執行工作檔，並列出每個工作的結果；*開啟* 可開啟它寫入的報告或計畫，
*比較* 可在分頁中開啟它的資料夾。*開啟* 只提供給報告檔案（`.html`、`.pdf`、`.csv`、`.txt`、
`.xml`、`.json`、`.diff` 或 `.patch`）。工作的執行方式與 `--job` 相同，並使用您儲存的選項，
而不是啟動 OxideMerge 時指定的選項。

含有同步工作、或在所在資料夾之外寫入報告或修補檔的工作檔，會先列出將變更的資料夾與將寫入的檔案；
允許刪除大量檔案的同步工作也會特別標示。按下 *執行並允許變更* 後才會執行；這相當於 `--yes`，
只適用於這一次執行。執行的是列出時的檔案內容，即使磁碟上的檔案在這期間有所變更；
*再次執行* 會重新讀取檔案並再次詢問。*停止* 會停止正在套用的同步、復原已做的變更，並略過之後的工作。
工作正在同步時，OxideMerge 會等它完成才結束。

[[integration]]
== 與其他工具整合

本章將 OxideMerge 設定為 Git、Subversion、Mercurial 或 Perforce
自行叫用的差異與合併工具。若要改為從 OxideMerge 內開啟某個修訂版本，請參閱 <<git-revision>>。

[[git]]
=== Git

請先安裝 Git，並確認 `oxidemerge` 在 `PATH` 中。
接著在 Bash 或 Git Bash 等 POSIX 命令殼層中執行下列命令，
將 OxideMerge 設為目前使用者的比較工具與合併工具：

[source,sh]
----
git config --global diff.tool oxidemerge
git config --global difftool.oxidemerge.cmd 'oxidemerge "$LOCAL" "$REMOTE"'
git config --global merge.tool oxidemerge
git config --global mergetool.oxidemerge.cmd \
  'oxidemerge "$LOCAL" "$BASE" "$REMOTE" -o "$MERGED" --dl Local --dr Remote --wl --wr'
git config --global mergetool.oxidemerge.trustExitCode false
----

在 macOS 上，除非已將程式連結到 `PATH`，否則請使用完整路徑
`/Applications/OxideMerge.app/Contents/MacOS/oxidemerge`。
在 Windows 上，請使用 `oxidemerge.exe` 的路徑。

`git difftool`:: 逐一開啟每個已變更的檔案。
`git difftool --dir-diff` 則以一個資料夾比較開啟所有已變更的檔案；
在檔案中的最後一個差異按 kbd:[Alt+↓]，會開啟下一個已變更的檔案。
`git mergetool`:: 開啟三方合併，中間為基底。
請使用「自動合併」，或將差異複製到中間，然後儲存。
中間窗格的內容會寫入合併結果檔，絕不會寫入基底。
Jupyter notebook 等平時會讀成文字的檔案，在這裡會以檔案本身合併，因此儲存的結果仍是有效的檔案。
+
設定 `trustExitCode false` 時，Git 會檢查輸出檔案是否有變更；
若看起來沒有變更，Git 可能會詢問合併是否成功。
請在儲存並檢查結果後，才回答成功。
只是關閉視窗，並不代表合併成功。

[[other-vcs]]
=== Subversion、Mercurial 與 Perforce（實驗性）

WARNING: 對 Subversion、Mercurial 與 Perforce 的支援屬於實驗性功能，尚未完整測試。
下列設定僅在 macOS 上以本機儲存庫與本機 Perforce 伺服器試過。
接受任何合併結果前請先檢查，若有無法運作之處請回報。

OxideMerge 接受 `diff` 用來指定標題的參數：`-u` 會被忽略，
每個 `-L <TITLE>` 依路徑順序為下一側命名。
因此窗格標題會顯示修訂版本名稱，而不是暫存檔的路徑。
`--dl`、`--dm` 與 `--dr` 優先於 `-L`。

Subversion 與 Perforce 傳入合併檔案的順序，OxideMerge 無法直接使用，
因此合併要透過一個小型包裝指令碼。
若合併結果檔沒有儲存，包裝指令碼會回報失敗，
所以未儲存就關閉視窗時，衝突仍會保持未解決。

==== Subversion

`svn diff --diff-cmd oxidemerge` 會逐一比較每個已變更的檔案。
Subversion 會傳入 `-u -L <舊標題> -L <新標題> <舊檔> <新檔>`，
因此標題會顯示如 `f.txt (revision 12)` 與 `f.txt (working copy)`。
若要讓每次 `svn diff` 都使用 OxideMerge，請在 `~/.subversion/config`
（Windows 上為 `%APPDATA%\Subversion\config`）中設定：

[source,ini]
----
[helpers]
diff-cmd = oxidemerge
merge-tool-cmd = /path/to/oxidemerge-svn-merge
----

請勿對 `svn diff` 傳入 `-x` 選項：Subversion 會改傳這些選項，而不傳 `-u`。

合併時，Subversion 會傳入五個路徑：基底、對方版本、我的版本、合併結果檔與工作檔。
請將下列包裝指令碼存為 `oxidemerge-svn-merge`，設為可執行，並在 `merge-tool-cmd` 中指定：

[source,sh]
----
#!/bin/sh
# Subversion passes: base, theirs, mine, merged, working file.
before=$(cksum < "$4")
oxidemerge "$3" "$1" "$2" -o "$4" --dl Mine --dm Base --dr Theirs --wl --wr
[ "$(cksum < "$4")" != "$before" ]
----

在 Subversion 的衝突提示中選擇 *l*（launch），或執行 `svn update --accept launch`。
包裝指令碼一成功（也就是您已儲存），Subversion 就會將衝突標示為已解決。

==== Mercurial

請將下列內容加入 `~/.hgrc`（Windows 上為 `%USERPROFILE%\mercurial.ini`）：

[source,ini]
----
[extensions]
extdiff =

[extdiff]
cmd.oxidemerge = oxidemerge

[diff-tools]
oxidemerge.diffargs = -L $plabel1 -L $clabel $parent $child

[ui]
merge = oxidemerge

[merge-tools]
oxidemerge.args = $local $base $other -o $output --dl $labellocal --dm $labelbase --dr $labelother --wl --wr
oxidemerge.checkchanged = true
----

`hg oxidemerge` 會比較已變更的檔案：只有一個檔案時直接比較，多個檔案時以資料夾比較開啟。
`hg oxidemerge -c REV` 則顯示單一變更集。
請勿同時設定 `opts.oxidemerge`：Mercurial 會因此忽略 `diffargs`，標題也就不會顯示。
`hg merge` 與 `hg resolve` 會開啟三方合併，中間為基底。
設定 `checkchanged` 後，若合併結果檔沒有變更，Mercurial 會詢問合併是否成功。

==== Perforce

Perforce 可從 p4 命令列、P4V 或兩者使用 OxideMerge。
兩者需分別設定：p4 讀取 `P4DIFF` 與 `P4MERGE`，P4V 則使用自己的偏好設定。

===== p4 命令列

p4 會以兩個檔案執行 `P4DIFF` 指定的程式：depot 修訂版本（暫存檔）與您工作區中的檔案。
並以四個檔案執行 `P4MERGE` 指定的程式：基底、對方版本、您的版本與結果。
OxideMerge 接受合併檔案的順序不同，因此合併需透過包裝指令碼。

設定步驟：

. 將下列指令碼存成 `PATH` 中某個資料夾內的 `oxidemerge-p4-merge`，例如
`~/bin/oxidemerge-p4-merge`：
+
[source,sh]
----
#!/bin/sh
# Perforce passes: base, theirs, yours, result.
before=$(cksum < "$4")
oxidemerge "$3" "$1" "$2" -o "$4" --dl Yours --dm Base --dr Theirs --wl --wr
[ "$(cksum < "$4")" != "$before" ]
----
+
最後一行會在結果未儲存時讓包裝指令碼失敗，使檔案維持未解決。
. 讓它可以執行：
+
[source,sh]
----
chmod +x ~/bin/oxidemerge-p4-merge
----
. 以 `p4 set`（或同名的環境變數）讓 p4 使用 OxideMerge：
+
[source,sh]
----
p4 set P4DIFF=oxidemerge
p4 set P4MERGE=$HOME/bin/oxidemerge-p4-merge
----
+
若 `oxidemerge` 不在 `PATH` 中，請使用完整路徑，例如 macOS 上的
`/Applications/OxideMerge.app/Contents/MacOS/oxidemerge`。
請勿在 `P4DIFF` 加上 `--cli`：檔案不同時它會以 1 結束，p4 會回報 *Execution Failed*。
. 執行 `p4 set` 檢查設定；兩行都應指向 OxideMerge。

要將檔案與 depot 比較，請執行 `p4 diff f.txt`；OxideMerge 會在左側顯示 depot 修訂版本，
右側顯示您工作區中的檔案。

合併衝突的步驟：

. 執行 `p4 resolve f.txt`。
. 在提示時輸入 *m*（merge）。
OxideMerge 會開啟，左側為 *Yours*、中間為 *Base*、右側為 *Theirs*。
. 以「下一個衝突」搭配「採用左側」、「採用右側」或「採用兩側」，或直接編輯中間窗格，解決每個衝突。
. 按一下「儲存結果」並關閉視窗。
. 回到提示後，p4 會建議 *ae*（accept edit）；輸入 *ae* 接受合併後的檔案。

若未儲存就關閉視窗，p4 會回報 *Execution Failed*，檔案仍維持未解決；
此時輸入 *ae* 會警告檔案仍含有變更標記。
請再次執行 `p4 resolve` 重新開始。

===== P4V

P4V 不會讀取 `P4DIFF` 或 `P4MERGE`，而是使用自己的比較與合併設定。
它會直接執行 OxideMerge，因此不需要包裝指令碼。

設定步驟：

. 在 P4V 中開啟 *Preferences*（macOS 上為 *P4V → Preferences*，Windows 與 Linux 上為
*Edit → Preferences*）。
. 在左側清單中選取 *Diff*。
. 選取 *Other application*。
只填寫下方欄位並不夠：只要仍選取 *P4Merge*，P4V 就會繼續使用 P4Merge。
. 在 *Location* 中填入 `oxidemerge` 程式本身的路徑，而不是應用程式套件或包裝指令碼：
+
[cols="1,3"]
|===
|macOS |`/Applications/OxideMerge.app/Contents/MacOS/oxidemerge`
|Windows |解壓縮資料夾中 `oxidemerge.exe` 的路徑
|Linux |`command -v oxidemerge` 的輸出，例如 `/usr/bin/oxidemerge`
|===
. 在 *Arguments* 中輸入 `%1 %2`。
. 在左側清單中選取 *Merge*，同樣選取 *Other application*，並填入相同的 *Location*。
. 在 *Arguments* 中輸入：
+
----
%2 %b %1 -o %r --dl Yours --dm Base --dr Theirs --wl --wr
----
+
在 P4V 的合併參數中，`%1` 是對方版本，`%2` 是您的版本，`%b` 是基底，`%r` 是結果。
. 按一下 *OK*。

合併衝突的步驟：

. 在 *Workspace* 或 *Pending* 分頁中選取檔案；需要解決的檔案會顯示問號圖示。
. 選擇 *Actions → Resolving → Resolve...*，或在檔案上按右鍵並選擇 *Resolve...*。
. 在 Resolve 對話方塊中按一下 *Run Merge Tool*。
OxideMerge 會開啟，左側為 *Yours*、中間為 *Base*、右側為 *Theirs*。
若開啟的是 P4Merge，請回到 *Preferences → Merge*，確認已選取 *Other application*。
. 解決每個衝突，按一下「儲存結果」並關閉視窗。
P4V 傳入的結果檔案已含有 P4V 自己的衝突標記；儲存後會取代這些標記。
. 在 Resolve 對話方塊中按一下 *Accept Merged*。
請先檢查結果：OxideMerge 只在您儲存時寫入結果，若未儲存就關閉，結果仍會保留 P4V 的標記。
若要整個採用對方版本或您的版本，請改用 *Accept Source* 或 *Accept Target*。

在 Windows 上，請將包裝指令碼寫成 `.cmd` 檔，內容為
`oxidemerge.exe "%3" "%1" "%2" -o "%4" --dl Yours --dm Base --dr Theirs --wl --wr`
（Subversion 請用 *Mine* 取代 *Yours*）。
它無法判斷您是否已儲存，因此接受結果前請先檢查。

NOTE: 已試過：在 macOS 上，以 Subversion 1.15 試過 Subversion 的命令與包裝指令碼，
以 Mercurial 7.2 試過 Mercurial 的設定，且僅使用本機儲存庫。
Perforce：以 p4 2026.1 試過 `P4DIFF` 與 `oxidemerge-p4-merge` 包裝指令碼，
並試過由 P4V 的 Resolve 對話方塊開啟 OxideMerge，皆使用本機個人伺服器。
尚未試過：Windows 與 Linux、Windows 的 `.cmd` 包裝指令碼、透過網路連線的 Subversion 伺服器
（`svn://`、`https://`）及其登入、透過網路連線的 Perforce 伺服器、P4V 的比較設定，
以及在 OxideMerge 中儲存後於 P4V 接受合併。

[[file-manager]]
=== 檔案管理員

透過「工具」選單或執行 `oxidemerge --register-shell`，可將 OxideMerge 加入檔案管理員：

Windows:: 「工具 → 加入檔案總管右鍵選單」會為檔案、資料夾、磁碟機與資料夾背景加入「OxideMerge」子選
單。
在 Windows 11 上，這些項目位於「顯示其他選項」中。
macOS:: 「工具 → 加入 Finder 快速動作」會在 Finder 的「快速動作」與「服務」選單中，
加入「OxideMerge: 比較」、「OxideMerge: 選為左側」與「OxideMerge: 選為中間」。
Linux:: 「工具 → 加入檔案管理員右鍵選單」會在 Nautilus、Nemo 與 Dolphin 中加入相同的項目。

這些項目的用法如下：

* 「比較」會比較選取的兩個或三個檔案或資料夾。
  只選取一個項目時，會將它與您先前選擇的一側比較；
  若尚未選擇任何一側，則開啟「選擇檔案或資料夾」對話框並帶入該項目。
* 「選為左側」與「選為中間」會記住一個項目，例如位於其他資料夾中的項目。
  之後「比較」會顯示為「與「名稱」比較」。
* 「比較方式」（僅限 Windows 的檔案）可指定以文字、二進位、影像或網頁比較。

這些項目會指向加入它們的程式；搬移程式後，請重新加入。
若要移除，請使用「工具」中對應的命令，或執行 `oxidemerge --unregister-shell`。

[[configuration]]
=== 設定檔

OxideMerge 以 JSON 格式將選項存放在您的設定資料夾中：

[cols="1,3"]
|===
|系統 |設定檔

|Windows |`%APPDATA%\OxideMerge\config.json`
|macOS |`~/Library/Application Support/OxideMerge/config.json`
|Linux |`~/.config/OxideMerge/config.json`
|===

「說明與快速鍵」會顯示設定檔的位置。
若 OxideMerge 無法讀取設定檔，會將它另存為 `config.json.bad` 並改用預設值；您可以修正該檔案後再放回
原處。

設定資料夾中也包含下列資料夾：

* `Rules`：比較規則檔。
* `Filters`：WinMerge 的 `.flt` 篩選器檔案。
* `Languages`：新增或修改過的語言套件。

=== 可攜式與獨立設定

可攜式使用:: 在程式所在的資料夾中建立一個名為 `oxidemerge.json` 的空白檔案。
OxideMerge 便會將選項存放在這個檔案中，`Rules` 資料夾也會位於程式旁。
程式所在的資料夾必須可以寫入。
獨立設定:: 將環境變數 `OXIDEMERGE_CONFIG_DIR` 設為某個資料夾，OxideMerge 便會使用該資料夾中的
`config.json`。
此設定優先於可攜式使用與預設的設定資料夾，
適合用於指令碼、測試，或區隔不同的工作環境。

=== 新增語言

. 將原始碼中的 `lang/en.json` 複製為 `<code>.json`，例如 `nl.json`。
. 翻譯其中的值，所有 `{placeholder}` 都必須維持原樣。
. 將檔案放到程式旁或設定資料夾中的 `Languages` 資料夾。

缺少的訊息，以及少了或多了預留位置的翻譯，都會改以英文顯示。

[[troubleshooting]]
== 疑難排解

請先閱讀錯誤訊息，並記下其中提到的路徑。
重新合併或儲存之前，請檢查目標位置、磁碟可用空間、存取權限，以及是否有其他程式修改了檔案。

=== 安裝與啟動

macOS 拒絕開啟應用程式::
請先嘗試開啟一次，再到「系統設定 → 隱私權與安全性」中選擇「強制打開」。
或在「終端機」中清除下載標記：
`xattr -dr com.apple.quarantine /Applications/OxideMerge.app`。

macOS 要求存取資料夾::
OxideMerge 第一次讀取「桌面」、「文件」、「下載項目」、卸除式磁碟區或網路磁碟區時，macOS 會詢問一次。
請允許存取，或之後在「系統設定 → 隱私權與安全性 → 檔案和資料夾」中開啟。

AppImage 無法啟動::
請先以 `chmod +x` 讓它可以執行。
若訊息提到 FUSE，請加上 `--appimage-extract-and-run` 啟動。

在 Linux 上視窗一片空白或無法開啟::
OxideMerge 以 OpenGL 繪製畫面。
若沒有可用的顯示卡驅動程式（例如在虛擬機器中），請以 `LIBGL_ALWAYS_SOFTWARE=1 oxidemerge` 啟動，改用
Mesa 的軟體繪圖。

在 Linux 上無法開啟檔案對話框::
檔案對話框使用 XDG 桌面入口服務。
請安裝 `xdg-desktop-portal`，以及適用於您桌面環境的套件，例如 `xdg-desktop-portal-gtk` 或
`xdg-desktop-portal-kde`。

檔案管理員中沒有 OxideMerge 的項目::
在 Windows 11 上，這些項目位於「顯示其他選項」中。
項目會指向加入它們的程式；若將程式移動或更新到其他資料夾，請從新的程式重新加入。
在 Linux 上，請重新啟動檔案管理員（例如執行 `nautilus -q`）才會看到新項目。

設定沒有儲存::
OxideMerge 無法儲存設定時，會顯示原因。
請確認設定資料夾（請參閱 <<configuration>>）可以寫入，且磁碟沒有滿。

=== 編輯與儲存

某個窗格無法編輯::
該窗格因下列原因之一而為唯讀：
+
--
* 標題列上的鎖頭已鎖上。
* 以 `--wl`、`--wm` 或 `--wr` 開啟。
* 是從檢閱快照或網頁的頁面樹狀結構解壓縮出來的。從壓縮檔比較（請參閱
  <<archives>>）解壓縮出來的檔案可以編輯，儲存時也會一併儲存壓縮檔；但已簽署的套件等
  仍為唯讀的壓縮檔除外。
* 是以格式化方式顯示的 JSON 或 XML 檔案。
  請關閉「比較前格式化 JSON 與 XML」，即可編輯與合併。
--

檔案因編碼問題而無法儲存::
所選的編碼無法表示編輯內容中的某些字元。
請復原加入這些字元的變更後再儲存。
若改選其他編碼，OxideMerge 會重新讀取檔案，因此請先將您的編輯另外保留一份。

檔案可以寫入，但儲存或複製仍失敗::
OxideMerge 還需要能在同一資料夾中建立並取代暫存檔（請參閱 <<saving-files>>）。
請檢查資料夾權限、磁碟可用空間，以及是否有其他程式鎖定該檔案。
OxideMerge 會回報失敗，而不會直接覆寫原始檔案。
在成功儲存編輯內容之前，請不要關閉比較。

=== 比較結果

檔案看起來相同，但位元組內容不同::
請檢查空白字元、大小寫、換行字元、編碼與註解相關的選項，以及比較規則。
文字比較可能依設定刻意忽略這些差異。
若要確認檔案完全相同，請使用二進位比較，或資料夾比較的「二進位內容」方法。

資料夾比較中缺少某些檔案::
請檢查篩選器、「略過隱藏的檔案與資料夾」、「包含子資料夾」與「顯示」設定。
「依名稱尋找」也會隱藏部分項目。
「所有差異」沿用資料夾比較的篩選器與顯示設定，不會包含被隱藏的結果。

檔案顯示為錯誤::
OxideMerge 無法讀取該檔案，訊息中會指出是哪個檔案。
請檢查檔案的權限；在 macOS 上，也請一併檢查上述的資料夾存取權限。

資料夾自動合併無法開始，或沒有合併任何項目::
請開啟「包含子資料夾」與「包含僅一側子資料夾的內容」，並等待比較完成。
若有檔案在比較後又有變更，就不會合併任何項目，並會列出該檔案。
若合併途中某項變更失敗，到目前為止的所有變更都會復原。
請重新整理比較後，再次檢查合併計畫。

=== 網頁

網頁比較缺少瀏覽器中看得到的內容::
OxideMerge 比較伺服器傳回的 HTML，看不到指令碼加入的內容。
它不會在瀏覽器中開啟網頁，因此網頁的指令碼一律不會執行。
框架中的內容不列入比較。
無法下載的資源，以及因位於本機或私人網路而被略過的資源，都會在狀態列中計數。

=== 效能

大型檔案比較緩慢或占用大量記憶體::
文字比較會在記憶體中保留解碼後的文字、比較資料與編輯紀錄，實際用量取決於內容與您的操作。
二進位與影像檢視也會載入完整的檔案。
+
--
* 16 MiB 以上的有效 UTF-8 檔案會分段載入；
  UTF-16 與舊式編碼的檔案則會整個解碼。
  文字仍可編輯，比較規則也照常運作。
* 超過 50,000 行或 16 MiB 的解碼文字時，會關閉語法醒目提示。
* 編輯、復原、自動換行與特殊的比較規則，仍可能增加記憶體用量。
--
+
若要減少記憶體用量，可使用二進位比較，或改以大小與日期而非內容比較資料夾（請參閱
<<compare-methods>>）。

[[limitations]]
== 已知限制

* 壓縮檔：支援 ZIP 類格式、TAR（未壓縮、gzip、bzip2 與 xz）與 7z，不支援 RAR。
* 文字窗格主要用於檢查與合併變更，並非完整的編輯器。
  內嵌檢視無法編輯。
* 解譯器外掛程式使用外部命令，不支援 WinMerge 的外掛程式動態連結程式庫與指令碼。
* 網頁比較不支援 Cookie 或登入，需要登入的網頁會顯示其登入畫面。
  網頁的指令碼不會執行，因此看不到指令碼加入的內容。
  框架中的內容不列入比較。
* 語意比較一次只複製一個值，且只在重新讀取檔案能確認編輯結果時才會複製。它不會移動陣列元素，也不會一
  次合併所有變更。
* 資料夾同步只適用於本機資料夾，且只在您啟動時執行。重新命名的檔案會顯示為一次刪除加一次複製。
* SFTP 與 FTP：FTP 主動模式無法經由代理伺服器使用，在 NAT 後方也很少能用。以採用 SHA-1 的 RSA 或
  ECDSA P-521 簽署的 SSH 主機憑證會被拒絕。`~/.ssh/config` 中的 `Match exec` 與 `Match canonical`
  永遠不符合。終端機上的問題只能以 `Ctrl+C` 中止。
* 介面翻譯由機器輔助完成，尚未經過母語人士審閱。
