== 關於本指南

[.lead]
OxideMerge 是一套快速、安全的檔案與資料夾比較及合併工具，可在 Windows、macOS 與 Linux 上執行。
在清楚的並排檢視中，您可以放心檢查變更、整合多個版本的修改，並解決合併衝突。
除了文字，OxideMerge 也能比較二進位檔、影像與網頁，並可融入您的版本控制與自動化流程。
OxideMerge 以 Rust 打造。

本指南另有 xref:user-guide.adoc[英文版]。

本指南說明如何安裝 OxideMerge、比較與合併檔案及資料夾，以及如何將 OxideMerge 整合到版本控制系統與自動化流程中。
內容適用於 Windows、macOS 與 Linux 上的 OxideMerge {revnumber}。

=== 適用對象

本指南適合所有需要在接受變更前確實掌握差異的使用者，包括軟體開發人員、程式碼審閱者、發行與建置工程師、系統管理員，以及文件與設定檔的撰寫者。
比較與合併檔案不需要程式設計經驗。
命令列與工具整合等章節則假設您熟悉終端機及所使用的版本控制系統。

== 簡介

OxideMerge 讓您清楚看出檔案與資料夾在不同版本之間的差異，並協助您將這些變更整合成想要的結果。
無論是檢閱原始碼與設定檔的變更、解決版本控制產生的衝突、比較兩個發行版本，
或是從指令碼執行比較、將它設為 Git 的比較與合併工具，都能交給 OxideMerge 處理。
除了文字之外，它也能比較資料夾、壓縮檔、二進位檔、影像與網頁。
本章簡介 OxideMerge 的功能、本指南的編排方式，以及後續章節使用的術語。

=== OxideMerge 能做什麼

* 比較兩個或三個資料夾（包括壓縮檔），並複製、刪除或合併其中的項目。
* 比較與編輯文字檔，在版本之間複製變更，以及解決版本控制產生的衝突。
* 比較二進位檔的位元組、影像的像素與網頁的內容。
* 透過比較選項與可重複使用的比較規則，略過不重要的差異。
* 匯出報告與修補檔，或儲存專案與比較結果，方便日後檢閱。
* 從指令碼執行比較，或將 OxideMerge 設為 Git 的比較與合併工具。

介面提供英文、繁體中文、簡體中文、日文、韓文、德文、法文、西班牙文、俄文、巴西葡萄牙文與義大利文。

=== 如何使用本指南

建議先閱讀 <<first-comparison>>，熟悉基本操作，再依需要的比較類型查閱對應章節。
最後幾章為參考資料，包括命令列、選項、鍵盤快速鍵與疑難排解。

本指南使用下列慣例：

* 「」括住的文字是程式中顯示的名稱，例如按鈕或選單命令。
* 「檔案 → 開啟...」這類寫法表示：先開啟「檔案」選單，再選擇「開啟...」。
* 命令列範例假設 `oxidemerge` 已在 `PATH` 環境變數中；若不在，請改用程式的完整路徑。
* 範例中的路徑（例如 `old-folder`）請換成您實際的路徑。

NOTE: *macOS 的快速鍵。* 本指南使用 Windows 與 Linux 的按鍵名稱。
在 macOS 上，請以 Command 鍵（kbd:[⌘]）取代 kbd:[Ctrl]，以 Option 鍵（kbd:[⌥]）取代 kbd:[Alt]。
唯一的例外是 kbd:[Ctrl+Tab]：在 macOS 上同樣使用 Control 鍵。
選單與工具提示一律顯示您所用系統的快速鍵。

=== 常用術語

本指南通篇使用下列術語。

側:: 比較中的一個版本，分為左側、中間與右側。
窗格:: 視窗中顯示某一側內容的區域。
差異:: 各版本之間不相同的地方。在文字比較中，一個差異可能包含好幾行。
基底（共同祖先版本）:: 兩份修改版本共同的原始版本。在三方比較中，基底位於中間。
衝突:: 兩份修改版本以不同方式變更了同一段文字，需要由您選擇或編輯結果。
合併:: 將變更複製或整合到目標版本。
篩選器:: 決定資料夾比較要包含哪些檔案與資料夾的條件。
比較規則:: 決定哪些文字差異要計入的規則，不會修改檔案本身。

IMPORTANT: 合併會變更目標內容。
複製或儲存前，請先確認來源、目標與輸出路徑。
只需要檢視的版本，建議設為唯讀。

== 安裝

OxideMerge 可在 Windows、macOS 與 Linux 上執行。
本章說明該下載哪個套件、各系統第一次啟動時需要注意的事項，以及如何從原始碼建置。

請從 https://github.com/kuopinghsu/OxideMerge/releases[GitHub 發行頁面]
下載適合您系統與處理器的套件。
每個版本也附有本指南的英文與繁體中文 PDF 檔。
發行頁面會列出每個下載檔案的 SHA-256 摘要值，您可以藉此確認檔案完整無誤。

[cols="1,3"]
|===
|系統 |套件

|Windows 10 或 11，x64 或 Arm64
|`oxidemerge-<version>-windows-x64.zip` 或 `oxidemerge-<version>-windows-arm64.zip`

|macOS 11 或更新版本
|`oxidemerge-<version>-macos-universal.dmg`，適用於 Apple 晶片與 Intel 處理器

|Linux x64 或 Arm64
|AppImage（適用於 Ubuntu 20.04、RHEL 8、Debian 10 及更新版本）或 TAR.GZ 壓縮檔。
Intel 與 AMD 處理器請選 `linux-x64`，64 位元 Arm 處理器請選 `linux-arm64`。
|===

=== Windows

Windows 版不需要安裝。
解壓縮 ZIP 檔後，直接執行 `oxidemerge.exe` 即可。

=== macOS

在 macOS 上安裝 OxideMerge：

. 開啟 DMG 檔，將「OxideMerge」拖移到「應用程式」檔案夾。
. 啟動 OxideMerge。
  本程式採用臨時簽署，未經 Apple 公證，因此 macOS 可能會阻擋第一次啟動。
  若遭到阻擋，請到「系統設定 → 隱私權與安全性」中選擇「強制打開」。
  在 macOS 14 及更早版本中，也可以按住 Control 鍵並按一下應用程式，再選擇「打開」。

若要從「終端機」啟動，請使用程式的完整路徑。
若想直接輸入 `oxidemerge` 啟動，請在 `PATH` 中的某個資料夾建立連結，例如：

[source,sh]
----
sudo ln -s /Applications/OxideMerge.app/Contents/MacOS/oxidemerge /usr/local/bin/oxidemerge
----

=== Linux

在 Linux 上啟動 OxideMerge 之前，請先確認下列事項：

* 請在使用 X11 或 Wayland 的桌面環境中執行。
* 啟動 AppImage 前，請先讓它可以執行：`chmod +x oxidemerge-*.AppImage`。
* 若系統沒有 FUSE，請加上 `--appimage-extract-and-run` 啟動 AppImage。
* 檔案對話框需要 `xdg-desktop-portal`，大多數桌面環境已內建。
* 若要顯示中文、日文與韓文，請安裝 Noto Sans CJK 等中日韓字型。

=== 從原始碼建置

若要自行建置 OxideMerge：

. 從 https://rustup.rs/ 安裝 Rust 工具鏈。
. 在儲存庫資料夾中執行 `cargo build --release --locked`。

建置完成的程式位於 `target/release/oxidemerge`（Windows 為 `target/release/oxidemerge.exe`）。
建置需求與檢查方式，請參閱 xref:development.zh-TW.md[開發指南]。

== 快速入門

本章帶您從起始頁開始，完成第一次比較。
接著介紹主視窗、開啟比較的各種方式（包括伺服器上的檔案與資料夾），以及 OxideMerge 提供的比較類型。
最後說明常見工作的建議做法，以及在程式中取得說明的方式。

=== 起始頁

不指定任何比較就啟動 OxideMerge 時，會顯示起始頁。
您可以在這裡開始新的比較、解決衝突檔案、比較兩個版本，或回到最近使用的比較。

.起始頁
image::start.png[OxideMerge 起始頁]

起始頁包含下列部分：

比較檔案或資料夾:: 輸入「左側」與「右側」的路徑。
您可以直接輸入或貼上路徑，也可以按欄位旁的檔案與資料夾按鈕選擇。
按「三方」可加入「中間」路徑。
按「更多選項…」會開啟「選擇檔案或資料夾」對話框，並帶入這些路徑。
開啟衝突檔案:: 解決含有衝突標記的檔案，請參閱 <<conflict-files>>。
版本摘要／比較基準:: 將兩個資料夾或已儲存的審閱當作兩個版本來比較，請參閱 <<baselines>>。
最近使用:: 以卡片列出最近的比較。
+
--
* 按一下卡片，即可再次執行該比較。
* 在卡片上按右鍵，可「變更路徑...」或「從最近使用中移除」。
* 按「最近使用」標題右側的「清除」，可清空整份清單。
  「檔案 → 開啟最近的比較 → 清除最近的比較」的效果相同。
  清除後出現的訊息會在幾秒內提供「復原」。
--

最近使用清單是空的時候（例如第一次啟動），起始頁會顯示「開啟範例」。
按下後會開啟兩個小型範例資料夾，讓您實際了解比較如何運作。
範例資料夾是暫時性的：關閉分頁時 OxideMerge 就會刪除它們，也不會將範例加入最近使用清單。

[[first-comparison]]
=== 第一次比較

以下簡短的操作示範會比較一個檔案的兩個版本，並將差異從一側複製到另一側。

比較兩個檔案：

. 在起始頁中，將較舊的檔案填入「左側」，較新的檔案填入「右側」。
. 按「比較」。
  若要避免某一側被修改，請改按「更多選項…」，並開啟該側的「唯讀」。
. 按 kbd:[Alt+↓] 移到下一個差異。
. 若要複製某個差異，請先確認哪個窗格是目標，再按指向該窗格的箭頭。
. 檢查結果。
  若要另存成新檔，請選擇「檔案 → 另存新檔」；若要更新窗格中的檔案，請選擇「儲存」。

如果只想檢視而不修改，請將兩側都設為唯讀。
若要分享檢閱結果但不傳送原始檔案，可以匯出 HTML 報告（請參閱 <<reports>>）。

=== 主視窗

您開啟的每個比較都會顯示在主視窗中。主視窗包含下列部分：

選單列:: 「檔案」、「編輯」、「檢視」、「比較」、「合併」、「工具」與「說明」。
不適用於目前分頁的命令無法選取。
選單或右鍵選單比視窗高時可以捲動：將指標停在選單頂端或底端的箭頭上，或使用滑鼠滾輪或方向鍵。
標題列:: 右側依序為「搜尋命令」（開啟命令面板）、「開啟」、淺色與深色主題切換、「選項」，
以及「說明與快速鍵」。
視窗較窄時，搜尋欄位會縮成圖示，放不下的按鈕會隱藏；選單中仍有相同的命令。
分頁:: 每個比較都在自己的分頁中開啟。
兩側檔名相同時，分頁只顯示一次檔名，後面接著不同的資料夾。
關閉按鈕的位置顯示圓點時，表示該分頁有尚未儲存的變更；將指標移到圓點上即可關閉分頁。
狀態列:: 顯示兩側是否不同，以及目前的行號或位移；最右側顯示介面語言。
差異與項目的數量則顯示在工具列與資料夾的篩選標籤上。

分頁操作：

* kbd:[Ctrl+Tab] 與 kbd:[Ctrl+Shift+Tab] 切換到下一個與上一個分頁。
* kbd:[Ctrl+W] 或 kbd:[Esc] 關閉目前的分頁。
  若有開啟中的對話框、搜尋列、預覽或編輯狀態，kbd:[Esc] 會先關閉它們。
  分頁有尚未儲存的變更時，OxideMerge 會先詢問再關閉。
* 在分頁上按右鍵，可關閉該分頁、其他分頁、右側的分頁或全部分頁。

若要變更介面語言，請使用「選項 → 一般」，或以 `--lang` 參數啟動 OxideMerge。

若要查看版本，請按一下應用程式標誌或旁邊的名稱，或選擇「說明 → 關於 OxideMerge」。
對話框也會顯示建置識別碼：

* 開發版本會顯示 Git 的簡短雜湊值；
  已追蹤的檔案或 Git 索引有未提交的變更時，會加上 `-dirty`。
* 依發行標籤建置、且沒有任何修改的最佳化版本，會顯示建置日期（UTC）。

執行 `oxidemerge --version` 也會顯示相同的識別碼。

=== 開啟比較

開始比較的方式有好幾種，您可以選擇最適合工作需求的一種：

* 在起始頁的「比較檔案或資料夾」中輸入路徑，再按「比較」。
* 選擇「檔案 → 開啟...」（kbd:[Ctrl+O]），或按起始頁的「更多選項…」，開啟「選擇檔案或資料夾」對話框。
* 將兩個或三個檔案或資料夾拖放到視窗上。
  只拖放一個項目時，會開啟對話框並帶入該項目。
* 從起始頁、「檔案 → 開啟最近的比較」或命令面板選擇最近使用的比較。
* 從命令列（請參閱 <<command-line>>）或檔案管理員（請參閱 <<file-manager>>）啟動 OxideMerge。
* 選擇「檔案 → 透過 SFTP/FTP 比較...」，或按一下起始頁或「選擇檔案或資料夾」對話框中路徑旁的地球圖示按鈕，
  先透過 SFTP、FTPS 或 FTP 從伺服器取得檔案或資料夾。請參閱 <<remote-sftp>>。

「選擇檔案或資料夾」對話框集中了新比較所需的路徑與設定。

.「選擇檔案或資料夾」對話框
image::dialog.png[「選擇檔案或資料夾」對話框]

使用「選擇檔案或資料夾」對話框：

. 輸入或瀏覽「左側」與「右側」的路徑。
  路徑可以是檔案、資料夾，或以 `http://`、`https://` 開頭的網址。
  若要比較三個版本，請開啟「三方比較」並輸入「中間」的路徑。
. 開啟某一側旁的「唯讀」，可避免它被修改。
  「左右互換」會對調兩側。
. 比較資料夾時，可選擇「包含子資料夾」、「篩選器」與「比較方法」。
. 在「比較方式」中選擇比較類型：文字、二進位、影像或網頁。
  選擇「自動」時，由程式判斷類型（請參閱 <<compare-types>>）。
. 按「比較」。

TIP: 若要比較不在檔案中的文字，請選擇「檔案 → 新增文字比較」（kbd:[Ctrl+N]），開啟兩個空白的窗格。
可按 kbd:[Ctrl+V] 貼上文字，或按兩下某一行開始輸入。

TIP: 若要將剪貼簿中的文字與即將貼上的文字比較，請選擇「檔案 → 比較剪貼簿」。
這會開啟一個文字比較，左側是剪貼簿目前的文字，右側是空白且可編輯的窗格；
按 kbd:[Ctrl+V] 貼上第二份文字即可。
「儲存」的用法與其他尚未存檔的比較相同，因為沒有原始檔案可寫回。

[[remote-sftp]]
=== 透過 SFTP 或 FTP 比較

需要比較的檔案位於伺服器上時，OxideMerge 可以替您取得檔案，並將您的變更寫回伺服器。
「檔案 → 透過 SFTP/FTP 比較...」，以及起始頁或「選擇檔案或資料夾」對話框中路徑旁的地球圖示按鈕，
可連線到伺服器取得要比較的檔案或資料夾，而不必瀏覽本機磁碟。

從伺服器取得檔案或資料夾：

. 選擇「通訊協定」。
  變更通訊協定時，「埠號」會改為該通訊協定的慣用埠號，除非您自行輸入了其他埠號。
  可選擇的通訊協定如下：
** 「SFTP（透過 SSH）」。
** 「FTPS（明確 TLS）」：連到 FTP 埠號（21），並在登入前切換為 TLS。
** 「FTPS（隱含 TLS，連接埠 990）」：適用於一開始就要求 TLS 的伺服器。
** 「FTP（未加密）」。
. 輸入伺服器的「主機」、「埠號」與「使用者」。
  使用 SFTP 時，主機可以是 `~/.ssh/config` 中的 `Host` 別名，使用者也可以留空，
  與 `ssh` 相同（請參閱 <<remote-ssh-config>>）。
. 使用 SFTP 時，選擇登入方式：「密碼」、「私密金鑰」（可另外設定「金鑰密碼」），或「SSH 代理程式」。
  「SSH 代理程式」使用 `ssh-agent`（Windows 上為 Pageant）持有的金鑰，以及 `~/.ssh/config` 指定的金鑰，
  這裡不需輸入任何內容。
  FTP 與 FTPS 以密碼登入。
. 如有需要，可展開「進階」設定代理伺服器、FTP 主動模式或 FTPS 用戶端憑證（請參閱 <<remote-advanced>>）。
. 輸入要取得的檔案或資料夾的「遠端路徑」，或按一下旁邊的資料夾按鈕，
  從伺服器的資料夾與檔案清單中選擇。
. 按一下「連線」。

資料夾按鈕會連線並列出「遠端路徑」所在的資料夾；若「遠端路徑」是空的，則列出您在伺服器上的主資料夾。
清單先列資料夾，再列檔案及其大小；名稱以點開頭的隱藏項目排在各組最後。
按一下資料夾即可開啟，按一下檔案即可選取。
「遠端路徑」會隨著您按的項目更新，因此「連線」會取得您所在的資料夾或選取的檔案。
按兩下檔案則會立即取得。
向上箭頭按鈕會開啟上一層資料夾，重新整理按鈕會再次列出「遠端路徑」，包括您自行輸入的路徑。
不存在的路徑會列出其上方最近的現有資料夾。
清單顯示期間會保持連線，因此切換資料夾時不必每次重新登入；
關閉對話框，或變更主機、埠號、使用者、密碼或金鑰時，清單就會關閉。
每個資料夾最多顯示前 10,000 個項目。

取得的路徑會填入「左側」、「中間」或「右側」路徑，用法與本機路徑相同。
再連線一次以取得另一側，即可比較兩個遠端位置；
或讓另一側維持本機路徑，以比較遠端路徑與本機路徑。
對話框會記住上次成功連線的主機、埠號、使用者與金鑰路徑，方便從同一台伺服器取得第二個路徑；
但密碼或金鑰的密碼短語不會被記住。

取得的**檔案**可編輯：編輯後按「儲存」，會在背景透過一個新的連線將檔案上傳回伺服器，
並提供「取消」按鈕。
若伺服器上的路徑是連結，會更新它指向的檔案。
若取得檔案後，伺服器上的檔案已被修改或刪除，上傳會在寫入之前被拒絕。

透過 SFTP 時，上傳內容會先寫到原檔旁邊的隱藏暫存檔（`.名稱.oxidemerge-new-...`），
檔名結尾保留原檔的副檔名（`config.php` 即為 `.config.oxidemerge-new-....php`），
因此網頁伺服器不會把指令碼的原始碼當成文字顯示。
這份副本在核對完成前只有您可讀取。
OxideMerge 接著把這份副本讀回來，與這裡的檔案比對。
只有完整且相符的副本，才會套用原檔的擁有者、群組與權限（包括 set-user-ID 與 set-group-ID 位元），並取代原檔。
若在這期間有人把其他檔案或連結放到副本的位置，儲存會被拒絕。
換上之前，OxideMerge 會再確認一次伺服器上的檔案沒有被別人修改。
因此連線中斷、磁碟已滿或按下「取消」時，伺服器上的檔案都維持原狀，訊息也會說明這點。

包括 OpenSSH 在內，大多數 SFTP 伺服器無法一步把檔案改名蓋過另一個檔案。
這時 OxideMerge 會先把原檔改名移到一旁（`.名稱.oxidemerge-old-...`），
再把新副本改名換上，然後刪除原檔。
這中間會有片刻找不到該檔案，但檔案絕不會只寫入一部分。
若連線在兩次改名之間中斷，訊息會指出另一個版本存放在哪個檔案，
方便您到伺服器上檢查，必要時再改名回來。
無法移除的暫存檔也會以同樣方式指出，您可以自行刪除。
若只是新副本換上之後，移到一旁的原檔無法刪除，檔案仍會儲存，並以警告指出要刪除的副本。
新副本換上原檔之後連線才中斷，也不會使儲存失敗。

取代原檔的副本是一個新檔案。
它保有原檔的擁有者、群組與權限，但不會保有存取控制清單（ACL），
也不再是原檔的硬連結之一。
SFTP 看不到這些資訊，所以 OxideMerge 無法判斷檔案是否有這些設定。
若伺服器上這點很重要，請開啟「檔案 → 直接覆寫遠端檔案」：
「儲存」就會直接覆寫原檔，保留這些設定。

以下四種情況，OxideMerge 也會不經詢問直接覆寫：

* 檔案屬於其他使用者。
* 無法在檔案所在的資料夾建立新檔案。
* 伺服器不提供檔案的擁有者資訊。
* 伺服器無法為檔案改名。

透過 FTP 時，「儲存」一律直接覆寫，因為 FTP 無法設定新檔案的擁有者與權限。

直接覆寫的上傳在開始寫入之前都可以取消。
開始寫入之後若連線中斷，伺服器上的檔案可能只寫入一部分。
訊息會說明這點，再按一次「儲存」即可完成寫入。

您的編輯仍保留在分頁中，可與伺服器上的版本比較。
在上傳成功之前，分頁視為尚未儲存，因此關閉分頁或結束程式時會先詢問，而「儲存」會再試一次。
在關閉分頁時選擇「儲存」，會等上傳完成後才關閉。

取得的**資料夾**同樣可寫入。
在資料夾比較中複製或刪除檔案，或從中開啟檔案並編輯後，按「儲存」就會把變更寫回伺服器：

* 新增或內容有變更的檔案會上傳。
* 新增的資料夾會建立。
* 已移除的檔案與資料夾會在伺服器上刪除。

未變更的檔案不會再次傳送。
每次上傳或刪除之前，OxideMerge 都會確認伺服器上的檔案仍是當初取得的那一份：
取得後在伺服器上被修改的檔案不會被覆寫或刪除，取得後才在伺服器上建立的同名新檔案也不會被覆寫。
取得前幾秒內才修改過的檔案也會比對其內容，因為同一秒內的第二次修改不會改變其大小與時間。
儲存後的訊息會列出這些檔案；您的副本仍保留在分頁中，可與伺服器上的版本比較後再儲存一次。
其餘變更照常寫入。
在所有變更都寫入之前，分頁視為尚未儲存。
若資料夾的本機副本已不存在，或其中有部分無法讀取，則不會寫入任何內容，
因此無法讀取的檔案絕不會在伺服器上被刪除。

檔案會先上傳，再刪除已移除的檔案。
因此，移到其他資料夾的檔案，要等新的副本已在伺服器上，才會從原位置刪除；
若該上傳失敗，舊的副本會保留。
取得的副本中的符號連結或特殊檔案，或不是有效 Unicode 的名稱，絕不會上傳，也絕不視為已移除；
伺服器上的檔案維持原樣，儲存後的訊息會列出它。

為避免不小心取得過大的資料夾，每次取得限制在 4 GiB、50,000 個檔案與資料夾，以及 64 層巢狀資料夾以內。
無法在本機作為檔名的名稱會被略過；
本機無法區分的兩個名稱（例如在不分大小寫的檔案系統上的 `A.txt` 與 `a.txt`），第二個也會被略過。
取得的副本中不會建立 `.bak` 備份，因為儲存時會一併上傳。

「檔案 → 從伺服器重新載入」會透過新的連線，再次取得目前分頁中遠端檔案或資料夾在伺服器上的副本，
並取代先前取得的副本。
若這樣會取代尚未儲存到伺服器的變更，會先詢問；
同意後，遠端檔案的編輯會被取代（可用「復原」找回），本機那一側的編輯則會保留。

使用 FTP 與 FTPS 時，OxideMerge 依伺服器回報的檔案大小與修改時間，判斷檔案是否在伺服器上被修改；
伺服器未回報修改時間時，則讀取檔案並比對其內容。
無法以標準機器可讀格式（`MLSD`）列出資料夾的伺服器，改從一般清單讀取；
連結會依其指向的檔案或資料夾處理。
除非勾選「主動模式」（請參閱 <<remote-advanced>>），傳輸使用被動模式，而且一律連到登入時所連的伺服器。

使用 FTPS 時，若下載的連線在沒有 TLS 結束訊息的情況下中斷（中間的任何人都能造成這種情況），
會與伺服器回報的大小比對，不足時拒絕。
許多 FTPS 伺服器（例如 ProFTPD 與 vsftpd）要求每次傳輸沿用登入時的 TLS 工作階段；
伺服器為此提供的每個工作階段票證只能用於一次傳輸，因此用完時，OxideMerge 會在下一次傳輸之前重新登入。

IMPORTANT: 一般 FTP 會以不加密的方式傳送密碼與檔案：在您與伺服器之間網路上的任何人都能讀取，
對話框也會如此提醒。
只要伺服器支援，請改用 FTPS 或 SFTP。

連線資訊（包括密碼或金鑰的密碼短語）只會保留在記憶體中，直到分頁關閉為止；
不再需要時，密碼會在記憶體中被覆寫。
這些資訊絕不會寫入設定檔。
顯示取得之檔案或資料夾的分頁，不會列入已儲存的工作區（請參閱 <<workspaces>>）、
OxideMerge 啟動時自動重新開啟的工作階段，以及最近使用的路徑，因為程式關閉後，它們的暫存副本就不存在了。
若要比較同一個遠端路徑，請重新連線。

在送出密碼或金鑰之前，OxideMerge 會先檢查伺服器的主機金鑰。
它會先以 `ssh` 的方式讀取您自己的 SSH `~/.ssh/known_hosts`：
`*.example.com`、`!host.example.com` 這類主機樣式（不分大小寫）與 `ssh-keygen -H` 雜湊過的名稱都能比對，
連接埠不是 22 的伺服器以 `[主機]:埠號` 查找。
若伺服器列在其中且金鑰相同，且也符合 OxideMerge 已記錄的金鑰（若有），即予以信任。
若列在其中的是同類型但不同的金鑰，或該金鑰在其中標記為 `@revoked`，則與 `ssh` 一樣拒絕連線。
若伺服器已重新安裝，請以 `ssh-keygen -R 主機`（或 `ssh-keygen -R "[主機]:埠號"`）移除舊金鑰後再重新連線。
OxideMerge 也會檢查設定檔旁它自己的 `known_hosts` 檔案。
第一次連線到兩者都沒有記錄的伺服器時，OxideMerge 會顯示金鑰的類型與指紋
（`SHA256:...`，與 `ssh` 顯示的格式相同），並詢問是否信任。
請先與伺服器管理員提供的指紋比對，再按「信任並連線」。
若您的 `~/.ssh/known_hosts` 為該伺服器只記錄了其他類型的金鑰，會顯示警告。

伺服器也可以用主機憑證證明身分，由您的 `~/.ssh/known_hosts` 以 `@cert-authority` 行指定的憑證授權單位簽署，
例如 `@cert-authority *.example.com ssh-ed25519 AAAA...`。
OxideMerge 只向有這類行指定的伺服器要求憑證。
若憑證由該授權單位簽署、主體（principals）中列有該伺服器（或其 `HostKeyAlias`）、目前在有效期間內，
且沒有關鍵選項（critical options），就直接信任，不會先詢問您。
不符合其中任何一項的憑證會被拒絕；授權單位或金鑰標記為 `@revoked` 的也會被拒絕。
可檢查以 Ed25519、ECDSA（P-256 或 P-384）或採用 SHA-2 的 RSA 簽署的憑證；
使用其他演算法的授權單位（例如採用 SHA-1 的 RSA 或 ECDSA P-521）會被拒絕。
沒有指定授權單位的伺服器若提供憑證，則以其一般金鑰檢查。

之後每次連線，都會比對記錄的金鑰。
若金鑰不再相符，OxideMerge 會拒絕連線，而不是信任一台可能不是您預期的伺服器。
這通常表示伺服器已經重建或重新安裝；若您確定是這種情況，
可從 OxideMerge 的 `known_hosts` 檔案中移除該伺服器的舊記錄（格式為「主機:埠號」加上其金鑰），再重新連線。
若任一個 `known_hosts` 檔案存在卻無法讀取，或含有無法解讀的行
（它自己檔案中的任何一行，或 `~/.ssh/known_hosts` 中它會檢查的金鑰類型的行），
OxideMerge 在能讀取之前不會連線到任何伺服器。

FTPS 伺服器的檢查方式與網頁瀏覽器檢查網站相同：憑證必須對該主機名稱有效，並由知名的憑證授權單位擔保。
許多 FTP 伺服器使用的是自我簽署的憑證。
第一次連線到這類伺服器時，OxideMerge 會顯示憑證的指紋並詢問是否信任，與未知的 SSH 主機金鑰相同。
信任後，憑證會記錄在設定檔旁的 `known_certs` 檔案中（可攜式使用時為 `oxidemerge-known_certs`），
之後若連線時出現不同的憑證，會拒絕連線。
若伺服器的憑證已更新，請從該檔案中移除該伺服器的那一行（「主機:埠號」加上憑證）。
兩種情況下都會在送出密碼之前檢查憑證；
不提供 TLS 的伺服器在 FTPS 下會被拒絕，而不會在沒有 TLS 的情況下登入。

[[remote-ssh-config]]
==== SSH 設定、跳板主機與登入問題

OxideMerge 連線到 SFTP 伺服器的方式與 `ssh` 相同，依照您的 `~/.ssh/config`（以及系統的 `/etc/ssh/ssh_config`）。
「主機」可以是其中的別名（例如 `prod`），其區塊可設定 `HostName`、`User`、`Port`、`IdentityFile`
（以及 `IdentitiesOnly`）、`HostKeyAlias`（查找與認證其金鑰時使用的名稱）與 `UserKnownHostsFile`。
位於字首的 `#` 表示註解。
`Include` 會就地讀取，但略過名稱以點開頭的檔案，除非樣式的檔名也以點開頭。
依 `host`（與 `ssh` 相同，為目前已設定的 `HostName`）、`originalhost`、`user`、`localuser` 或 `all`
條件的 `Match` 區塊也會套用；`Match exec` 絕不會執行。
與 `ssh` 相同，先找到的值優先，而在對話框中輸入的使用者，或 22 以外的埠號，優先於設定檔；
命令列的位址中寫明的任何埠號都優先，包括 `:22`。
未指定使用者時，使用設定檔的 `User`，或您自己的使用者名稱。

需經由跳板主機連線的伺服器（`ProxyJump bastion` 或 `ProxyJump user@hop1,hop2:2222`），
會與 `ssh -J` 一樣依序經過每一台（最多 8 台）連線。
跳板主機以 SSH 代理程式的金鑰及其區塊指定的金鑰登入，且在送出任何內容之前，會像伺服器一樣檢查其金鑰。
`ProxyCommand` 與 `ssh` 一樣交由 shell 執行，並代入 `%h`、`%p`、`%r` 與 `%n`，連線會經由它進行。
與 OpenSSH 相同，主機或使用者名稱若含有 shell 會解讀的字元（引號、`$`、`;`、`|`、空白等），
或以 `-` 開頭，會在執行任何命令之前被拒絕。

伺服器在登入時可能提出問題（*鍵盤互動式*登入），例如一次性密碼、第二道驗證或新密碼。
OxideMerge 會在標示伺服器名稱的「登入問題」視窗中顯示這些問題；
除非伺服器表示答案可以顯示，否則答案會隱藏；「取消」則表示拒絕回答。
伺服器若只詢問一次密碼，會自動以您提供的密碼回答。
未提供金鑰密碼的加密私密金鑰，也會以同樣方式詢問其密碼；
若旁邊有其 `.pub` 檔，則要等伺服器表示接受該金鑰後才會詢問。
伺服器拒絕過的密碼不會再次送出。
登入方式會從您選擇的那一種開始依序嘗試，以支援需要多種方式登入的伺服器。

[[remote-advanced]]
==== 代理伺服器、主動模式與用戶端憑證

連線對話框中的「進階」包含大多數伺服器用不到的設定：

* 「代理伺服器」：經由 SOCKS5 代理伺服器（`socks5://host:1080`，或 `socks5://user@host:1080` 並填寫
  「代理伺服器密碼」）或允許 `CONNECT` 的 HTTP 代理伺服器（`http://host:8080`）連線。
  輸入在位址中的密碼，會在離開該欄位時移到會隱藏內容的「代理伺服器密碼」。
  SFTP 與 FTP 都會使用代理伺服器，包括每一條 FTP 資料連線。
  對於 `~/.ssh/config` 中設有跳板主機或 `ProxyCommand` 的伺服器，改用後者；
  第一台跳板主機則經由代理伺服器連線。
* 「主動模式」（FTP）：每次傳輸時由伺服器反向連線到這台電腦（使用 `EPRT`，伺服器不支援時改用 `PORT`），
  適用於拒絕被動模式的伺服器。
  資料連線只接受來自伺服器位址的連線。
  主動模式無法經由代理伺服器使用，在位址轉譯（NAT）路由器或阻擋連入連線的防火牆後方通常也無法使用。
* 「用戶端憑證」與「憑證金鑰」（FTPS）：提供給要求憑證之伺服器的 PEM 憑證，
  其私密金鑰可放在同一個檔案或金鑰檔中。
  金鑰不可加密。

對話框會連同上次成功的連線，記住代理伺服器位址、主動模式與憑證檔案，但絕不記住代理伺服器密碼。

[[remote-command-line]]
==== 命令列與工作中的伺服器路徑

在命令列與工作檔中（請參閱 <<jobs>>），路徑也可以是伺服器上的檔案或資料夾，以位址表示：

[source,sh]
----
oxidemerge sftp://ann@build.example.com/var/www/site ./site     # SFTP，埠號 22
oxidemerge ftpes://ann@ftp.example.com/public/index.html index.html  # 明確 FTPS，埠號 21
oxidemerge ftps://ann@ftp.example.com:990/public ./public -r    # 隱含 FTPS
oxidemerge --cli ftp://ftp.example.com/pub/README README         # 匿名的一般 FTP
oxidemerge sftp://ann@host/~/notes.txt notes.txt                # 在 ann 的主資料夾中
----

位址的格式為 `scheme://[使用者@]主機[:埠號]/路徑`。
IPv6 位址要加上方括號，例如 `sftp://ann@[2001:db8::1]/srv`。
以 `/~/` 開頭的路徑位於使用者在伺服器上的主資料夾，其他字元可寫成 `%XX`。
SFTP 的主機可以是 `~/.ssh/config` 中的別名（請參閱 <<remote-ssh-config>>），
未指定使用者名稱時，使用其 `User` 或您自己的使用者名稱。
FTP 未指定使用者名稱時以 `anonymous` 登入，密碼為 `anonymous@`，絕不使用 `OXIDEMERGE_REMOTE_PASSWORD` 中的密碼。

密碼絕不放在位址中，否則任何看得到命令列或工作檔的人都能讀到；位址中含有密碼會被拒絕。
請改為設定在環境變數 `OXIDEMERGE_REMOTE_PASSWORD` 中。
SFTP 在指定 `--ssh-key 檔案` 時以該金鑰登入（此時環境變數存放金鑰密碼，若有的話），
否則使用環境變數中的密碼，再否則使用 `ssh-agent` 與 `~/.ssh/config` 指定的金鑰。
FTP 與 FTPS 需要密碼，以 `anonymous` 登入時除外。
OxideMerge 啟動時會移除這個環境變數，因此它所執行的程式（例如外部工具）不會繼承它。
伺服器在登入時提出的問題，以及未提供密碼之加密金鑰的密碼，會在終端機上詢問，輸入時不顯示
（此時按 *Ctrl+C* 會在結束程式時恢復顯示輸入）；沒有終端機時則拒絕回答。

`--proxy URL` 經由代理伺服器連線，作用同對話框中的「代理伺服器」。
代理伺服器密碼從環境變數 `OXIDEMERGE_PROXY_PASSWORD` 讀取（啟動時同樣會移除），位址中含有密碼會被拒絕。
`--ftp-active` 使用 FTP 的主動模式。
`--client-cert 檔案` 提供 FTPS 用戶端憑證，金鑰不在同一個檔案時以 `--client-key 檔案` 指定。

伺服器的檢查方式與程式中相同，使用同樣的 `known_hosts` 與 `known_certs` 檔案。
尚未信任的伺服器會被拒絕，錯誤訊息會顯示其指紋。
請與管理員提供的指紋比對，再加上 `--trust-fingerprint SHA256:...` 重新執行以信任它；
之後就會記住，與按「信任並連線」相同。
金鑰或憑證已變更的伺服器會被拒絕。

每個伺服器路徑都會在比較前取得為暫存副本，再像本機路徑一樣開啟。
在視窗中，「儲存」會如上所述將變更寫回伺服器。
不開啟視窗時，執行過程對取得之副本所做的變更（例如 `sync` 工作對目的地所做的變更），
會在執行後以相同的檢查寫回伺服器；在伺服器上已被修改的檔案會回報為錯誤（結束代碼 2）。
這些寫入會依照設定中儲存的「檔案 → 直接覆寫遠端檔案」進行。
同步中途停止且未能復原所有變更時（結束代碼 5），會改為在取得的副本中復原這些變更，且不寫回任何內容。
以 `--sync-plan` 製作的同步計畫會以位址識別伺服器上的資料夾，
因此 `--sync-apply` 會將它套用到該次執行取得的副本；
與本機資料夾相同，若計畫要變更的檔案已與規劃時不同，就會被拒絕。

NOTE: 已在 Linux 上以 OpenSSH 10.5p1 與 vsftpd 3.0.5 檢查。
SFTP 使用私密金鑰時，會拒絕尚未被告知要信任的伺服器，並顯示該伺服器的指紋，
與 `ssh-keygen -lf` 印出的相同；加上 `--trust-fingerprint` 後即可連線，金鑰也會被記住。
相同的檔案結束代碼為 0，不同的檔案為 1，資料夾比較會列出不同的檔案。
視窗會把取得的檔案開啟為可寫入，並顯示差異。
`sync` 工作會上傳新檔案。
上傳較短的內容會就地覆寫檔案；若伺服器上的檔案在取得之後已變更，上傳會被拒絕。
匿名 FTP 使用以目前使用者身分執行、未 chroot 的 vsftpd，因此遠端路徑是磁碟上的實際目錄。
相同的檔案結束代碼為 0，不同的檔案為 1，視窗會把它開啟為可寫入。
`sync` 工作會上傳檔案，再次執行會更新它。
`--ftp-active` 比較相同檔案時結束代碼為 0。
位址中含有密碼時，兩種通訊協定都會被拒絕。

[[compare-types]]
=== 比較類型

OxideMerge 提供五種比較類型，分別針對不同的內容設計：

[cols="1,4"]
|===
|類型 |顯示內容

|文字
|並排顯示各行，並醒目標示變更的字詞。
您可以編輯與合併文字；比較選項與比較規則決定哪些變更算是差異。
適用於原始碼、設定檔、CSV 檔與其他可閱讀的文字。

|二進位
|以十六進位檢視顯示位元組。
差異可以複製與儲存，但各行不會對齊。
例如在開頭附近插入一個位元組，其後的所有位元組都會跟著位移。

|影像
|以並排、疊加、滑動分隔線、閃爍或差異影像等方式顯示像素。
有差異的區域可以從一張影像複製到另一張。

|資料夾
|比較兩個或三個資料夾中的項目。
您可以複製、刪除與合併項目，也可以在個別的比較中開啟每個檔案。

|網頁
|比較兩個或三個網頁：可見文字、格式化的 Markdown、HTML 原始碼或下載的資源。
網頁為唯讀，OxideMerge 不會將任何內容存回網頁伺服器。
|===

文件、試算表與程式是以 OxideMerge 從中讀取到的文字進行比較，屬於文字或表格比較，而非獨立的比較類型。
Word 文件、活頁簿與加上標籤的 PDF 也能以*格式化*顯示，包含標題、清單與表格；請參閱 <<documents>>。

「比較方式」設為「自動」時，OxideMerge 會依序檢查下列條件，並採用第一個符合的條件：

. 任一側為 `http://` 或 `https://` 網址：網頁比較。
. 每一側都是 HTML 檔案（`.html` 或 `.htm`）：網頁比較。
  除非您先前選過其他模式，否則使用格式化模式。
  例外：指定輸出檔（`-o`）的合併，或在主控台產生修補檔（`--patch`）時，會以文字比較。
. 每一側都是資料夾：資料夾比較。
. 所有檔案都是 OxideMerge 能讀取為文字的類型 —— 文件、試算表或 ELF 程式（請參閱 <<documents>>）——
  或可由解譯器外掛程式轉換（請參閱 <<unpackers>>）：以讀取到的文字進行比較，且為唯讀。
  由 OxideMerge 自行讀取的試算表會以表格比較開啟。
  這一條在壓縮檔與二進位規則之前，因此 `.docx`、`.xlsx` 與 `.odt` 會以其中的文字開啟，
  而非視為實際的 zip 壓縮檔。
  在「選項 → 外掛」中取消「將文件、試算表與 ELF 檔讀取為文字」，這些檔案就會交由下列規則處理。
. 每一側都是壓縮檔：解壓縮後以資料夾比較。
. 所有檔案的副檔名都是影像格式（例如 `.png`、`.jpg`、`.gif`、`.bmp`、`.tif` 或 `.webp`）：影像比較。
. 檔案的前 8 KB 含有零位元組：二進位比較。
  例外：帶有位元組順序標記的 UTF-16 文字仍視為文字。
. 其他情況：文字比較。

若要自行指定類型，請使用對話框中的「比較方式」、已開啟分頁中的「比較 → 比較方式」，或命令列的 `-t` 參數。

PDF、文件、試算表、Jupyter notebook 與 ELF 程式，OxideMerge 同樣以文字方式讀取，
請參閱 <<documents>>。

=== 文字比較視窗

比較的每一側，上方都有標題列，下方都有頁尾：

* 標題列顯示檔案名稱與所在資料夾；按一下鎖頭按鈕，即可將該側設為唯讀。
* 頁尾顯示儲存時使用的換行格式與編碼，以及目前行號與總行數。

在頁尾選擇其他編碼時，OxideMerge 會以該編碼重新讀取檔案。
變更編碼後請檢查文字是否正確，在編輯或儲存之前尤其需要確認。

差異以顏色區分：

* 變更的行為藍色。
* 雙向比較時，只存在於一側的行為綠色。
* 三方比較時，尚未解決的衝突為紅色。
* 在變更的行中，有變更的字詞或字元會醒目標示。

在「選項 → 一般」中開啟「色盲友善的差異顏色」後，變更的行會改為紫色，只存在於一側的行會改為藍色。

兩個窗格之間的連接線會將每個差異的兩側相連，目前的差異則會醒目標示。
只有在差異成為目前的差異，或指標移到它上方時，才會顯示它的複製箭頭。

工具列的按鈕分為四組：

* 「差異」：移到下一個、上一個、第一個或最後一個差異。
* 「複製」（三方比較時為「合併」）：在各側之間複製差異。
* 「編輯」：復原與重做。
* 「檢視」：尋找、摺疊未變更的行，以及切換自動換行。

視窗夠寬時，工具列也會顯示各組的名稱。
差異編號旁的 +/− 數字，分別是新增與刪除的行數。

右側的位置窗格顯示整個檔案的概覽，按一下即可跳到該位置。
二進位比較、網頁比較的格式化模式，以及文件的格式化檢視，也都有位置窗格。

=== 在差異之間移動

您可以使用下列按鍵在檔案中移動：

[cols="1,2"]
|===
|按鍵 |動作

|kbd:[Alt+↓]、kbd:[Alt+↑]
|移到下一個或上一個差異

|kbd:[Alt+Home]、kbd:[Alt+End]
|移到第一個或最後一個差異

|kbd:[Alt+PgDn]、kbd:[Alt+PgUp]
|移到下一個或上一個衝突（三方比較）

|kbd:[Ctrl+G]
|跳至指定行號
|===

若檔案是從資料夾比較開啟的，您可以接著切換到其他檔案：
在最後一個差異按 kbd:[Alt+↓]，會開啟下一個有差異的檔案；
在第一個差異按 kbd:[Alt+↑]，則會開啟上一個有差異的檔案，並停在它的最後一個差異。
在三方資料夾比較中，kbd:[Alt+PgDn] 與 kbd:[Alt+PgUp] 也會以相同方式，
前往下一個或上一個仍有未解決衝突的檔案。

將指標停在導覽按鈕上，即可看到它會逐一走過哪些項目、對應的按鍵，
以及它到結尾就會停止，不會從頭再開始。

[[folder-navigation]]
==== 在資料夾的差異之間移動

在資料夾比較中，同樣的按鍵可用於資料夾清單下方顯示的檔案，並可延續到資料夾中的其他檔案：

* kbd:[Alt+↓] 前往該檔案的下一個差異；過了最後一個差異後，會選取下一個有差異的檔案，
  並前往它的第一個差異。
* kbd:[Alt+↑] 方向相反：在第一個差異之前，會前往上一個檔案的最後一個差異。
* kbd:[Alt+Home] 與 kbd:[Alt+End] 分別前往第一個檔案的第一個差異，以及最後一個檔案的最後一個差異。
* 狀態列會顯示目前位置，例如「檔案 2 / 5 · 差異 3 / 7」。

導覽涵蓋資料夾清單中顯示為不同的檔案，並依清單順序進行。
二進位檔也包含在內，但無法讀取的檔案不包含在內。
到達最後一個檔案的最後一個差異時，OxideMerge 會告知您，不會從頭再開始。

若在檔案仍在載入時按下按鍵，OxideMerge 會記住這個動作，等檔案顯示後再移動，因此不會略過任何差異。
若檔案無法讀取，窗格會加以說明，並提供「重試」與「略過」。
資料夾仍在比較時，後面可能還有其他檔案，訊息會如此說明，而不會直接結束。
若比較已被停止，結尾的訊息會說明它只涵蓋已比較的檔案。

比較之後又變更的檔案，會以目前的內容顯示；若已不再有差異，下一步會接著前往下一個檔案。
清單下方顯示的檔案若在磁碟上變更，會重新載入並停在同一個差異。

在三方資料夾比較中，kbd:[Alt+PgDn] 與 kbd:[Alt+PgUp] 會逐一走過兩側都有變更之檔案中的未解決衝突。
變更可以無衝突合併的檔案，會在載入後略過；只有一側變更的檔案則不會前往。
kbd:[Alt+↓] 仍會停在每個有變更的檔案。

=== 複製差異

複製差異可將某一側的變更帶到另一側。
OxideMerge 會修改目標窗格中的文字，但要等到儲存後，磁碟上的檔案才會變更。
複製之前，請先確認目前作用中的窗格，以及箭頭指向的方向。

* 按一下兩個窗格之間分隔線上的箭頭，可複製目前的差異或指標所在的差異。
* 按 kbd:[Alt+→] 或 kbd:[Alt+←]，可將目前的差異或選取的行複製到右側或左側。
* 按 kbd:[Ctrl+Alt+→] 或 kbd:[Ctrl+Alt+←]，可將所有差異複製到右側或左側。
* 三方比較時，工具列的「合併」群組可將目前的差異或所有差異，從左側或右側複製到中間。
  您也可以在差異上按右鍵，將它從左側或右側複製到中間，或從中間複製到左側或右側。
* 按 kbd:[Ctrl+Z] 復原變更，按 kbd:[Ctrl+Y] 或 kbd:[Ctrl+Shift+Z] 重做。

[[saving-files]]
=== 儲存檔案

您可以使用下列命令將變更寫入磁碟：

* kbd:[Ctrl+S] 儲存目前分頁中所有已修改的窗格。
* kbd:[Ctrl+Shift+S] 儲存所有分頁中已修改的窗格。
* 「檔案 → 另存新檔」以其他名稱儲存某一側。

OxideMerge 以兩個步驟安全地儲存檔案：

. 先將新內容寫入同一資料夾中的暫存檔。
. 再以暫存檔取代原始檔案。

任一步驟失敗時，OxideMerge 會顯示錯誤，絕不會直接覆寫原始檔案。
因此，即使檔案本身可以寫入，所在資料夾仍必須允許 OxideMerge 建立與取代檔案。

若要保留檔案先前的內容，請在「選項 → 一般」中開啟「覆寫檔案時保留 .bak 備份」，
OxideMerge 便會將舊內容保留為 `<name>.bak`。
下次儲存時會取代這份備份，因此它並不是版本紀錄。

=== 編輯文字

非唯讀的窗格都可以編輯。
在文字中按一下，即可將游標放在該處並開始輸入，操作方式與一般的文字編輯器相同。

* kbd:[Enter] 會開始新的一行，並沿用上一行的縮排。
  kbd:[Backspace] 與 kbd:[Delete] 會刪除一個字元，或將一行與相鄰的行合併。
* kbd:[Ctrl+V] 會在游標處貼上，可一次貼上任意行數。
* 若要選取文字，請拖曳、按住 kbd:[Shift] 再按一下，或按住 kbd:[Shift] 移動游標。
  按兩下會選取一個字，按三下會選取整行（含換行），kbd:[Ctrl+A] 會選取整個檔案。
  拖曳超過窗格頂端或底部時，窗格會捲動並繼續選取。
  輸入或貼上的內容會取代選取的文字。
* kbd:[Ctrl+C] 複製選取的文字，kbd:[Ctrl+X] 剪下。
  沒有選取任何文字時，會複製或剪下整行。
* 方向鍵、kbd:[Home]、kbd:[End]、kbd:[PgUp] 與 kbd:[PgDn] 可移動游標。
  kbd:[Ctrl+Home] 與 kbd:[Ctrl+End] 移到檔案開頭與結尾。
  在 macOS 上，kbd:[Cmd+←] 與 kbd:[Cmd+→] 移到行首與行尾。
  開啟自動換行時，上下方向鍵、kbd:[PgUp] 與 kbd:[PgDn] 會以顯示行為單位移動，
  因此長的一行需要按數次；kbd:[Home] 與 kbd:[End]（kbd:[Cmd+←] 與 kbd:[Cmd+→]）
  會先移到該顯示行的開頭或結尾，再按一次才移到整行的開頭或結尾。
  按住 kbd:[Shift] 時，這些按鍵都會延伸同一個選取範圍。
* kbd:[Tab] 會輸入定位字元；選取範圍跨越多行或為整行時，則會增加這些行的縮排。
  kbd:[Shift+Tab] 會減少選取行（或游標所在行）的縮排。
  游標在窗格中時，kbd:[Ctrl+\]] 與 kbd:[Ctrl+[] 的作用相同。
  若檔案中以定位字元縮排的行多於以空格縮排的行，會以定位字元縮排；
  其他檔案則以「Tab 寬度」個空格縮排。
  空白行不會增加縮排；減少縮排時，會移除一個定位字元，或最多「Tab 寬度」個空格。
  選取範圍結束於某行開頭時，該行不受影響；選取範圍會隨文字移動，
  因此在 kbd:[Tab] 之後立即按 kbd:[Shift+Tab]，即可還原相同的文字與選取範圍。
  每次操作都是一個復原步驟。
* kbd:[Ctrl+←] 與 kbd:[Ctrl+→]（macOS 上為 kbd:[Option+←] 與 kbd:[Option+→]）以單字為單位移動，
  按住 kbd:[Shift] 時則以單字為單位選取。
  以單字移動時，會移到下一個單字的結尾，或前一個單字的開頭；在行尾或行首時，會移到下一行或上一行。
  字母、數字與 `_` 組成一個單字（`snake_case` 與 `camelCase` 都是一個單字），
  連續的標點符號自成一個單字（`x.len` 是三個單字），每個中文、日文或韓文字也各算一個單字。
* kbd:[Ctrl+Backspace] 與 kbd:[Ctrl+Delete]（macOS 上為 kbd:[Option+Backspace] 與
  kbd:[Option+Delete]）會刪除游標前或後的單字；有選取範圍時，則刪除選取的文字。
  按一次 kbd:[Ctrl+Z] 即可復原該單字。
* 在 macOS 上，游標在文字中時，kbd:[Option+←] 與 kbd:[Option+→] 會以單字移動，而不是複製差異；
  請按 kbd:[Esc] 離開文字，或使用複製按鈕。
  kbd:[Option] 加上字母、數字或符號會輸入對應的字元（kbd:[Option+S] 輸入 ß），因此
  kbd:[Alt+C]、kbd:[Alt+Z]、kbd:[Alt+P] 與 kbd:[Alt+S] 要等游標離開文字後才會作用；
  這些命令仍可從選單執行。
* 每按一次 kbd:[Esc] 只執行一個動作，依序取第一項適用的動作：
. 關閉開啟中的選單。
. 關閉對話方塊，或正在輸入的欄位。
. 關閉搜尋列。
. 從多個游標回到一個游標。
. 結束選取（游標留在原處）。
. 移除游標，方向鍵便恢復逐列移動。
. 關閉分頁。
* 輸入法可在游標處使用，因此您可以輸入中文、日文或韓文。
* 在非常大的檔案中，於同一行內輸入仍然流暢：OxideMerge 會在您稍停片刻後，
  或在其他按鍵、按一下或命令之前重新比較，因此正在輸入的那一行，顏色可能會稍晚更新。
  新增一行、貼上或復原則會立即重新比較。
* 跨越多行的選取也會選取這些列，因此複製按鈕以及 kbd:[Alt+→] 與 kbd:[Alt+←] 可將這些行複製到另一側。
* kbd:[Ctrl+\]] 增加選取行的縮排，kbd:[Ctrl+[] 減少縮排（使用文字游標時，也可以使用 kbd:[Tab] 與
  kbd:[Shift+Tab]，請參閱上文）。
* kbd:[Ctrl+D] 會在選取的行（或游標所在的行）下方放置一份複本，並選取該複本。
  kbd:[Alt+Shift+↑] 與 kbd:[Alt+Shift+↓] 會將這些行連同選取範圍，越過相鄰的一行上移或下移。
  與 kbd:[Tab] 相同，這些命令作用於文字選取範圍所在的行（結束於某行開頭的選取不包含該行）；
  沒有文字游標時，則作用於使用中窗格在所選列中的行。
  每個動作都是一個復原步驟，也都可以從「編輯」選單執行。
  不按 kbd:[Shift] 時，kbd:[Alt+↓] 與 kbd:[Alt+↑] 仍是前往下一個與上一個差異。
* 沒有游標時，按 kbd:[F2] 或 kbd:[Enter] 會將游標放在目前這一行的結尾。

[[multiple-cursors]]
==== 多個游標

若要在同一窗格的多個位置輸入相同內容，可以使用多個文字游標：

* 按住 kbd:[Ctrl] 按一下（macOS 上為 kbd:[Cmd]），會在該處新增游標，或移除該處的游標。
  按住 kbd:[Ctrl] 按兩下或按三下，則會新增單字或整行的選取。
* kbd:[Ctrl+Alt+↑] 與 kbd:[Ctrl+Alt+↓]（macOS 上為 kbd:[Cmd+Option+↑] 與 kbd:[Cmd+Option+↓]）
  會在第一個游標的上一行，或最後一個游標的下一行，於相同欄位處新增游標。
  部分 Linux 桌面環境以這些按鍵切換工作區；按住 kbd:[Ctrl] 按一下則在任何環境中都能使用。

之後，輸入、刪除、kbd:[Enter]、方向鍵、kbd:[Home] 與 kbd:[End] 都會在每個游標處作用；
相遇的游標會合而為一。
每次編輯對所有游標而言都是一個復原步驟，復原時游標也會回到原處。
貼上的行數與游標數相同時，每個游標各貼上一行；其他文字則會貼到每個游標處。
複製時，各選取範圍會依文字順序排列，每段一行。
kbd:[Tab]、kbd:[Shift+Tab]、「複製行」與「移動行」作用於所有游標所在的行，每行只處理一次。
唯讀窗格會拒絕在所有游標處進行的編輯。

畫面會跟隨最後新增的游標，輸入法也會在該處顯示組字內容。
kbd:[Esc] 會先回到這一個游標；不按 kbd:[Ctrl] 直接按一下也有相同效果。
欄選取（kbd:[Alt]+拖曳）與多個游標是分開的功能：建立欄選取時，會移除多出的游標。

有游標的窗格，標題列下方會出現一條彩色線。
可輸入文字時，游標是一條實心的豎線；在唯讀窗格中、搜尋列等欄位取得鍵盤輸入時，
以及視窗位於背景時，游標會變細變淡。
在唯讀窗格中輸入不會變更任何內容，狀態列會說明是哪一側，以及如何解除鎖定。

游標可在並排檢視中使用。
在內嵌檢視中，按兩下某一行，或按 kbd:[Enter] 或 kbd:[F2]，即可在並排檢視中編輯該行
（請參閱 <<inline-view>>）；在表格檢視中，請按兩下儲存格進行編輯。

每個窗格下方的列會顯示該窗格是否可以編輯：

* 「可寫入」：可以編輯並儲存檔案。
* 「唯讀」：窗格已鎖定（例如使用標題列中的鎖定按鈕），不接受編輯。
* 「磁碟上為唯讀」：可以編輯，但檔案標示為唯讀，因此「儲存」不會取代該檔案，並會保留您的編輯。
  請以其他名稱儲存，或清除唯讀標示後再儲存。
* 「僅供比較」：窗格顯示的是 OxideMerge 從檔案讀取的文字，而不是檔案本身，
  例如文件、試算表、PDF、程式、網頁，或 JSON 與 XML 的格式化副本。
  這類窗格無法解除鎖定、編輯或存回。
  若要編輯這些文字，請以「檔案 → 另存新檔」存成一般檔案（例如 `.txt` 檔），窗格之後就會編輯該檔案；
  無論選項如何設定，都不會存到本身是以這種方式讀取的檔案上。
* 檔案有尚未儲存的變更時，會顯示「已修改」。

視窗底部的狀態列也會顯示目前作用中窗格的這些狀態。
樹狀檢視、格式化檢視，以及以 Markdown 顯示的網頁，也會在狀態列顯示「僅供比較」。

若要選取一欄文字，請按住 kbd:[Alt]（macOS 上為 kbd:[Option]）並拖曳。
選取範圍在經過的每一行都涵蓋相同的欄。
開啟自動換行時或在表格檢視中，無法使用欄選取。

* 輸入文字會取代每一行中選取的欄。
  寬度為零的選取範圍，等於每一行各有一個游標，輸入的文字會插入到每一行。
* kbd:[Backspace] 與 kbd:[Delete] 會移除選取的欄，或在每一行各移除一個字元。
* kbd:[Ctrl+C] 複製這些欄（每列一行），kbd:[Ctrl+X] 剪下。
* kbd:[Ctrl+V] 貼上。
  單行文字會貼到每一個選取的行。
  多行文字會逐行貼上，超出選取範圍的行會貼到下方的行。
* 按 kbd:[Esc] 或按一下，即可結束欄選取。

欄依各行的顯示方式計算：Tab 會延伸到下一個定位點。
貼到較短行尾端之後的文字，會以空格補齊以便對齊。
顯示寬度較大的字元（例如中文字）仍算一欄，因此跨越這類字元的欄選取，看起來可能不整齊。

每次編輯、貼上、剪下或刪除都是一個復原步驟；在同一行中連續輸入，在游標移動之前算一個步驟。
儲存時會保留各檔案的行尾、編碼與位元組順序標記。

在某一行上按右鍵，可以編輯該行、在下方插入一行、刪除該行、複製其文字、設定書籤，
或依該行建立比較規則（請參閱 <<add-rule>>）。
在選取的文字上按右鍵會保留選取範圍，此時「複製文字」只會複製選取的文字；
在其他位置按右鍵，則會先將游標移到該處。

行號區中的編輯標記，會標示自開啟檔案以來變更過的行。

其他程式修改了檔案時，OxideMerge 會在其視窗重新成為作用中視窗時偵測到：

* 沒有未儲存變更的檔案會自動重新載入。
* 有未儲存變更的檔案會顯示訊息，並提供重新載入的選項。
  重新載入會以磁碟上的檔案取代您的編輯。

=== 尋找與取代

* kbd:[Ctrl+F] 開啟尋找列。
  kbd:[F3] 與 kbd:[Shift+F3] 尋找下一個與上一個符合項目，kbd:[Esc] 關閉尋找列。
* kbd:[Ctrl+H]（macOS 上為 kbd:[Cmd+Alt+F]）開啟尋找與取代。
* 搜尋選項包括「大小寫須相符」、「全字拼寫須符合」與「規則運算式」。
  使用規則運算式時，取代文字中的 `$1` 代表第一個擷取群組。
* 「全部取代」可以一次復原。

=== 書籤

書籤可標記特定的行，方便您隨時回到該處。

* kbd:[Ctrl+F2] 在目前這一行設定或移除書籤。
* kbd:[F4] 與 kbd:[Shift+F4] 移到下一個與上一個書籤。
* 「編輯 → 書籤 → 書籤註解...」可為書籤加上註解。
  將指標移到行號區時會顯示註解，HTML 報告中也會列出。
* 「編輯 → 書籤 → 清除所有書籤」會移除全部書籤。

書籤會標示在行號區與位置窗格中。

[[sync-points]]
=== 同步點

比較有時會將不相關的行配對在一起，例如某個函式經過改寫並搬到其他位置時。
這時可以使用同步點，告訴 OxideMerge 哪些行應該對齊。

若要設定同步點：

. 將游標移到某一側的某一行，然後選擇「合併 → 設定同步點」（kbd:[Alt+S]），或在該行按右鍵。
. 以相同方式選擇另一側中對應的行；三方比較時，第三側也要選擇。

這些行會顯示在同一列，前後的文字則分開比較。

* 您可以加入任意數量的同步點，但會與其他同步點交叉的同步點將被拒絕。
* 同步點會標示在行號區；編輯、復原或重新載入時，同步點會跟著對應的行移動，
  也會一併存入已儲存的比較。
* 若要取消已選取的行，請在該行再執行一次此命令。
* 若要移除某個同步點，請在其中一行再執行一次此命令。
* 若要移除所有同步點，請選擇「合併 → 清除同步點」。

=== 檢視選項

「檢視 → 文字比較」提供下列選項：

* 「位置窗格」與「行詳細資料窗格」。
  行詳細資料窗格會將各側的目前這一行上下排列並自動換行，方便您找出長行中的細微差異。
* 「行號」、「編輯標記」、「顯示空白字元」與「語法醒目提示」。
* 「摺疊未變更的行」（kbd:[Alt+C]）：將未變更的行收合成一列，每個差異前後保留三行。
  按一下該列即可展開。
* 「自動換行」（kbd:[Alt+Z]）。

「檢視 → 縮放」（kbd:[Ctrl+{plus}]、kbd:[Ctrl+-] 與 kbd:[Ctrl+0]）可調整文字大小。

「排列方式」位於「檢視 → 排列方式」與「選項 → 一般」中，文字比較與二進位比較的工具列上也有「緊密排列」與「對齊排列」按鈕（一對畫著兩欄文字行的圖示，緊密或中間留空）：

緊密排列:: 預設值。每一側只顯示自己的行，不留空白。
對齊排列:: 在新增或刪除行的另一側留白，讓後面的行維持左右對齊。

此設定會套用到所有已開啟的雙向與三方文字比較，並保留到下次使用。
二進位比較的移動區塊也依同一個設定排列（請參閱 <<binary-comparison>>）。
內嵌檢視與表格檢視不論哪種排列都不留空白，因此在這兩種檢視中無法使用工具列按鈕。
切換排列方式不會變更檔案內容或比較規則。

* 開啟「摺疊未變更的行」時，未變更的行會收合，按一下即可展開。
* 差異之間的移動與複製照常運作，也可以復原與重做；方向鍵可逐行移動，kbd:[Ctrl+C] 複製目前這一行。
* 內嵌檢視僅供檢視檔案：上方的列會說明這一點，輸入、貼上、增加縮排與「取代」在此都沒有作用。
  若要編輯，請按一下該列上的「在並排檢視中編輯」、按兩下某一行，或按 kbd:[Enter] 或 kbd:[F2]；
  並排檢視隨即開啟，文字游標位於目前這一行的開頭。
* 在兩種檢視之間切換時，所有編輯、選取的差異，以及並排檢視中的文字游標與其選取範圍都會保留，
  切換回來時即可繼續。

[[table-compare]]
=== CSV 與 TSV 檔案

CSV、TSV 檔案與試算表會以「表格」檢視開啟。
窗格上方的「文字」／「表格」切換可在檔案的文字行與表格之間切換，位置與文件的「文字」／「格式化」切換相同；
活頁簿則三種檢視都有。
表格檢視以記錄而非行為單位進行比較，因此引號內的欄位可以包含換行。

.兩個 CSV 檔案的表格檢視
image::csv.png[兩個 CSV 檔案的表格檢視]

表格的外觀類似試算表：有格線與列號，欄位標題為欄位字母；若第一列為標題，則顯示欄名。

* 互相比較的欄位並排顯示，左側在前。
* 按一下儲存格即可選取。表格上方的列會顯示其位置（例如 `B4`）以及各側在該處的內容，並標示不同的部分。
* 表格上方的篩選按鈕可列出「全部」的列或僅列出「有變更」的列；依鍵配對時，還可只列出「新增」、「刪除」、
  「修改」、「順序變動」或「不明確」的列，並各自顯示筆數。
  跳至未列出的列時，會重新顯示所有的列。
* 「僅變更的欄」只顯示含有變更儲存格的欄，以及鍵欄。
  若要隱藏某一欄及與其比較的欄，請在該欄按右鍵並選擇「隱藏欄」；「顯示隱藏的欄」可將其恢復。
* 「自動調整欄寬」會依內容調整所有欄的寬度，再按一次即恢復先前的欄寬；按兩下欄位邊界則只調整該欄。
* 數字靠右對齊。有變更的儲存格會標示出來；只有一側才有的記錄整列著色，沒有該記錄的一側則以斜線顯示。
* 拖曳欄位邊界可調整欄寬。
* 水平捲動時，記錄編號（依鍵比對時還有鍵值）會固定在左側。
* 若要編輯儲存格，請按兩下儲存格，或按右鍵並選擇「編輯儲存格」；也可以選取後按 kbd:[F2] 或
  kbd:[Enter]。
  儲存格可以包含多行文字。
* 若要將某個欄位複製到另一側的對應記錄，請在儲存格上按右鍵並選擇「複製儲存格」。
  兩筆記錄都必須有該欄。
* 方向鍵可在記錄與欄位之間移動；
  kbd:[PgUp] 與 kbd:[PgDn] 逐頁移動記錄，kbd:[Ctrl+Home] 與 kbd:[Ctrl+End] 選取第一筆與最後一筆記錄。
* 「跳至行」使用檔案中的實際行號。

在 Excel 活頁簿（`.xlsx` 或 `.xlsm`）中，垂直合併會延伸到涵蓋的各列，包括對齊時產生的空位。
水平合併所涵蓋的延續儲存格會在各自的窗格內以底色與符號標示，讓互相比較的欄位保持並排。
合併區域的左上角顯示儲存格的值。將游標停在合併儲存格上，即可查看其合併範圍（例如 `B2:D4`）；
選取儲存格後，表格上方會顯示各側的合併範圍。
表格會將被合併涵蓋的儲存格視為空白，並依儲存格的值比較。只變更合併範圍不會增加差異。
特別大的合併區域可能超出格線的顯示範圍，範圍標示仍會顯示工作表中的座標。
開啟兩側範例中的 `docs/budget.xlsx`，再選取 *Merged Cells* 索引標籤，即可查看相同、重疊與分開的合併範圍。

編輯儲存格時，OxideMerge 會保留該欄位以外的引號與換行格式，您也可以復原與重做變更。
經過轉換或唯讀的文件無法編輯。

在表格檢視中複製差異時，只會變更所選的行。
若這樣會破壞 CSV 的引號格式，OxideMerge 會拒絕複製，文件維持不變；
此時請改為複製儲存格，或切換到文字檢視處理。
含引號的記錄格式不正確時，表格會顯示錯誤，請切換到文字檢視修正。

[[table-keys]]
==== 依鍵配對列

表格檢視預設依位置配對記錄，就像逐行比較一樣。
若記錄的排序不同，或有新增、刪除的記錄，請改為依鍵配對。
若依位置配對時大多數列都不同，但有某一欄可以辨識各筆記錄，表格上方的列會提供依該欄配對的按鈕，按一下即可改為依鍵配對。

雙向比較時，表格上方的列提供下列設定；除前兩項外，其餘都在「選項」中：

「列配對方式」:: 「位置」（預設）或「鍵欄」。
「鍵」:: 用來識別記錄的欄，例如 `id`；可選擇一欄或多欄。
「第一列為標題」:: 以第一列作為欄名，該列不列入比較；欄名會顯示在欄位標題，按兩下欄名即可編輯。
「欄配對方式」:: 依「位置」或「標題名稱」配對欄，即使欄的順序改變也能正確對應。
「忽略列順序」:: 只移動過位置的記錄不算差異：上一個與下一個差異會略過它，但仍保留 `↕` 標記。
「數值容差」:: 相差在此範圍內的數字視為相等。`0.01` 表示差值，`1%` 表示較大數字的比例；
留空則精確比較。
「列順序」:: 「左側順序」（預設）依左側表格的順序列出，只在右側的記錄會排在它前一筆記錄之後；
「右側順序」依右側表格的順序；
「鍵順序」依鍵排序：數字依數值排序並排在文字之前，沒有鍵的列排在最後。

篩選按鈕會顯示新增、刪除、修改、順序變動與不明確的記錄數。
列標記為：`+` 新增、`−` 刪除、`~` 修改、`↕` 移動、`?` 不明確。

* 「下一個差異」與「上一個差異」會逐一走過內容不同的記錄。
* 「複製儲存格」會複製到對應記錄中配對的欄。
  複製整筆記錄時，會取代對應記錄的儲存格，或新增、刪除該記錄。
* 鍵為空白，或有多筆記錄使用同一個鍵時，該記錄即為「不明確」。
  不明確的記錄絕不會被複製；「下一個不明確的列」可找到它們。
* 若某一側缺少鍵欄，OxideMerge 會改依位置配對並說明原因。

兩側合計超過 100,000 筆記錄的表格會在背景配對，上方的列會顯示已處理的記錄數，並提供「取消」。
取消後，列會改依位置配對；按「依鍵配對」可重新開始。

依鍵配對之表格的 HTML 與 XML 報告，會記錄列的配對方式：
鍵、標題列、欄的配對方式、列順序、容差、各項計數與警告。
XML 報告將這些資訊放在 `<table-match>` 元素中。

這些設定會儲存在專案中；較舊的專案開啟時會依位置配對。

[[git-revision]]
=== 與修訂版本比較

「檔案 → 與修訂版本比較...」可將檔案或資料夾與 Git、Subversion 或 Mercurial 中較早的版本比較。
路徑上方最近的工作複本，決定使用哪一種版本控制系統。
對話方塊會列出最近變更過該路徑的修訂版本供您選擇。

可以輸入的版本取決於版本控制系統：

* 在 Git 中，版本可以是 `HEAD`、分支、標籤或某次提交；留空即為 `HEAD`。
* 在 Subversion 中，可以是 `BASE`（工作複本更新到的修訂版本）、`PREV`、`HEAD`、
  `1234` 或 `r1234` 這類編號，或 `{2026-11-01}` 這類日期；留空即為 `BASE`。
* 在 Mercurial 中，可以是 `.`（工作複本的父修訂版本）、`.^`、`tip`、編號、雜湊值、標籤、書籤
  或其他 revset；留空即為 `.`。

較早的版本以唯讀方式顯示在左側，目前的檔案或資料夾則顯示在右側。

必須先安裝 Git、Subversion 或 Mercurial，並將其加入 `PATH`。
Git 與 Mercurial 會從本機儲存庫讀取修訂版本。
路徑為 ASCII 時，Subversion 會從工作複本讀取 `BASE`。
在 Windows 上，該版 `svn` 只保留 ASCII 參數，因此路徑不是 ASCII 時，
OxideMerge 會在所在資料夾中啟動 `svn`，資料夾名稱會完整傳給它。
資料夾會在該處以 `.` 傳給它，讀取方式與 ASCII 路徑相同。
檔案則以儲存庫 URL 讀取，並固定在工作複本所在的修訂版本，
因此即使檔案在較早的修訂版本中是另一個名稱，也找得到，與 ASCII 路徑相同。
這類檔案的 `BASE` 是工作複本裡的原始複本，行尾依提交時的 `svn:eol-style` 轉換，與 `svn cat` 相同；
提交時設有 `svn:keywords` 的檔案則從伺服器讀取 `BASE`，由伺服器填入關鍵字。
其他修訂版本來自伺服器。
最近修訂版本清單也來自伺服器，而伺服器可能要求 OxideMerge 無法提供的登入，
請先使用 `svn` 本身登入。
在 Windows 上，Mercurial 以 ANSI 字碼頁讀取名稱，這與 `hg` 本身相同：
字碼頁拼不出來的名稱無法比較。
在 Windows 上，`svn` 與 `hg` 會把資料夾的修訂版本寫入您的暫存資料夾；
暫存資料夾的路徑不是 ASCII 時，傳給它們的是該路徑的短檔名（8.3）。
若該磁碟機關閉了短檔名，請將 `TMP`（Windows 會先於 `TEMP` 讀取）設為 ASCII 資料夾，
才能將資料夾與修訂版本比較；並將 `TEMP` 設為同一個資料夾，讓其他程式一致。

修訂版本會在背景讀取；伺服器緩慢或沒有回應時，按「取消」即可停止，並回到對話方塊。
按下「比較」時，Mercurial 會讀取儲存庫本身的 `.hg/hgrc`，如同會套用 Git 的篩選器；
輸入路徑時讀取的最近修訂版本清單則會略過它；略過此檔案需要 Mercurial 5.4 或更新版本。
比較工作複本的最上層資料夾時，`.git`、`.svn` 或 `.hg` 資料夾只會列在右側；
「Exclude Source Control」篩選器可將其隱藏。
匯出修訂版本的資料夾時，若會超過 8 GB 或 500,000 個檔案，就會被拒絕，
這與<<archives,解壓縮壓縮檔>>的限制相同，可避免誤選或過大的修訂版本耗盡磁碟空間。

在命令列中使用 `--rev`（或作用相同的選項 `--git-rev`）：

[source,sh]
----
oxidemerge --rev HEAD~1 src/main.rs
oxidemerge --rev PREV src/main.c
oxidemerge --rev .^ docs
----

另請參閱 <<integration>>：OxideMerge 也可以設定為 Git、Subversion、Mercurial 或 Perforce
自身叫用的差異與合併工具，由這些工具啟動，而不是從 OxideMerge 內開啟某個修訂版本。

[[merging]]
== 合併檔案與解決衝突

當同一個檔案有兩份各自修改過的版本需要整合時，三方合併會將兩者分別與共同的基底比較，
並把變更整合成單一結果。
OxideMerge 會替您複製不衝突的變更，並引導您逐一處理剩下的衝突。
含有版本控制衝突標記的檔案，也可以直接在同樣的三方檢視中開啟並解決。

[[three-way-merge]]
=== 三方合併

.三方比較
image::three.png[三方文字比較]

三方合併會整合同一個檔案的兩份修改版本。
請依序開啟：您的版本、基底、另一份版本。
OxideMerge 會分別比較左右兩側與基底，並將變更整合到中間窗格。

==== 步驟一：選擇輸出檔案

預設情況下，儲存中間窗格會覆寫基底檔案。
若要保留基底檔案，請在啟動時另外指定輸出檔案：

[source,sh]
----
oxidemerge mine.txt base.txt theirs.txt -o merged.txt
----

中間窗格一開始會顯示基底檔案的內容，儲存時則會將結果寫入 `merged.txt`。
您也可以選擇「檔案 → 另存新檔」，將結果存到其他檔案。

TIP: 若左右兩側只當作合併來源使用，建議將它們設為唯讀。

==== 步驟二：合併並解決衝突

窗格上方的合併列會顯示剩餘的衝突數，並提供下列按鈕：

* 「下一個衝突」。
* 「採用左側」、「採用兩側」與「採用右側」：處理目前的衝突。
* 「標記為已解決」：用於您手動編輯過的衝突，會保留中間的文字，並將該衝突計為已解決。
* 「儲存結果」：位於最右側，用來儲存中間窗格；沒有剩餘衝突時，它會成為主要按鈕。

若要合併檔案：

. 選擇「合併 → 自動合併」。
  這會將兩類變更複製到中間窗格：只在一側出現的變更，以及兩側完全相同的變更。
. 以 kbd:[Alt+PgDn] 與 kbd:[Alt+PgUp] 逐一前往剩餘的衝突。
. 從左側或右側複製需要的變更，或直接編輯中間窗格。
. 若要同時保留兩側的變更，請在差異上按右鍵，選擇「採用左側，再採用右側」或「採用右側，再採用左側」，
  然後檢查結果是否有重複或互相矛盾的內容。
. 儲存結果，並確認目標路徑正確。

IMPORTANT: 自動合併只處理文字，不會檢查結果是否正確。
使用合併結果之前，請先檢查內容，並執行專案所需的驗證。

[[conflict-files]]
=== 解決衝突檔案

.以三方檢視開啟的衝突檔案
image::conflict.png[以三方檢視開啟的衝突檔案]

衝突檔案是含有版本控制衝突標記的檔案，標記包括
`<<<<<<<`、`|||||||`、`=======` 與 `>>>>>>>`。
OxideMerge 會以三方檢視開啟這類檔案。

您可以使用下列任一方式開啟衝突檔案：

* 「檔案 → 開啟衝突檔案...」。
* 起始頁上的「開啟衝突檔案」。
* 命令列：`oxidemerge conflict.txt`。

左側是「我的」，右側是「他們的」，中間是「合併結果」。
解決每個衝突後，請儲存中間窗格，OxideMerge 會將結果寫回衝突檔案。

NOTE: 這與開啟三個獨立檔案不同：解決衝突檔案時，原本的檔案就是輸出目標。

[[folder-comparison]]
== 比較資料夾

資料夾比較可讓您逐一項目掌握兩個或三個資料夾之間的差異。
您可以用它檢查整個原始碼樹狀結構或發行版本中的變更、開啟任何有變更的檔案進行詳細比較，
並在資料夾之間複製、同步或合併項目。

.資料夾比較
image::folder.png[資料夾比較]

資料夾比較會列出兩個或三個資料夾中的項目，以及每個項目的比較結果。
結果會在比較進行中陸續顯示：OxideMerge 在掃描資料夾的同時比較檔案，一發現差異就立即列出。
若耗時較久的比較在視窗位於背景時完成，OxideMerge 會提醒您。

=== 資料夾清單

清單中的每一列會顯示下列欄位：

* 「名稱」。
* 「資料夾」：項目所在的資料夾。此欄只在平面清單中顯示。
* 「比較結果」。
* 「修改時間」：各側中最新的日期。
  日期不同時，日期後面會標示較新的一側；將指標移到日期上，即可查看每一側的日期。
* 各側的檔案大小。
* 「副檔名」。

按一下欄位標題即可依該欄排序，再按一次則反轉順序。
列左緣的彩色線條，標示有差異或只存在於一側的項目。

比較結果為下列其中之一：

[cols="1,2"]
|===
|結果 |意義

|「相同」、「不同」
|檔案相同或不同；二進位檔另標示「二進位」。

|例如「3 個不同 · 1 個僅在左側」
|有差異的資料夾，文字會說明其中哪些項目不同。

|「僅左側有」、「僅中間有」、「僅右側有」
|項目只存在於某一側。

|「左側不同」、「中間不同」、「右側不同」
|三方比較：某一側與另外兩側不同。

|「左側不存在」、「中間不存在」、「右側不存在」
|三方比較：項目只存在於另外兩側。

|「錯誤」
|OxideMerge 無法讀取該項目。
|===

將指標移到比較結果上，即可查看完整說明，例如「文字檔案不同」。

路徑下方的篩選標籤會統計各類項目的數量：「全部」、「不同」、「僅在左側」、「僅在右側」、
「僅在中間」（僅限三方比較）與「相同」。
按一下標籤即可隱藏或顯示該類項目。
關於計數，請注意下列幾點：

* 在三方比較中，只缺少一側的項目算作「不同」。
* 空資料夾與未掃描的資料夾，依其顯示的結果計數。
* 關閉「包含子資料夾」時，不會比較子資料夾；
  這些子資料夾只計入「全部」，也不會被任何標籤隱藏。

狀態列會顯示比較所花費的時間。

[[compare-methods]]
=== 比較方法

比較方法決定 OxideMerge 如何判斷兩個檔案是否相同。
您可以使用工具列上的「比較方法」選擇。

[cols="1,3"]
|===
|方法 |比較檔案的方式

|完整內容
|逐行比較文字檔，並套用比較選項與比較規則。
只在被忽略的部分不同的檔案，視為相同。

|快速內容
|比較位元組。
大小不同的檔案不必讀取即可判定為不同。

|二進位內容
|與「快速內容」一樣比較位元組，並將結果標示為二進位。

|修改日期
|比較修改日期。
「選項 → 資料夾」中的「日期容許誤差（秒）」決定兩個日期可以相差多少。

|修改日期與大小
|日期與大小都必須相同。

|大小
|只比較大小。
|===

如何選擇比較方法：

* 需要套用比較規則或忽略特定差異時，請使用「完整內容」。
* 需要確認檔案完全相同時，請使用「快速內容」或「二進位內容」。
* 需要快速初步檢查時，可使用日期或大小相關的方法。
  請注意，日期與大小相同，並不代表內容相同。

位元組比較會分段讀取檔案，因此大型檔案不必整個載入記憶體。
不過，完整的文字比較仍可能將有變更的檔案載入記憶體。

=== 選取與開啟項目

您可以使用滑鼠或鍵盤選取項目：

* 方向鍵、kbd:[PgUp]、kbd:[PgDn]、kbd:[Home] 與 kbd:[End] 可移動選取位置；
  按住 kbd:[Shift] 可擴大選取範圍。
* 按住 kbd:[Ctrl] 再按一下項目，可將它加入或移出選取範圍。
* 按 kbd:[Ctrl+A] 可選取所有項目。

開啟項目的方式：

* 按兩下項目或按 kbd:[Enter]，即可在獨立分頁中比較該項目。
  在樹狀模式中，這個動作會改為展開或摺疊資料夾。
  若要以獨立的資料夾比較開啟某個資料夾，請使用平面清單，或在資料夾上按右鍵並選擇「比較」。
* 按 kbd:[Space] 可開啟「快速預覽」：不必開啟新分頁，即可查看所選檔案以顏色標示的差異。
  在預覽中，kbd:[↑] 與 kbd:[↓] 可切換項目，kbd:[Enter] 可開啟項目，
  kbd:[Space] 或 kbd:[Esc] 則關閉預覽。

=== 複製與刪除項目

您可以直接在資料夾清單中複製與刪除項目：

* 按 kbd:[Alt+→] 或 kbd:[Alt+←]，可將選取的項目複製到右側或左側。
* 在項目上按右鍵，可使用更多命令：
** 「複製」到另一側。
** 「複製到資料夾...」：將某一側選取的項目複製到另一個資料夾，並保留相對路徑。
** 從某一側「刪除」。
** 「以關聯的應用程式開啟」。
** 「在檔案管理員中顯示」。
** 「複製完整路徑」。
** 「依名稱選取...」。

「選項 → 一般」中的下列設定會影響檔案操作：

* 「複製前先確認」：複製項目前先詢問；刪除項目前則一律會詢問。
* 「刪除時使用資源回收筒」：刪除的項目會移到資源回收筒或垃圾桶。
  無法移入的項目，OxideMerge 不會刪除。
* 「覆寫檔案時保留 .bak 備份」：取代檔案時保留其舊內容。

IMPORTANT: 複製與刪除會立即變更磁碟上的檔案，不會等到「儲存」，
也無法以文字編輯器的「復原」命令還原。
操作前，請先確認選取的項目與目標位置。

=== 檢查所有差異

.所有差異
image::alldiffs.png[所有差異]

「所有差異」會在單一分頁中顯示資料夾比較裡所有已變更的文字檔，讓您在同一處檢查並編輯所有變更。
若要開啟，請按一下資料夾比較工具列上的「所有差異」，或選擇「比較 → 所有差異」。
資料夾比較的篩選器與「顯示」設定同樣適用。

* 左側清單列出每個檔案及其差異數量。
  使用「篩選檔案…」（kbd:[Ctrl+F]）可縮短清單；按一下檔案即可捲動到該檔案。
* 每個檔案以一張卡片並排顯示其差異。
  按一下卡片標題中的箭頭可摺疊或展開該卡片，工具列則可摺疊或展開全部卡片。
* kbd:[Alt+↓] 與 kbd:[Alt+↑] 可依序瀏覽所有檔案的差異。
  從資料夾比較開啟「所有差異」時，會從您在該處選取的差異開始。
  仍在載入的卡片會等候載入完成，不會被略過。
  狀態列會顯示目前位置，與 <<folder-navigation>> 相同。
* 差異旁的箭頭可將該差異複製到另一側。
  在雙向比較中，卡片標題中的按鈕可複製整個檔案。
* 「復原」可取消上一個變更。
* 「儲存」會寫入已變更的檔案，之後資料夾比較會重新整理。
* 卡片標題最右側的按鈕會在獨立分頁中開啟該檔案。

補充說明：

* 從檔案不存在的一側複製時，儲存後會刪除該檔案，變空的資料夾也會一併刪除。
  若已開啟備份，刪除的檔案會保留為 `.bak`，因此其所在資料夾也會保留。
* 若檔案在載入後於磁碟上有變更，便無法儲存該卡片。
  卡片會改為提供捨棄編輯並重新載入檔案的選項；選擇前，請先另外保留需要的編輯內容。
* 磁碟上標示為唯讀的檔案不會被儲存、取代或刪除；其卡片會保留您的編輯。
* 沒有編輯過的卡片，會在檔案於磁碟上變更時自動重新載入。
* 「重新整理」（kbd:[F5]）也會重新載入比較規則與選項。
* 若要納入開啟「所有差異」之後才變更的檔案，請先儲存或捨棄目前的編輯，
  再重新開啟「所有差異」。

[[folder-merge]]
=== 自動合併資料夾

自動合併資料夾可在一次操作中，將兩側所做的變更合併到共同的基底資料夾。
在三方資料夾比較中，中間的資料夾是基底。
「合併 → 自動合併資料夾...」會將兩側的變更帶入中間資料夾：

* 只在某一側變更、新增或刪除的項目，會被複製或刪除。
* 兩側完全相同的變更只套用一次。
* 兩側都有變更的文字檔，若變更之間沒有重疊，會逐行合併。

==== 開始之前

合併前，請先完成下列準備：

. 在「選項 → 資料夾」中，開啟「包含子資料夾」與「包含僅一側子資料夾的內容」。
. 等待比較完成。

IMPORTANT: 合併結果會寫入中間資料夾。
若要保留原本的基底資料夾，請先複製一份，再以複本作為中間資料夾。

==== 檢查合併計畫

OxideMerge 會先列出計畫：預計複製、刪除與合併的項目，以及無法自動解決的衝突。
確認前，請先仔細檢查計畫。

下列檔案不會被變更：修改互相衝突的檔案、內容無法合併的檔案、符號連結，以及無法讀取的檔案。
若檔案在比較後又有變更，請重新整理比較後再試一次。

==== 合併如何保護您的檔案

合併只有兩種結果：所有變更全部完成，或中間資料夾完全維持原狀。

* _合併前_，OxideMerge 會檢查每個項目。
  若有項目在計畫產生後又有變更、會寫到中間資料夾之外，或其備份檔會取代比較中的檔案，
  就不會合併任何項目，並列出這些項目。
* _合併期間_，OxideMerge 會在寫入每個檔案前再檢查一次。
  若其他程式變更了檔案，合併會停止。您也可以按一下「停止」中止合併。
* _合併停止或失敗時_（例如資料夾為唯讀或磁碟已滿），OxideMerge 會復原到目前為止的所有變更。
  中間資料夾會恢復原狀，被移除的資料夾也會恢復原本的權限。
  合併時移到垃圾桶的檔案會從副本還原，因此垃圾桶中也會保留一份。

為了能夠復原，OxideMerge 會將原始檔案的副本放在中間資料夾最上層的
`.oxidemerge-undo-…` 資料夾中。
若無法在該處建立此資料夾，則改用系統的暫存資料夾。
資料夾比較不會列出這個資料夾。
被刪除的檔案其實只是移到這個資料夾，復原合併時會再移回原處。

若 OxideMerge 無法將某個檔案放回原處，會保留這個復原資料夾並顯示其位置。
資料夾中的 `index.txt` 列出每個副本的原始路徑，方便您手動還原。

[[folder-sync]]
=== 同步兩個資料夾

在雙向資料夾比較中，「同步資料夾...」（位於工具列與「合併」選單）會讓一個資料夾
（「目的地」）與另一個資料夾（「來源」）一致。
您會先看到計畫，在套用之前不會變更任何檔案。

image::sync.png[同步資料夾預覽]

==== 模式

「鏡像 左 → 右」、「鏡像 右 → 左」::
目的地最後會擁有與來源相同的檔案：複製新增與變更的檔案，並刪除只有目的地才有的檔案與資料夾。
「以左側更新右側」、「以右側更新左側」::
複製新增與變更的檔案，不刪除任何項目。

唯讀的一側（例如 Git 修訂版本）不能作為目的地。
OxideMerge 依內容（SHA-256）判斷，絕不會只因修改時間較新就覆寫。
比較結果相同、但大小或時間不同的檔案，會讀取內容再次確認。

==== 開始之前

同步前，請先完成下列準備：

. 在「選項 → 資料夾」中，開啟「包含子資料夾」與「包含僅一側子資料夾的內容」。
. 等待比較完成。已停止的比較無法同步。

兩個資料夾必須是不同的資料夾，且任一個都不能位於另一個之中。

==== 預覽

預覽為唯讀，會列出每個項目的動作與原因：

[cols="1,3"]
|===
|動作 |意義

|建立資料夾、複製
|項目只在來源中。

|取代
|內容不同，目的地的檔案會被覆寫。

|刪除、移除資料夾
|項目只在目的地中（僅限鏡像）。資料夾只有在之後變成空的時才會移除。

|略過
|項目只在目的地中，且模式為更新。

|衝突
|無法安全判斷，OxideMerge 不會變更該項目。
|===

下列項目屬於衝突：

* 無法讀取的項目；
* 符號連結（絕不跟隨或複製）；
* 裝置；
* 一側是檔案、另一側是資料夾；
* 名稱與另一個名稱只差在大小寫或拉丁字母重音寫法（組合或分解）；
* 比較後又變更的項目。

若某個檔案在兩側的名稱只差在大小寫或上述重音寫法，且兩側內容相同，鏡像時不算衝突，
而會重新命名（見下文）。

在 macOS 與 Linux 上，勾選「將符號連結以連結本身複製」即可同步連結，而不是略過它們。
此時連結會被當作連結本身，絕不當作它所指向的內容：

* 只在來源中的連結，會以相同的目標文字建立在目的地。
* 目標文字不同的連結會被取代。
* 鏡像時，只在目的地中的連結會被刪除；更新則會保留。
* 與同名檔案或資料夾對應的連結仍算衝突。

連結所指向的內容絕不會被讀取、寫入或刪除，即使它位於兩個資料夾之外。
變更過的連結也會像檔案一樣記錄在復原日誌中，因此復原時會將它們放回原處。

按一下項目可查看詳細資料：兩側的大小與 SHA-256 開頭，
以及該動作是向目的地新增內容，還是會覆寫或刪除目的地的內容。

若某個複製項目的內容與計畫要刪除的檔案相同，代表該檔案在來源中被重新命名或移動過。
「重新命名」會以「舊名稱 → 新名稱」列出這些配對，複製與刪除項目也會顯示對方的名稱。
套用重新命名時，會在目的地中移動該檔案，因此不需複製，也不會在日誌中保留副本：
檔案會先改成日誌所記錄的暫存名稱，再改成新名稱。
只改變名稱大小寫或重音寫法的重新命名也以相同方式進行，
即使檔案系統把兩個名稱視為同一個（例如 Windows 與 macOS 的檔案系統）也一樣。
若新舊位置位於不同磁碟，則會先複製，再刪除舊檔案。
只差在大小寫的資料夾重新命名，以及只差在大小寫且內容也有變更的檔案，仍不會被變更。

清單上方會顯示警告：

* 若篩選器或隱藏檔案設定排除了某些項目，鏡像不會刪除它們，因此目的地可能不是完全一致的鏡像；
  仍含有這類項目的資料夾會保留。
* 大量刪除會被標示，並需要再確認一次。

「匯出計畫...」會將計畫儲存為 JSON，內含版本編號與相對於資料夾的路徑，不含資料夾的絕對路徑。
計畫會記錄篩選條件，以及兩個資料夾路徑的 SHA-256，因此只會套用到製作計畫時的資料夾。

==== 套用計畫

「套用變更...」會要求確認並指出目的地。
若要刪除的項目很多，您還必須勾選一個註明刪除數量的核取方塊。

接著 OxideMerge 依下列順序處理：建立資料夾、複製與取代檔案、刪除檔案，最後移除空的資料夾。
對話方塊會顯示已完成的數量與正在變更的項目。
處理每個項目前，都會先確認來源與目的地仍與預覽時相同。
每個檔案會先複製到目的地旁的暫存檔，與計畫中的 SHA-256 核對後，再改名放到定位；
重新命名的檔案則改為移動。
最後，會再檢查一次所有複製與移動的檔案。

若有檔案在預覽後被變更（即使大小與修改時間相同），就不會套用任何變更，並會指出該檔案。

目前無法讀取的檔案會如實回報為無法讀取，而不會被說成已變更：在 Windows 上，
若有其他程式開啟某個檔案且不允許共用，同步會在變更任何檔案之前停止，並指出該檔案。
請關閉該程式後重新預覽。

在 Windows 上，超過舊有 260 字元限制的路徑，也會與其他路徑一樣複製與刪除。

若新增與取代的檔案，或被取代與刪除檔案的日誌副本，超出所在磁碟的可用空間，同樣不會套用任何變更。
訊息會指出該磁碟、所需空間與可用空間。
只在目的地內移動的檔案不計入。
此檢查僅在 macOS 與 Linux 上進行，Windows 不會測量可用空間。
若磁碟仍在中途寫滿，該次寫入會失敗，並復原已做的變更。

==== 發生問題時

取代或刪除檔案之前，OxideMerge 會先將它複製到設定資料夾中 `sync-recovery` 資料夾內的復原日誌，
絕不會放在被同步的資料夾裡。

* 若某項變更失敗，或您按一下「停止」，OxideMerge 會從最後一項開始，復原目前已完成的變更。
* 若某個檔案在這期間又被變更，OxideMerge 不會覆寫它，而是顯示「部分套用 — 需要復原」，
  並保留含有副本的日誌。
* 若 OxideMerge 在同步完成前結束，下次啟動時會詢問要復原這些變更，還是讓資料夾保持現狀。
  在您做出選擇之前，這些資料夾無法再次同步。
* 無論 OxideMerge 在哪個時間點停止，以上都成立：建立日誌時、副本仍是暫存檔名時、
  重新命名的兩個步驟之間、刪除檔案之後、最後檢查時，或正在復原時。
  復原時會先移除同步留下的暫存檔，再逐一還原每項變更。
* 復原可以安全地重複執行：已還原的項目會略過。
  若仍有項目無法復原，訊息會列出每個路徑及原因。
  請逐一處理（有程式開著該檔案、磁碟已滿、缺少權限，或檔案之後又被修改），
  再選一次「復原這些變更」。

IMPORTANT: 對多個檔案的套用並非單一的不可分割操作。
每個檔案都是以不可分割的方式取代，但其他程式可能會看到部分檔案已變更。
此操作不會使用資源回收筒。

=== 文件、試算表與程式

有些檔案本身不是純文字，卻含有文字。
OxideMerge 會自行讀取這些檔案，不需另外安裝程式，讓您依內容比較 PDF、文書文件、試算表、程式與
notebook：

[cols="1,3"]
|===
|檔案 |比較的內容

|`.pdf`
|每一頁的文字，依繪製順序排列，頁與頁之間以空行分隔，也包含頁面所繪製之表單（Form）中的文字。
字元取自檔案為各字型所附的 `ToUnicode` 對照表，或取自字型所指定的編碼。
加密的檔案會明確回報，而非讀取為空白。
若檔案有部分內容無法讀取（例如採用 OxideMerge 不支援之壓縮方式的串流，
或字型沒有字形對應字元的對照表），結尾會以一行說明文字並不完整及其原因；
若完全讀不出任何文字，則會明確回報。

|`.docx`、`.odt`、`.rtf`
|文件的文字，每個段落或標題一行。
表格的儲存格以 Tab 分隔，每列一行。
標示為已刪除的文字與功能變數代碼不會列入。

|`.xlsx`、`.xlsm`、`.ods`
|每個工作表，每列一行，儲存格以逗號分隔。
資料列之間的空白列會保留，使各列維持原本的位置；最後一列之後的空白列則不列入。
活頁簿會以<<table-compare,表格比較>>開啟。
只有一個工作表時，欄位、排序與「列配對方式 → 鍵欄」皆可使用。
有多個工作表時，表格下方會為每個工作表顯示一個索引標籤，並標示其中有幾列不同；
由於這些工作表並非同一個表格，各列一律依位置配對。
工作表依名稱配對，因此只有一側才有的工作表會整個顯示為差異。
「格式化的值」會依數值格式顯示數字與日期，如同試算表程式所顯示；關閉後則顯示儲存的值。
無論如何，列都是以儲存的值比較。
在文字檢視中，每個工作表的資料前會標示其名稱。

|ELF 程式、共用程式庫與目的檔
|首先是標頭（類別、位元組順序、種類、機器、ABI、進入點與各項數量）。
接著是程式標頭，每個區段（segment）一行，含類型、位移、虛擬與實體位址、檔案中與記憶體中的大小、
對齊與 `R`、`W`、`E` 旗標（動態連結的程式還會列出所需的解譯器）。
然後是區段表，每個區段一行，含名稱、類型、位址、位移、大小、對齊與旗標。
最後是各符號表（`.symtab`、`.dynsym`）的符號，依名稱排序，每個符號一行，
含位址、大小、類型、繫結、可見性與所在區段（未定義為 `UND`，絕對值為 `ABS`）。
因此兩次建置可逐一函式對照，變大或搬移的函式會顯示為變更的一行。
ARM 與 RISC-V 組譯器加入的對應符號（`$x`、`$d` 等）會略過，只列出數量；
每個符號表最多列出 100,000 個符號。

|`.ipynb`
|Jupyter notebook，逐一儲存格比較：每個儲存格上方有一行，標示它是程式碼儲存格、
Markdown 儲存格或原始（raw）儲存格，並只比較該儲存格本身的原始內容。
儲存格不編號，因此新增一個儲存格，不會改變其後每個儲存格的標示。
執行後附加的輸出、執行次數等中繼資料都不會列入，因此未變更內容而重新執行的 notebook 會視為相同。
較舊的 nbformat 3 notebook 也能讀取，其標題儲存格會讀成 Markdown 標題。
最多讀取 20,000 個儲存格，文字結尾會說明略過了多少個。
無法以這種方式讀取的 notebook（例如已損毀的檔案）會以其 JSON 文字比較。
|===

以這種方式讀取的檔案為*唯讀*：窗格會標示讀取的內容（例如 `report.docx [文件文字]`），
且無法編輯或覆寫原始檔案。
這些文字是對檔案的解讀，而非檔案的複本，因此版面、字型、公式等格式中的其他內容並不會被比較。

兩個或三個 `.docx` 檔案也可以在窗格上方選擇「格式化」來比較。
文件會以 Markdown 逐一區塊並排顯示：標題、含粗體、斜體與刪除線文字的段落、清單項目、連結與表格；
不同的區塊會連同變更的文字一起標示。
表格以表格形式繪製，合併儲存格會橫跨其涵蓋的列與欄；
在合併儲存格內新增的列會在其所在位置標示，標題儲存格向下延伸到的列也屬於標題。
圖片以其描述加上圖片內容的簡短指紋顯示，因此即使描述相同，圖片變更了也會顯示為差異。
「下一個差異」與「上一個差異」會在變更的區塊間移動。
與文字一樣，格式化檢視不包含頁首、頁尾、註腳與註解，追蹤修訂則以接受後的內容顯示。

活頁簿（`.xlsx`、`.xlsm`）無論只有一個或有多個工作表，也都能以「格式化」比較。
每個工作表以一個標題加上一個表格呈現。
工作表依名稱對齊，因此新增或移除的工作表會整個顯示為差異。
合併儲存格會橫跨其涵蓋的儲存格繪製。
數字以其數值格式顯示：日期與時間不論格式中的順序，一律以 ISO 形式顯示（`2026-09-30 18:00`），
金額則包含小數位數、千分位、貨幣符號與百分比符號。
公式顯示儲存時的計算結果。
連續三列以上的空白列會顯示為一列並註明列數，因此往下移動一列的值仍會顯示為差異。
工作表上的每張圖片會列在表格之後，附上描述、所在儲存格與圖片內容的指紋，
因此圖片變更或移動都會顯示為差異。
填色、字型、框線、公式本身以及由資料繪製的圖表不會被比較。

加上標籤（tagged）的 PDF 檔案也能以「格式化」比較。
多數文書處理程式匯出 PDF 時會加上標籤，註明哪些文字是標題、段落、清單項目、表格儲存格或圖片，
以及哪些儲存格橫跨多列或多欄。
格式化檢視依這些標籤讀取，因此由文件產生的 PDF，讀起來與文件本身大致相同。
以粗體或斜體字型繪製的文字會保留其格式；但整個段落或標題都是同一格式時，視為樣式而不另外標示。
圖片以其替代文字加上圖片內容的指紋顯示。
頁首、頁尾與頁碼在檔案中標為非內容（artifact），因此不會顯示。
沒有標籤的 PDF（例如掃描檔，或由不加標籤的程式產生的檔案）會顯示相關說明；請改以文字比較。

當每一側都是 `.docx` 檔案、都是活頁簿（`.xlsx`、`.xlsm`）或都是 `.pdf` 檔案，
且由 OxideMerge 自行讀取時，窗格上方會出現「文字」／「格式化」切換。
`.odt`、`.rtf` 與 `.ods` 檔案不提供此切換。
即使「選項 → 外掛程式」中為這些檔案設定了轉換工具，格式化檢視仍會自行讀取檔案。
區塊是否不同只取決於其文字；比較選項只決定變更區塊中要醒目提示哪些字詞。
檔案或選項變更時，會重新產生檢視。
顯示格式化檢視時，工具列上的差異計數仍是文字比較的差異數；
「下一個差異」與「上一個差異」則在格式化檢視中變更的區塊間移動。

其他限制與規則：

* PDF 或 RTF 檔案最大 256 MiB，因為這兩種格式需要整份讀取；超過的檔案會明確回報，而不會讀取。
* `.docx`、`.odt`、`.xlsx` 或 `.ods` 檔案中的每個組成部分最大 64 MiB。
  若有組成部分超過此大小或無法讀取，會明確回報，而不會略過該部分繼續比較。
* ELF 檔案沒有大小限制：只會讀取其標頭、區段表與符號表，每一部分最多 64 MiB。
  由於兩個不同的建置仍可能讀出相同的內容，以「完整內容」進行資料夾比較時，程式檔會依位元組比較。
* 一個 PDF 檔案解碼後的內容總計最多 1 GiB；需要更多的檔案會明確回報，而不會讀取。
* 每個檔案讀出的文字最多 16 MiB，「文字」與「格式化」模式皆然；
  其餘部分會略過，並在結尾以一行說明。
* 在「格式化」模式中，一個表格最多顯示 1,048,576 個儲存格與 1,024 欄；
  超過的列會略過，並在結尾以同樣的一行說明。
  元素超過 300 萬個的部分太大，無法以格式化顯示，會明確回報；「文字」模式仍可讀取。
* 若活頁簿所列的工作表在檔案中都找不到，會明確回報，而不會當作空白比較。

「選項 → 外掛程式」中設定的轉換指令會優先使用，因此您隨時可以改用更合適的讀取方式，
例如 PDF 使用 `pdftotext`，或以 Pandoc、Tika 處理更多格式。
轉換指令的輸出一律以文字比較，試算表也不例外。
若在該處取消「將文件、試算表與 ELF 檔讀取為文字」，則會改以封存檔或位元組的形式比較這些檔案。

NOTE: 目前尚未支援舊版 Word `.doc` 與舊版 Excel `.xls`；請在「選項 → 外掛程式」中設定轉換指令。
PDF 記錄的是字形的位置而非詞語，因此分欄、表格與連字可能無法完全依原樣還原；
版面較複雜的頁面，建議改用 `pdftotext -layout` 之類的轉換指令。

=== 壓縮檔

OxideMerge 會將壓縮檔解壓縮後，以資料夾的方式比較，讓您能像處理一般資料夾一樣檢查與編輯壓縮檔的內容。
支援下列格式：

* ZIP 類格式：`.zip`、`.jar`、`.apk`、`.docx`、`.xlsx`、`.odt`、`.epub`、`.nupkg` 等，
  項目可為未壓縮，或以 Deflate、Deflate64、bzip2、LZMA、xz、Zstandard 或 PPMd 壓縮。
* `.tar`、`.tar.gz` / `.tgz`、`.tar.bz2` / `.tbz2`、`.tar.xz` / `.txz` 與 `.tar.zst` /
  `.tzst`。
* `.7z`。

開啟受密碼保護的 ZIP（傳統 ZIP 加密「ZipCrypto」或 WinZip AES）或 7z（包括連檔名也加密的）時，
會出現「壓縮檔密碼」視窗詢問密碼；密碼錯誤時會再次詢問，按一下「取消」則放棄開啟。
密碼只保存在記憶體中，且只在比較開啟期間保留，不再需要時會在記憶體中覆寫清除。

編輯解壓縮後的檔案並儲存，變更就會寫回壓縮檔：
複製、刪除、合併或編輯檔案後儲存，會以新的壓縮檔取代原始檔案，並保留其權限。
只有檔案有變更的壓縮檔才會寫入；您未變更的項目會完全維持原樣，包括日期、壓縮方式與順序，
有變更的項目則使用目前時間。
有變更的 ZIP 項目會保留其壓縮方式；以只能讀取的 Deflate64 或 LZMA 壓縮的項目則改以 Deflate 壓縮，
未變更的 LZMA 項目也是如此，因為其他工具會拒絕原樣複製的這類項目。
7z 會將項目一起封裝成壓縮區塊：只含未變更項目的區塊會原樣複製，
其他區塊則以 LZMA2 重新壓縮，其中的項目保留日期與屬性。

加密的壓縮檔寫回後仍維持加密。
有變更與新增的項目，會以開啟時的密碼，依壓縮檔原本的方式加密
（相同金鑰長度的 AES，或 ZipCrypto；7z 的檔名原本有加密就繼續加密）。
未變更的 AES 加密 ZIP 項目與 7z 區塊會原樣複製；
未變更的 ZipCrypto 項目則會重新加密，因為原樣複製會失去標示其已加密的旗標。

`.tar.xz` 會以 `xz` 的預設方式重新壓縮，`.tar.zst` 則以 `zstd` 的預設方式重新壓縮。
大型的 `.tar.xz` 或 7z 壓縮需要一段時間，因此會在背景寫入，同時以視窗顯示正在寫入哪個壓縮檔；
上傳、關閉分頁與結束程式都會等候寫入完成。
若壓縮檔本身在解壓縮後已在磁碟上被修改，或為唯讀，則會拒絕寫入，以免遺失那些變更。
解壓縮後的壓縮檔內不會建立 `.bak` 備份。
透過 SFTP 或 FTP 取得的壓縮檔，儲存後會再上傳回伺服器。

位於解壓縮壓縮檔內的壓縮檔也可以編輯：儲存時會一併寫入它所在的壓縮檔，一路寫到最外層；
已開啟的該壓縮檔比較也會重新比較。

下列壓縮檔仍為唯讀，因為沒有可寫回變更的原始檔案，或重新寫入會使其損壞：

* 以檢閱快照開啟的壓縮檔，或從網頁比較出的頁面樹狀結構；
* 已簽署的套件（`.apk`、`.ipa`、`.appx`、`.msix`、`.crx`、`.xpi`，以及含有 `META-INF` 簽章或
  `_xmlsignatures` 資料夾的 zip），因為重新寫入會使簽章失效；
* 位於上述壓縮檔內的壓縮檔。

解壓縮後超過 8 GB 或 500,000 個檔案的壓縮檔不會開啟。
不支援 RAR 格式。

[[binary-comparison]]
== 比較二進位檔

二進位比較可用來檢查與修正非文字檔，例如編譯後的程式、韌體映像檔、封存檔與資料檔。
OxideMerge 會逐一位元組顯示兩個檔案，精確指出差異所在，
並讓您直接編輯個別位元組，或將差異從一個檔案複製到另一個檔案。

二進位檔會以並排的十六進位檢視開啟。
不同的位元組會醒目標示，兩側會同步捲動。

* kbd:[Alt+↓] 與 kbd:[Alt+↑] 可移到下一個與上一個差異。
* kbd:[Ctrl+F] 可尋找十六進位位元組（例如 `DE AD BE EF`）或文字。
* kbd:[Ctrl+G] 可跳至指定位移，位移可寫成 `0x1F00`、`1F00h` 或十進位數字。
* 與文字比較相同，您可以將差異複製到另一側並儲存。

若要變更每行顯示的位元組數，請使用「選項 → 影像 / 二進位」中的「每行位元組數（二進位）」。

=== 移動區塊

插入、刪除或重新排列資料後，相同的位元組會落在兩個檔案中不同的位移。
二進位工具列的「移動區塊」會在十六進位欄、文字欄與位置窗格中，標示位於不同位移的相同區塊。

位置窗格中，每一側各有一欄。
移動區塊以淺色標示，實心長條則標示變更的位元組，也就是沒有移動區塊可以解釋的不同位元組，
例如插入或覆寫的位元組；目前差異的長條以強調色顯示。
按一下長條即可捲動到該處。

選取已標示的位元組後，按「前往相符區塊」即可跳到另一側的對應位置，並保留您在區塊內的相對位移。
您也可以按 Tab 將焦點移到按鈕，再按 Enter；跳轉後焦點會回到位元組格，方便您繼續使用方向鍵。

雙向與三向比較都支援移動區塊；在三向比較中，按鈕會前往其旁邊顯示的第一個相符側。
取消勾選後，只會顯示一般差異。
OxideMerge 會記住這個勾選狀態，並在下次開啟二進位比較時沿用。

勾選此方塊時，工具列上的「緊密排列」與「對齊排列」決定位元組的排列方式，
與文字比較的「排列方式」是同一個設定，也可在「檢視 → 排列方式」中切換：

緊密排列:: 每一側都在自己的位移顯示位元組，因此每一列在兩側都是相同的位移。
對齊排列:: 每個移動區塊都與其相符區塊顯示在同一列；
區塊之間的位元組對面留下空白儲存格，就像文字比較中新增或刪除行對面的空白。
每一列開頭顯示該側在這一列的第一個位元組的位移。

若要實際試用，請比較 `samples/left/bin/firmware.bin` 與 `samples/right/bin/firmware.bin`。
左側檔案在位移 `0x20` 多了一個位元組 `A5`，後面還有幾處不同。

.使用緊密排列的移動區塊
image::binary-compact.png[以緊密排列比較韌體範例的二進位比較]

使用「緊密排列」時，`A5` 之後的每個位元組在左側都比右側晚一個位移，
因此從 `00000020` 這一列起，兩側同一列顯示的位元組並不相同；相符的位元組會標示為移動區塊。

.以對齊排列顯示相同檔案
image::binary-aligned.png[以對齊排列比較韌體範例的二進位比較]

使用「對齊排列」時，右側會在 `A5` 對面留下一個空白儲存格，之後的位元組便重新對齊。
在下一處差異，左側會在只有右側檔案才有的 `52 71` 對面留下兩個空白儲存格。
從這裡起，兩側每一列的開頭位移不同，例如左側為 `0000004E`，右側為 `0000004D`。

互相交錯的區塊（例如兩個交換位置的區塊）無法全部並排，只會並排在兩側順序一致的最長一組區塊。
在三向比較中，左側與右側會各自與中間側對齊；只有左右兩側共有的區塊會標示，但不會對齊。
方向鍵會依畫面上的列移動；按一下空白儲存格會選取該側的下一個位元組。
編輯期間，各列會維持原位，直到重新找到區塊為止。
差異導覽與差異計數仍比較兩側相同位移的位元組。

偵測可找到兩種相同的位元組：

* _因插入或刪除而位移的資料_：位於編輯處附近、往前或往後移動最多 128 個位元組的資料，
  包括兩處編輯之間較短的資料段。
* _移到較遠處或交換順序的區塊_：至少 16 個位元組、且只在檔案中出現一次的資料。
  重複出現的資料（例如整段填充位元組）不會以這種方式配對。

NOTE: 標示只是額外提供的資訊，差異範圍、複製差異、檔案內容與儲存的位元組都不會因此改變。

偵測在背景執行：開啟比較時執行一次；之後每次編輯、復原、重做或複製差異，
待您停止輸入片刻後會再執行。
編輯或關閉比較會立即停止進行中的偵測，因此不會拖慢編輯，也不會額外占用記憶體。
大型檔案會以取樣方式偵測，因此可能略過部分較短的相符區塊；每對檔案最多標示 1,024 個區塊。

=== 編輯位元組

您可以直接在比較中修改二進位檔，以十六進位值或字元輸入皆可。

若要編輯位元組：

. 在要修改的一側按一下位元組。
  按一下十六進位欄可輸入十六進位數字，按一下右側的文字欄則可輸入字元。
. 輸入新的值。
  在十六進位欄中，兩個數字構成一個位元組：第一個數字修改位元組的前半，第二個數字修改後半。
  在文字欄中，每個字元會取代一個位元組，且只能輸入 ASCII 字元。
. 按 kbd:[Ctrl+S] 儲存。

根據預設，輸入的內容會取代游標處的位元組。
若要改為插入位元組，請按 kbd:[Insert]，或按一下工具列上的「插入」。
在最後一個位元組之後輸入時，一律會新增位元組。

* 方向鍵、kbd:[PgUp]、kbd:[PgDn]、kbd:[Home] 與 kbd:[End] 可移動游標。
  kbd:[Ctrl+Home] 與 kbd:[Ctrl+End] 會移到檔案的開頭與結尾。
* kbd:[Delete] 會刪除游標處的位元組，kbd:[Backspace] 會刪除游標前的位元組。
* 在十六進位欄中貼上（kbd:[Ctrl+V]）會寫入 `DE AD BE EF` 這類十六進位位元組，其他文字則無法貼上。
  在文字欄中，文字會依原樣寫入。
* kbd:[Ctrl+Z] 可復原上次移動游標後輸入的內容，或復原一次貼上。

唯讀的一側無法修改。
若要變更此設定，請按一下該側上方的鎖頭圖示。

[[image-comparison]]
== 比較影像

影像比較能清楚呈現同一張圖片的兩個版本之間有哪些變更，例如螢幕擷取畫面、圖示或設計素材。
多種檢視模式可協助您找出明顯與細微的變化，您也可以將變更的區域從一張影像複製到另一張，並儲存結果。

.影像比較
image::image.png[影像比較]

請依要找的變更選擇檢視模式：

並排:: 兩張影像左右並排。
疊加:: 一張影像疊在另一張上，「不透明度」決定上層影像的透明程度。
滑動:: 分隔線左邊顯示一張影像，右邊顯示另一張；拖曳分隔線即可移動。
閃爍:: 交替顯示兩張影像，方便看出細微的變化。
差異:: 只顯示像素的差異。

若要找出與複製差異：

* 「醒目提示差異」會標出不同的區域。
** 「色彩距離門檻」決定兩個像素要相差多少才算不同。
** 「區塊大小」決定標示區塊的大小。
* 按一下某個區域即可選取它。
  kbd:[Alt+↓] 與 kbd:[Alt+↑] 可移到下一個與上一個區域。
* kbd:[Alt+→] 與 kbd:[Alt+←] 可將目前的區域複製到另一張影像。
  「復原」可取消複製，kbd:[Ctrl+S] 可儲存變更後的影像。

若要縮放與平移：

* 您可以使用按鈕、滑鼠滾輪或雙指縮放手勢縮放，縮放時會以指標位置為中心。
* 「符合視窗」讓影像符合視窗大小，「1:1」以實際大小顯示。
* 拖曳或以雙指捲動，即可一起平移所有影像。

狀態列會顯示有多少像素不同，以及分布在幾個區域。

[[web-comparison]]
== 比較網頁

網頁比較可呈現網頁不同版本之間的變更，適合用來確認部署結果或審閱內容的修改。
您可以依需要比較網頁的文字、格式化檢視、HTML 原始碼，或網頁載入的資源。

您可以比較兩個或三個網址（`http://` 或 `https://`），或本機的 HTML 檔案。
本機 `.html` 與 `.htm` 檔案預設就會以網頁比較開啟。
若要將其他類型的檔案當作網頁比較，請選擇「比較方式 → 網頁」，或在命令列使用 `-t web`。

=== 比較模式

每種模式會從不同的角度比較網頁。
請在分頁上方的模式選擇器中選擇模式；OxideMerge 會記住您上次使用的模式。

[cols="1,3"]
|===
|模式 |比較的內容

|文字
|每個網頁的文字，以文字比較開啟。
每個標題、段落與清單項目各占一行；表格的每一列占一行，儲存格之間以定位字元分隔。
隱藏的元素不列入比較。
變更的字詞會醒目標示，比較選項、篩選器與報告也都適用。

|格式化
|預設模式。將每個網頁轉換成 Markdown，並排顯示格式化的結果。
請參閱 <<web-formatted>>。

|HTML 原始碼
|每個網頁的 HTML，以文字比較開啟。
經過壓縮的長行會在標籤之間斷開。

|資源樹
|下載每個網頁及其樣式表、指令碼、影像、框架與媒體，再以資料夾比較來比較這些下載的檔案。
|===

切換到其他模式時，會重新載入網頁。
網頁有變更後，請按「重新載入網頁」（kbd:[F5]）。

若要逐行比較本機檔案的 HTML 原始碼，請使用 HTML 原始碼模式，或選擇「比較方式 → 文字」（`-t text`）。

[[web-formatted]]
=== 格式化模式

格式化模式讓您以接近讀者看到的樣子審閱網頁。
它會保留標題、段落、強調、連結、清單、引言、程式碼區塊與表格的樣式；影像則以連結顯示。

.以格式化模式比較兩個網頁
image::web.png[格式化模式的網頁比較]

OxideMerge 以區塊為單位比較網頁。
區塊是指一個標題、段落、清單項目、表格、引言或程式碼區塊。

* 不同的區塊會醒目標示，並與其他網頁上同類型的變更區塊對齊。
* 只在一個網頁出現的區塊，對面會留白。
* 在變更的區塊中，變更的字詞或字元會以較深的顏色標示；與文字比較相同，此行為由「行內差異」選項控制。
* 表格會以框線畫出儲存格，各列也會對齊。
  不同的列中會醒目標示變更的字詞；另一個網頁缺少的列或欄，整個儲存格都會醒目標示。
* 橫跨多列或多欄的儲存格（`rowspan`、`colspan`）會畫過其涵蓋的儲存格，
  因此同列的其他儲存格仍會留在各自的欄中。
* 每個變更的區塊各算一個差異，即使緊接在另一個變更的區塊之後也一樣。

若要在差異之間移動，請使用網頁上方的按鈕，或與文字比較相同的按鍵。

* 目前的差異會以較深的顏色標示，正在比較的區塊在每個網頁上都會加上外框；
  您最後按一下的網頁，外框最明顯。
* 按一下某個區塊，即可將它設為目前的區塊，之後的下一個與上一個差異就從該處開始尋找。
* 只有在差異不在畫面中時，網頁才會捲動，並將差異顯示在距離頂端約三分之一的位置。

網頁右側的位置窗格會顯示所有差異：目前的差異以強調色顯示，網頁目前可見的部分會加上外框。
在位置窗格中按一下或拖曳，即可前往該處。
若要顯示或隱藏位置窗格，請選擇「檢視 → 文字比較 → 位置窗格」。

=== 網頁的載入方式

所有模式都直接使用伺服器傳回或檔案中儲存的原始 HTML。
OxideMerge 不會在瀏覽器中開啟網頁，因此開啟速度很快。
由於網頁的指令碼不會執行，指令碼加入的內容也不會出現。

文字與格式化模式會略過網頁隱藏的內容：帶有 `hidden`、`aria-hidden="true"` 屬性，
或以行內 `display: none`、`visibility: hidden` 樣式隱藏的元素。
只由樣式表隱藏的內容仍會比較。

OxideMerge 解碼網頁的方式與瀏覽器相同，會依序採用第一個找到的資訊：
位元組順序標記、HTTP `Content-Type` 標頭中的字元集、`<meta>` 中的字元集，最後才依內容推測。

* 伺服器傳回非 2xx 的狀態碼時，窗格標題列會顯示該狀態碼，並比較隨之傳回的網頁。
* 網頁無法連線、超過 30 秒未回應、回應格式不正確或大於 50 MB 時，OxideMerge 會連同網址一併回報。

=== 資源樹的限制

資源樹模式只下載每個網頁本身列出的資源，不會再追蹤樣式表或指令碼中的連結。

* 每個網頁最多 400 個資源，每個資源最大 20 MB。
* 無法下載的資源會在狀態列中計數，其餘資源仍會照常比較。
* 為了安全起見，網頁不得載入本機檔案。
  只有位於本機或私人網路（例如 `localhost` 或 `192.168.x.x`）的網頁，
  才能從這類位址載入資源或被重新導向到這類位址；
  其他這類資源會被略過，並在狀態列中計數。
* 您自行輸入的網址一律會載入。

=== 在主控台比較網頁

您也可以在指令碼或終端機中比較網頁。
主控台比較（以 `--cli` 比較 HTML 檔案，或指定 `-t web` 時）會沿用您在視窗中最後選擇的模式：

* 格式化模式（預設）會逐行比較網頁的 Markdown。
* HTML 原始碼模式會比較 HTML。
* 其他模式會比較可見文字。

NOTE: 所有模式都不會執行網頁的指令碼。
不支援登入，因此需要登入的網頁可能只會顯示登入畫面。
所有模式都不會將變更存回網頁伺服器。

[[differences-shown]]
== 控制要顯示的差異

並非檔案之間的每一處變更都值得關注。
重新排版的程式碼、紀錄中的時間戳記或自動產生的標頭，可能會掩蓋您真正需要審閱的少數差異。
OxideMerge 讓您自行決定哪些內容算是差異，使比較結果只呈現與工作相關的變更。

有三類設定會決定 OxideMerge 將哪些內容顯示為差異：

* 篩選器：選擇資料夾比較要包含哪些檔案與資料夾。
* 比較選項：決定哪些文字變更要計入，例如空白字元或大小寫。
* 比較規則：忽略或取代符合樣式的文字。

這些設定只會改變比較結果，絕不會修改檔案。

TIP: 若預期中的變更沒有顯示，請先檢查這些設定，再判斷檔案是否相同。

[[compare-options]]
=== 比較選項

比較選項決定 OxideMerge 要將哪些類型的文字變更視為差異。
「比較 → 比較選項」提供最常用的選項，「選項 → 比較」則包含全部選項：

空白字元::
「比較」：空白字元列入比較。
「忽略變更」：空白字元的數量不同時不算差異。
「全部忽略」：完全忽略空白字元。
忽略空白行:: 多出來的空白行不算差異。
忽略大小寫:: 大寫與小寫字母視為相同。
忽略換行字元差異（Windows/Unix/Mac）:: `CRLF`、`LF` 與 `CR` 三種換行字元視為相同。
忽略數字:: 忽略所有數字。
忽略字碼頁差異:: 編碼不同但文字相同的檔案視為相同。
忽略註解變更:: 只有註解的變更不算差異。
適用於已知註解語法的語言：C 類語言、指令碼語言、SQL、HTML、XML、CSS、Lua、Haskell 等。
比較前格式化 JSON 與 XML:: 重新縮排 JSON 與 XML，並排序 JSON 的鍵，避免排版變更被當成差異。
格式化後的檢視為唯讀；若要編輯或合併檔案，請關閉此選項。
偵測移動的行:: 被搬移的整段行會標示為移動。
差異演算法:: 「Myers」、「Patience」或「LCS」。
行內差異:: 行內變更的標示方式：「關閉」、「單字層級」或「字元層級」。
數字差距在此範圍內視為相同:: 差距不超過此值（例如 `0.001`）的數字視為相同，
適合比較量測值或自動產生的資料。

在資料夾比較中，只有比較方法為「完整內容」時，這些選項才會套用到文字檔；其他方法不使用這些選項。

[[compare-rules]]
=== 比較規則

比較規則以規則運算式忽略或改寫符合的文字，專門處理時間戳記、自動產生的段落或授權聲明等
檔案特有的雜訊。
比較規則檔（`.oxrules`）包含三類規則：

忽略符合的行:: 每行一個規則運算式。
只由符合的行組成的差異會被忽略。
取代規則:: 每行一條規則，寫成 `+規則運算式 => 取代文字+`。
OxideMerge 會在比較前將取代規則依序套用到兩側，每條規則套用到前面的規則處理後的文字；
行內有變更的字詞也以同樣方式標示。
取代規則適合處理預期中就會不同的文字。
忽略起始行與結束行之間的區塊:: 每行一個區塊，寫成 `+起始規則運算式 => 結束規則運算式+`。
區塊內的差異會被忽略，適合處理自動產生的段落或授權聲明。

規則運算式採用 Rust `regex` 套件的語法。

==== 管理規則檔

.選項 → 比較規則
image::rules.png[比較規則選項]

您可以在「選項 → 比較規則」中管理規則檔：

* 選擇「無」或某個規則檔。
  沒有另外指定規則檔的比較，會預設使用這個檔案。
* 「新增規則檔」會建立新檔案，「編輯」會以規則編輯器開啟檔案，「刪除」則會移除檔案。
* 「開啟規則資料夾」會在檔案管理員中顯示該資料夾；在其中變更檔案後，請按「重新載入」。
* 「匯入...」可加入其他人分享的規則檔；
  「匯出」可匯出單一檔案，或以「所有規則檔到資料夾...」將全部檔案匯出到資料夾。

資料夾比較可以使用不同的規則檔，請從工具列的「規則」或「比較 → 比較規則」中選擇。
「重新整理」（kbd:[F5]）會重新讀取規則檔。

您也可以用拖放的方式匯入規則檔：

* 將一個 `.oxrules` 檔案拖放到視窗上即可匯入；拖放兩個時，OxideMerge 會改為比較這兩個檔案。
* 將任意數量的 `.oxrules` 檔案拖放到選項對話方塊上，即可一次匯入。

匯入規則檔時，OxideMerge 會依下列方式處理：

* 已有名稱與規則都相同的檔案時，略過新檔案。
* 已有名稱相同但規則不同的檔案時，新檔案的名稱會加上編號。
* 已有規則相同但名稱不同的檔案時，新檔案以自己的名稱加入。

==== 規則檔格式

規則檔存放在設定檔旁的 `Rules` 資料夾中（請參閱 <<configuration>>）。
OxideMerge 也會讀取程式旁的 `Rules` 資料夾。

規則檔是 JSON 檔案，規則的名稱就是去掉 `.oxrules` 的檔名。
以下是 `samples/rules/Build logs.oxrules`：

.Build logs.oxrules
[source,json]
----
{
  "description": "Timestamps, generated headers and load addresses in samples/*/logs/build.log",
  "ignore_lines": ["^// Generated on .*$"],
  "substitutions": [
    { "find": "^\\[\\d{2}:\\d{2}:\\d{2}\\] ", "replace": "[time] " },
    { "find": "\\b0x[0-9a-fA-F]{8,}\\b", "replace": "0xADDR" }
  ],
  "ignore_blocks": [{ "start": "^/\\* BEGIN LICENSE", "end": "END LICENSE \\*/$" }]
}
----

每個欄位都可以省略：

`description`:: 顯示在「選項 → 比較規則」中名稱的旁邊。
`ignore_lines`:: 規則運算式的清單。
若某個差異的每一行都符合其中之一，該差異就會被忽略。
`substitutions`:: `find` 與 `replace` 的配對清單。
比較前，兩個檔案中每個符合 `find` 的地方都會依清單順序換成 `replace`。
取代文字可以使用符合內容的群組：`$1` 是第一個群組。
窗格中顯示的仍是檔案中原本的文字。
`ignore_blocks`:: `start` 與 `end` 的配對清單。
區塊從符合 `start` 的行開始，到下一個符合 `end` 的行結束；
這兩行都屬於區塊，區塊內的差異會被忽略。
結束也可以出現在起始行中較後面的位置。
只有起始而沒有結束行的不算區塊，因此不會忽略任何內容。

每個規則運算式一次只比對一行，因此 `^` 與 `$` 代表行首與行尾。
在 JSON 中，規則運算式的每個反斜線都要寫兩次：檔案中的 `\\d` 就是規則運算式中的 `\d`。
「選項 → 比較規則」中的規則編輯器顯示的是未重複反斜線的規則運算式。

==== 範例：建置紀錄

本範例說明如何以一個小型規則檔，將雜訊繁多的比較精簡到只剩真正重要的變更。
`samples/left/logs/build.log` 與 `samples/right/logs/build.log` 是同一個建置的兩次執行紀錄。
不使用規則時，幾乎每一行都不同，因為建置主機、日期、每個時間戳記與載入位址每次都不一樣。

.不使用規則的兩份建置紀錄
image::rules-off.png[不使用規則比較兩份建置紀錄]

若要以 *Build logs* 規則比較這兩份紀錄，請匯入 `samples/rules/Build logs.oxrules`
（「選項 → 比較規則 → 匯入...」）、選取它，再開啟這兩個檔案。
您也可以在命令列上為單次比較指定規則：

[source,sh]
----
oxidemerge --rules "Build logs" samples/left/logs/build.log samples/right/logs/build.log
----

`--rules` 也接受檔案路徑，因此不必匯入也能使用這些規則：
`--rules "samples/rules/Build logs.oxrules"`。

每條規則各處理紀錄中的一種雜訊：

* 從 `^/\* BEGIN LICENSE` 到 `END LICENSE \*/$` 的忽略區塊涵蓋第 1 到 4 行的授權標頭，
  因此 `Build host: build-01` 與 `build-07` 不再算作差異。
* 忽略的行 `^// Generated on .*$` 涵蓋記錄執行日期的第 5 行。
* 第一條取代規則會將每行開頭的時間戳記（例如 `[09:12:05]`）換成 `[time]`。
  規則運算式結尾包含時間戳記後的空格，因此取代文字也以空格結尾。
* 第二條取代規則會將 8 位以上十六進位數字的載入位址（例如 `0x7FF6A1B20000`）換成 `0xADDR`，
  因此第 8 行兩側相同。

剩下的就是唯一真正的差異：第 10 行，有一項測試失敗。
被忽略的行以灰色顯示，差異計數顯示 *1/1*。
第 10 行的時間戳記沒有標示，因為取代規則已讓兩側相同。

.使用 Build logs 規則的同一組建置紀錄
image::rules-on.png[使用 Build logs 規則比較兩份建置紀錄]

若要在規則編輯器中查看同樣的規則（每行一條），
請在「選項 → 比較規則」中按一下 *Build logs* 旁的「編輯」。
取代規則寫成 `+find => replace+`；第一條取代規則的 `=>` 前有兩個空格，因為規則運算式以空格結尾。

.規則編輯器中的 Build logs 規則
image::rules-editor.png[顯示 Build logs 規則的規則編輯器]

在指令碼中，同樣的規則也會決定結束代碼。
對這兩份紀錄執行 `oxidemerge --cli --rules "samples/rules/Build logs.oxrules" ...` 時，
會因第 10 行而以 `1` 結束。
若只剩規則忽略的差異，則不會輸出任何內容，並以 `0` 結束。

[[add-rule]]
=== 從文字比較建立規則

您不必從頭撰寫樣式，可以直接從文字比較中的某一行建立規則，並由 OxideMerge 建議樣式。

若要從文字比較建立規則：

. 在文字比較中的某一行上按右鍵，選擇「新增比較規則」。
. 選擇規則的類型：
+
--
忽略類似的行:: 符合該行（或變更行的每一側）的樣式。
取代:: 將一側文字轉換成另一側文字的取代規則。
忽略區塊:: 從該行開始的區塊。
--
. 檢查 OxideMerge 建議的樣式，視需要修改。
. 選擇要加入的「規則檔」，或輸入「檔案名稱」建立新檔案。

目前的比較會立即套用新規則；
其他使用相同規則檔的資料夾比較，會在重新整理（kbd:[F5]）後套用。

[[filters]]
=== 篩選器

篩選器決定資料夾比較要包含哪些檔案與資料夾，讓您排除不需要比較的建置輸出、相依套件等項目。
請從資料夾比較工具列的「篩選器」中選擇；若要管理篩選器，請選擇「工具 → 篩選器...」。

篩選遮罩是以 `;` 分隔的萬用字元清單：

* 開頭加上 `!` 表示排除符合的項目。
* 結尾加上 `\` 或 `/` 表示符合資料夾。

例如，下列遮罩會包含 Rust 與 TOML 檔案，並排除 `target` 資料夾：

----
*.rs;*.toml;!target\
----

OxideMerge 也會列出 WinMerge 的 `.flt` 篩選器檔案，
來源為設定資料夾中的 `Filters` 資料夾，以及程式旁的 `Filters` 資料夾。
「工具 → 篩選器...」會列出這些篩選器，並可開啟篩選器資料夾及新增篩選器。

[[unpackers]]
=== 解譯器外掛程式

解譯器外掛程式可讓 OxideMerge 比較它本身無法以文字讀取的檔案格式。
外掛程式會在比較前將檔案轉換為文字，OxideMerge 再比較轉換程式寫到標準輸出的文字。

OxideMerge 本身即可讀取 PDF、`.docx`、`.odt`、`.rtf`、`.xlsx`、`.ods`、`.ipynb` 與 ELF 程式
（請參閱 <<documents>>），因此只有在遇到它尚未支援的格式（例如舊版 Word `.doc` 與 Excel `.xls`），
或想以更好的方式讀取上述格式時，才需要外掛程式。
只要外掛程式的檔案樣式符合，就一律優先使用。

若要新增外掛程式：

. 安裝轉換程式，並確認命令找得到它。
. 在「選項 → 外掛程式」中新增項目，填入「檔案樣式」（例如 `*.docx`）與「命令列」。
  命令列中的 `${file}` 會替換為已加上引號的檔案路徑。
. 啟用該項目。

預設按鈕可新增 PDF 文字（`pdftotext`）、Office 與 OpenDocument 文件（`pandoc`），
以及一般文件擷取（`tika`）的項目；這些項目新增後預設為停用。
將指標移到項目的核取方塊上，即可查看它需要哪個程式。
這項檢查只看命令中的第一個程式名稱；若命令實際執行失敗，OxideMerge 會顯示轉換程式的輸出訊息。

以已安裝的 Pandoc 為例：

----
pandoc -t plain ${file}
----

凡是以文字比較檔案的地方都會使用轉換程式：單一檔案、以「完整內容」比較的資料夾、命令列、
檔案比較窗格、「所有差異」，以及資料夾報告中的差異。
資料夾比較的大小、日期、快速內容與二進位方法，仍然會比較原始檔案。

下列限制與規則適用：

* 擷取出的文字為唯讀，絕不會覆寫原始文件。
* 每次轉換最多執行 30 秒，每個輸出串流最多 16 MiB。
* 轉換程式以非零的結束代碼結束時，即使已輸出部分文字，仍視為錯誤。
* 停止資料夾掃描時，進行中的轉換也會一併停止。

[[projects]]
=== 專案

專案可讓您日後回到相同的比較，不必重新選擇檔案與選項。

「檔案 → 專案與工作 → 另存為專案...」會將目前分頁所比較的內容存成 `.oxmproj` 檔案。
專案會儲存：

* 路徑、說明文字與唯讀的側；
* 比較類型、篩選器、「包含子資料夾」與比較方法；
* 比較規則檔。

若要再次開啟專案，請選擇「檔案 → 專案與工作 → 開啟專案...」。
OxideMerge 也能開啟 WinMerge 的專案檔（`.WinMerge`）。

路徑會以相對於專案檔的方式儲存，因此專案可以和檔案一起搬移。
位於其他 Windows 磁碟機的路徑會保留為絕對路徑，網址也不會變更。

專案不包含檔案本身；開啟專案時，OxideMerge 會載入這些路徑上當下的檔案。
將專案搬到其他電腦時，請一併複製其中的檔案，以及專案使用的外部規則檔。

TIP: 若要分享目前的文字與審閱註記，請改為儲存比較。

[[workspaces]]
=== 工作區

工作區會以您指定的名稱儲存一組已開啟的比較分頁，方便您隨時一次全部重新開啟。

若要儲存已開啟的分頁，請選擇「檔案 → 工作區 → 另存為工作區...」，並輸入最多 80 個字元的名稱。
OxideMerge 會儲存所有擁有自己檔案的文字、二進位、影像、網頁與資料夾比較分頁。
名稱以及各分頁的路徑與設定都儲存在您的設定中，而不會另外存成檔案。

沒有可重新開啟之自身內容的分頁不會列入，這與 OxideMerge 自動重新開啟的工作階段省略它們的方式
相同：

* 「所有差異」與審閱分頁；
* 剪貼簿；
* 暫存副本的分頁，例如透過 SFTP 或 FTP 取得的檔案或資料夾（請參閱 <<remote-sftp>>）、修訂版本，
  或從壓縮檔比較中開啟的檔案。

儲存後，訊息會說明儲存了多少個分頁、略過了多少個。
若目前開啟的分頁都無法儲存，對話方塊會告知您，且不會儲存任何內容。

工作區名稱不分大小寫。
以既有工作區的名稱儲存時，OxideMerge 會先告知您，並在您按一下「取代」後才取代其分頁。

「檔案 → 工作區」選單會列出已儲存的工作區（前 15 個；「管理工作區...」會列出全部）。
選擇其中一個，即可一次重新開啟它的所有分頁，與目前已開啟的分頁並存。
檔案已不存在的分頁不會重新開啟，訊息會說明有多少個分頁無法開啟。

「管理工作區...」會列出已儲存的工作區，供您開啟或刪除。
若要找回已刪除的工作區，請在刪除後出現的訊息中按一下「復原」。

NOTE: 工作區與 OxideMerge 啟動時自動重新開啟的那一個未命名工作階段不同：
該工作階段會自動保留並取代，而工作區只會依您指定的名稱保留與重新開啟。
同時執行兩個 OxideMerge 視窗時，在其中一個視窗儲存或刪除的工作區，在另一個視窗儲存設定時仍會
維持儲存或刪除後的狀態。

[[recovery]]
=== 復原未儲存的工作

在「選項 → 一般」中開啟「保留未儲存的工作以便復原」（預設為關閉）後，OxideMerge 執行時會為開啟的比較保留一份快照：
包括路徑與設定、選取的差異、文字游標所在的行、書籤、每個比較檔案的大小與修改時間，以及每一側尚未儲存之編輯的完整文字。
有未儲存的編輯時每 5 秒寫入一次，否則每 30 秒寫入一次，存放在設定檔旁邊的私人 `recovery` 資料夾
（在 Linux 與 macOS 上只有您可讀取），絕不會放在比較的檔案旁邊。
在可攜模式下，這個資料夾位於程式旁邊。
每個執行中的視窗各有自己的快照；視窗正常關閉，或您關閉此選項時，快照就會刪除。
關閉此選項，或在此選項關閉時啟動，也會不經詢問刪除未正常關閉之視窗留下的快照。

若有視窗未正常關閉（當機、強制結束、斷電），OxideMerge 下次啟動時會詢問如何處理留下的快照：

* 「復原」會重新開啟比較，並將未儲存的文字放回各側。
  復原的各側會標示為已修改，只有在您儲存時才會寫入檔案。
  訊息會列出快照之後已變更的每個比較檔案，方便您在儲存前核對復原的編輯。
  若已以相同類型開啟相同檔案且未經編輯的比較，文字會放回該比較，而不會再開啟一次。
  檔案已無法開啟（已移動、已刪除，或位於未連接的磁碟）的比較，其未儲存的文字會在新的文字比較中開啟，
  各側以其檔案命名，由您選擇儲存位置。
  在您儲存之前，這些文字會像其他未儲存的編輯一樣保留在此視窗的快照中，因此若此視窗也未正常關閉，下次仍會再次提供。
* 「顯示詳細資料」會列出快照中的比較、其中哪些檔案之後已變更，以及有多少側含未儲存的編輯。
* 「捨棄」會刪除快照。
* 「稍後」或 kbd:[Esc] 會保留快照，下次啟動時再詢問。

限制：

* 只保留能從檔案重新開啟的比較，與 OxideMerge 自動重新開啟的工作階段相同；暫存副本的分頁
  （透過 SFTP 或 FTP 取得的檔案、修訂版本、壓縮檔內的檔案）不會列入。
  未儲存的文字只保留文字比較的部分。
* 一份快照最多保留 32 MB 的未儲存文字；超過的各側不會保留，詳細資料會說明有多少側。
* 快照只與最後一次寫入一樣新：當機前幾秒內的編輯可能遺失。
* 執行中的視窗會鎖定自己的快照，因此不論多久以前寫入，其他視窗都不會提供它；視窗結束後，下次啟動時會立即提供。
  無法取得鎖定時，快照超過 2 分鐘未寫入即視為遺留。最多保留五份，最舊的先刪除。
* 由較新版本 OxideMerge 寫入的快照會顯示，但不會復原。

若要排除某個比較，請在其分頁上按右鍵，關閉「保留以便復原」：從下一份快照起，就不會再寫入該比較及其未儲存的文字。
若完全不希望未儲存的文字保存在磁碟上，請關閉此選項。

[[saved-comparisons]]
=== 已儲存的比較

已儲存的比較會保留文字比較的內容與您的註記，方便您日後再回來查看，或交給其他檢閱者。

「檔案 → 儲存比較...」會將文字比較存成 `.oxmcmp` 檔案，
內容包括各側的文字、書籤與註解，以及同步點。

您可以日後再開啟此檔案，或傳送給其他檢閱者。
檔案會以唯讀方式開啟，不需要原始檔案。
它是文字當時的快照：與專案不同，不會依路徑載入目前的檔案。

[[folder-reviews]]
=== 資料夾審閱

資料夾審閱會將完整的資料夾比較（包含檔案內容與您的審閱註記）封裝成單一可攜式檔案，
檢閱者不需要原始檔案即可開啟。

資料夾比較完成後，「檔案 → 儲存比較...」會將其存成 `.oxmreview` 檔案。
這個可攜式封裝檔包含篩選器納入的所有項目。

* 若只要儲存部分項目，請選取檔案或資料夾，按右鍵並選擇「儲存所選資料夾審閱…」。
  選取的資料夾會包含其中已掃描的所有內容。
* 「顯示」設定與篩選標籤只會改變畫面上看到的項目，不會從完整的封裝檔中移除項目。
* 請先完成所有檔案操作；若檔案有變更，請重新整理比較後再儲存。

若要加上註記，請在檔案或資料夾上按右鍵，選擇「切換書籤」或「書籤註解」。
加上書籤的項目，名稱前會顯示 `*`；將指標移到項目上即會顯示註解。
這些註記會存入封裝檔，也會出現在 HTML、XML 與純文字的資料夾報告中，但不會納入 CSV 摘要。
若在已開啟的封裝檔中修改註記，請再次儲存比較以保留變更。

您可以用下列任一方式開啟封裝檔：

* 在命令列執行 `oxidemerge review.oxmreview`；
* 將檔案拖放到視窗上；
* 選擇「檔案 → 專案與工作 → 開啟專案...」。

封裝檔會以唯讀快照開啟，並沿用儲存時的比較選項。
它不需要原始檔案、具名篩選器或外部規則檔。
經轉換的文件會以擷取出的文字儲存，轉換命令則不會儲存，因此檢閱者不必安裝轉換程式。
在樹狀檢視中展開資料夾，即可查看其中的內容。

資料夾審閱有下列限制：

* 支援兩側或三側，最多 10,000 個項目與 256 MiB 未壓縮內容。
* OxideMerge 不接受符號連結、特殊檔案、在其他系統上不安全的路徑，以及比較後已變更的檔案。
* 封裝檔包含每個檔案的完整內容，二進位檔也不例外。

審閱工作區可在資料夾審閱中加入審閱決定，請參閱 <<review-workspace>>。

[[html-reports]]
=== HTML 報告

HTML 報告可讓您與任何擁有網頁瀏覽器的人分享差異，對方不需要使用 OxideMerge。

建立 HTML 報告的步驟如下：

. 開啟文字或資料夾比較，並等待比較完成。
. 檢查比較選項、比較規則與資料夾篩選器，這些設定會決定報告中顯示哪些差異。
. 按一下工具列上的「匯出 HTML」，或選擇「檔案 → 匯出 → HTML 報告...」（kbd:[Ctrl+Shift+E]）。
. 選擇輸出檔案。建議的檔名由比較項目的名稱組成，空格會換成 `_`。
. OxideMerge 會在瀏覽器中開啟報告。分享前請先確認報告內容。

報告是單一的 HTML 檔案，內含顯示所需的一切資源；
收件者可以用任何瀏覽器開啟，不需要安裝 OxideMerge。

* 每個差異以一張卡片呈現，附有行號與前後三行內容，並醒目標示變更的字詞。
* 報告包含摘要卡片、索引、並排或統一檢視、淺色與深色主題、狀態篩選與搜尋。
* 頁首的「上一個」與「下一個」，或 kbd:[P] 與 kbd:[N]，可跨檔案移到上一個與下一個差異；
  計數器會顯示目前位置，該差異會短暫閃動。
  指向差異的連結（例如 `report.html#f-3f9a0c12d4e7-d0`）會展開其檔案，並捲動到頁首下方。
  檔案的連結由其路徑產生，而非其在清單中的位置，因此在下次比較同樣資料夾的報告中仍指向同一個檔案。
  文字報告則依序編號差異：`#d0` 是第一處。
  切換檢視時，正在閱讀的差異會留在原處。
* 搜尋框可搜尋檔名或路徑；選擇「搜尋差異內容」則搜尋所顯示差異的文字，無論檔案是否展開。
  搜尋框會顯示符合的檔案或差異數量，按「清除」即可清空。
* 頁首帶有 OxideMerge 圖示，頁面開啟時會播放動畫：各區塊淡入，摘要卡片中的數字逐步遞增。
  瀏覽器設定為減少動態效果時會顯示靜態頁面，列印時也是如此。
* 報告會列出使用的比較規則檔，並統計被忽略的差異數量。
* 在較窄的視窗或手機上，索引會收合成可點按展開的標題，頁面寬度也會符合螢幕。
* 停用 JavaScript 時，報告仍會顯示所有檔案、差異與連結，只會隱藏需要 JavaScript 的按鈕。

資料夾報告會包含每個已變更文字檔的差異，另外還有：

* 分別統計內容不同的檔案、僅存在於一側的檔案，以及已匯出與略過的差異區塊；
* 列出所有已變更或僅存在於一側之檔案的索引；只列出而不顯示差異的檔案會標示「僅摘要」並說明原因，
  例如二進位檔或內容過長；
* 每個檔案的比較方式，例如「文字」、「試算表儲存格」、「文件文字」或轉換程式；檔案有工作表與列、
  PDF 頁面或筆記本儲存格時，會標示每個差異的位置；CSV、TSV 或試算表中變更的列會列出變更的欄位，
  例如 `Alice · score · 90 → 95`。試算表的值會以工作表顯示的樣子呈現，若與儲存的值不同，
  會在後面附上儲存的值，例如 `741,700 (741700)`；
* 對於 OxideMerge 或轉換程式能讀取的已變更二進位檔（例如 ELF 程式的標頭與區段），
  會顯示讀取出之文字的差異；若文字相同，報告會說明檔案的差異在於文字未包含的位元組；
* 「比較設定」區段，列出比較方法、檔案篩選、選項、行篩選、取代規則與報告上限，
  以及資料夾檢視顯示了哪些檔案；
* 註明報告略過或縮短了哪些內容。

[[report-detail]]
==== 報告顯示多少內容

每份 HTML 報告開頭都有一個方塊，說明報告是否完整。「此報告完整顯示每一處差異」表示沒有略過任何內容；
否則方塊標題為「此報告未包含全部內容」，並統計缺少的部分：只列出而不含差異的檔案、略過的差異區塊，
以及被縮短的差異區塊。方塊下方會寫出產生報告時採用的匯出原則。

「檔案 → 匯出 → HTML 報告詳細程度」可選擇該原則（命令列為 `--report-detail`，工作檔為 `report_detail`）：

[cols="1,3,3"]
|===
|詳細程度 |報告顯示的內容 |大小與時間

|「摘要」
|統計數字與每處差異的位置，不含內容行（最多 20,000 處差異，其餘只計數）。資料夾報告列出檔案及其狀態，且不讀取任何檔案。
|約與檔案清單相當。資料夾報告所需時間不超過比較本身。

|「標準」（預設）
|差異總計最多 20,000 列，每個差異區塊最多 400 列，每行最多 2,000 個字元。
|無論檔案多大，差異部分最多數 MB。

|「完整」
|每處差異的每一列，且顯示整行。
|隨差異增加。兩個大型檔案若處處不同，報告可能與兩個檔案加起來一樣大，瀏覽器開啟也會較慢。
|===

無論詳細程度為何，資料夾報告只顯示 16 MiB 與 50,000 行以內之檔案的差異；
更大的檔案會列出並說明未顯示的原因，並計入上述方塊。
資料夾報告容納的差異達到 1 GiB 後也會停止顯示差異：該檔案其餘的差異區塊只計數，之後的檔案會列出此原因且不讀取。
詳細程度只適用於 HTML 報告。PDF 報告有自己的上限（請參閱 <<pdf-reports>>），投影片每個差異最多顯示 400 列。

報告一律是單一 HTML 檔案。OxideMerge 不會把大型報告拆成多個頁面或檔案：單一檔案才能隨處附加、
封存與開啟。比較規模很大時，可匯出「標準」用於分享、「完整」供自己審閱，或先用篩選縮小比較範圍。

列印報告時，每頁頂端會重複差異上方的側別標題，所有檔案都會展開，並使用淺色主題。
新增、刪除與變更的列以顏色區分，因此在單色印表機上，每處差異的種類寫在其標題中，
統一檢視的 `+` 與 `-` 符號則標示每一列屬於哪一側。

若要分享資料夾報告但不透露資料夾的路徑，請開啟「檔案 → 匯出 → 在報告中隱藏資料夾路徑」
（命令列為 `--report-hide-paths`）。
報告會以側別稱呼資料夾，其路徑不會出現在報告中的任何地方，包括審閱註記與審閱摘要。
HTML 報告會包含審閱註記。若要將工作區摘要另存為 JSON 檔案，請使用審閱面板中的「匯出審閱摘要…」。
檔名與顯示的差異仍可能是敏感資訊，分享前請先確認報告內容。

若只想儲存報告而不開啟，請關閉「檔案 → 匯出 → 儲存後在瀏覽器開啟報告」。

NOTE: 匯出報告絕不會將您的編輯存回比較的檔案。

[[other-reports]]
=== 其他報告

除了 HTML 之外，您也可以將比較結果存成適合試算表、文字檔與其他程式使用的格式。
「檔案 → 匯出 → HTML 報告...」同樣能儲存這些格式：請在儲存對話方塊中選擇檔案類型。

* 資料夾比較：HTML（含每個已變更文字檔的差異）、CSV、純文字或 XML。
  CSV 與純文字報告會列出檔案及其狀態、大小與日期。
* 文字比較：HTML 或 XML。

「工具 → 統計資料...」會顯示目前比較的統計數字：

* 資料夾比較：相同、不同與僅一側的檔案數量、錯誤數，以及各側的總大小；
* 文字比較：每一對窗格之間相同、變更、新增、刪除與忽略的行數。

==== XML 報告

XML 報告是提供給其他程式讀取的，例如指令碼、審閱工具，或檢查變更內容的建置流程。
若要建立 XML 報告，請在「檔案 → 匯出 → HTML 報告...」的儲存對話方塊中選擇 XML 類型，
或在命令列使用 `--report <名稱>.xml`。

* 文字比較報告會列出每個差異的種類、是否被忽略，以及各側的行與行號；最後列出書籤及其註解。
* 差異種類包括 `changed`、`added` 與 `removed`；
  三方比較另有 `left-only`、`right-only`、`both-same`、`compatible` 與 `conflict`。
* 資料夾報告會列出每個檔案與資料夾的狀態，以及在各側的日期與大小。

以下是文字比較報告的範例：

[source,xml]
----
<comparison format="1" tool="OxideMerge" version="0.9.8" type="text" created="…">
  <side index="0" role="left" name="a.txt"/>
  <side index="1" role="right" name="b.txt"/>
  <statistics differences="1" ignored="0" identical-lines="1" changed-lines="1" added-lines="0" removed-lines="0"/>
  <differences>
    <difference index="1" kind="changed" ignored="false">
      <lines side="0" start="2" count="1"><line number="2">two</line></lines>
      <lines side="1" start="2" count="1"><line number="2">TWO</line></lines>
    </difference>
  </differences>
</comparison>
----

* 行號從 1 開始。
* 某一側在差異中沒有任何行時，`count` 為 `0`，`start` 表示文字應插入在第幾行之前。
* 只有在格式的變更可能影響讀取程式時，`format` 的值才會改變。

[[slideshows]]
=== 投影片

「檔案 → 匯出 → 投影片報告...」會儲存一個一次顯示一個差異的 HTML 網頁，
適合在會議或審閱時逐一說明變更。

* 標題投影片會列出比較的各側與差異數量。
* 接著每個差異各有一張投影片，顯示差異的行、前後幾行、變更的字詞，以及書籤註解。
* 資料夾比較會為每個已變更文字檔的每個差異各建立一張投影片。
  每張投影片會標示檔案的比較方式，例如「文字」或「試算表儲存格」，列出差異所在的工作表與列、
  PDF 頁面或筆記本儲存格，以及 CSV、TSV 或試算表中變更的列裡變更的欄位。
* 資料夾比較的標題投影片會像 HTML 報告一樣計算檔案（請參閱 <<html-reports>>），
  並列出已匯出的差異區塊，說明投影片省略了哪些內容。
* 資料夾比較的最後一張投影片會列出每個已變更或僅存在於一側的檔案。按一下檔案即可前往它的
  第一張投影片；沒有投影片的檔案會標示「僅摘要」與原因，例如二進位檔。
  清單下方的「比較設定」會列出比較方法、篩選、選項與上限。
* 開啟「在報告中隱藏資料夾路徑」時，各側會命名為左側、中間與右側。
* 被忽略的差異不會列出。

在瀏覽器中：

* 按 kbd:[→]、kbd:[←]、kbd:[Space]、kbd:[PgUp] 或 kbd:[PgDn] 可切換投影片。
* 按 kbd:[Home] 或 kbd:[End] 可跳到第一張或最後一張。
* 按 kbd:[F] 可切換全螢幕。
* 每張投影片都有自己的網址（例如第三張為 `#3`），可以直接連結。
* 列印時，每張投影片各印成一頁。
* 頁首帶有 OxideMerge 圖示，可連到專案網頁；最後一張投影片也有此連結。

[[pdf-reports]]
=== PDF 報告與列印

PDF 報告可將文字或資料夾比較製成可列印的文件，內容與 HTML 報告相同。

「檔案 → 匯出 → PDF 報告...」會將文字或資料夾比較的報告儲存為 PDF 檔案。
「檔案 → 列印...」（kbd:[Ctrl+P]）會把同樣的 PDF 寫入只有您能讀取的暫存檔，並以系統的 PDF
檢視器開啟，您再從檢視器列印。
暫存檔會在 OxideMerge 關閉時刪除。整個過程不使用瀏覽器。

PDF 報告的內容與 HTML 報告相同：

* 比較的檔案、比較規則檔、差異數與新增、刪除、變更的行數，以及書籤註解。
* 每個差異及其前後三行、行號與標記的變更字詞，以並排方式顯示。
  開啟行內檢視時，雙向比較的報告改為單欄，刪除的行在新增的行上方，並使用直式頁面。
* 資料夾比較會有摘要、報告省略內容的說明、比較設定、已變更檔案的索引，以及所有檔案及其狀態、
  大小與日期的清單，接著是每個已變更檔案各自的部分、審閱註記與審閱摘要。
* 以鍵比對的表格會附上鍵比對的結果。

PDF 資料夾報告具備 HTML 報告的資料夾報告附加內容（請參閱 <<html-reports>>）：

* 摘要會計算內容不同的檔案、僅存在於一側的檔案、已匯出的差異區塊，以及略過的區塊。
* 「此報告未包含全部內容」會列出未顯示差異的檔案、因大小上限而略過的區塊，以及被縮短的區塊。
* 「比較設定」會列出報告中的檔案、比較方法、檔案篩選、空白字元與忽略選項、篩選與轉換程式、
  每個區塊周圍未變更的行數（或「整個檔案」），以及報告上限。
* 「檔案差異」會列出每個已變更或僅存在於一側的檔案，以及繪製的區塊數，或「僅摘要」與原因，
  還有檔案的比較方式，例如「文字」、「試算表儲存格」或「ELF 標頭與區段」。
  按一下項目即可前往該檔案的部分。
* 每個檔案的部分以其狀態與比較方式開頭。每個差異會標示其工作表與列、PDF 頁面或筆記本儲存格；
  CSV、TSV 或試算表中變更的列會列出變更的欄位，例如 `Alice · score · 90 → 95`。
* 開啟「在報告中隱藏資料夾路徑」時，各側會命名為左側、中間與右側，
  報告的附註與設定中也不會出現資料夾路徑。

每頁的頁首有 OxideMerge 圖示與報告標題，頁尾有「第 n 頁，共 m 頁」與「OxideMerge」，
後者連結到專案網頁（https://github.com/kuopinghsu/OxideMerge）。PDF 也為每個檔案與每個差異建立書籤。
OxideMerge 使用的字型會內嵌在檔案中，而且只包含報告需要的字元，
因此中文、日文與韓文會依照畫面上的樣子列印。
每一欄都標示其所屬的一側；差異延續到下一頁時，也會標示其檔案。
資料夾報告的檔案清單表頭會在每一頁重複。

一份報告最多繪製 20,000 行比較文字（約 400 頁），所有檔案合計；折行的長行占幾行就計算幾次。
除非顯示整個檔案，否則每個差異最多顯示 400 列。
差異被截斷時，變更上方最多保留 100 行未變更的內容，因此一定會顯示變更本身，
並以「…還有 1,200 行」之類的文字說明省略的部分。
超過上限之後的差異只會計數；資料夾報告會將其數量列為「略過的差異區塊」。

每行由左至右閱讀，其中的希伯來文與阿拉伯文則由右至左，文中的數字與括號維持在正確位置
（日期、電話號碼、百分比與價格保持完整），阿拉伯與波斯字母也會連寫。
這比瀏覽器的排版簡單，因此以特殊方式混合兩種方向的行，可能與瀏覽器顯示的不同。
程式字型不會把 `!=` 或 `->` 合成一個符號。
希伯來文、阿拉伯文與泰文會使用已安裝、且授權允許嵌入子集的字型列印，例如 SF Hebrew、Geeza Pro、
Tahoma、Segoe UI 或 Noto。
所有字型都沒有的字元會印成 `?`；報告結尾（以及命令列的標準錯誤輸出）會附註，以碼位列出這些字元。

顏色從來不是唯一的提示，因此以黑白列印的報告仍能看出變更：

* 每個變更的行開頭都有符號：`-` 刪除、`+` 新增、`~` 變更、`!` 衝突、`=` 忽略。
* 變更的字詞除了醒目標示，也會加上底線。
* 某一側缺少的行，其位置以斜線網底表示。
* 在「選項 → 一般」中開啟「色盲友善的差異顏色」時，會以藍色與橘色取代綠色與紅色，變更為紫色，
  衝突為黃色。

頁面為 A4 橫式。若要改用 Letter 紙張，請選取「檔案 → 匯出 → PDF 報告使用 US Letter 紙張」。
在命令列中，可用 `--page-size`、`--portrait`、`--unified`、`--whole-file` 與 `--context` 設定版面
（請參閱 <<command-line>>）：

[source,sh]
----
oxidemerge old.c new.c --report changes.pdf
oxidemerge -r old new --report review.pdf --report-diffs --page-size letter
oxidemerge old.c new.c --report full.pdf --whole-file --unified --portrait
----

[[patches]]
=== 修補檔

修補檔可讓您以其他工具能套用的格式傳送變更，也可讓您套用收到的修補檔。

「檔案 → 匯出 → 產生修補檔...」會將兩個檔案或資料夾之間的差異寫成修補檔。
您可以選擇格式（「一般」、「上下文」或「統一」）與上下文的行數。

* 只能從雙向比較產生修補檔。
* 匯出哪些差異，仍由忽略選項決定。
* 支援 UTF-8 檔案（不論有無位元組順序標記）、LF、CRLF 或混合的換行字元，以及結尾沒有換行字元的
  檔案。
* 其他編碼或只使用 CR 換行的檔案，必須先轉換。
  遇到這類檔案時，OxideMerge 會顯示錯誤，而不會產生無法正確還原變更的修補檔。

「檔案 → 套用修補檔...」可套用統一格式的差異，包括 `git diff` 與 `svn diff` 的輸出。

* 即使行的位置已經移動，OxideMerge 仍能找到每個修補區塊。修補區塊是修補檔中的一組變更。
* 每個修補後的檔案會與原始檔案並排開啟，方便您檢查後再儲存。
* 無法套用的修補區塊會列在訊息中。
  儲存前請先閱讀這些訊息並檢查比較結果；套用修補檔不會自動儲存任何結果。

[[analysis]]
== 分析工具

分析工具可協助您在儲存合併結果前後加以檢查，並有條理地審閱大量變更。
您可以用它們確認合併後的檔案與預覽一致、看清結構化資料檔實際變更了什麼、
追蹤整個資料夾的審閱決定，以及摘要兩個版本之間的變更。

OxideMerge 提供下列選用工具：

* <<merge-verification>>：預覽合併並檢查已儲存的結果。
* <<semantic>>：依結構比較 JSON、XML、TOML 與 YAML 檔案；<<tree>> 則將其中兩個檔案顯示為一棵對齊的
  樹。
* <<review-workspace>>：記錄每個檔案與每個差異的審閱決定。
* <<baselines>>：摘要兩個版本之間的變更。
* <<impact>>：列出變更的檔案可能在哪些地方被使用。

這些工具都是唯讀的，絕不會修改您的檔案；在您開啟之前，也不會執行任何動作。
在視窗中，這些工具位於側邊抽屜：按一下工具列最右側的「側邊面板」，再選擇分頁。
您也可以從命令列執行這些工具（請參閱 <<analysis-command-line>>）。

各項分析的詳細規則，請參閱 xref:analysis-guide.md[分析指南]（英文）。

[[merge-verification]]
=== 合併驗證

合併驗證可讓您在儲存前檢視合併的結果，並在儲存後確認檔案與預覽一致。

==== 文字檔

在三方文字比較中，開啟「合併驗證」分頁。

.執行「預覽合併」後的合併驗證
image::verify.png[合併驗證]

* 「預覽合併」會以「唯讀預覽」顯示合併的結果，不會變更中間窗格。
  預覽中的衝突處會保留基底的文字，必須由您自行解決。
* 「驗證已儲存的結果」會重新讀取已儲存的結果檔，
  並將其位元組、編碼、位元組順序標記、換行字元與檔案結尾換行與預覽比較。
* 編輯文字後，畫面上顯示的驗證狀態即不再有效。

有些合併雖然沒有衝突，仍值得仔細檢查，預覽也會針對這類情況提出警告：

* 兩側編輯的行相距不超過兩行；
* 兩側在不同位置變更了同一個設定，例如 `name = value`、`name: value` 或 `"name": value`。

警告不會使檢查判定為失敗。

IMPORTANT: 這些檢查只比較文字與位元組，無法證明合併結果正確無誤。

==== 資料夾

資料夾合併可使用下列兩個命令列選項。

`--merge-plan` 會列出資料夾合併的各項操作與衝突，但不會實際執行。

`--validate-merge` 會依計畫檢查合併結果：
它會檢查計畫中的複製、合併與刪除，以及應維持不變的檔案，並再次確認來源檔案沒有變更。
結果可以放在另一個資料夾中：

[source,sh]
----
oxidemerge --validate-merge result-folder left-folder base-folder right-folder
----

TIP: 建議依下列順序進行：先預覽合併，再執行合併，最後依計畫驗證結果。

[[semantic]]
=== 語意比較

語意比較可讓您依內容審閱結構化的資料檔。
比較 JSON、XML、TOML 與 YAML 檔案時，請選擇「語意」，依資料結構而非逐行比較。
比較本身絕不會寫入檔案；只有下文所述的複製按鈕會修改窗格。
若 OxideMerge 無法讀取檔案，檢視中會說明原因，按一下即可返回文字檢視。

.兩個 JSON 檔案的語意比較
image::semantic.png[語意比較]

==== 哪些變更會計入

JSON::
* 物件鍵的順序不計。
* 陣列元素的順序會計入。
* 缺少的值與 `null` 視為不同。
* 重複的鍵視為錯誤。
XML::
* 屬性的順序不計。
* 名稱會連同完整的命名空間一起比較。
* 子元素的順序、文字中的空白、混合內容與註解都會計入。
* 不支援 DTD、宣告或未知的實體，以及 XML 1.1；支援內建的字元參照。
TOML 與 YAML::
* 比較方式與 JSON 相同：表格與對應的順序不計。
* 數字依數值比較，整數與小數之間也是如此。
  例如 `1` 等於 `1.0`，TOML 中的 `8_080` 等於 `8080`。
* 註解與排版不計。
* TOML 中含時區的日期時間，依其所代表的時刻比較。
  例如 `10:00+02:00` 等於 `08:00Z`。
* YAML 採用 YAML 1.2 核心結構描述，因此 `yes` 與 `on` 都是文字，
  `0777` 是數字 777，而不是 YAML 1.1 所解讀的八進位數字。
  鍵也依值比較，因此 `0x10:` 與 `16:` 是同一個鍵。

適用下列限制：

* TOML 或 YAML 檔案最大 4 MiB。
* YAML 檔案只能包含一份文件，且不得使用別名、複合鍵或自訂標籤；
  `!!int` 這類核心標籤必須與其值相符。

文字比較的比較規則，不會當作語意檢視的篩選條件。

==== 解讀結果

變更會依路徑以樹狀顯示，每個分支會標出其中包含的變更數量。
按一下變更的來源按鈕，即可跳到檔案中對應的行。

陣列需要特別留意：

* 若陣列以新的順序保有相同的元素，被移動的元素會列為「移動」，並註明原本的位置。
* 若要依某個成員而非位置來配對陣列中的物件，請在「陣列配對鍵」中輸入成員名稱，例如 `id`
  （適用於 JSON、TOML 與 YAML）。
  如此一來，插入或重新排序會顯示為新增與移動的元素，而不是其後每個位置都有變更。
* 若無法以該鍵配對某個陣列（某個元素沒有可唯一識別的簡單值），變更清單上方會說明原因，
  該陣列則改依位置比較。

若陣列元素不是單純依路徑配對，每項變更都會註明配對方式：
依陣列配對鍵、依完全相同的重新排序，或在長度不同的陣列中依位置配對。

若另一種解讀也同樣說得通，該變更會標示為「有歧義」，請自行確認。
常見的情況如下：

* 兩個元素互換位置時，任一個都可能是被移動的元素。
* 被移動的元素有重複。
* 插入元素使後面的元素錯位，而該變更是依位置找到的。

報告會記錄每項變更的 `confidence`（`parser_exact`、`array_key`、`reordered` 或 `position`）、
有標示時的 `ambiguous`，以及 `notes`。

==== 複製值

每項變更都有「將值複製到左側」與「將值複製到右側」按鈕（唯讀的窗格除外）。
複製會取代另一側的值、將值加到它應在的位置，或在來源側沒有該值時將其移除。

* 只會修改寫有該值的文字，註解、排版與檔案的其餘部分都保持原樣。
  被移除的成員會連同其所在的行一起移除，包括行尾的註解；獨立成行的註解則會保留。
* 值會依來源側的寫法複製：包括引號、數字的每一位（即使超出 64 位元數字的範圍），以及 XML 元素的命名空間前置詞。
  若另一個檔案未宣告該元素的前置詞，則不會複製，因為元素到了那裡會變成另一個名稱。
* 保留複製結果之前，會重新讀取編輯後的檔案。
  若結果與預期的結構不完全相同，就不做任何變更，並在檢視中說明原因。
  這類值請在文字檢視中編輯。
* 移動不會被複製，因為移動會改變整個陣列的順序。
* 每次複製都是「復原」的一個步驟。檔案只有在您儲存時才會寫入。

[[tree]]
==== 樹狀檢視

比較兩個 JSON、YAML、TOML 或 XML 檔案時，選擇「樹狀」會將兩份文件顯示為一棵對齊的樹。
節點與其對應節點位於同一列：左側檔案在左、右側檔案在右，兩側一起捲動。
只存在於一側的節點，另一側會顯示空白的占位列。
此檢視只讀取檔案。

image::xml-tree.png[樹狀檢視]

兩側之間的欄位以符號標示每一列的狀態，不只靠顏色區分：
`+` 新增、`−` 移除、`~` 修改、`↕` 移動、`•` 內含變更、`?` 不明確。
收合且內含變更的節點會顯示數量，例如「3 項變更」。
每一列顯示的內容依格式而定：

* 「JSON、YAML 與 TOML」：索引鍵與其值，例如 `port: 8080`；物件或陣列及其成員數，例如 `env {2}` 或
  `ports [2]`；陣列元素則依其位置顯示，並附上 `id`、`name` 或 `key` 成員，例如 `[0] id="report"`。
* 「XML」：元素會顯示原始寫法的名稱，並以簡短標籤顯示 `id`、`name`、`key`、`ref` 屬性及有變更的屬性。
  展開元素即可看到其屬性、文字、註解與處理指令。

列只會在已配對的父節點之下配對，因此節點絕不會顯示在其他父節點之下：

* 物件成員與 XML 屬性依其索引鍵或名稱配對，不論寫出的順序為何。
* 陣列元素與 XML 子節點依同層節點逐一配對：
. 依您指定的索引鍵規則；若陣列中的每個物件都有值各不相同的 `id`、`name` 或 `key` 成員，則依該成員
  （請參閱下文「索引鍵規則」）；
. 依相同內容，並保持順序；
. 依順序不同的相同內容，且該內容在兩側各只出現一次：即「移動」列；
. 在已配對的列之間，依種類與名稱配對。

插入一個元素只算一項新增：其後的元素仍與各自的對應元素配對。
語意檢視依位置比較，因此對同樣的檔案可能列出較多變更。
變更的認定方式與語意檢視相同：

* 「JSON、YAML 與 TOML」：索引鍵順序、註解、引號以及區塊或流式寫法都不計。
  在 YAML 與 TOML 中，數字的寫法（`8_080`、`0x1F90`、`1.0`）也不計；在 JSON 中，`1` 與 `1.0` 不同。
  型別改變的值（例如數字變成字串）會顯示為「型別變更」。
* 「XML」：屬性順序與命名空間前置詞不計，CDATA 視為文字，子節點順序、文字中的空白與註解都會比較。
  未變更且只有空白的文字列不會顯示；
  在新增或移除的元素旁新增或移除的空白（例如其縮排），屬於該元素的一部分。

「在變更之間移動」:: 上一個與下一個差異指令（`Alt+↑` 與 `Alt+↓`、`Alt+Home` 與 `Alt+End`），
以及樹狀上方的按鈕，會依樹狀順序走訪變更。
收合節點內的變更不會被略過：其父節點會自動展開。
「變更 3 / 12」顯示目前的位置。
篩選條件只顯示並走訪新增、移除、修改、移動或不明確的變更，收合列上的變更數量也會依篩選條件計算。

「鍵盤操作」:: 依照樹狀元件的慣例，樹狀在 Tab 順序中只佔一站：按 `Tab` 直到樹狀出現外框，
或直接按一下其中一列。
之後即可用方向鍵移動：kbd:[↑] 與 kbd:[↓] 在列之間移動，kbd:[→] 展開一列，
kbd:[←] 收合該列或移到其父節點。
再按 `Tab` 會離開樹狀，而不是跳到下一列；按 `Esc` 則放開樹狀。
樹狀取得鍵盤焦點時，螢幕閱讀器會讀出選取列的狀態，再讀出兩側的內容。
無論樹狀是否取得鍵盤焦點，每一列都在無障礙樹中，可逐列朗讀。

「展開與收合」:: 「展開變更」（也是初始狀態）會展開所有內含變更的節點。
「收合未變更」會收合其餘節點，「展開至層級」會展開到指定深度，「重設展開」則回到初始狀態。

「詳細資料與原始碼」:: 樹狀下方會顯示選取列在兩側的路徑（例如 `$.server.port` 或
`/catalog/book[2]/@id`）、配對方式、行號與欄號、值，以及檔案中寫有該節點的原始內容。
「顯示原始碼」會在文字檢視中開啟該行。
若文字游標位於某個節點（包括其索引鍵所在的行）時選擇「樹狀」，就會選取該節點。

「搜尋」:: 輸入索引鍵、名稱或值，即可顯示符合的列及其父節點。
在 JSON、YAML 與 TOML 中，以 `$` 開頭的文字為路徑，例如 `$.server.port`，會顯示該節點及其下的內容。
在 XML 中，以 `/` 開頭的文字為 XPath 的小型子集：
由元素名稱或 `*`、`@name`、`text()` 與 `comment()` 組成的 `/` 與 `//` 步驟，
可加上 `[@a]`、`[@a='value']` 與 `[n]` 條件，例如 `//book[@id='b102']/title`。
其他 XPath 會被拒絕，並顯示訊息。

「索引鍵規則」:: 重複的節點預設依位置配對，除非可以區分它們。
在 JSON、YAML 與 TOML 中，若陣列中的物件在每一側都有值各不相同的 `id`、`name` 或 `key` 成員，
不需規則即會依該成員配對，工具列也會顯示配對的數量，例如「3 個物件依其 id 成員配對」。
否則，您可以寫成 `name@key` 形式的規則。
在 JSON、YAML 與 TOML 中，`servers@name` 依 `name` 成員配對名為 `servers` 的陣列中的物件，
`ports@name+protocol` 依兩個成員配對，`spec/ports@name` 則只套用於 `spec` 之下；
`*@id` 涵蓋所有陣列，包括整個檔案就是一個陣列的情況，以及直接位於另一個陣列中、沒有名稱的陣列。
在 XML 中，`book@id` 依 `id` 屬性配對 `book` 元素，`book@id+lang` 依兩個屬性配對，
`catalog/book@id` 則只套用於 `catalog` 之下；規則比對的是區域名稱，但絕不會配對不同命名空間的元素。
多條規則以 `;` 分隔，停止輸入後即會套用。
如此一來，互換位置的項目會顯示為一項移動加上變更的內容，而不是兩項取代。
只有當規則涵蓋的節點在兩側都有完整且唯一的索引鍵時，才會對該組同層節點使用規則；
否則會顯示警告並列出重複與缺少的索引鍵數量，這些節點會改以未套用規則的方式配對，並標示為不明確。
索引鍵規則只屬於此檢視，不會改變語意檢視或 `--semantic` 報告。

「集合」:: 選取的列含有物件陣列或重複的 XML 元素時，「以集合檢視」會將它們列成表格，每個項目一列。
每一列顯示狀態與兩側的值：每個只含單一值的成員各一欄，
或每個屬性、每個只含文字的子元素及該子元素的每個屬性各一欄（若項目只含文字，另有文字欄）。
您可以選擇欄位並依狀態篩選；按一下某一列，即可在樹狀中選取該項目。
含有更深層的物件、陣列、子元素或混合內容的項目會另行標示，因為表格不會顯示這些內容。
+
image::xml-collection.png[集合表格]

不明確的列:: 當另一種配對同樣合理時，該列會標示為不明確：一側有數個同名的同層節點而另一側較少、
索引鍵規則無法使用、新增的節點旁有相同的同層節點，或互換位置時兩個節點都可能是移動的那一個。
請自行確認這些列。

樹狀檢視會在背景建立，並顯示進度與「取消」，限制與語意檢視相同（100,000 個節點與 64 層）。
此檢視適用於兩個檔案；三向比較請使用語意檢視。

==== 三個檔案

在三向比較中，「語意」會將左側與右側檔案分別與中間的檔案比較。
每個不同的路徑只會列出一次，並以它在中間檔案中的路徑表示：

* 「僅左側不同」或「僅右側不同」：只有一側變更了它。
* 「兩側改法相同」：兩側做了相同的變更。
* 「衝突」：兩側的變更不同，或一側變更了另一側所變更之值內部的值。
  同一個物件中不同成員的變更不會衝突。
  若兩側都變更了一個元素可用多種方式配對的陣列（例如依位置配對、長度不同的陣列），
  整個陣列即視為一個衝突。

您可以使用篩選器只顯示衝突。
「採用左側」與「採用右側」會將該側的值複製到中間窗格，方式與複製值相同。
中間窗格會以目前的內容比較：採用某一側後，該路徑就不再與所採用的一側不同。

=== 審閱工作區

審閱工作區會逐一檔案、逐一差異記錄您對資料夾比較的審閱。
資料夾比較的「審閱工作區」分頁會記錄下列內容：

* 每個檔案與每個差異區塊的狀態；
* 「審閱註解」、「判斷理由」與選填的「標籤（以逗號分隔）」；
* 「審閱者（自行填寫的名稱）」：這只是自由填寫的文字，並非經過驗證的身分。

.審閱工作區
image::review.png[審閱工作區]

「下一個未審閱項目」會移到下一個尚待審閱的檔案。
若要審閱個別差異區塊，請從資料夾比較中開啟該檔案。

若要保留審閱決定與目前位置，請儲存資料夾審閱（請參閱 <<folder-reviews>>）。
OxideMerge 會等到比較、檔案操作與先前決定的檢查都完成後才儲存；
若比較已停止或失敗，則會拒絕儲存。

==== 更新審閱

「更新審閱來源…」可讓您選擇新的資料夾，並與先前的審閱決定對照。
它會保留所選的比較規則、以唯讀方式開啟資料夾，並標示不再相符的決定。

* 檔案只改名而內容未變時，審閱決定會跟著檔案，並註明原本的名稱。
* 若有多個新檔案的內容相同，每個檔案都會標示為需要重新審閱。
* 轉換後的內容、轉換程式或規則有變更時，先前的決定可能失效。
* 過期的決定一律列為「需要處理」，絕不會視為「已接受」。
* 編輯已審閱的檔案時，該檔案的決定會過期；
  差異區塊的決定只有在編輯改到其內容或前後兩行時才會過期，其他差異的決定保持不變。
* 差異區塊的前後文重複或無法明確對應時，必須手動審閱。

==== 檔案版本與安全性

* OxideMerge 以第 2 版格式儲存 `.oxmreview` 檔案。
  開啟第 1 版檔案時，所有項目都會設為尚未審閱；無法識別的版本則會被拒絕。
* 開啟封裝檔時，OxideMerge 會檢查所儲存檔案的摘要值。
* 下列封裝檔會被拒絕：路徑指向封裝檔以外、有缺少、未列出或為連結的項目，
  或由較新版本的 OxideMerge 儲存。

[[baselines]]
=== 版本摘要／比較基準

「版本摘要／比較基準」面板用來比較兩個版本，讓您概覽兩者之間的變更。
此面板位於起始頁，以及資料夾比較的側邊抽屜中。

.開啟「潛在影響」的版本摘要
image::baseline.png[版本摘要]

請直接選擇每一側的來源，不必先比較兩個資料夾。
每一側的來源可以是下列其中一種：

[cols="1,2"]
|===
|來源 |意義

|`folder:路徑`
|資料夾目前的內容。

|`git:修訂版本:路徑`
|Git 修訂版本中的路徑。
OxideMerge 只解析一次修訂版本，並記錄其提交識別碼；不包含尚未提交的變更。

|`review:側:路徑`
|已儲存資料夾審閱中的某一側，第一側為 `0`。
|===

使用 Git 來源時，與 <<git-revision,Git 修訂版本比較>> 相同，您的 Git 設定與篩選器必須是可信任的。

==== 摘要

摘要會統計下列變更：

* 新增、刪除、修改與未變更的檔案；
* 內容完全相同的唯一檔案的移動；
* 疑似重新命名並修改的檔案；
* 二進位內容變更與檔案類型變更；
* JSON、XML、TOML 與 YAML 檔案的語意變更；
* 被排除的檔案。

摘要也會顯示每一側的擷取時間。

* 清單上方的計數可當作篩選條件，按一下一個或多個類別，即可只顯示這些變更。
* 「高優先」只顯示有風險標記的變更：符合重要路徑，或檔案中仍留有衝突標記。
  這些變更也會排在最前面。
* 選取某一列，即可以唯讀方式開啟擷取的檔案。
  這些檔案來自基準，即使來源在擷取後有變更也不受影響。

==== 重新命名

同時符合下列所有條件時，OxideMerge 會判定為疑似重新命名並修改：

* 一個刪除的檔案與一個新增的檔案，都是同類型的文字檔。
* 兩者至少有一半、且至少三行相同。
* 兩者明確是彼此最相符的對象。

該列會顯示舊名稱，以及相同行數所占的比例。

* 按一下「不是重新命名」，可將兩個檔案維持為刪除與新增。
  在命令列中，請使用 `--split-rename 路徑`；若該路徑不是新增的檔案，OxideMerge 會提出警告。
* 按一下「重新偵測重新命名」可復原此操作。

==== 重要路徑

重要路徑是您想特別留意的文字，例如 `config/` 或 `api`。
包含這段文字的變更路徑會標示為高優先；從這類路徑移動或重新命名的檔案也會標示。
請在「重要路徑片段（以 ; 分隔）」中輸入重要路徑；在命令列中則使用 `--important-path 文字`。

`--important-path` 與 `--split-rename` 都可以重複指定，
並需搭配 `--impact`、`--release-report` 或 `--baseline-left` 使用。

NOTE: 重要路徑只是協助您決定審閱的先後順序，並不保證相容性。

[[impact]]
=== 潛在影響

潛在影響可協助您找出變更還可能影響到哪些地方。
開啟「潛在影響」，即可列出變更的檔案可能在哪些地方被使用。
每項發現都會顯示檔案、行號、內容摘要值與一段摘錄。

==== 確切發現

匯入陳述式明確指向某個變更、刪除或重新命名的檔案時，該發現會標示為「確切」。
OxideMerge 能辨識下列匯入方式：

* JavaScript 與 TypeScript：相對路徑的匯入、重新匯出與 `require`。
  匯入 `./util.js` 時，也會找到變更的 `util.ts`。
* Python 的匯入。
* C 與 C++ 的 `#include "…"`，以及 Objective-C 的 `#import "…"`。
* CSS 的 `@import`。
* Rust 的 `mod name;`，以及以 `crate::`、`super::` 或 `self::` 開頭的 `use` 路徑。
* JSON 的 `$ref` 檔案參照。

JavaScript、TypeScript、Python、C、C++ 與 Rust 檔案的匯入，是從 Tree-sitter 產生的語法樹中讀取；
`.h` 標頭檔以 C 剖析，只有在只能以 C++ 剖析時才視為 C++。
其他檔案則依程式碼的語法單位辨識；Vue 與 Svelte 元件只讀取其中的 `<script>` 區塊。
因此，匯入可以跨越多行，而註解或字串中的文字不會被當成匯入。
若剖析器無法讀取檔案的某些部分，該檔案會列為部分評估，因為其中的匯入與定義可能有所遺漏。

OxideMerge 也會比較變更的 JavaScript、TypeScript、Python、C、C++ 與 Rust 檔案中
最上層的函式、型別與常數，但不包括 C 與 C++ 的全域變數。
`#[derive(…)]` 這類 Rust 屬性，視為其後定義的一部分。

若某個檔案依名稱匯入了變更或移除的定義，會在第一次使用該名稱之處產生「確切」發現，
並說明該定義是變更還是移除；以其他名稱匯入時也同樣適用。
這類匯入的範例：

* `import { parse } from "./parser"`
* `from .parser import parse`
* `use crate::parser::parse`

==== 推測發現

推測發現是可能的使用位置，需要您自行確認：

* 在同一語言的其他檔案中，第一次使用變更的定義名稱之處；
* 文字中以獨立字詞出現的變更檔案名稱或路徑；
* 變更的 JSON、TOML 與 YAML 鍵，也包括 `db.timeout` 這類以點連接的路徑。

大範圍的變更若產生超過 500 個名稱與鍵的相符處，只會列出前 500 個，
發現清單上方會註明其餘的數量；其他類型的發現則一律完整列出。

==== 影響分析找不到的項目

* 條件式、自動產生或由巨集建立的匯入。
* 方法，以及經由命名空間使用的名稱，例如 `ns.parse`。

OxideMerge 絕不會執行儲存庫的建置、測試或指令碼。

==== 處理發現

* 按一下「略過此發現」可隱藏該發現，不會修改檔案。
* 在資料夾比較中，按一下「審閱」可在審閱工作區開啟該發現所在的檔案。
* 沒有結果時，面板會說明尚未評估影響。
* 變更來源時，舊的發現會被清除。
* 取消分析時，不會顯示部分結果。

[[analysis-limits]]
=== 限制

分析工具適用下列限制：

* 每個檔案最大 16 MiB。
* 每個基準最多 10,000 個項目與 256 MiB 的擷取內容。
* 結構化檔案最多 64 層巢狀結構與 100,000 個節點。
* 影響分析的發現超過 2,000 個時會失敗，並要求您縮小範圍；只有名稱與鍵的相符處會被截斷。
* 超過限制的檔案會被拒絕或列為排除，絕不會被判定為相同。

耗時較久的分析會顯示進度，也可以取消。
某些步驟（例如剖析或合併單一檔案）只在開始前與結束後檢查是否取消，因此取消時可能要等該步驟完成。
這些限制不影響一般的比較。

oxidemerge --semantic left.yaml base.yaml right.yaml --report conflicts.json
oxidemerge --review-summary review.oxmreview --report review-summary.json
oxidemerge --baseline-left git:v1.0:/repo --baseline-right git:v1.1:/repo --release-report release.html
oxidemerge --impact old-folder new-folder --report impact.json
----

輸出：

* 未指定報告路徑時，分析會將附有版本編號的 JSON 輸出到標準輸出。
* `.xml` 報告與大多數分析的 `.html` 報告都包含這份 JSON，其格式與一般比較報告分開。
* 版本基準的 `.html` 報告是易讀的摘要，列出計數、高優先的變更以及每項變更的段落，並附上 JSON。
* 報告不得覆寫任何輸入檔案，也不得位於所選的輸入資料夾中。

結束代碼：

[cols="1,3"]
|===
|代碼 |意義

|`0`
|相同，或已成功產生計畫或摘要。

|`1`
|不同、有警告、計畫中仍有衝突，或審閱摘要中有過期的決定。

|`2`
|發生錯誤，或基準範圍不完整。
被篩選器刻意排除的檔案屬於範圍之外，不算錯誤。

|`3`
|僅 `--validate-merge`：檢查失敗。
|===

其他說明：

* `--format` 可為 `json`、`xml`、`toml` 或 `yaml`；預設依第一個檔案的副檔名判斷。
* 每次執行只能使用一個分析選項。
* `--semantic` 只會產生報告。若要複製值，請開啟檔案並使用語意檢視（請參閱 <<semantic>>）。
* 三個檔案的 `--semantic` 報告會列出每個路徑的 `state`（`left`、`right`、`both` 或 `conflict`），
  以及每一側的變更。只要有任何路徑不同（包括衝突），結束代碼即為 `1`。
* 語意結果中的來源位置，是解碼後 UTF-8 文字的位元組範圍與檔案中的行號，
  而不是 UTF-16 或舊式編碼檔案中的位元組位置。

[[command-line]]
== 命令列

透過 `oxidemerge` 指令，您可以從終端機或其他工具啟動比較，
也可以在不開啟視窗的情況下執行比較、產生報告與修補檔，以及同步資料夾。
無論是快速開啟檔案與資料夾，或是以指令碼與工作檔自動處理每晚的報告、備份等例行作業，都很適用。
本章列出各項選項，說明撰寫指令碼時會用到的結束代碼，並介紹工作檔。

=== 開啟比較

不加任何參數執行 `oxidemerge`，會開啟起始頁。
指定兩個或三個路徑即可進行比較；指定單一路徑則可開啟衝突檔案、專案或已儲存的比較。
路徑包含空格時，請以引號括住。

範例採用 POSIX 命令殼層語法。
在 Windows 上，請使用 Git Bash，或依您使用的命令殼層調整範例。

[source,sh]
----
oxidemerge left.txt right.txt                   # 雙向文字比較
oxidemerge mine.txt base.txt theirs.txt         # 三方比較（中間為基底）
oxidemerge -r old-folder new-folder             # 包含子資料夾
oxidemerge -r -f "*.rs;!target/" old new        # 套用篩選器的資料夾比較
oxidemerge conflict.txt                         # 解決含有衝突標記的檔案
oxidemerge -t image a.png b.png                 # 指定比較類型
oxidemerge https://example.com https://example.org   # 網頁比較
oxidemerge left.txt right.txt -o merged.txt     # 「儲存」會將右側窗格寫入 merged.txt
oxidemerge release.oxmproj                      # 開啟已儲存的專案
oxidemerge -r old.tar.gz new.tar.gz             # 將壓縮檔當作資料夾比較
oxidemerge --git-rev HEAD~1 src/main.rs         # 與較早的 Git 修訂版本比較
oxidemerge review.oxmcmp                        # 開啟已儲存的比較
----

=== 選項

下列各表依用途分類列出選項。

.路徑與各側
[cols="2,3"]
|===
|選項 |說明

|`PATHS...`
|兩個或三個檔案、資料夾、網址或伺服器路徑（`sftp://`、`ftp://`、`ftpes://`、`ftps://`；
請參閱 <<remote-command-line>>）；或是單一衝突檔案、專案檔或已儲存的比較。

|`-t`、`--compare-as <T>`
|指定比較類型：`text`、`binary`、`image` 或 `web`。

|`-o`、`--output <PATH>`
|指定「儲存」寫入結果的位置：雙向比較為右側窗格，三方比較為中間窗格。

|`--dl`、`--dm`、`--dr <TEXT>`
|以指定的說明文字取代左側、中間與右側的路徑顯示。

|`-L`、`--label <TITLE>`
|依序為每一側指定標題，用法與 `diff -L` 相同（請參閱 <<other-vcs>>）。
`--dl`、`--dm` 與 `--dr` 的優先順序較高。

|`--wl`、`--wm`、`--wr`
|以唯讀方式開啟左側、中間或右側。

|`--ssh-key <FILE>`
|指定登入 `sftp://` 路徑時使用的私密金鑰（請參閱 <<remote-command-line>>）。

|`--trust-fingerprint <FINGERPRINT>`
|伺服器路徑的伺服器尚未受信任時，若其金鑰或憑證的指紋與此值相同，即信任並記住該伺服器
（請參閱 <<remote-command-line>>）。

|`--proxy <URL>`
|經由 SOCKS5（`socks5://[使用者@]主機:埠號`）或 HTTP CONNECT（`http://[使用者@]主機:埠號`）
代理伺服器連線到伺服器路徑。
代理伺服器的密碼取自 `OXIDEMERGE_PROXY_PASSWORD`（請參閱 <<remote-advanced>>）。

|`--ftp-active`
|`ftp://`、`ftpes://` 與 `ftps://` 路徑改用主動模式（請參閱 <<remote-advanced>>）。

|`--client-cert <FILE>`、`--client-key <FILE>`
|指定提供給 FTPS 伺服器的用戶端憑證（PEM），以及私密金鑰（金鑰不在同一個檔案時）
（請參閱 <<remote-advanced>>）。

|`--rev`、`--git-rev <REV>`
|將指定的單一路徑，與它在 Git、Subversion 或 Mercurial 修訂版本中的內容比較
（請參閱 <<git-revision>>）。
|===

.資料夾比較
[cols="2,3"]
|===
|選項 |說明

|`-r`、`--recursive`
|包含子資料夾。

|`-f`、`--filter <MASK>`
|套用篩選遮罩，例如 `*.c;*.h` 或 `!*.bak`；或以 `"[F] 名稱"` 指定具名篩選器。

|`-m`、`--method <M>`
|指定比較方法：`full`、`quick`、`binary`、`date`、`datesize` 或 `size`。
|===

.比較選項
[cols="2,3"]
|===
|選項 |說明

|`--ignore-ws <MODE>`
|指定空白字元的處理方式：`compare`、`change` 或 `all`。

|`--ignore-case`、`--ignore-blank`、`--ignore-eol`、`--ignore-numbers`
|分別忽略大小寫、空白行、換行字元差異或數字。

|`--ignore-comments`
|忽略註解中的變更。

|`--prettify`
|比較前先格式化 JSON 與 XML。

|`--structured`
|在資料夾比較中，將結構相同的 JSON、XML、TOML 與 YAML 檔案視為相同。

|`--numeric-tolerance <AMOUNT>`
|差距不超過此值的數字視為相同。

|`--rules <NAME>`
|指定比較規則檔：規則資料夾中的名稱，或 `.oxrules` 檔案的路徑。
`""` 表示不使用規則檔。
|===

.報告與修補檔
[cols="2,3"]
|===
|選項 |說明

|`--cli`
|不開啟視窗直接比較。結束代碼請參閱 <<scripting>>。

|`--report <FILE>`
|產生報告。
資料夾比較支援 `.html`、`.pdf`、`.csv`、`.txt` 或 `.xml`；文字比較支援 `.html`、`.pdf` 或 `.xml`。
請參閱 <<pdf-reports>>。

|`--report-diffs`
|在 HTML 或 PDF 資料夾報告中，加入每個已變更文字檔的差異。

|`--report-hide-paths`
|在資料夾報告中以左側、中間、右側稱呼比較的資料夾，而不顯示其路徑。

|`--report-detail <DETAIL>`
|`.html` 報告顯示多少差異內容：`summary`、`standard`（預設）或 `full`。請參閱 <<report-detail>>。

|`--slideshow`
|將 `.html` 報告寫成投影片，每張投影片呈現一個差異。

|`--patch <FILE>`
|為兩個檔案或資料夾產生修補檔。

|`--patch-style <S>`
|修補檔格式：`normal`、`context` 或 `unified`（預設）。

|`--context <N>`
|上下文與統一格式修補檔，以及 PDF 報告中的前後文行數。預設為 3。

|`--page-size <SIZE>`
|PDF 報告的紙張大小：`a4`（預設）或 `letter`。

|`--portrait`
|PDF 報告使用直式頁面；預設為橫式。

|`--unified`
|雙向比較的 PDF 報告以單欄顯示，刪除的行列在新增的行上方。

|`--whole-file`
|PDF 報告顯示完整檔案，而非只顯示差異與其前後文。
|===

.分析
[cols="2,3"]
|===
|選項 |說明

|`--merge-plan`
|為三個檔案或資料夾（左側、基底、右側）產生唯讀的合併計畫。

|`--validate-merge <RESULT>`
|對照三個檔案或資料夾（左側、基底、右側）檢查合併結果。

|`--semantic`
|依結構比較兩個 JSON、XML、TOML 或 YAML 檔案。
若指定三個檔案（左側、基底、右側），則列出每一側相對於基底的變更，以及其中的衝突。

|`--format <FORMAT>`
|語意比較的格式：`json`、`xml`、`toml` 或 `yaml`。需搭配 `--semantic`。

|`--array-key <MEMBER>`
|依此成員配對陣列中的物件。需搭配 `--semantic`。

|`--review-summary <SNAPSHOT>`
|彙整已儲存的 `.oxmreview` 資料夾審閱中的決定。

|`--impact`
|列出兩個資料夾或基準中，已變更的檔案可能在哪些地方被使用。

|`--baseline-left <SPEC>`、`--baseline-right <SPEC>`
|版本基準：`folder:路徑`、`git:修訂版本:路徑` 或 `review:側:路徑`。
兩者都須指定，用來取代路徑參數。

|`--release-report <FILE>`
|以 `.json`、`.html` 或 `.xml` 格式產生版本基準報告。

|`--important-path <TEXT>`
|將包含此文字的變更路徑標示為重要。可重複指定。
需搭配 `--impact`、`--release-report` 或 `--baseline-left`。

|`--split-rename <PATH>`
|將此新增的路徑維持為新增，而不視為疑似重新命名。可重複指定。
需搭配 `--impact`、`--release-report` 或 `--baseline-left`。

|`--sync-plan <MODE>`
|產生同步兩個資料夾（來源、目的地）的唯讀計畫。`MODE` 為 `mirror` 或 `update`。
計畫以 JSON 格式寫到標準輸出，或寫到 `--report` 指定的檔案。

|`--sync-links`
|搭配 `--sync-plan` 使用：將符號連結以連結本身同步，絕不跟隨連結（macOS 與 Linux）。
計畫會記錄此設定，因此 `--sync-apply` 不需再加上此旗標。未指定時，連結會保持不動。

|`--sync-apply <PLAN>`
|將計畫套用到產生計畫時的資料夾，資料夾須依相同順序指定。需搭配 `--yes`。

|`--yes`
|確認 `--sync-apply` 或 `--job` 的同步工作可以取代與刪除目的地中的檔案，
以及 `--job` 的工作可以在工作檔所在資料夾之外寫入報告與修補檔。

|`--sync-recover`
|復原未完成的資料夾同步。

|`--job <FILE>`
|依序執行工作檔中的工作，並輸出 JSON 摘要（請參閱 <<jobs>>）。不接受路徑。
|===

每次執行只能使用一個分析選項，
且分析選項不能與 `-o`、`--patch`、`--git-rev`、`--slideshow` 或 `--report-diffs` 併用。

|選項 |說明

|`--lang <CODE>`
|指定介面語言，例如 `ja` 或 `zh-TW`。

|`--list-languages`
|列出可用的語言。

|`--register-shell`、`--unregister-shell`
|在檔案管理員中加入或移除項目（請參閱 <<file-manager>>）。

|`--select-left <PATH>`、`--select-middle <PATH>`
|記住某一側，供之後的 `--compare-to` 使用。

|`--compare-to <PATH>`

[[scripting]]
=== 撰寫指令碼與結束代碼

由於 OxideMerge 可以在不開啟視窗的情況下比較，您可以從指令碼呼叫它，並依結束代碼判斷結果。
`--cli`、`--report` 與 `--patch` 都不會開啟視窗，並傳回下列結束代碼：

[cols="1,4"]
|===
|代碼 |意義

|`0`
|套用目前的選項與規則後，內容相同。

|`1`
|找到差異。成功產生報告或修補檔時，也會傳回此代碼。

|`2`
|發生錯誤。
|===

IMPORTANT: 結束代碼 `1` 代表比較結果，而不是錯誤，請確認您的指令碼依此處理。

資料夾同步（請參閱 <<folder-sync>>）使用另一組結束代碼：

[cols="1,4"]
|===
|代碼 |意義

|`0`
|`--sync-plan`：沒有需要處理的項目。`--sync-apply`：所有變更都已套用並檢查。
`--sync-recover`：已全部復原。

|`1`
|`--sync-plan`：計畫中有變更或衝突。

|`2`
|發生錯誤，或計畫遭到拒絕且未變更任何檔案，例如有檔案在計畫產生後被變更。

|`4`
|`--sync-apply` 失敗或被停止，所有變更都已復原。

|`5`
|部分套用：有些變更無法復原。`--sync-recover` 無法全部復原時，也會傳回此代碼。
輸出中列出的日誌保留了原始檔案。
|===

[source,sh]
----
oxidemerge --sync-plan mirror source destination --report plan.json
oxidemerge --sync-apply plan.json --yes source destination
----

`--sync-apply` 會重新比較資料夾；若計畫已與資料夾不符、是以不同的篩選條件或為其他資料夾製作，
或是由較新版本產生，就會拒絕套用。

`--sync-apply` 與 `--sync-recover` 會輸出 JSON 結果，其中 `status` 為 `applied`、`not_applied`、
`rolled_back`、`recovery_required` 或 `recovered`。
結果不是單純成功時，還會包含 `problem`：`stale`（計畫製作後檔案或資料夾有變更）、`unsupported`、
`read_failure`、`write_failure`（例如沒有權限或可用空間不足）、`canceled` 或 `recovery_needed`。
這些問題名稱連同第七個名稱 `ambiguous`（輸入還有同樣可能的另一種解讀，例如無法區分的重複項目），
在 OxideMerge 中的用法一致：凡是先標示問題類型、再說明細節的檢視，都使用同樣的名稱，
讓相同的情況在各處都有相同的稱呼。

撰寫指令碼時，請留意下列事項：

* 命令列會使用您已儲存的選項，除非您以參數另外指定。
  若要讓執行結果不受個人設定影響，請將 `OXIDEMERGE_CONFIG_DIR` 指向一個專用資料夾
  （請參閱 <<configuration>>）。
* 報告支援文字與資料夾比較。
  二進位或影像比較不會產生 HTML 報告，OxideMerge 會改為顯示說明訊息。

[source,sh]
----
# 不開啟視窗進行比較，同時輸出差異
oxidemerge --cli -r dirA dirB

# 資料夾比較的 HTML 報告，並附上每個已變更檔案的差異
oxidemerge -r dirA dirB --report report.html --report-diffs

# 兩個檔案的 HTML 報告，忽略註解的變更
oxidemerge old.c new.c --ignore-comments --report diff.html

# 含 5 行前後文的統一格式差異
oxidemerge old.c new.c --patch changes.patch --context 5

# 使用比較規則檔
oxidemerge --cli -r build1 build2 --rules "Build logs"
----

若命令殼層啟用了 `set -e`，請明確將結束代碼存入變數，以免指令碼在找到差異時就中止：

[source,sh]
----
result=0
oxidemerge --cli -r old-folder new-folder || result=$?
case "$result" in
  0) echo "沒有差異" ;;
  1) echo "找到差異" ;;
  *) echo "比較失敗" >&2; exit "$result" ;;
esac
----

[[jobs]]
=== 工作

工作檔可將一組執行集中在一處，讓每晚的報告或備份只需一個指令即可完成。
工作檔是 JSON 檔案，副檔名通常為 `.oxjob`：

[source,json]
----
{
  "version": 1,
  "continue_on_error": false,
  "jobs": [
    {
      "name": "nightly report",
      "left": "a",
      "right": "b",
      "recursive": true,
      "report": "report.html"
    },
    {
      "name": "plan",
      "kind": "sync_plan",
      "source": "a",
      "destination": "${env:BACKUP}",
      "mode": "mirror",
      "report": "plan.json"
    },
    {
      "name": "backup",
      "kind": "sync",
      "source": "a",
      "destination": "${env:BACKUP}",
      "mode": "mirror",
      "apply": true
    }
  ]
}
----

[source,sh]
----
oxidemerge --job nightly.oxjob          # 執行前兩個工作，拒絕同步
oxidemerge --job nightly.oxjob --yes    # 執行全部三個工作
----

每個工作都會轉換成一組命令列選項，並依該命令列的方式執行，因此工作與對應命令列的結果相同。
與命令列一樣，工作也會套用您已儲存的選項。
`--job` 不接受路徑，除了 `--yes` 與 `--lang` 之外也不接受其他選項；每個工作的選項都寫在檔案中。

工作檔包含下列最上層欄位：

`version`:: 必填，值為 `1`。版本較新的檔案會被拒絕。
`continue_on_error`:: 為 `false`（預設）時，若某個工作以錯誤結束（代碼 2 或以上），
之後的工作都不會執行。為 `true` 時，所有工作都會執行。
`jobs`:: 依序列出的工作。OxideMerge 不認得的欄位一律視為錯誤，因此拼錯的名稱絕不會被忽略。

每個工作都有選用的 `name`（顯示在摘要與錯誤訊息中），以及 `kind`：

`compare`（預設）:: 必須指定 `left` 與 `right`（三方比較另需 `base`）。
選項：`recursive`、`report`、`report_diffs`、`report_hide_paths`、`slideshow`、`patch`、
`patch_style`、`context`、`compare_as`。
`sync_plan`:: 寫出同步計畫。必須指定 `source`、`destination`、`mode`（`mirror` 或 `update`）
與 `report`（計畫檔）。
`sync`:: 一次完成同步的規劃與套用。必須指定 `source`、`destination`、`mode` 與 `"apply": true`；
執行時還需要 `--yes`。會刪除大量項目的同步會被拒絕，除非工作中設定 `"allow_large_deletion": true`。
兩種同步工作都可以用 `"copy_links": true` 代替 `--sync-links`。

所有類型也都接受 `filter`、`method`、`rules`、`whitespace`、`ignore_case`、`ignore_blank`、
`ignore_eol`、`ignore_numbers`、`ignore_comments`、`prettify`、`structured` 與 `numeric_tolerance`；
比較類型另外接受用於 `.pdf` 報告的 `page_size`、`portrait`、`unified` 與 `whole_file`。
這些欄位的意義與同名的命令列選項相同。
不符合工作類型的欄位（例如比較工作中的 `apply`）會視為錯誤。
針對伺服器路徑，所有類型都接受 `ssh_key`、`trust_fingerprint`、`proxy`、`ftp_active`、`client_cert`
與 `client_key`，作用分別等同 `--ssh-key`、`--trust-fingerprint`、`--proxy`、`--ftp-active`、
`--client-cert` 與 `--client-key`（請參閱 <<remote-command-line>>）。
`destination` 為伺服器路徑的 `sync` 工作，會將變更寫回伺服器。

路徑（包括 `rules`）相對於工作檔所在的資料夾，但絕對路徑、URL 與伺服器路徑除外。
在路徑與 `rules` 中，`${env:NAME}` 會替換為環境變數 `NAME` 的值；未設定的變數會視為錯誤。
除此之外不會展開任何內容，工作檔也不會指定任何命令或命令殼層。
比較由您的解包器讀取的檔案時（請參閱 <<unpackers>>），會和任何比較一樣執行該解包器。

工作寫入報告或修補檔時，只會建立新檔案或覆寫一般檔案，絕不會經由符號連結寫入。
位於工作檔所在資料夾之外的報告或修補檔（例如 `../report.html` 或 `${env:HOME}` 底下的路徑），
只有在指定 `--yes` 時才會寫入，因此他人傳來的工作檔無法取代您的檔案。

`--job` 會輸出 JSON 摘要。其中的 `exit_code` 是所有工作中最差的代碼，也是這次執行的結束代碼。
`jobs` 的每個項目包含 `name`、`kind` 與 `exit_code`；工作失敗時另有 `error`，
同步工作則另有與 `--sync-apply` 輸出相同的 `sync` 結果。
`not_run` 列出因先前失敗而略過的工作；在程式中停止執行時，`stopped` 為 `true`：

[source,json]
----
{
  "exit_code": 2,
  "jobs": [
    { "name": "nightly report", "kind": "compare", "exit_code": 1 },
    { "name": "plan", "kind": "sync_plan", "exit_code": 1 },
    { "name": "backup", "kind": "sync", "exit_code": 2,
      "error": "此工作會變更 …，僅在允許時執行：命令列中的 --yes" }
  ]
}
----

[[jobs-in-the-program]]
==== 在程式中儲存與執行工作

您也可以直接在 OxideMerge 視窗中建立及執行工作檔。

「檔案 → 專案與工作 → 另存為工作...」會將目前的資料夾比較儲存為工作檔。
工作會記下比較的資料夾、篩選器、比較方法、比較規則檔，以及已開啟的比較選項，
因此比較方式與該分頁完全相同。
請選擇工作內容：

* 「比較並寫入報告」：報告檔案的路徑相對於工作檔，副檔名（`.html`、`.pdf`、`.csv`、`.txt` 或 `.xml`）
  決定報告格式。
* 「規劃同步」：寫入 JSON 計畫，不變更任何內容。
* 「同步」：一次完成規劃與套用，可選擇左到右或右到左，以及鏡像或更新。工作會含有 `"apply": true`；
  勾選「允許刪除大量檔案」則會加上 `"allow_large_deletion": true`。

若要將工作與其資料夾一起搬移，請勾選「以相對於工作檔的路徑儲存」。
只有兩個資料夾的比較才能存成同步工作。
修訂版本、網頁或壓縮檔的比較是透過暫存副本進行，因此無法存成工作。

「檔案 → 專案與工作 → 執行工作...」會執行工作檔，並列出每個工作的結果。
按一下「開啟」可開啟工作寫入的報告或計畫，按一下「比較」則可在分頁中開啟它的資料夾。
「開啟」只提供給報告檔案（`.html`、`.pdf`、`.csv`、`.txt`、`.xml`、`.json`、`.diff` 或 `.patch`）。
工作的執行方式與 `--job` 相同，使用的是您已儲存的選項，而不是啟動 OxideMerge 時指定的選項。

含有同步工作，或會在所在資料夾之外寫入報告或修補檔的工作檔，
執行前會先列出將變更的資料夾與將寫入的檔案；允許刪除大量檔案的同步工作也會特別標示。
必須按一下「執行並允許變更」才會執行；這相當於 `--yes`，且只適用於這一次執行。
實際執行的是列出時的檔案內容，即使磁碟上的檔案在這期間有所變更；
「再次執行」會重新讀取檔案並再次詢問。
「停止」會停止正在套用的同步、復原已做的變更，並略過之後的工作。
工作正在同步時，OxideMerge 會等它完成後才結束。

[[integration]]
== 與其他工具整合

您的版本控制系統可以在您檢閱變更或解決合併衝突時開啟 OxideMerge，
讓您在與其他比較相同的窗格中完成這些工作。
本章說明如何將 OxideMerge 設定為 Git、Subversion、Mercurial 或 Perforce
自行叫用的差異與合併工具，以及如何將 OxideMerge 加入檔案管理員。
若要改為從 OxideMerge 內開啟某個修訂版本，請參閱 <<git-revision>>。

[[git]]
=== Git

只要幾項設定，Git 就會在執行 `git difftool` 與 `git mergetool` 時開啟 OxideMerge。

請先安裝 Git，並確認 `oxidemerge` 在 `PATH` 中。
接著在 Bash 或 Git Bash 等 POSIX 命令殼層中執行下列命令，
將 OxideMerge 設為目前使用者帳戶的比較工具與合併工具：

[source,sh]
----
git config --global diff.tool oxidemerge
git config --global difftool.oxidemerge.cmd 'oxidemerge "$LOCAL" "$REMOTE"'
git config --global merge.tool oxidemerge
git config --global mergetool.oxidemerge.cmd \
  'oxidemerge "$LOCAL" "$BASE" "$REMOTE" -o "$MERGED" --dl Local --dr Remote --wl --wr'
git config --global mergetool.oxidemerge.trustExitCode false
----

在 macOS 上，除非您已將程式連結到 `PATH`，否則請使用完整路徑
`/Applications/OxideMerge.app/Contents/MacOS/oxidemerge`。
在 Windows 上，請使用 `oxidemerge.exe` 的路徑。

`git difftool`:: 逐一開啟每個已變更的檔案。
`git difftool --dir-diff` 則以單一資料夾比較開啟所有已變更的檔案；
在檔案中的最後一個差異處按 kbd:[Alt+↓]，即可開啟下一個已變更的檔案。
`git mergetool`:: 開啟三方合併，中間為基底。
請使用「自動合併」，或將差異複製到中間，然後儲存。
中間窗格的內容會寫入合併結果檔，絕不會寫入基底。
Jupyter notebook 等 OxideMerge 平時會讀成文字的檔案，在這裡會以檔案本身進行合併，
因此儲存的結果仍是有效的檔案。
+
設定 `trustExitCode false` 時，Git 會檢查輸出檔案是否有變更；
若檔案看起來沒有變更，Git 可能會詢問合併是否成功。
請在儲存並檢查結果之後，才回答成功。
只是關閉視窗，並不代表合併成功。

[[other-vcs]]
=== Subversion、Mercurial 與 Perforce

本節的設定可讓 Subversion、Mercurial 與 Perforce 在比較與合併時開啟 OxideMerge。

OxideMerge 接受 `diff` 用來指定標題的參數：`-u` 會被忽略，
每個 `-L <TITLE>` 則依路徑順序為下一側命名。
因此窗格標題會顯示修訂版本名稱，而不是暫存檔的路徑。
`--dl`、`--dm` 與 `--dr` 的優先順序高於 `-L`。

合併可以直接指定 OxideMerge 本身，不必再寫包裝指令碼。
Subversion 的 `merge-tool-cmd` 會傳入五個檔案：基底、對方版本、我的版本、合併結果檔與工作檔，
最後兩個是同一個檔案。
Perforce 的 `P4MERGE` 會傳入四個：基底、對方版本、您的版本與結果，結果當時可以還不存在；
除了您的版本，其餘都是 p4 的暫存檔，名稱在 Windows 上類似 `t1t2t3.tmp`，在 macOS 與 Linux 上類似 `tmp.1.2.3`。
其他四個或五個檔案（例如 `*.txt` 這類樣式比對到的檔案）會因路徑太多而被拒絕，
因此儲存時絕不會覆寫其中某個檔案。
命令列只有這些檔案時，OxideMerge 會在左側開啟我的版本或您的版本、中間開啟基底、右側開啟對方版本，
並將中間窗格存到結果檔。
關閉視窗時若該檔案沒有變更，OxideMerge 會以結束代碼 1 離開，衝突維持未解決。
只要還有其他選項（包括 `-o`），就不會採用這個辨識方式，參數會照原樣使用。
會重新排列檔案並傳入 `-o` 的包裝指令碼仍然可用。

==== Subversion

`svn diff --diff-cmd oxidemerge` 會逐一比較每個已變更的檔案。
Subversion 會傳入 `-u -L <舊標題> -L <新標題> <舊檔> <新檔>`，
因此標題會顯示如 `f.txt (revision 12)` 與 `f.txt (working copy)`。
若要讓每次 `svn diff` 都使用 OxideMerge，請在 `~/.subversion/config`
（Windows 上為 `%APPDATA%\Subversion\config`）中設定：

[source,ini]
----
[helpers]
diff-cmd = oxidemerge
merge-tool-cmd = oxidemerge
----

請勿對 `svn diff` 傳入 `-x` 選項，否則 Subversion 會改傳這些選項，而不傳 `-u`。
若 `oxidemerge` 不在 `PATH` 中，請使用完整路徑。

在 Subversion 的衝突提示中選擇 *l*（launch），或執行 `svn update --accept launch`。
OxideMerge 以結束代碼 0 離開（也就是合併結果檔有變更）時，Subversion 會將衝突標示為已解決。
未儲存就關閉視窗，衝突會維持未解決。

==== Mercurial

請將下列內容加入 `~/.hgrc`（Windows 上為 `%USERPROFILE%\mercurial.ini`）：

[source,ini]
----
[extensions]
extdiff =

[extdiff]
cmd.oxidemerge = oxidemerge

[diff-tools]
oxidemerge.diffargs = -L $plabel1 -L $clabel $parent $child

[ui]
merge = oxidemerge

[merge-tools]
oxidemerge.args = $local $base $other -o $output --dl $labellocal --dm $labelbase --dr $labelother --wl --wr
oxidemerge.checkchanged = true
----

`hg oxidemerge` 會比較已變更的檔案：只有一個檔案時直接比較，
有多個檔案時則以資料夾比較開啟。
`hg oxidemerge -c REV` 會顯示單一變更集。
請勿同時設定 `opts.oxidemerge`，否則 Mercurial 會忽略 `diffargs`，標題也就不會顯示。
`hg merge` 與 `hg resolve` 會開啟三方合併，中間為基底。
設定 `checkchanged` 後，若合併結果檔沒有變更，Mercurial 會詢問合併是否成功。

==== Perforce

您可以從 p4 命令列、P4V 或兩者使用 OxideMerge。
兩者需要分別設定：p4 讀取 `P4DIFF` 與 `P4MERGE`，P4V 則使用自己的偏好設定。

無論使用哪一種，都必須先能連線。
請在工作區中執行 `p4 info`：結果應顯示您的 *User name*、
作為 *Client name* 的工作區，以及作為 *Server address* 的伺服器。
若顯示 *Client unknown* 或無法連線，請先設定 `P4PORT`、`P4USER` 與 `P4CLIENT`，
或團隊使用的 `P4CONFIG` 檔案。

===== p4 命令列

p4 會以兩個檔案執行 `P4DIFF` 指定的程式：depot 修訂版本（暫存檔）與您工作區中的檔案；
並以四個檔案執行 `P4MERGE` 指定的程式：基底、對方版本、您的版本與結果。
命令列只有這些檔案時，OxideMerge 會接受這個順序。

設定 p4 命令列的步驟如下：

. 以 `p4 set`（或同名的環境變數）讓 p4 使用 OxideMerge：
+
[source,sh]
----
p4 set P4DIFF=oxidemerge
p4 set P4MERGE=oxidemerge
----
+
若 `oxidemerge` 不在 `PATH` 中，請使用完整路徑，例如 macOS 上的
`/Applications/OxideMerge.app/Contents/MacOS/oxidemerge`。
請勿在 `P4DIFF` 加上 `--cli`：加上後，
OxideMerge 會改為列出差異而不開啟視窗，且在檔案不同時以 1 結束，
macOS 上的 p4 會將此回報為 *Execution Failed*。
+
`p4 set` 在 macOS 與 Linux 上會將設定存於 `~/.p4enviro`，在 Windows 上則存於登錄檔。
. 執行 `p4 set` 檢查設定；兩行都應指向 OxideMerge：
+
----
P4DIFF=oxidemerge (enviro)
P4MERGE=oxidemerge (enviro)
----
+
括號中的文字表示 p4 從何處取得該值：`(enviro)` 代表 macOS 與 Linux 上的 `p4 set`，
`(set)` 代表 Windows 上的 `p4 set`，`(config '...')` 代表 `P4CONFIG` 檔案。
後面沒有括號的值來自環境變數，其優先順序高於 `p4 set`。
若某一行指向其他工具，請在設定該值的地方修改。

要將檔案與 depot 比較，請執行 `p4 diff f.txt`。
OxideMerge 會在左側顯示 depot 修訂版本，右側顯示您工作區中的檔案。
depot 修訂版本是暫存檔，名稱類似 `tmp.1.2.3`。
只有工作區中的檔案可以編輯。
由於 p4 會將 `P4DIFF` 中的字詞傳給 OxideMerge，您也可以改為替窗格命名：

[source,sh]
----
p4 set P4DIFF="oxidemerge --dl Depot --dr Workspace"
----

p4 會以空格切分 `P4DIFF`，因此每個標題請只用一個字詞。

.窗格命名為 Depot 與 Workspace 的 `p4 diff`
image::p4-diff.png[由 p4 diff 開啟的 OxideMerge]

合併衝突的步驟如下：

. 執行 `p4 resolve f.txt`。
p4 會顯示找到的變更，並建議一個動作：
+
----
/home/you/ws/f.txt - merging //depot/main/f.txt#2
Diff chunks: 0 yours + 1 theirs + 0 both + 1 conflicting
Accept(a) Edit(e) Diff(d) Merge (m) Skip(s) Help(?) e:
----
. 在提示時輸入 *m*（merge）。
OxideMerge 會開啟，左側為 *Yours*、中間為 *Base*、右側為 *Theirs*。
中間窗格一開始是基底內容；「儲存結果」會將它寫入 p4 傳入的結果檔案，絕不會寫入基底。
. 以「下一個衝突」搭配「採用左側」、「採用右側」或「採用兩側」，
或直接編輯中間窗格，解決每個衝突。
請確認工具列顯示「沒有剩餘衝突」：即使仍有衝突，「儲存結果」也會儲存，
衝突處會保留基底的文字。
. 按一下「儲存結果」並關閉視窗。
. 回到提示後，p4 會建議 *ae*（accept edit）；若結果與對方版本相同，則建議 *at*（accept theirs）。
輸入 *ae* 以接受您所儲存的合併檔案。
接著 p4 會回報類似 `//ws/f.txt - edit from //depot/main/f.txt` 的訊息。

.由 `p4 resolve` 開啟的衝突
image::p4-merge.png[由 p4 resolve 開啟的三方合併]

若未儲存就關閉視窗，OxideMerge 會以結束代碼 1 離開，檔案仍維持未解決：
p4 會建議 *e* 而非 *ae*（在 macOS 與 Linux 上還會回報 *Execution Failed*；Linux 接著顯示 *No such file or directory*，那是它回報這個結束代碼的方式），
此時輸入 *ae* 會警告檔案仍含有變更標記。
請再次執行 `p4 resolve` 重新開始。

===== P4V

P4V 不會讀取 `P4DIFF` 或 `P4MERGE`，而是使用自己的比較與合併設定。
由於 P4V 會直接執行 OxideMerge，因此不需要包裝指令碼。

設定 P4V 的步驟如下：

. 在 P4V 中開啟 *Preferences*（macOS 上為 *P4V → Preferences*，Windows 與 Linux 上為
*Edit → Preferences*）。
. 在左側清單中選取 *Diff*。
. 選取 *Other application*。
只填寫下方欄位並不夠：只要仍選取 *P4Merge*，P4V 就會繼續使用 P4Merge。
. 在 *Location* 中填入 `oxidemerge` 程式本身的路徑，而不是應用程式套件或包裝指令碼的路徑：
+
[cols="1,3"]
|===
|macOS |`/Applications/OxideMerge.app/Contents/MacOS/oxidemerge`
|Windows |解壓縮資料夾中 `oxidemerge.exe` 的路徑
|Linux |`command -v oxidemerge` 的輸出，例如 `/usr/bin/oxidemerge`
|===
. 在 *Arguments* 中輸入 `%1 %2`。
+
.P4V Preferences → Diff
image::p4v-diff-prefs.png[將 OxideMerge 設為其他應用程式的 P4V 比較偏好設定]
. 在左側清單中選取 *Merge*，同樣選取 *Other application*，並填入相同的 *Location*。
. 在 *Arguments* 中輸入：
+
----
%2 %b %1 -o %r --dl Yours --dm Base --dr Theirs --wl --wr
----
+
在 P4V 的合併參數中，`%1` 是對方版本，`%2` 是您的版本，`%b` 是基底，`%r` 是結果。
+
.P4V Preferences → Merge
image::p4v-merge-prefs.png[將 OxideMerge 設為其他應用程式的 P4V 合併偏好設定]
. 按一下 *OK*。

*Specify diff application by extension* 與 *Specify merge application by extension*
下方的清單，會針對其中列出的副檔名覆寫預設工具。
保持空白即可讓所有檔案都使用 OxideMerge；
若某類檔案仍會開啟 P4Merge，請在清單中尋找它的副檔名。

將檔案與 depot 比較的步驟如下：

. 在 *Workspace* 或 *Depot* 分頁中選取檔案，按一下工具列的 *Diff*。
. 在 Diff Files 對話方塊中，第一個路徑是最新修訂版本，第二個是您工作區中的檔案；
按一下 *Diff*。
OxideMerge 會開啟，左側為 depot 修訂版本（名稱類似 `server#head.conf` 的暫存檔），
右側為您工作區中的檔案。

合併衝突的步驟如下：

. 在 *Workspace* 或 *Pending* 分頁中選取檔案；需要解決的檔案會顯示問號圖示。
. 選擇 *Actions → Resolving → Resolve...*，或在檔案上按右鍵並選擇 *Resolve...*。
. 在 Resolve 對話方塊中按一下 *Run Merge Tool*。
OxideMerge 會開啟，左側為 *Yours*、中間為 *Base*、右側為 *Theirs*。
若開啟的是 P4Merge，請回到 *Preferences → Merge*，確認已選取 *Other application*。
+
.P4V 的 Resolve 對話方塊
image::p4v-resolve.png[含 Run Merge Tool 的 P4V Resolve 對話方塊]
. 解決每個衝突，按一下「儲存結果」並關閉視窗。
P4V 傳入的結果檔案已含有 P4V 自己的衝突標記；儲存後會取代這些標記。
*Yours* 就是您工作區中的檔案本身，而非複本，因此請在中間窗格修改：
在左側窗格儲存的內容會立即寫入您的工作區檔案。
. 在 Resolve 對話方塊中按一下 *Accept Merged*，P4V 詢問是否以合併結果取代檔案時，
按一下 *Yes*。
對話方塊仍會顯示合併前的衝突數；在您接受之前，P4V 不會重新讀取結果。
請先檢查結果：OxideMerge 只在您儲存時寫入結果，若未儲存就關閉，結果仍會保留 P4V 的標記。
若要整個採用對方版本或您的版本，請改用 *Accept Source* 或 *Accept Target*。

NOTE: 已在 Windows 上以 SlikSVN 1.14.2、Mercurial 7.1.2 與 p4/p4d 2026.1 檢查，
並在 Linux 上以 Git 2.55.0、Subversion 1.14.5、Mercurial 7.2.4 與 p4/p4d 2026.1（3089746）檢查，
使用本機儲存庫與本機 Perforce 伺服器。
「與修訂版本比較」涵蓋 Git、Subversion 與 Mercurial，包含名稱不是 ASCII 的 Subversion 檔案
（在 Linux 上該路徑會直接傳給 `svn`），以及在 Windows 上 ANSI 字碼頁拼得出來的 Mercurial 名稱。
並以上面的設定，從 `git mergetool`、`svn update --accept launch`、`hg merge` 與 `p4 resolve` 進行合併，
儲存後衝突即解決，未儲存就關閉則維持未解決。
P4V 仍使用上面的參數字串。
在 Linux 上已以 P4V 2026.1（2933292）檢查：比較時左側為 depot 修訂版本、右側為工作區檔案；
儲存合併後按 *Accept Merged* 即解決檔案；未儲存就關閉則結果仍保留 P4V 的標記，檔案維持未解決。
它的比較設定，以及在儲存後接受合併，先前曾在 macOS 上以 P4V 2026.3 試過，
這次沒有在 Windows 上重做。
透過網路連線的 Subversion 或 Perforce 伺服器仍可能要求 OxideMerge 無法提供的登入，
請先使用 `svn` 或 `p4` 登入。
Subversion 與 Mercurial 的測試也會在 Linux 的 Docker 測試環境中執行。

[[file-manager]]
=== 檔案管理員

將 OxideMerge 加入檔案管理員後，您就能直接從正在瀏覽的檔案與資料夾開始比較。
您可以透過「工具」選單或執行 `oxidemerge --register-shell` 加入這些項目：

Windows:: 「工具 → 加入檔案總管右鍵選單」會為檔案、資料夾、磁碟機與資料夾背景
加入「OxideMerge」子選單。
在 Windows 11 上，這個子選單位於「顯示其他選項」中。
macOS:: 「工具 → 加入 Finder 快速動作」會在 Finder 的「快速動作」與「服務」選單中，
加入「OxideMerge: 比較」、「OxideMerge: 選為左側」與「OxideMerge: 選為中間」。
Linux:: 「工具 → 加入檔案管理員右鍵選單」會在 Nautilus、Nemo 與 Dolphin 中加入相同的項目。

這些項目的用法如下：

* 「比較」會比較選取的兩個或三個檔案或資料夾。
  只選取一個項目時，會將它與您先前選擇的一側比較；
  若尚未選擇任何一側，則開啟「選擇檔案或資料夾」對話方塊並帶入該項目。
* 「選為左側」與「選為中間」會記住一個項目，例如位於其他資料夾中的項目。
  之後「比較」會顯示為「與「名稱」比較」。
* 「比較方式」（僅限 Windows 的檔案）可指定以文字、二進位、影像或網頁進行比較。

這些項目會指向加入它們的程式，因此搬移程式後，請重新加入。
若要移除，請使用「工具」選單中對應的命令，或執行 `oxidemerge --unregister-shell`。

[[options]]
== 選項與設定

您可以依照自己的工作方式，調整 OxideMerge 的外觀、比較行為與檔案處理方式。
本章說明各項可用的選項，以及 OxideMerge 存放這些選項的位置。
您也可以使用可攜式或獨立設定執行程式，例如用於指令碼與測試。
本章也說明如何自行新增介面語言。

=== 應用程式選項

若要開啟選項，請選擇「編輯 → 選項...」，或按一下右上角的設定按鈕（兩條滑桿圖示）。
您可以使用「搜尋設定」依名稱尋找選項，或以「還原預設值」恢復所有預設值。

選項分為下列幾組。

一般::
* 「語言」、「主題」（「淺色」、「深色」或「跟隨系統」）、「字型大小」與「Tab 寬度」。
* 「行號」、「位置窗格」、「顯示空白字元」與「語法醒目提示」。
* 「醒目提示的檔案上限」：超過此大小（MB）的檔案會不套用語法醒目提示
  （預設為 16 MB；請參閱 <<troubleshooting>> 的「效能」）。
* 「排列方式」（請參閱 <<text-comparison>> 中的檢視選項）。
* 「覆寫檔案時保留 .bak 備份」、「刪除時使用資源回收筒」與「複製前先確認」。
* 「啟動時重新開啟上次的比較」。
* 「協助工具」：
** 「色盲友善的差異顏色」：新增的行顯示為藍色、刪除的行為橘色、變更的行為紫色，衝突則為黃色。
** 「高對比」：使用更鮮明的顏色，且每種行顏色上的文字對比至少為 4.5:1，符合 WCAG 對文字的要求。
   在所有外觀中，文字游標在每種行顏色上的對比都至少為 3:1。
** 「減少動態效果」：不使用動畫。
** 「緊湊密度」：使用較矮的列與較緊密的間距。
+
這四項設定也可以從命令面板切換。
+
螢幕閱讀器會在內容變更時讀出，不必移動鍵盤焦點：差異計數（「第 3 個差異，共 12 個」）、
三方比較的合併狀態、狀態列的各部分，以及每則出現的訊息；錯誤訊息會打斷正在讀出的內容。
核取方塊會報告是否已勾選。
比較::
比較選項（請參閱 <<compare-options>>）。
比較規則::
比較規則檔（請參閱 <<compare-rules>>）。
資料夾::
「比較方法」、「包含子資料夾」、「包含僅一側子資料夾的內容」、「略過隱藏的檔案與資料夾」、
「將結構相同的 JSON、XML、TOML 與 YAML 檔案視為相同」、「日期容許誤差（秒）」
與「工作執行緒（0 = 自動）」。
+
結構選項需搭配「完整內容」比較方法使用。
文字內容不同的檔案會改以結構化資料讀取，只要值相同即視為相同；
與 <<semantic>> 相同，鍵的順序、排版與註解都不列入比較。
TOML 與 YAML 的數字依數值比較：`30` 與 `30.0` 視為相同，即使讀取該檔案的程式會區分兩者。
開啟這類檔案時，畫面仍會顯示文字差異；選擇「語意」即可確認結構相同。
資料夾同步仍會複製內容不同的檔案。
+
「工作執行緒」是資料夾比較同時比較的檔案數；設為 *0* 時，每個處理器執行緒使用一個，最多八個。
不論此設定為何，大型文字比較都會將工作分給最多八個執行緒；同時進行的比較會共用這些執行緒。
影像 / 二進位::
「色彩距離門檻」、「區塊大小」與「每行位元組數（二進位）」。
外掛程式::
解譯器外掛程式（請參閱 <<unpackers>>）。

[[configuration]]
=== 設定檔

OxideMerge 以 JSON 格式將選項存放在您的設定資料夾中：

[cols="1,3"]
|===
|系統 |設定檔

|Windows |`%APPDATA%\OxideMerge\config.json`
|macOS |`~/Library/Application Support/OxideMerge/config.json`
|Linux |`~/.config/OxideMerge/config.json`
|===

「說明與快速鍵」會顯示設定檔的位置。

IMPORTANT: 若 OxideMerge 無法讀取設定檔，會將它另存為 `config.json.bad` 並改用預設值。
您可以修正該檔案後再放回原處。

設定資料夾中也包含下列資料夾：

* `Rules`：比較規則檔。
* `Filters`：WinMerge 的 `.flt` 篩選器檔案。
* `Languages`：新增或修改過的語言套件。

=== 可攜式與獨立設定

OxideMerge 預設使用您使用者帳戶的設定資料夾。
您也可以將設定與程式放在一起，或指定 OxideMerge 使用您選擇的資料夾。

可攜式使用:: 在程式所在的資料夾中建立一個名為 `oxidemerge.json` 的空白檔案。
OxideMerge 便會將選項存放在這個檔案中，`Rules` 資料夾也會位於程式旁。
程式所在的資料夾必須可以寫入。
獨立設定:: 將環境變數 `OXIDEMERGE_CONFIG_DIR` 設為某個資料夾，OxideMerge 便會使用該資料夾中的
`config.json`。
此設定優先於可攜式使用與預設的設定資料夾。
它適合用於指令碼、測試，或區隔不同的工作環境。

=== 新增語言

只要提供語言檔，即可新增使用者介面的翻譯。

若要新增語言：

. 將原始碼中的 `lang/en.json` 複製為 `<code>.json`，例如 `nl.json`。
. 翻譯其中的值，所有 `{placeholder}` 都必須維持原樣。
. 將檔案放到程式旁或設定資料夾中的 `Languages` 資料夾。

NOTE: 缺少的訊息，以及少了或多了預留位置的翻譯，都會改以英文顯示。

[[troubleshooting]]
== 疑難排解

本章協助您解決安裝、啟動與使用 OxideMerge 時最常遇到的問題。
每個項目都會說明問題的症狀、已知的原因，以及解決方法。

發生錯誤時，請先閱讀錯誤訊息，並記下其中提到的路徑。
重新合併或儲存之前，請檢查目標位置、磁碟可用空間與存取權限，並確認是否有其他程式修改了檔案。

=== 安裝與啟動

macOS 拒絕開啟應用程式::
解決方法：請先嘗試開啟一次，再到「系統設定 → 隱私權與安全性」中選擇「強制打開」。
您也可以在「終端機」中清除下載標記：
`xattr -dr com.apple.quarantine /Applications/OxideMerge.app`。

macOS 要求存取資料夾::
原因：OxideMerge 第一次讀取「桌面」、「文件」、「下載項目」、卸除式磁碟區或網路磁碟區時，
macOS 會詢問一次。
+
解決方法：請允許存取，或之後在「系統設定 → 隱私權與安全性 → 檔案和資料夾」中開啟。

AppImage 無法啟動::
解決方法：請先以 `chmod +x` 讓 AppImage 可以執行。
若訊息提到 FUSE，請加上 `--appimage-extract-and-run` 啟動。

在 Linux 上視窗一片空白或無法開啟::
原因：OxideMerge 以 OpenGL 繪製畫面，需要可正常運作的顯示卡驅動程式；
例如在虛擬機器中，可能就沒有這樣的驅動程式。
+
解決方法：請以 `LIBGL_ALWAYS_SOFTWARE=1 oxidemerge` 啟動，改用 Mesa 的軟體繪圖。

在 Linux 上無法開啟檔案對話框::
原因：檔案對話框使用 XDG 桌面入口服務。
+
解決方法：請安裝 `xdg-desktop-portal`，以及適用於您桌面環境的套件，例如
`xdg-desktop-portal-gtk` 或 `xdg-desktop-portal-kde`。

檔案管理員中沒有 OxideMerge 的項目::
解決方法：在 Windows 11 上，這些項目位於「顯示其他選項」中。
+
項目會指向加入它們的程式。
若將程式移動或更新到其他資料夾，請從新的程式重新加入。
+
在 Linux 上，請重新啟動檔案管理員（例如執行 `nautilus -q`）才會看到新項目。

設定沒有儲存::
OxideMerge 無法儲存設定時，會顯示原因。
+
解決方法：請確認設定資料夾（請參閱 <<configuration>>）可以寫入，且磁碟沒有滿。

=== 編輯與儲存

某個窗格無法編輯::
原因：該窗格因下列原因之一而為唯讀：
+
--
* 標題列上的鎖頭已鎖上。
* 以 `--wl`、`--wm` 或 `--wr` 開啟。
* 是從檢閱快照或網頁的頁面樹狀結構解壓縮出來的。從壓縮檔比較（請參閱
  <<archives>>）解壓縮出來的檔案可以編輯，儲存時也會一併儲存壓縮檔；但已簽署的套件等
  仍為唯讀的壓縮檔除外。
* 是以格式化方式顯示的 JSON 或 XML 檔案。
  請關閉「比較前格式化 JSON 與 XML」，即可編輯與合併。
--

檔案因編碼問題而無法儲存::
原因：所選的編碼無法表示編輯內容中的某些字元。
+
解決方法：請復原加入這些字元的變更，然後再儲存一次。
+
WARNING: 若改選其他編碼，OxideMerge 會重新讀取檔案，因此請先將您的編輯另外保留一份。

檔案可以寫入，但儲存或複製仍失敗::
原因：OxideMerge 還需要能在同一資料夾中建立並取代暫存檔（請參閱 <<saving-files>>）。
+
解決方法：請檢查資料夾權限、磁碟可用空間，以及是否有其他程式鎖定該檔案。
OxideMerge 會回報失敗，而不會直接覆寫原始檔案。
+
IMPORTANT: 在成功儲存編輯內容之前，請不要關閉比較。

=== 比較結果

檔案看起來相同，但位元組內容不同::
原因：依選項與比較規則的設定，文字比較可能刻意忽略部分差異。
+
解決方法：請檢查空白字元、大小寫、換行字元、編碼與註解相關的選項，以及比較規則。
若要確認檔案完全相同，請使用二進位比較，或資料夾比較的「二進位內容」方法。

資料夾比較中缺少某些檔案::
解決方法：請檢查篩選器、「略過隱藏的檔案與資料夾」、「包含子資料夾」與「顯示」設定。
「依名稱尋找」也會隱藏部分項目。
+
「所有差異」沿用資料夾比較的篩選器與顯示設定，不會包含被隱藏的結果。

檔案顯示為錯誤::
原因：OxideMerge 無法讀取該檔案，訊息中會指出是哪個檔案。
+
解決方法：請檢查檔案的權限；在 macOS 上，也請一併檢查上述的資料夾存取權限。

資料夾自動合併無法開始，或沒有合併任何項目::
解決方法：請開啟「包含子資料夾」與「包含僅一側子資料夾的內容」，並等待比較完成。
+
若有檔案在比較後又有變更，就不會合併任何項目，並會列出該檔案。
若合併途中某項變更失敗，到目前為止的所有變更都會復原。
請重新整理比較後，再次檢查合併計畫。

=== 網頁

網頁比較缺少瀏覽器中看得到的內容::
原因：OxideMerge 比較伺服器傳回的 HTML，看不到指令碼加入的內容。
它不會在瀏覽器中開啟網頁，因此網頁的指令碼一律不會執行。
框架中的內容不列入比較。
+
無法下載的資源，以及因位於本機或私人網路而被略過的資源，都會在狀態列中計數。

=== 效能

大型檔案比較緩慢或占用大量記憶體::
原因：文字比較會在記憶體中保留解碼後的文字、比較資料與編輯紀錄，實際用量取決於內容與您的操作。
二進位與影像檢視也會載入完整的檔案。
+
--
* 16 MiB 以上的有效 UTF-8 檔案會分段載入；
  UTF-16 與舊式編碼的檔案則會整個解碼。
  文字仍可編輯，比較規則也照常運作。
* 檔案合計 32 MB 以上的文字比較會在背景開啟：右下角的「正在開啟」視窗會顯示檔名與經過的秒數，
  視窗的其他部分仍可照常使用。
  按下其中的「取消」會停止比較，通常在不到一秒內停止，且不會開啟分頁。
* 檔案大於「選項 → 一般」中的「醒目提示的檔案上限」（預設為 16 MB），
  或每 MB 超過 3,125 行（16 MB 即 50,000 行）時，會關閉語法醒目提示，並顯示訊息說明超過的是哪一項上限。
  若要醒目提示更大的檔案，請提高上限；醒目提示每一行都需要時間與記憶體。
* 編輯、復原、自動換行與特殊的比較規則，仍可能增加記憶體用量。
--
+
解決方法：若要減少記憶體用量，可使用二進位比較，或改以大小與日期而非內容比較資料夾（請參閱
<<compare-methods>>）。

[[limitations]]
== 已知限制

本章列出 OxideMerge 不支援或僅部分支援的功能。
若您的工作流程需要用到其中某個領域，請先閱讀本章。

* 壓縮檔：支援 ZIP 類格式、TAR（未壓縮、gzip、bzip2、xz 與 Zstandard）與 7z，
  包括受密碼保護的 ZIP 與 7z。
  不支援 RAR 與分割成多個部分的壓縮檔（`.zip.001`、`.7z.001`）。
* 文字窗格主要用於檢閱與合併變更，並非完整的編輯器。
  內嵌檢視無法編輯。
* 解譯器外掛程式使用外部命令，不支援 WinMerge 的外掛程式動態連結程式庫與指令碼。
* 網頁比較不支援 Cookie 或登入，需要登入的網頁會顯示其登入畫面。
  網頁的指令碼不會執行，因此看不到指令碼加入的內容。
  框架中的內容不列入比較。
* 語意比較一次只複製一個值，且只在重新讀取檔案能確認編輯結果時才會複製。
  它不會移動陣列元素，也不會一次合併所有變更。
* 資料夾同步只適用於本機資料夾，且只在您啟動時執行。
  重新命名的檔案會顯示為一次刪除加一次複製。
* SFTP 與 FTP：FTP 主動模式無法經由代理伺服器使用，在 NAT 後方也很少能用。
  以採用 SHA-1 的 RSA 或 ECDSA P-521 簽署的 SSH 主機憑證會被拒絕。
  `~/.ssh/config` 中的 `Match exec` 與 `Match canonical` 永遠不符合。
  終端機上的提問只能以 `Ctrl+C` 中止。
* 介面翻譯由機器輔助完成，尚未經過母語人士審閱。
